# 실기기 E2E — 시안 · iOS · 안드로이드를 나란히 본다

골든 대조(`test/figma_conformance_test.dart`)는 **위젯을 그려 픽셀만** 맞댄다.
글꼴 대체·이모지 폭·상태바 높이·안전영역처럼 **기기에서만 드러나는 것**은 못 잡는다.
여기는 그걸 본다.

## 쓰는 법

```bash
bash tool/e2e_shot.sh guardian_home         # 두 기기에서 찍는다
python3 tool/e2e_compare.py guardian_home   # 시안과 나란히 붙인다
# → e2e/shots/compare/guardian_home.png
```

한쪽만 돌리려면 `bash tool/e2e_shot.sh guardian_home ios`.

**나란히로는 몇 px 어긋났는지 모른다.** 겹쳐야 보인다.

```bash
python3 tool/e2e_overlay.py guardian_home vs    # iOS 위에 안드로이드 (권장)
python3 tool/e2e_overlay.py guardian_home ios   # 시안 위에 iOS
```

### 무엇 위에 무엇을 겹치나 — 골라 써야 한다

| 겹치기 | 언제 | 왜 |
|---|---|---|
| **iOS ↔ Android** (`vs`) | 거의 항상 | 같은 계정이라 **데이터가 같다.** 남는 붉은 것이 곧 플랫폼 차이 |
| 시안 ↔ 기기 | 데이터가 안 바뀌는 화면만 (로그인·역할 선택·온보딩) | 목록 화면은 시안 문구와 실데이터가 달라 **붉은 것의 대부분이 데이터 차이**다 |
| 시안 ↔ 골든 (`tool/figma_diff.py`) | 자리를 수치로 재야 할 때 | 시험 데이터가 시안과 같게 맞춰져 있다 |

> ⚠️ **`vs` 가 못 쓰이는 화면이 있다.** 로그인은 시안이 플랫폼별로 나와 **두 기기가
> 일부러 다른 그림을 그린다** (#338) — 병아리가 서로 반대쪽을 본다. 겹치면 33%가
> 붉어지는데 전부 의도한 차이다. 이런 화면은 **각자 제 시안과** 겹친다.
> `flows.json` 의 `figma` 를 `{"ios": …, "android": …}` 로 적어 두면 도구가 알아서 고른다.

**겹치기는 세로를 자동으로 맞춘다.** 기기마다 상태바가 달라(시안·iPhone 59,
에뮬레이터 24) 그대로 겹치면 통째로 어긋난다. 몇 px 밀어 보며 가장 잘 맞는 자리를
찾고 그 값을 그림에 찍는다 — **찾은 이동량이 −35쯤이면 상태바 차이라 정상**이고,
그 밖이면 진짜로 밀린 것이다.

보호자 홈을 `vs` 로 겹치면 **6.18%**가 다른데, 붉은 것이 **글자에만** 몰려 있고
카드 상자·진행률 원·버튼은 멀쩡하다 — 자리는 같고 글꼴 래스터라이저만 다르다는 뜻이다.

### 금방 사라지는 화면은 연사로 잡는다

```bash
python3 tool/e2e_burst.py splash android    # 찍고 나서 고른다
```

`launchApp` 은 **프로세스가 떴을 때** 돌아온다 — 첫 프레임이 아니다. 시작 화면은
**1.7초만** 떠 있는데 에뮬레이터는 명령 사이가 수백 ms 라, 기다렸다 찍으면
이미 다음 화면이다. 실제로 `assertNotVisible` 을 통과한 직후 찍힌 것이 로그인이었다.

연사는 앱을 올리며 쉬지 않고 찍은 뒤 **시안에 가장 가까운 한 장**을 남긴다.
고른 값이 20%를 넘으면 그 화면을 한 번도 못 잡은 것이므로 경고하고 실패한다 —
엉뚱한 프레임이 조용히 증적이 되는 것을 막는다. 시안이 없는 플로우에는 쓸 수 없다.

## 화면을 하나 더 올리려면

1. `e2e/flows/<이름>.yaml` 에 플로우를 쓴다. 끝에 `takeScreenshot: <이름>` 을 둔다.
2. `e2e/flows.json` 에 제목·시안 경로·노드 번호를 적는다.
   시안이 플랫폼별로 갈렸으면 `"figma": {"ios": …, "android": …}` 로 적는다.
3. 위 두 명령을 돌린다.

### 글자 없는 화면에는 이름을 준다

시작 화면에는 로고 하나뿐이라 Maestro 가 기다릴 것이 없었다. `semanticsLabel` 을
주면 **화면 낭독기에도 읽히고** 시험도 그 화면이 떴는지 알 수 있다.
없으면 앱이 뜨기도 전에 셔터가 내려가 **런처 화면이 찍힌다.**

## 지켜야 할 것

**`clearState` 를 쓰지 않는다.** 세션이 날아가면 소셜 로그인부터 다시 해야 하는데
그건 자동화할 수 없다. 한 번 로그인해 둔 기기를 계속 쓴다.

**`extendedWaitUntil` 로 화면이 다 뜬 것을 확인하고 찍는다.** 덜 뜬 화면을 찍으면
돌릴 때마다 다른 그림이 나와 비교가 무의미해진다.

**세 벌은 크기가 다르다.** iPhone 16 Pro 1206×2622 · 에뮬레이터 1080×2400 ·
시안 export 393×852. 가로를 맞춰 줄일 뿐 **픽셀을 맞대지 않는다** — 사람이 눈으로
견주는 그림이다. 수치가 필요하면 `tool/figma_diff.py` 를 쓴다.

## ⚠️ 안드로이드는 언제나 위로 올라가 보인다 — 헛경보의 첫 번째 원인

첫 화면(보호자 홈)을 올리자마자 안드로이드가 30~40 위로 밀려 보였다. **결함이 아니다.**

| | 상태바 | 내용 시작 | **상태바 아래 여백** |
|---|---|---|---|
| 시안 | 59 | 85.0 | **26** |
| iOS | 59 | 86.7 | **27.7** |
| Android | **24** | 48.8 | **24.8** |

에뮬레이터 상태바가 iPhone 보다 35 낮아서 그만큼 통째로 올라간 것이고,
**상태바 아래 여백은 셋이 같다.** 안전영역을 제대로 따르고 있다는 뜻이다.

> **절대 y 를 맞대지 않는다.** 안드로이드는 늘 위로 보인다. 재야 할 것은
> **상태바 아래 여백**이고, 그게 같으면 맞은 것이다.

## 알아둘 것

- `takeScreenshot` 은 실행한 자리가 아니라 `~/.maestro/tests/…/takeScreenshot/` 에
  떨어지고 **14일 뒤 지워진다.** 러너가 레포 안으로 옮겨 온다.
- 기기를 고정하지 않으면 Maestro 가 시뮬레이터·에뮬레이터 중 아무거나 잡는다.
  러너가 `--udid` 를 항상 박는다.

겹쳐 봐도 거의 붉지 않다 — 붉은 것은 글자와 시안에 없는 알약뿐이다.
