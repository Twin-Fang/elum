# 3. 강화(Reinforcement)

이번 자문에서 가장 중요한 전문 개념이다.

소장님은 행동 카드를 단순히 보여주는 것보다, 행동을 수행했을 때 얻을 수 있는 것을 보호자가 설정하고 앱에서 이를 계속 상기시키는 것이 중요하다고 반복해서 설명했다.

이후 설명에서 다음 개념까지 연결되었다.

- 사회적 강화
- 지연 강화
- 즉각 강화

## 정확한 의미

행동분석에서 강화는 단순히 **“상을 준다”**는 의미가 아니다.

> 어떤 행동 이후 특정 결과가 주어졌고, 그 결과로 인해 앞으로 그 행동이 더 자주 발생한다면 해당 결과가 행동을 강화했다고 본다.

예를 들어 다음 상황만으로는 엄밀하게 강화를 확정할 수 없다.

```text
학교에 감
→ 엄마가 김밥을 줌
```

이후 실제로

```text
다음에도 학교에 가는 행동이 증가함
```

까지 나타나야 행동분석적으로 강화라고 할 수 있다.

## ELUM에서의 적용

보호자 UI에서는 사용 편의를 위해 **“보상 설정”**이라고 표현할 수 있다.

다만 전문적인 발표나 문서에서는 다음과 같이 표현하는 것이 더 정확하다.

> 강화물(Reinforcer) 설정

또는

> 사용자에게 동기를 제공할 수 있는 강화물(보상)을 보호자가 설정

---

# 4. 강화물(Reinforcer)

전사에서는 주로 “보상”이라고 표현했지만, 행동분석에서 더 정확하게 연결되는 용어는 **강화물(Reinforcer)**이다.

강화물은 행동 뒤에 제공되었을 때 해당 행동의 미래 발생 가능성을 높이는 자극이나 상황이다.

예:

- 김밥
- 유튜브
- 산책
- 게임
- 좋아하는 캐릭터 영상
- 특정 놀이

다만 강화물은 사람마다 다르다.

A에게 김밥이 강화물이라고 해서 B에게도 강화물이 되는 것은 아니다.

따라서 소장님이 설명한 것처럼 앱이 임의로 강화물을 결정하기보다 **보호자가 사용자의 실제 선호를 바탕으로 설정하는 구조**가 더 적절하다.

### 권장 구조

```text
보호자가 실제 선호 강화물 설정
↓
앱이 행동 수행 전·중·후에 해당 강화물을 상기
```

---

# 5. 사회적 강화(Social Reinforcement)

소장님은 자문 중 **“사회적 인정, 사회적 강화”**라는 표현을 사용했다.

사회적 강화란 다음과 같은 타인의 사회적 반응이 행동 증가에 영향을 주는 경우를 말한다.

- 칭찬
- 미소
- 인정
- 관심
- 긍정적인 말
- 하이파이브

ELUM에서 사용하는

> “잘했어요!”

같은 캐릭터 반응 역시 사회적 강화와 유사한 목적을 가질 수 있다.

다만 화면에 칭찬 문구를 표시했다고 해서 자동으로 강화가 되는 것은 아니다.

해당 사용자의 행동을 실제로 증가시키는 기능을 해야 강화라고 할 수 있다.

---

# 6. 지연 강화(Delayed Reinforcement)와 즉각 강화

소장님은 발달장애 사용자의 행동 동기를 설명하면서 지연 강화와 즉각 강화 개념을 언급했다.

## 지연 강화

행동 이후 강화물이 일정 시간이 지난 후 제공되는 구조이다.

```text
오늘 행동 수행
↓
한 달 뒤 보상
```

## 즉각 강화

행동을 수행한 직후 또는 가까운 시점에 강화가 제공되는 구조이다.

```text
목표 행동 수행
↓
바로 칭찬 / 선호 활동 / 보상
```

## 서비스 적용 시 주의

전사에서는 발달장애인의 지연 강화가 매우 어렵다는 취지의 강한 표현이 있었지만, 이를 모든 발달장애인에게 일반화해서 표현하는 것은 적절하지 않다.

개인차가 크기 때문에 문서에서는 다음 정도가 안전하다.

> 일부 발달장애인은 장기간 지연된 결과보다 행동과 가까운 시점의 명확한 강화에서 행동-결과 관계를 이해하기 쉬울 수 있으므로, 초기에는 즉각적이고 명확한 강화를 고려한다.

# 7. ABA — 응용행동분석(Applied Behavior Analysis)

전사에서 가장 중요한 전사 오류 가능성이 있는 부분이다.

전사에는 다음과 같이 기록되어 있다.

- “AB 원리”
- “응용해로운 분석”

문맥상 **ABA / 응용행동분석(Applied Behavior Analysis)**을 의미한 것으로 보는 것이 매우 자연스럽다.

다만 음원 자체를 다시 대조하지 않은 상태이므로 100% 단정해서는 안 된다.

## ABA란?

응용행동분석은 행동분석의 원리를 실제 생활에서 의미 있는 행동에 적용하는 체계적인 접근이다.

주로 다음과 같은 목적과 연결된다.

- 새로운 기술 습득
- 독립 행동 증가
- 행동 수행 지원
- 환경과 행동 결과의 관계 분석
- 필요한 행동의 유지 및 일반화

ABA에서 자주 활용되는 개념으로는 다음과 같은 것들이 있다.

- Reinforcement
- Prompting
- Task Analysis
- Chaining
- Naturalistic Intervention

따라서 이번 자문에서 나온

```text
강화
과제분석
체이닝
단계별 수행
독립 수행
보호자 지원 감소
```

는 서로 별개의 이야기가 아니라 행동분석적인 하나의 구조로 연결될 수 있다.

## ELUM 발표에서 주의할 표현

현재 단계에서

> “ABA 기반 치료 앱”

이라고 표현하는 것은 피하는 것이 좋다.

현재 서비스는 ABA의 일부 원리를 참고할 수 있지만, 임상적인 ABA 중재 프로그램으로 검증된 것은 아니다.

따라서 다음 정도가 적절하다.

> ABA 및 특수교육에서 활용되는 과제분석·강화·연쇄 원리를 참고했다.

# 8. 과제분석(Task Analysis)

ELUM의 행동 카드 생성과 가장 직접적으로 연결되는 전문 개념이다.

## 의미

하나의 복잡한 행동을 **가르치거나 수행 가능한 작은 행동 단위로 분해하는 것**이다.

예를 들어 다음 과제가 있다고 한다.

```text
학교 가기
```

과제분석을 적용하면 다음과 같이 분리할 수 있다.

```text
1. 옷 입기
2. 가방 챙기기
3. 신발 신기
4. 집 밖으로 나가기
5. 정류장으로 가기
6. 버스 타기
7. 버스에서 내리기
8. 학교로 이동하기
```

ELUM에서 AI가 사용자 입력을 행동 카드 여러 개로 나누는 기능은 **AI를 활용한 과제분석 초안 생성**과 매우 가까운 구조라고 볼 수 있다.

---

# 9. 과제분석과 개별화

소장님은 같은 10단계 과제라고 하더라도 사용자마다 도움이 필요한 단계가 다를 수 있다고 설명했다.

예:

```text
사용자 A
→ 1, 2, 8단계에 도움 필요

사용자 B
→ 4, 5, 6, 7, 8단계에 도움 필요

사용자 C
→ 1, 10단계에만 도움 필요
```

따라서 AI가 동일한 일과에 항상 같은 개수의 행동 카드를 생성하는 구조는 적절하지 않을 수 있다.

### 단순한 구조

```text
AI가 항상 8단계 생성
```

### 개선된 구조

```text
AI가 초기 과제분석 생성
        ↓
보호자가 사용자 수행 수준에 맞게
추가 / 삭제 / 수정 / 재배열
        ↓
개인별 행동 시퀀스 완성
```

즉 AI 결과는 **최종 정답이 아니라 보호자가 수정할 수 있는 초안**으로 다루는 것이 적절하다.

# 10. 체이닝(Chaining, 연쇄)

소장님이 직접 **“체인잉, 연쇄작업”**이라는 용어를 사용했다.

## 의미

과제분석을 통해 나누어진 작은 행동을 순서대로 연결하여 하나의 전체 기술을 습득하도록 하는 방법이다.

예:

```text
칫솔 집기
→ 치약 열기
→ 치약 짜기
→ 양치하기
→ 헹구기
```

### 과제분석과 체이닝의 차이

**Task Analysis**

> 어떤 단계로 나눌 것인가?

**Chaining**

> 나눈 단계를 어떤 순서와 방법으로 가르치고 연결할 것인가?

ELUM에서는 행동 카드 자체가 과제분석 결과에 가깝고, 사용자가 카드를 하나씩 순서대로 수행하도록 하는 과정은 체이닝과 연결할 수 있다.

# 11. 백워드 체이닝(Backward Chaining)

전사에서 소장님은 **“뒤에서부터 완성하게 하는 방법은 백워체닝”**이라고 설명했다.

정식 용어는 **Backward Chaining**이다.

## 예시

양치가 다음과 같은 5단계라고 가정한다.

```text
1. 칫솔 집기
2. 치약 짜기
3. 양치하기
4. 입 헹구기
5. 칫솔 정리하기
```

처음에는 보호자나 지도자가 1~4단계를 지원하고, 사용자는 마지막 단계만 수행한다.

```text
5. 칫솔 정리하기
```

이 단계가 익숙해지면:

```text
4. 입 헹구기
5. 칫솔 정리하기
```

를 사용자가 수행한다.

점차 앞 단계까지 독립 수행 범위를 넓힌다.

## 관련 개념

### Forward Chaining

처음 단계부터 순차적으로 늘린다.

```text
1단계
→ 1~2단계
→ 1~3단계
→ ...
```

### Total Task Teaching

전체 과제를 매번 수행하면서 필요한 단계에서만 도움을 제공하는 방식이다.

이 세 방식은 향후 사용자별 행동 지원 수준을 개인화할 때 참고할 수 있다.

# 12. 개별화교육계획

소장님은 **“개별화된 교육 계획”**이 필요하다는 표현을 사용했다.

특수교육 분야에서 실제로 존재하는 개념이다.

한국에서도 특수교육대상자의 교육적 요구에 맞게 개별화교육계획을 수립하는 제도가 존재한다.

## ELUM에서의 표현 주의

ELUM이 직접

> 개별화교육계획을 자동 생성한다.

라고 표현하면 안 된다.

공식적인 개별화교육계획은 교사, 보호자 및 관련 인력이 참여하는 교육적 계획이다.

ELUM에서는 다음 정도로 표현하는 것이 적절하다.

> 사용자의 개별 수행 수준에 맞춘 행동 단계 개인화

# 13. 생활연령(Chronological Age)

생활연령은 실제 출생일부터 계산한 연령을 의미한다.

예:

```text
2005년 출생
2026년 현재 21세
→ 생활연령 21세
```

서비스 대상을 단순히 생활연령만으로 제한하는 것은 현재 ELUM 구조에는 적절하지 않을 수 있다는 것이 소장님의 의견이었다.

# 14. 발달연령(Developmental Age)

발달연령은 특정 발달 영역에서의 수행 수준을 연령 등가로 표현하는 개념이다.

예를 들어 실제 연령과 언어, 인지, 사회성 등의 발달 수준이 다를 수 있다.

## 중요한 주의점

한 사람 전체를 하나의 발달연령으로 환원하는 방식은 ELUM 개인화에는 적절하지 않다.

같은 사람도 다음 능력들이 서로 다를 수 있기 때문이다.

- 언어
- 사회성
- 읽기
- 이동
- 스마트폰 사용
- 일상생활 기술
- 행동 순서 이해

따라서 ELUM 초기 설정에서도 다음처럼 단일 숫자를 받기보다는:

```text
발달연령: 7세
```

다음과 같이 기능별 능력을 받는 것이 더 적절하다.

```text
글 읽기 가능
그림 이해 가능
행동 순서 이해 가능
스마트폰 독립 조작 가능
대중교통 일부 독립 수행 가능
```

# 15. 셀프 모델링(Self-modeling)

소장님은 사용자의 얼굴을 행동 카드나 캐릭터에 반영하는 방식을 설명하면서 **셀프 모델링**이라는 표현을 사용했다.

다만 학술적으로 흔히 사용하는 **Video Self-Modeling**과는 차이가 있다.

## Video Self-Modeling

사용자가 자신이 목표 행동을 수행하는 영상을 보고 해당 행동을 학습하는 방식이다.

예:

```text
자신이 교실에 들어가 인사하는 모습
↓
편집된 영상을 시청
↓
실제 인사 행동 연습
```

반면 ELUM에서 현재 고려하는

```text
사용자 얼굴을 AI 캐릭터에 반영
```

은 엄밀히 말하면 Video Self-Modeling이라고 하기 어렵다.

따라서 다음 표현을 권장한다.

- 사용자 모습을 반영한 개인화 시각자료
- 자기참조형 시각자료
- 사용자 캐릭터 기반 행동 카드

실제 본인의 행동 영상을 활용하는 기능을 구현한다면 Video Self-Modeling과 더 직접적으로 연결할 수 있다.

# 16. 추상화와 Iconicity

소장님은 실제 사진과 그림 카드를 비교하면서, 이미지가 추상화될수록 일부 사용자가 이해하기 어려울 수 있다고 설명했다.

예:

```text
실물 사진
→ 사실적 그림
→ 카툰
→ 선화
→ 추상 기호
```

이 문제와 연결되는 개념 중 하나가 **Iconicity(도상성)**이다.

Iconicity는 시각적 표현이 실제 대상과 얼마나 유사한지를 의미한다.

일반적으로:

```text
실물 사진        → 실제 대상과 높은 유사성
사실적 그림
카툰
단순 선화
추상 기호        → 낮은 유사성
```

정도로 생각할 수 있다.

다만 이를

> 발달장애인은 사진만 이해하고 그림은 이해하지 못한다.

라고 일반화해서는 안 된다.

개인차가 크기 때문에 ELUM에서는 장기적으로 다음처럼 사용자별 시각자료 수준을 선택하는 기능을 고려할 수 있다.

```text
시각자료 유형
- 실제 사진
- 사실적 이미지
- 카툰 이미지
```

# 17. 시퀀스(Sequence) / 시퀀싱(Sequencing)

소장님은 사용자가 행동의 **시퀀스**를 이해할 수 있어야 한다고 설명했다.

시퀀스는 단순 일정과 구분할 필요가 있다.

## 스케줄

```text
09:00 학교
12:00 점심
16:00 귀가
```

## 행동 시퀀스

```text
가방 챙기기
→ 신발 신기
→ 집 나가기
→ 버스 타기
→ 학교 도착
```

ELUM은 단순 일정 관리보다 후자의 **순차적인 행동 수행 지원**에 더 가깝다.

따라서 서비스 성격도 단순 Schedule Management보다는 **Sequential Routine / Task Support** 성격이 강하다.

# 18. 발달장애와 신경발달장애 구분

후반부에서 소장님은 다음과 같은 여러 장애를 함께 언급했다.

- 지적장애
- 자폐
- 학습장애
- ADHD
- 운동장애
- 틱
- 언어 관련 장애

여기서는 **한국 법률상 발달장애인과 정신의학적 신경발달장애 범주를 구분해야 한다.**

## 국내 법률상 발달장애인

국내 발달장애인 지원 법체계에서 주요 대상은 다음과 같다.

- 지적장애인
- 자폐성장애인
- 그 밖에 법령에서 정한 발달장애인

따라서 ADHD가 있다고 해서 자동으로 국내 법률상 발달장애인이 되는 것은 아니다.

## 정신의학적 신경발달장애

정신의학적 Neurodevelopmental Disorders 범주는 더 넓으며 다음 등이 포함된다.

- 지적장애
- 자폐스펙트럼장애
- ADHD
- 의사소통장애
- 특정학습장애
- 운동장애
- 틱장애

따라서 발표에서 다음처럼 단순하게 표현하면 부정확하다.

> 발달장애에는 ADHD도 포함된다.

대신 다음 정도가 적절하다.

> 정신의학적 신경발달장애 범주에는 ADHD와 특정학습장애 등이 포함되지만, 국내 법률상 발달장애인 범주와는 구분된다.

# 19. 경계선 지적 기능(Borderline Intellectual Functioning)

전사에는 **“경계성급”**이라는 표현이 기록되어 있다.

`경계성급`은 표준 전문용어로 확인되지 않았으며, 문맥상 **경계선 지능 또는 경계선 지적 기능(Borderline Intellectual Functioning)**을 의미한 것으로 추정된다.

과거에는 특정 IQ 구간을 중심으로 설명하기도 했지만, 현재는 단순 IQ 숫자 하나만으로 기능 수준을 판단하는 데 한계가 있다는 점이 강조된다.

ELUM에서도 다음처럼 IQ 숫자만으로 기능을 분기하는 것은 권장하기 어렵다.

```text
IQ 80 → 기능 A
IQ 60 → 기능 B
```

대신 실제 서비스 이용에 필요한 기능을 직접 확인하는 것이 더 적절하다.

예:

- 문장 이해 여부
- 그림 이해 여부
- 순서 이해 여부
- 스마트폰 사용 여부
- 일상 행동 독립 수행 수준

---

# 20. 장애 급수 표현 주의

소장님은 후반부에서 과거의 1급·2급·3급 등의 장애등급 체계를 설명했고, 본인도 **“옛날 기준”**이라고 언급했다.

한국의 장애등급제는 현재 과거와 같은 1~6급 체계를 그대로 사용하지 않는다.

따라서 ELUM의 신규 사용자 프로필을 다음과 같이 구성하는 것은 적절하지 않다.

```text
지적장애 1급
지적장애 2급
지적장애 3급
```

서비스 개인화를 위해서는 장애등급 자체보다 다음 정보가 더 직접적이다.

- 글 이해 가능 여부
- 그림 이해 가능 여부
- 순서 이해 가능 여부
- 스마트폰 조작 가능 여부
- 각 행동 단계의 독립 수행 여부

# 21. ‘소상강화’ 표현

전사에는 **“소상강화”**라는 표현이 기록되어 있다.

해당 표현이 행동분석의 표준 전문용어인지 확인할 수 없었다.

따라서 정확한 원어는 **모르겠습니다.**

다만 당시 문맥은 다음과 같다.

```text
최종 강화물
        ↑
단계 4 완료
        ↑
단계 3 완료
        ↑
단계 2 완료
        ↑
단계 1 완료
```

즉 각 중간 단계를 완료하고 다음으로 넘어가는 것 자체가 작은 동기부여나 강화적 기능을 할 수 있다는 설명이었다.

문서에서는 `소상강화`라는 단어를 그대로 사용하기보다 다음과 같이 표현하는 것이 안전하다.

- 단계별 완료에 따른 강화
- 중간 단계 완료가 제공하는 강화적 효과
- 단계 수행 자체가 제공하는 중간 동기

|---|---|---:|

이번 전문가 자문을 기준으로 ELUM의 서비스 구조를 전문 개념과 연결하면 다음과 같이 정리할 수 있다.

```text
[보호자 / 지도자]
사용자의 현재 수행 수준 확인
        ↓

        ↓

        ↓

[체이닝 / Chaining]

        ↓

처음에는 도움

        ↓

[자립 지원]
보호자 없이도 일과 수행
```

# 24. AI가 담당할 부분과 보호자가 담당할 부분

## AI가 담당하기 적절한 부분

ELUM의 AI가 가장 자연스럽게 담당할 수 있는 영역은 **과제분석의 초안 생성**이다.

```text
보호자의 자연어 입력
↓
AI가 행동 단계 초안 생성
↓
행동 카드 및 시각자료 생성
```

## 보호자가 담당해야 할 부분

```text
과제분석 검토
+
사용자별 단계 추가·삭제
+
단계 순서 수정
+
강화물 설정
+
실제 수행 결과 확인
```

AI가 모든 것을 결정하기보다 보호자가 사용자 특성에 맞게 최종 조정하는 구조가 중요하다.

# 25. 발표·보고서에서 권장하는 설명

단순히 다음과 같이 설명하기보다:

> AI가 루틴을 행동 카드로 바꿔준다.

전문가 자문을 반영하여 다음과 같이 설명하는 것이 더 적절하다.

> **보호자가 입력한 일상 과제를 AI가 과제분석(Task Analysis) 방식의 작은 행동 단계로 구조화하고, 보호자가 사용자의 실제 수행 수준에 따라 이를 개별화한 뒤, 강화와 순차적 행동 지원을 통해 독립 수행을 돕는다.**

단, 다음 표현은 현재 근거상 피하는 것이 좋다.

> ABA 기반 치료 앱

대신:

> **ABA 및 특수교육에서 활용되는 과제분석·강화·연쇄 원리를 참고한 일상생활 자립 지원 서비스**

정도가 현재 서비스 성격과 가장 잘 맞는다.

# 26. 최종 핵심 용어 관계

이번 미팅에서 가장 중요한 전문용어만 관계도로 정리하면 다음과 같다.

```text
응용행동분석(ABA)
│
├─ 강화(Reinforcement)
│   ├─ 사회적 강화
│   ├─ 즉각 강화
│   └─ 지연 강화
│
├─ 과제분석(Task Analysis)
│   └─ 복잡한 행동을 작은 단계로 분해
│
└─ 연쇄(Chaining)
    ├─ Forward Chaining
    ├─ Backward Chaining
    └─ Total Task 방식
```

ELUM에서는 이를 다음처럼 연결할 수 있다.

```text
자연어 일과 입력
→ AI 과제분석 초안
→ 보호자 개별화
→ 행동 시퀀스 제시
→ 단계별 수행
→ 강화물 상기
→ 보호자 도움 감소
→ 독립적인 일과 수행 지원
```
