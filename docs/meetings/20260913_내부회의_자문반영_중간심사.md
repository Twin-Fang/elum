## 안건 1 — 강화(보상) 기능을 9/18 전에 넣을 것인가 ⏱️ 30분

**이 회의의 핵심이다.** 자문의 최대 지적이자, 구현하면 완성도 20점에 직결되고,
못 하면 "자문 받고 반영 안 한 팀"이 된다.

| 안 | 범위 | 소요 | 리스크 |
| --- | --- | --- | --- |
| **A. 전부 구현** | `Routine` 보상 필드 + 설정 화면 + 아동 배너 + 완료 화면 연동 | 3~4일 | 서버·클라 동시 변경 → APK 빌드 실패 시 **제출물 자체가 위험** |
| **B. 최소 구현 (권장)** | 보상 **설정 화면 + 아동 수행 화면 배너** 2개 화면. 저장은 기존 일과 필드 확장 최소화 | 1.5~2일 | 리포트·알림은 다음으로 미룸 |
| **C. 미구현 + 발표 반영** | 코드는 그대로, PPT에 "자문 반영 계획"으로만 제시 | 0.5일 | 완성도 점수 손해 · "말만 했다"는 인상 |

> **결정 시 함께 정할 것**
> - 보상 입력 방식 — **프리셋(간식·유튜브·놀이·산책) + 직접 입력** vs 자유 텍스트만
>   → 자문·토닥이 실증 모두 *"보호자 자유 서술 부담이 크다"* 를 지적했다. 프리셋 우선이 안전하다.
> - **보상 텍스트도 DLP를 태울 것인가** — 서비스 원칙 2번 유지하려면 태워야 한다.

**결정: ✅ B — 최소 구현**

- 범위: **보상 설정 화면 1개 + 아동 수행 화면 보상 배너 1개**
- 제외: 수행률 리포트 · 알림 · 카드 추가/순서 변경 → **본선(10/28)까지로 미룬다**
- 보상 입력: **프리셋(간식·유튜브·놀이·산책) + 직접 입력** — 보호자 입력 부담 최소화
- 보상 텍스트도 **DLP 경유** (서비스 원칙 2번 유지)

**실제 변경 지점 (코드 확인 완료)**

| 서버 | 클라이언트 |
| --- | --- |
| `V9__add_reward_to_routine.sql` 🆕 | `reward_setup_screen.dart` 🆕 |
| `Routine.java` 필드 | `app_router.dart` 라우트 (question → reward → generating) |
| `RoutineCreateRequest` / `RoutineResponse` | `routine.dart` 모델 필드 |
| `RoutineService` 매핑 | `child_routine_detail_screen.dart` 배너 |
| DLP 진입점 재사용 | `child_routine_notifier.dart` 값 전달 |

신규 파일 2개, 나머지는 필드 추가 수준 — **기존 구조를 바꾸지 않아 APK 빌드 위험이 낮다.**

## 안건 2 — 타겟 정의를 발표에서 어떻게 말할 것인가 ⏱️ 15분

자문 결과 **"7~12세 아동" → "행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인"** 으로 문서를 바꿨다.
그런데 **앱의 디자인·문구·캐릭터는 여전히 아동용**이다.

| 쟁점 | 선택지 |
| --- | --- |
| 발표에서 대상을 어디까지 말할지 | ① 아동 중심 유지 + "성인도 확장 가능" ② 발달장애인 전반으로 전면 재정의 |
| 앱 문구("아이", "하늘아") 수정 여부 | 중간심사 전 / 본선 전 / 유지 |
| 캐릭터(루미·포포·루루) | 유지 — 자문에서 카툰형 이미지도 충분하다고 확인됨 |

> ⚠️ 토닥이는 중간심사에서 **"구체적인 타겟 명확화가 필요하다"** 는 지적을 받았다.
> 우리도 같은 질문을 받을 가능성이 높으니, **한 문장으로 답할 수 있게** 정리해 둔다.

**결정: ✅ 발달장애인 전반으로 전면 재정의**

> **"행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인"** — 연령으로 나누지 않는다.

### ⚠️ 따라오는 문제 — 앱 UI는 아직 아동용이다

| 지점 | 현재 | 성인 사용자 관점 |
| --- | --- | --- |
| 보상 화면 문구 | "루미가 {name}에게 별을 가져왔어요" | 28세 근로자에게는 맞지 않는다 |
| 호칭 | "하늘아", 반말 | 성인에게 반말 |
| 캐릭터 | 병아리·여우·고양이 | 자문에서 **카툰형도 충분**하다고 확인됨 → 유지 가능 |

**대응 (후속 결정)**

| 시점 | 할 일 |
| --- | --- |
| **중간심사 (9/18)** | UI는 그대로 두고, 발표에서 **"구조는 연령 무관 · 현재 빌드는 아동 프리셋"** 으로 설명한다 |
| **본선 (10/28)** | 온보딩에 **사용자 유형(아동/성인) 선택**을 넣어 호칭·말투 프리셋을 분기한다 |

> 캐릭터는 바꾸지 않는다. 자문에서 *"현재 타겟 기준에서는 카툰형 이미지도 충분하다"* 고 확인됐다.

## 안건 3 — 토닥이 대비 차별화 메시지 확정 ⏱️ 15분

PPT 필수 항목에 "국내·외 유사 사례 비교"가 있고, 참신성 배점이 20점이다.
[분석 문서](../hackathon/전년도수상작_토닥이_분석.md)의 초안을 팀 문장으로 확정한다.

```text
초안 — "토닥이는 정해진 일정을 예측 가능하게 보여줍니다.
        이룸은 그 앞단, '학교 갈 준비를 해야 해'라는 한 문장을
        수행 가능한 행동 단계로 쪼갭니다.
        그리고 그 과정에서 아이의 이름도 학교도 진단명도 AI에게 넘기지 않습니다."
```

| 확정할 것 | 내용 |
| --- | --- |
| 차별점 우선순위 | ① 과제분석 자동화 ② AI DLP ③ 진단명 없는 개인화 ④ 보호자 승인 게이트 — **이 순서가 맞는가** |
| 비교 대상 범위 | 토닥이만 vs 종이 그림카드·일정관리 앱까지 포함 |

**결정: ✅ 과제분석 자동화를 맨 앞에**

```text
1) 한 문장 → 행동 단계 자동 분해   (ABA의 과제분석 자동화)
2) AI DLP Gateway
3) 진단명 없는 개인화
4) 보호자 승인 게이트
```

**이유** — 심사위원 5명 중 **3명이 장애인 전문가**이고, 본선 **시민평가단 30점**도 현장 감각으로 채점한다.
DLP는 기술 전문가 2명에게 강하지만, 첫 문장으로 쓰면 "장애 서비스"가 아니라 "보안 서비스"로 들린다.

**비교 대상은 토닥이 + 종이 그림카드 + 일정관리 앱** 세 가지로 넓힌다 —
토닥이만 비교하면 대회 내부 비교로만 보인다.

## 안건 5 — 시연 영상 시나리오 ⏱️ 10분

**현장 실시간 시연은 하지 않는다.** 네트워크·AI 응답 지연으로 배점이 날아갈 수 있다.

```text
녹화 시나리오 (2~3분)
  보호자 온보딩 (호칭 + 도움 목표)
    → 일과 입력 "내일 비가 많이 올 예정이야…"
    → DLP 전/후 비교 화면          ← 기술 심사위원용 핵심 장면
    → AI 추가 질문
    → 카드 생성 → 보호자 수정·승인
    → [보상 설정]                   ← 안건 1에서 B 이상 선택 시
    → 아동 모드 전환 → 카드 수행 → 별 보상
```

### ✅ 확정

| 항목 | 확정 |
| --- | --- |
| 길이 | **2분 30초 내외** — 발표 10분 중 시연에 3분을 배정 |
| 녹화 기기 | 실기기 화면 녹화 (에뮬레이터는 "진짜 도는가" 의심을 산다) |
| 자막 | **필수** — 현장 스피커 상태를 신뢰할 수 없다. TTS 음성은 자막으로 함께 보여준다 |
| 나레이션 | 넣지 않는다 — 발표자가 직접 설명하며 재생 |
| 강조 장면 | **카드 생성 순간 + 캐릭터가 동일하게 등장하는 삽화**에서 2초 정지 |
| DLP 화면 | 흐름상 지나가되 **설명하지 않는다** (결정 10) — 편집으로 짧게 넘긴다 |
| 개인정보 | 실명·실제 학교명 입력 금지 — 데모 페르소나 `하늘이` 고정 |
| 백업 | 영상 외에 **주요 장면 스크린샷 5~6장**을 PPT에 별도 삽입 |

## 안건 6 — 실증 계획 ⏱️ 15분

**본선 필수 요건이다.** 안 하면 최종심사 발표 요건을 못 채운다.

| 정할 것 | 내용 |
| --- | --- |
| 협력 기관 | 서울 ABA연구소 — 소장님께 실증 협조를 **언제 정식으로 요청할지** |
| 참여자 규모 | 최소 3~4명 (실증보고서 예시 표가 A~D 4명 기준) |
| 동의 절차 | 보호자 동의서 양식 필요 — 누가 만들지 |
| 실증 시기 | **10월 초~중순** (10/28 보고서 마감 역산 — 보고서 작성에 최소 1주 필요) |
| 요청 시점 | ✅ **중간심사 직후** 정식 요청 — 심사 피드백까지 반영한 빌드로 실증한다 |
| 설문지 | 보호자용·아동용 2종 — 토닥이 방식(리커트 5점 + 자유서술 4문항) 차용 |
| 사진 | 최소 3장 · 얼굴 비노출 |
