## 안건 1 — 강화(보상) 기능을 9/18 전에 넣을 것인가 ⏱️ 30분

**이 회의의 핵심이다.** 자문의 최대 지적이자, 구현하면 완성도 20점에 직결되고,
못 하면 "자문 받고 반영 안 한 팀"이 된다.

| 안 | 범위 | 소요 | 리스크 |
| --- | --- | --- | --- |
| **A. 전부 구현** | `Routine` 보상 필드 + 설정 화면 + 아동 배너 + 완료 화면 연동 | 3~4일 | 서버·클라 동시 변경 → APK 빌드 실패 시 **제출물 자체가 위험** |
| **B. 최소 구현 (권장)** | 보상 **설정 화면 + 아동 수행 화면 배너** 2개 화면. 저장은 기존 일과 필드 확장 최소화 | 1.5~2일 | 리포트·알림은 다음으로 미룸 |
| **C. 미구현 + 발표 반영** | 코드는 그대로, PPT에 "자문 반영 계획"으로만 제시 | 0.5일 | 완성도 점수 손해 · "말만 했다"는 인상 |

> **결정 시 함께 정할 것**
> - 보상 입력 방식 — **프리셋(간식·유튜브·놀이·산책) + 직접 입력** vs 자유 텍스트만
>   → 자문·토닥이 실증 모두 *"보호자 자유 서술 부담이 크다"* 를 지적했다. 프리셋 우선이 안전하다.
> - **보상 텍스트도 DLP를 태울 것인가** — 서비스 원칙 2번 유지하려면 태워야 한다.

**결정:** ☐ A ☐ B ☐ C → ______________

## 안건 2 — 타겟 정의를 발표에서 어떻게 말할 것인가 ⏱️ 15분

자문 결과 **"7~12세 아동" → "행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인"** 으로 문서를 바꿨다.
그런데 **앱의 디자인·문구·캐릭터는 여전히 아동용**이다.

| 쟁점 | 선택지 |
| --- | --- |
| 발표에서 대상을 어디까지 말할지 | ① 아동 중심 유지 + "성인도 확장 가능" ② 발달장애인 전반으로 전면 재정의 |
| 앱 문구("아이", "하늘아") 수정 여부 | 중간심사 전 / 본선 전 / 유지 |
| 캐릭터(루미·포포·루루) | 유지 — 자문에서 카툰형 이미지도 충분하다고 확인됨 |

> ⚠️ 토닥이는 중간심사에서 **"구체적인 타겟 명확화가 필요하다"** 는 지적을 받았다.
> 우리도 같은 질문을 받을 가능성이 높으니, **한 문장으로 답할 수 있게** 정리해 둔다.

**결정:** 발표에서 쓸 타겟 한 문장 → ______________

PPT 필수 항목에 "국내·외 유사 사례 비교"가 있고, 참신성 배점이 20점이다.
[분석 문서](../hackathon/전년도수상작_토닥이_분석.md)의 초안을 팀 문장으로 확정한다.

```text
초안 — "토닥이는 정해진 일정을 예측 가능하게 보여줍니다.
        이룸은 그 앞단, '학교 갈 준비를 해야 해'라는 한 문장을
        수행 가능한 행동 단계로 쪼갭니다.
        그리고 그 과정에서 아이의 이름도 학교도 진단명도 AI에게 넘기지 않습니다."
```

## 안건 5 — 시연 영상 시나리오 ⏱️ 10분

**현장 실시간 시연은 하지 않는다.** 네트워크·AI 응답 지연으로 배점이 날아갈 수 있다.

```text
녹화 시나리오 (2~3분)
  보호자 온보딩 (호칭 + 도움 목표)
    → 일과 입력 "내일 비가 많이 올 예정이야…"
    → DLP 전/후 비교 화면          ← 기술 심사위원용 핵심 장면
    → AI 추가 질문
    → 카드 생성 → 보호자 수정·승인
    → [보상 설정]                   ← 안건 1에서 B 이상 선택 시
    → 아동 모드 전환 → 카드 수행 → 별 보상
```

| 정할 것 | |
| --- | --- |
| 녹화 기기 · 화면 크기 | |
| 나레이션 · 자막 여부 | |
| 개인정보 노출 점검 | 실명·실제 학교명 입력 금지 |
