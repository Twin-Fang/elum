📝 현재 문제점
---

- 그림 화풍은 서버 전체에 하나("플랫 벡터, 파스텔")뿐이고 사용자별로 고를 수 없다. 카드에는 캐릭터(루루, 포포)가 들어간다.
- 현장 피드백: 애니메이션풍 그림은 발달장애인에게 추상화가 어렵다. 실제 물건과 장소를 사진처럼 보여 주는 그림이 필요하다.
- AI 그림을 아예 쓰고 싶지 않은 사용자도 있다. 지금은 AI 그림 생성 여부를 서버 전체 스위치와 요금제 권한으로만 정한다.

🛠️ 해결 방안 / 제안 기능
---

- 프로필(이룸이 단위)에 **그림 방식**을 저장한다: `만화`(기본, 지금 방식), `실사`, `직접 사진`.
- `실사`: 사진처럼 그리는 프롬프트를 새로 만든다. **캐릭터는 넣지 않고** 캐릭터 참조 이미지도 보내지 않는다. 물건이나 장소 하나를 또렷하게, 단순한 배경으로 그린다.
- `직접 사진`: AI 그림 생성을 건너뛴다. 카드 글 생성은 계속 AI가 한다(범위는 그림만). 그림이 없는 카드는 기본 카드로 보인다(클라 이슈).
- 그림 방식을 바꾸는 API를 만들고, 프로필 응답에 그림 방식을 내려 준다. 값이 없거나 이상하면 `만화`로 처리한다.
- 이미 만든 카드 그림은 바꾸지 않는다. 새로 만드는 카드부터 적용한다.
- 신규 프롬프트는 DB에 없으면 코드 기본값이 심긴다. 이미 있는 프롬프트를 고치는 경우는 관리자 화면에서 운영 값도 고친다.
- 실사 품질 시험은 **가장 싼 모델(FLUX schnell)로만** 몇 장 해 보고, 부족해서 다른 모델이 필요하면 호출 전에 가격을 말하고 확인받는다. 생성 호출을 반복하지 않는다.
- 진단명은 받지 않는다(원칙 1). 그림 방식은 개인화 목표(`supportGoals`)와 별개의 화면 설정이다.

⚙️ 작업 내용
---

- 프로필 그림 방식 필드와 마이그레이션(현재 마지막 번호 V27 다음), 조회·변경 API
- 실사 프롬프트 키 추가와 화풍별 프롬프트 선택, 실사에서 캐릭터 참조 제외
- `직접 사진`이면 이미지 생성 호출 생략(크레딧도 쓰지 않음)
- 서버 테스트: 화풍별 프롬프트 선택, 실사에서 참조 이미지 미전송, 직접 사진에서 생성 미호출, 이상한 값은 만화로
- 로컬 DB 리허설로 마이그레이션 확인(AI 키는 가짜로)
