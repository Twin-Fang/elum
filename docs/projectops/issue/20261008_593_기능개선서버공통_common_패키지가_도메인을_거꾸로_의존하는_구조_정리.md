📝 현재 문제점
---

- 공통 패키지 `common`이 도메인 패키지를 import한다. 의존 방향이 거꾸로다.
  - `GlobalExceptionHandler`가 admin 컨트롤러 두 개를 import한다.
  - `JwtProvider`와 `JwtAuthenticationFilter`가 `link.core.LinkRole`을 import한다.
  - `EnabledLocales`, `MaintenanceModeFilter`, `AppStatusController`, `SecurityConfig`가 `SystemConfigService`를 직접 쓴다.
- 서비스가 다른 도메인의 repository를 직접 import한다. member 쪽이 28건, credit 쪽이 25건이다. 한 도메인의 스키마가 바뀌면 다른 도메인과 admin이 같이 깨진다.
- 이런 규칙을 지키는지 자동으로 검사하는 장치가 없다.

🛠️ 해결 방안 / 제안 기능
---

- common의 역의존을 없앤다.
  - 예외 핸들러 대상은 마커 애노테이션으로 지정한다.
  - 설정 조회는 common에 인터페이스를 두고 systemconfig가 구현한다.
- 다른 도메인 repository를 직접 쓰는 곳은 그 도메인의 조회·서비스를 거치게 바꾼다. 트랜잭션 경계가 바뀌지 않는 곳부터 바꾼다.
- ArchUnit 테스트로 규칙을 고정한다. 아직 남은 위반은 동결 목록으로 두어 새로 생기는 위반만 막는다.

⚙️ 작업 내용
---

- 운영 중이므로 동작은 그대로 둔다. API 경로, 응답 모양, 에러 코드, 트랜잭션 전파를 바꾸지 않는다.
- `./gradlew test` 통과 확인
