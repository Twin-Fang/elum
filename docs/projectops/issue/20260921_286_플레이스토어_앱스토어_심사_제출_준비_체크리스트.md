📝 현재 문제점
---

이룸을 Google Play와 App Store에 정식 출시하려고 합니다. 빌드 파이프라인은 이미 돌고 있습니다.
`main`에 푸시할 때마다 Android AAB는 Play 내부 테스트 트랙으로, iOS 빌드는 TestFlight로 자동으로 올라갑니다. 2026-09-21에 1.22.0으로 둘 다 성공했습니다.

**Google Play (2026-09-21 콘솔 직접 확인)**

- 앱이 `앱 초안` 상태입니다. 대시보드의 `앱 설정` 할 일 11개가 **전부 미완료**입니다. 앱 콘텐츠 선언 10개(개인정보처리방침, 광고, 로그인 세부정보, 콘텐츠 등급, 타겟층, 데이터 보안, 광고 ID, 정부 앱, 금융 기능, 건강 앱)와 스토어 설정, 스토어 등록정보입니다.
- 개인 개발자 계정이라 **테스터 12명 이상이 14일 이상 참여한 비공개 테스트**를 마쳐야 프로덕션 액세스를 신청할 수 있습니다. 지금 참여 테스터는 0명입니다.
- 비공개 테스트는 `앱 설정`을 끝내야 시작할 수 있습니다. **그래서 앱 설정이 전체 일정의 첫 관문입니다.**
- 내부 테스트 트랙은 동작 중입니다. 1.23.0이 내부 테스터에게 배포돼 있습니다.
- **앱 서명 키가 업로드 키와 다릅니다**(Play 앱 서명 사용 중). 그래서 4단계의 SHA-1 등록이 필요합니다.
- 개발자 계정 정책 상태는 문제없음, Android 개발자 인증 등록은 완료입니다.
- 개발자 이름이 `ROMROM`입니다. 이대로 두면 스토어에 이룸의 개발자로 `ROMROM`이 표시됩니다.
- 로그인 세부정보 선언에 "Google은 앱 검토를 위해 **새 계정을 만들 수 없다**"고 명시돼 있습니다. 소셜 로그인만 있는 지금 구조로는 심사관이 쓸 로그인 정보를 따로 준비해야 합니다.

**App Store (2026-09-21 콘솔 직접 확인)**

- TestFlight에는 1.23.0 (155)까지 올라가 있습니다. App Store 심사 제출 이력은 없습니다.
- 버전 페이지(`1.0 제출 준비 중`), 앱 정보(부제, 카테고리, 콘텐츠 권한, 연령 등급), 개인정보(처리방침 URL, 설문), 가격 및 배포 국가가 **전부 비어 있습니다.**
- 비즈니스 → **대한민국 규정 준수가 미완료**입니다. 대한민국 법에 따라 연락처 이메일을 한국 App Store 제품 페이지에 공개하고, 사업자등록번호가 있는지 답해야 합니다.
- 가격 및 사용 가능 여부에서 **Apple Silicon Mac 배포가 기본으로 켜져 있습니다.** Mac에서는 검증한 적이 없습니다.
- 무료 앱 계약은 활성 상태입니다. 유료 앱 계약은 미서명이지만 무료 앱이라 지금은 필요 없습니다.

**코드를 점검해 보니 심사 전에 손봐야 할 것이 있습니다**

- 개인정보처리방침, 고객 지원, 계정 삭제 안내를 볼 수 있는 **공개 웹 주소가 없습니다.** 두 스토어 모두 필수입니다. 서버에는 JSON API(`/api/consents/documents`)만 있습니다.
- 개인정보처리방침(`server/src/main/resources/consent/privacy.txt`)에 **외부 AI로 보내는 내용, 처리 위탁, 국외 이전, 개인정보 보호책임자**가 없습니다. Apple은 개인정보를 외부 AI로 보낼 때 분명히 알리고 동의를 받으라고 요구합니다(가이드라인 5.1.2(i)).
- 가입한 뒤에는 앱 안에서 **개인정보처리방침을 다시 볼 곳이 없습니다.** 설정 메뉴에는 휴대폰 연결, 로그아웃, 회원 탈퇴만 있습니다(`guardian_settings_screen.dart`). Apple은 앱 안에서도 쉽게 찾을 수 있어야 한다고 요구합니다(5.1.1(i)).
- AI가 만든 카드를 **신고할 방법이 없습니다.** Google Play의 AI 생성 콘텐츠 정책은 앱을 벗어나지 않고 신고할 수 있는 기능을 요구합니다.
- 회원 탈퇴 때 **Apple 로그인 토큰을 철회하지 않습니다.** Apple 로그인을 제공하는 앱은 탈퇴 시 철회 API를 불러야 합니다(5.1.1(v)).
- iOS가 **iPad까지 지원**하도록 설정돼 있습니다(`TARGETED_DEVICE_FAMILY = 1,2`). 이대로 두면 iPad 스크린샷이 필수가 되고 심사관이 iPad에서도 확인합니다.
- 세로 고정이 없어 **휴대폰을 가로로 돌리면 화면도 돌아갑니다.** 가로 화면은 검증한 적이 없습니다.
- 홈 화면 앱 이름이 iOS는 `Elum`, Android는 `elum`입니다.

(나) 심사 전용 카카오 계정: 카카오톡이 없는 기기에서는 카카오계정 웹 로그인으로 들어갑니다. (다) 아이디, 비밀번호 로그인 추가: 가장 확실하지만 코드 작업이 필요합니다. **롬롬 심사 때 통과한 방법이 있으면 그대로 씁니다.** iOS는 Apple 로그인으로도 가입할 수 있다고 심사 노트에 함께 적습니다. 🔒

- [ ] **Mac 배포**: App Store에서 Apple Silicon Mac 배포를 끄기를 추천합니다. 기본으로 켜져 있고, Mac에서는 검증한 적이 없습니다.
- [ ] **수출 규정(암호화) 답변**: App Store Connect 앱 정보 화면은 "Apple 운영체제의 암호화 대신, 또는 함께 쓰는 표준 암호화 알고리즘"이면 문서를 내라고 안내합니다. 이룸은 AI 요청을 AES-256-GCM으로 직접(Dart 패키지) 암호화합니다(`aidlp_crypto.dart`). 그래서 지금 `Info.plist`의 `ITSAppUsesNonExemptEncryption = false`가 사실과 어긋날 가능성이 큽니다. 설문을 같이 보며 답을 정하고, 필요하면 `Info.plist`를 고칩니다.

### 4단계. 소셜 로그인 운영 전환 (콘솔 작업) 🔒

Play에서 받은 앱은 **Google이 다시 서명**합니다(Play 앱 서명). 콘솔에서 확인해 보니 **앱 서명 키가 업로드 키와 다릅니다.** 업로드 키 값만 등록해 두면 스토어에서 받은 앱에서 로그인이 실패합니다. 심사관이 로그인에서 막히면 바로 반려입니다.

- [ ] Play Console → Google Play로 보호됨 → 앱 서명에서 **앱 서명 키 인증서 SHA-1, SHA-256** 확인
- [ ] Google Cloud Console의 Android OAuth 클라이언트(`kr.twinfang.elum`)에 앱 서명 키 SHA-1 추가 (Firebase 프로젝트에도 등록돼 있다면 거기도)
- [ ] Google OAuth 동의 화면 게시 상태가 `프로덕션`인지 확인 (`테스트` 상태면 등록한 테스트 사용자만 로그인됩니다)
- [ ] 카카오 Developers의 Android 키 해시에 앱 서명 키 해시 추가
- [ ] 네이버 Developers에서 애플리케이션이 `개발 중` 상태면 **검수 요청** (개발 중에는 멤버로 등록한 아이디만 로그인됩니다. 검수 기간이 걸리므로 일찍 넣습니다)
- [ ] 확인: **Play 내부 테스트 링크로 설치한 앱**에서 카카오, 네이버, 구글 로그인 모두 성공 (직접 설치한 APK로는 확인이 안 됩니다)
