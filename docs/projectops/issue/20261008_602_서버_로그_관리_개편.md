📝 현재 문제점
---

- 관리자 "서버 로그" 화면은 현재 파일의 끝 1000줄만 2초 폴링으로 보여준다. 몇 시간 전 오류는 밀려나 볼 수 없다.
- 롤링된 지난 로그(`.log.gz`)는 화면, API 어디서도 볼 수 없고 파일째 받을 방법이 없다.
- 운영 로그 레벨에 `org.hibernate.type.descriptor: TRACE`가 남아 SQL 바인딩 값이 줄마다 찍혀 오류가 소음에 묻힌다.
- Blue/Green 배포에서 두 컨테이너가 같은 NAS 폴더(`/app`)를 마운트해 같은 `logs/elum-server.log`에 쓴다.
  - 배포 중 1~2분간 서로 다른 JVM이 한 파일에 쓰고 각자 롤링한다. 줄이 엉뚱한 파일로 가거나 유실될 수 있다.
  - 컨테이너 안 PID가 항상 1이라 어느 색 로그인지 구분할 수 없다.
  - 헬스체크에 실패한 새 컨테이너는 `docker rm`되며 콘솔 로그도 사라져 배포 실패 원인을 볼 곳이 없다.
- 참고: 서버는 log4j가 아니라 Spring Boot 기본 logback(`logback-spring.xml`)을 쓴다.

🛠️ 해결 방안 / 제안 기능
---

- 로그를 색깔별 폴더로 나눈다: `logs/blue/`, `logs/green/` 아래 `elum.log`, `elum-error.log`(WARN 이상, 30일 보관). 줄마다 `[blue]`/`[green]` 표시.
- 배포 워크플로가 컨테이너에 인스턴스 색과 포트를 넘기고, 서버가 기동/준비완료/종료를 `logs/deploy-history.log`에 남긴다.
- 관리자 로그 화면을 탭으로 재구성한다.
  - 상단: 지금 응답 중인 서버(색, 버전, 시작 시각, 포트)와 최근 24시간 ERROR 건수
  - 실시간: 색/파일 선택, 레벨 필터, 키워드 하이라이트
  - 파일: 폴더별 목록, 용량, 다운로드, 삭제(현재 쓰는 파일은 삭제 불가)
  - 검색: `.gz` 포함 레벨, 키워드 검색. 스택트레이스는 한 건으로 묶음
  - 배포 이력: 성공/종료/실패/기동 중 타임라인
  - 레벨: 재배포 없이 로거 레벨 변경(응답 중인 서버에만, 재배포 시 원래 값)
- 사이드바와 대시보드에 최근 ERROR 건수를 표시한다.
- 운영 로그 레벨에서 TRACE만 끈다. DEBUG는 유지한다.

⚙️ 작업 내용
---

- `logback-spring.xml` 색깔별 폴더, 오류 전용 파일, 최근 ERROR 메모리 집계
- `application-prod.yml` TRACE 제거
- `PROJECT-SPRING-CICD.yaml` 컨테이너 환경변수(인스턴스 색, 포트) 추가
- `build.gradle` 빌드 정보(버전) 생성
- 관리자 로그 API: 인스턴스, tail, 파일 목록, 다운로드, 검색, 삭제, 배포 이력, 로거 레벨, 최근 오류
- 경로 검증(로그 폴더 밖, 패턴 밖 파일 거부)
- `logs.html` 재구성, 사이드바 배지, 대시보드 카드
- 단위, 보안 테스트와 배포 후 운영 실측
- 설계: `docs/superpowers/specs/2026-10-08-admin-log-management-design.md`
