📝 현재 문제점
---

**iOS에서 일과 입력 화면을 빠져나와도 키보드가 남습니다.** (iPhone 17 Pro에서 확인)

**재현**

1. 보호자 홈 → `새로운 일과 만들기`
2. `오늘은 어떤 준비가 필요한가요?` 화면에서 입력칸을 눌러 키보드를 띄운다
3. 왼쪽 위 **뒤로가기**를 누른다
4. 홈으로 돌아왔는데 **키보드가 화면 아래 그대로 떠 있다**

홈 화면 절반이 키보드에 가려집니다. `지난 일과`가 잘려 보이고, 빈 곳을 한 번 눌러야 사라집니다.

**원인** — 화면을 떠날 때 **포커스를 놓지 않습니다.**

`routine_input_screen.dart`에는 `unfocus`를 부르는 곳이 **하나도 없습니다.** 입력칸이 포커스를 쥔 채 라우트가 닫히면, iOS는 키보드를 내릴 까닭을 알지 못해 그대로 둡니다. 안드로이드는 대체로 알아서 내려 주기 때문에 **iOS에서만 드러납니다.**

나가는 길이 셋인데 어느 쪽에도 처리가 없습니다.

| 어디 | 무엇 |
|---|---|
| `PopScope` (76행) | 시스템 뒤로가기(스와이프) |
| 뒤로가기 버튼 (148행) | 적은 내용이 없을 때 바로 닫기 |
| 확인 팝업 뒤 (150행) | 적다 만 내용이 있을 때 |

**같은 문제가 있을 곳을 전수로 봤습니다.**

입력칸이 있는 화면은 일곱이고, 그중 **셋만** 포커스를 놓고 있습니다.

| 화면 | `unfocus` |
|---|---|
| 연결 암호 입력 | ✅ |
| 이름 입력 | ✅ |
| 비밀암호 | ✅ |
| **일과 입력** | ❌ ← 이번에 제보된 화면 |
| **추가 질문** | ❌ |
| **카드 편집 시트** | ❌ |
| **보상 입력 칩** | ❌ |

**넷이 같은 결함을 안고 있을 수 있습니다.** 나머지 셋은 어느 화면에서 나갈 때 처리하는지까지 확인해야 합니다.

🛠️ 해결 방안 / 제안 기능
---

**화면을 떠나기 직전에 포커스를 놓습니다.**

```dart
FocusManager.instance.primaryFocus?.unfocus();
```

- **나가는 길마다 넣지 않습니다.** 세 곳에 흩뿌리면 넷째 길이 생겼을 때 또 빠뜨립니다. 닫는 동작을 한 곳으로 모으고 거기서 한 번만 부릅니다
- `dispose`에 넣는 것으로는 늦습니다. 라우트가 이미 닫힌 뒤라 iOS가 키보드를 남긴 채 화면만 바꿉니다
- 나머지 세 화면(추가 질문 · 카드 편집 시트 · 보상 칩)도 **같은 방식으로 함께** 고칩니다. 하나씩 제보를 기다리면 같은 이슈를 네 번 씁니다

**확인할 것**

| 경우 | 기대 |
|---|---|
| 뒤로가기 버튼 | 키보드가 함께 사라진다 |
| 화면 가장자리 스와이프(iOS) | 같다 |
| 적다 만 내용이 있어 확인 팝업이 뜰 때 | 팝업 뒤에 키보드가 남지 않는다 |
| 팝업에서 **머무르기**를 고를 때 | 키보드가 다시 올라오거나, 적어도 입력칸을 가리지 않는다 |
| 바텀시트(카드 편집) | 시트를 내릴 때 함께 사라진다 |
