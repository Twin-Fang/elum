🗒️ 설명
---

AI 크레딧(#407) 화면을 상태별로 렌더해 디자인 요청(#420)을 만들다가, **안내 문구나 사전 확인이 실제 서버 동작과 어긋나는 곳 3군데**를 찾았다. 시안과 상관없이 고칠 수 있는 동작 결함이다.

**① 잔액 0인데 "끝까지 만들어져요"라고 안내한다**
- `CreditLowNotice`(`client/lib/features/guardian/presentation/widgets/credit_low_notice.dart`)는 `available < 11`이면 뜬다. **0도 포함된다.**
- 0일 때 문구는 `크레딧이 0개 남았어요. 그림이 여러 장 생성돼도 이번 일과는 끝까지 만들어지고 크레딧은 0이 될 수 있어요`다.
- 실제로는 `카드 만들기` → `POST /api/routines`에서 `AI_CREDIT_INSUFFICIENT`(403)로 막힌다. 정책상 "끝까지"는 **1 이상일 때 시작한** 일과에만 적용된다 (#407 정책 4번).
- 흐름 도중 0이 되는 경우는 흔하다. 다른 보호자 휴대폰에서 쓰거나, 흐름을 시작한 뒤 다른 일과가 완성되는 경우다.

**② 이미 만드는 중이어도 홈에서 미리 막지 않는다**
- 홈 사전 확인(`client/lib/features/credit/application/credit_start_gate.dart`)은 `enabled && !canStartRoutine`만 본다.
- 서버의 `canStartRoutine`은 "사용 가능 ≥ 일과 글 단가 && 멈춘 계정 아님"이다 (`CreditControllerDocs.java:32`). **진행 중인 작업은 반영되지 않는다.**
- 그래서 입력 → 질문 → 보상까지 다 채운 뒤, 생성 요청에서 `AI_CREDIT_JOB_IN_PROGRESS`(409)로 실패 화면을 본다. 입력한 내용은 버려진다.

**③ 다시 채워지는 시각에 시간대가 없다**
- 서버 `CreditSummaryResponse.nextResetAt`은 `LocalDateTime`이라 시간대 없이 `2026-09-28T00:00:00`처럼 간다.
- 앱은 이것을 **기기 시각**으로 읽어 `9월 28일(월) 0시`로 보여준다.
- 기기 시간대가 한국이 아니면 날짜와 시각이 실제 초기화 시각(한국 월요일 0시)과 어긋난다. 해외 체류 보호자나 시간대 설정이 다른 기기가 해당된다.

🔄 재현 방법
---

**①**
1. 보호자 A 휴대폰에서 일과 만들기를 시작해 추가 질문 화면까지 간다 (잔액 1 이상)
2. 같은 계정의 다른 휴대폰에서 일과를 만들어 잔액을 0으로 만든다
3. A에서 답을 고른다 → 띠에 "0개 남았어요… 끝까지 만들어지고" 표시
4. `카드 만들기` → 실패 화면 `카드를 만들지 못했어요` + `AI_CREDIT_INSUFFICIENT`

**②**
1. 일과 하나를 만드는 중(생성 로딩)에 앱을 나가거나 다른 휴대폰에서
2. 홈 `새로운 일과 만들기` → 막히지 않고 입력 화면으로 들어간다
3. 끝까지 채우고 `카드 만들기` → `AI_CREDIT_JOB_IN_PROGRESS`

**③**
1. 기기 시간대를 미국 등으로 바꾼다
2. 설정 크레딧 카드와 홈 0 잔액 팝업의 `…에 다시 채워져요` 날짜·시각을 확인한다

✅ 예상 동작
---

- **①** 잔액 0이면 "끝까지 만들어져요"라고 하지 않는다. 0 전용 안내("이번 주 크레딧을 다 썼어요. {초기화 시각}부터 다시 만들 수 있어요")를 보이거나, `카드 만들기`를 누르기 전에 막는다. 입력한 내용은 임시저장으로 남길 수 있게 한다.
- **②** 홈 사전 확인에서 진행 중인 `ROUTINE_CREATE`가 있으면 "이미 만들고 있어요" 안내로 미리 막는다. 서버가 `canStartRoutine`에 진행 중 여부를 반영하거나, 앱이 `inProgress`를 함께 본다. 어느 쪽인지는 설계 때 정한다.
- **③** 초기화 시각을 시간대가 있는 형식(`OffsetDateTime`, 예 `2026-09-28T00:00:00+09:00`)으로 보내고, 앱은 그것을 기기 시간대로 바꿔 보여준다. 옛 앱이 시간대 없는 값을 받던 계약이 깨지지 않는지 확인한다.

**함께 볼 것**
- ①의 문구와 모양은 디자인 요청 #420 결과에 따라 바뀔 수 있다. 동작(0이면 끝까지 만든다고 말하지 않음)만 먼저 고친다.
- 홈 사전 확인 중(최대 3초) 반응이 없는 것은 디자인 결정이 필요해 #420에 넣었다.
