📝 현재 문제점
---

- Figma 행동 카드의 그림 칸은 **313×230 (비율 1.361)** 이다(2026-09-30 Figma에서 직접 확인: 보호자_카드확인 262:5211, 일과 진행 1197:6514, 둘 다 `objectFit: cover`).
- 서버가 만드는 그림 비율은 제공자마다 다르고 칸과 맞지 않는다.

| 제공자 | 지금 요청 크기 | 칸(1.361)에 채울 때 잘림 |
|---|---|---|
| OpenAI | 1024×1024 (정사각, 상수) | 위·아래 26.5% |
| FLUX (fal) | 1024×864 (1.185) | 위·아래 12.9% |
| Gemini | 4:3 (1.333) | 위·아래 2.0% |

- 앱은 여기에 1.03배 확대를 더 해서 가장자리가 약 1.5% 더 잘린다. 정사각 그림은 실제로 약 28%가 잘린다.
- 화질을 아끼려고 낮은 품질을 쓰니, 잘리는 만큼 보이는 그림이 더 작고 흐리다.
- 코드 주석이 낡았다: `OpenAiImageClient`는 "칸이 1.19:1이라 정사각이 가장 가깝다"고 하고 `action_card_view.dart` 일부 주석은 그림이 `contain`이라 잘리지 않는다고 하는데, 실제 코드는 `cover`다.
- 앱의 이룸이 상세 그림 칸 상수는 313×264(1.186)인데 오늘 읽은 Figma는 313×230이다. 시안이 바뀌었거나 앱이 예전 값을 쓰고 있다. 어느 쪽인지는 확인하지 못했다.

🛠️ 해결 방안 / 제안 기능
---

**비용을 올리지 않고 시안 비율에 가깝게 만든다.**

- OpenAI: `1024x1024` → `1536x1024`(1.5). 시안에 가장 가까운 공식 지원 크기다. 잘림이 위·아래 26.5%에서 좌·우 9.3%로 줄고 픽셀은 1.5배라 같은 품질 설정(low)에서도 더 선명하다. gpt-image-1-mini의 크기별 정확한 가격은 공식 페이지에서 확인하지 못했다(low 1024×1024 약 $0.005, 큰 크기는 약 $0.006으로 추정). 장당 약 $0.001 늘 수 있다.
- FLUX: `1024×864` → `1152×848`(1.358). 1MP 미만이라 fal의 최소 청구 안에 든다. 이 값은 시안(1.361)과 0.2% 차이다.
- Gemini: 4:3 그대로(이미 2% 안쪽).
- 실사 경로(`generateRealisticImage` 등)도 같은 크기를 쓴다.
- 이미 저장된 옛 그림(정사각 등)은 그대로 둔다. 칸이 `AspectRatio`로 고정이라 어떤 비율이 와도 깨지지 않고, 옛 그림은 지금처럼 위·아래가 잘려 보일 뿐이다.
- 시안 확인: 이룸이 카드 상세의 그림 칸이 313×264인지 313×230인지 디자이너(예람)에게 확인한다. **앱 상수는 이 확인 전에 바꾸지 않는다**(시안과 다르게 바꾸려면 허락이 필요하다). 지금 값에서는 정사각이 오히려 덜 잘린다(15.7%).

**하지 않는 것**: 저품질로 아끼던 것을 medium/high로 올리는 것(비용), 옛 이미지를 다시 만드는 것.

⚙️ 작업 내용
---

- `OpenAiImageClient` size 상수를 `1536x1024`로, 만화·실사 두 경로 모두
- `FluxImageClient` image_size를 `1152x848`로
- 낡은 주석 정정(서버 3개 클라이언트, 클라이언트 `action_card_view.dart`의 contain 주석)
- 단가 설정(`PRICE_OPENAI_IMAGE_PER_IMAGE`)은 크기별 가격 확인 전까지 그대로 두고 이슈에 기록
- 서버 테스트: 요청에 실린 size가 바뀐 값이다
- 이룸이 상세 칸 상수는 디자이너 확인 후 별도로
