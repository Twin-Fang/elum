iOS **2.12.1 (230)** 심사가 **가이드라인 2.1 - Information Needed** 로 리젝됐다. 앱이 AppTrackingTransparency(ATT)를 쓴다고 선언했는데, 심사관이 앱을 열어 보니 추적 허용 팝업을 한 번도 보지 못했다는 내용이다.

한 줄 요약: **ATT 팝업이 "광고를 처음 불러올 때"에만 뜨는 구조라서, 광고가 안 뜨는 경로(광고 꺼짐·로그인 전·요금제 조회 전)로 앱을 쓰는 심사관은 팝업을 영영 못 본다.**

Apple이 요구한 것은 둘 중 하나다.

1. ATT를 구현했다면: 권한 요청이 **최신 OS에서 실제로 뜨도록** 고치고, 아래를 담은 **실기기 화면 녹화**를 답장하거나 App Review Information의 Notes에 넣는다.
   - 새로 설치(또는 추적 권한 초기화) 후 앱 실행
   - 추적 데이터가 수집되기 **전에** ATT 요청이 나타나는 장면
   - 요청 이후의 사용자 흐름
2. 앱이 추적하지 않는다면: App Privacy에서 "추적함" 선언을 빼야 한다(Account Holder/Admin 권한).

### 현재 동작 (코드 근거, `origin/develop` 기준)

ATT는 앱 시작 때 묻지 않는다. 광고 로더 세 곳이 광고를 요청하기 직전에만 `AdConsent.useNonPersonalized()`를 부른다.

- `client/lib/core/ads/ad_consent.dart`: ATT 상태가 `notDetermined`면 500ms 기다린 뒤 `requestTrackingAuthorization()` 호출
- 호출처: `ad_banner_loader.dart:52`, `ad_native_loader.dart:58`, `rewarded_ad_loader.dart:60` (모두 광고 로드 직전)
- `client/lib/core/ads/ad_sdk.dart`: 광고 SDK도 "처음 광고를 요청할 때 한 번만" 초기화한다. `main.dart`에는 ATT·SDK 초기화가 없다.
- `client/lib/core/ads/ad_gate.dart`: 광고는 **로그인한 보호자의 요금제 조회가 끝나고 `adsRemoved == false`일 때만** 요청된다. 조회 중·실패·광고 제거 요금제면 광고도, ATT도 없다.
- `client/ios/Runner/Info.plist`: `NSUserTrackingUsageDescription`은 이미 있다(문구 문제는 아님).
- `client/ios/fastlane/review_notes.txt`: 심사 메모에 "보호자 화면 첫 진입 시 ATT 팝업이 한 번 뜬다"고 적혀 있다.

### 왜 심사관이 못 봤나 (원인 후보)

확정이 아니라, 코드로 좁힌 후보다. 실측 결과를 이 이슈에 댓글로 남긴다.

1. **(유력) 팝업이 광고 요청에 종속돼 있다.** 로그인 전 화면, 역할 선택, 비밀암호 설정, 이룸이 화면에는 광고도 ATT도 없다. 심사관이 보호자 홈까지 가기 전에 끝내면 팝업이 없다.
2. **서버 요금제 플래그.** `FREE_ADS_REMOVED`/`PRO_ADS_REMOVED`가 운영에서 광고를 꺼 둔 상태이면 보호자 홈에 가도 광고 요청이 없어 ATT가 안 뜬다. 운영 값 확인이 필요하다.
3. **타이밍.** 광고 로드가 첫 프레임 직후 앱이 완전히 활성화되기 전에 ATT를 요청하면 iOS가 팝업을 조용히 무시한다. 현재 500ms 대기는 임시방편이다.
4. **iPad.** 심사 기기에 iPad Air가 포함돼 있다(현재 iPhone 전용으로 좁혀 둔 상태인지 빌드 설정 확인).

### 재현 절차

1. 추적 권한 초기화(설정 > 개인정보 보호 > 추적, 또는 앱 삭제 후 재설치)
2. 앱 실행 → 로그인 화면, 역할 선택, 비밀암호 설정 중에는 추적 허용 팝업이 없다.
3. 보호자 홈에서 광고가 요청돼야만 팝업이 뜬다. 광고가 꺼진 계정이면 끝까지 뜨지 않는다.

### 수정 방향 (제안: 앱 시작 직후 묻는다)

앱이 첫 화면을 그린 뒤, **광고 요청과 무관하게** 곧바로 추적 허용 팝업을 띄운다.

- iOS에서만, 상태가 `notDetermined`일 때만 한 번 묻는다. 이미 답한 휴대폰에서는 다시 묻지 않는다.
- 앱이 활성화(`AppLifecycleState.resumed`)된 뒤에 요청해 팝업이 무시되지 않게 한다.
- 허용하면 개인화, 거부·실패하면 비개인화 광고로 요청한다. 거부해도 앱 흐름은 그대로다.
- 광고 로더는 이미 받은 응답(`trackingAuthorizationStatus`)을 읽기만 하고, 로더 안에서 다시 팝업을 띄우는 경로는 안전망으로만 둔다.
- 광고가 꺼진 계정(Pro·요금제 조회 실패)이어도 팝업은 뜬다. 광고를 안 보여 주는 계정에서 추적 허용을 묻는 것이 어색하면, 문구 수정이 필요한지 별도로 검토한다(이 이슈에서는 심사 통과가 우선).
- 팝업 문구는 기존 `NSUserTrackingUsageDescription`을 쓴다.
- 실패 경로: ATT 호출이 예외를 내도 앱은 계속 진행하고 `AppLogger.error`로 남긴다.
