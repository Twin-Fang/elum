📝 현재 문제점
---

- 스토어에 새 버전을 올려도 앱을 연 사람은 새 버전이 나온 걸 모른다. 스토어 자동 업데이트를 꺼 둔 기기는 옛 버전에 계속 머문다.
- 권장 업데이트 팝업은 #660에서 들어갔다. 다만 아래 셋이 문제다.
  - 서버의 `최신 버전` 값(관리자 화면에서 손으로 입력)만 본다. 값을 안 올리면 새 버전을 내도 안 뜬다.
  - 보호자 홈에서만 뜬다. 이룸이 기기는 새 버전 소식을 받지 못한다.
  - 글자뿐인 기본 팝업이다 (#415에서 캐릭터 안내를 제안했다).

🛠️ 해결 방안 / 제안 기능
---

- 앱을 열거나 다시 앞으로 가져올 때, **스토어에 실제로 올라간 버전**을 앱이 직접 확인한다.
  - iOS: App Store 공개 조회로 지금 판매 중인 버전을 읽는다.
  - Android: Play 스토어의 앱 내 업데이트 확인으로 새 버전이 있는지 받는다.
  - 서버의 `최신 버전` 값은 비상용으로 남긴다 (스토어 확인이 안 될 때만 쓴다).
- 심사 중인 버전으로 업데이트를 권하지 않는다. 스토어에 아직 없는 버전을 권하면 사용자가 스토어에 가도 받을 게 없다. 그래서 배포 워크플로가 값을 올리는 방식은 쓰지 않는다.
- 새 버전이 있으면 **닫을 수 있는 업데이트 안내**를 지금 화면 위에 띄운다.
  - 모바일: 아래에서 올라오는 창
  - 태블릿: 가운데 카드
  - 보호자 화면, 이룸이 화면 모두 같은 안내
- `업데이트하기`를 누르면 스토어의 이룸 화면을 연다 (강제 업데이트 화면과 같은 주소, 같은 실패 처리 `E-UPDATE-STORE`).
- `나중에`를 누르면 닫고 하던 화면을 이어서 쓴다. 다시 띄우는 주기는 #660 그대로 **하루 한 번**이다.
- 문구는 #660 문구(5개 언어)를 그대로 쓴다.
- 확인에 실패해도(네트워크, 스토어 응답 형식 다름) 조용히 넘어가고 앱을 막지 않는다.

⚙️ 작업 내용
---

- 스토어 버전 확인 (iOS 공개 조회, Android 앱 내 업데이트 확인)
- 권장 업데이트 안내 (모바일 하단 창, 태블릿 가운데 카드), 새 루미 그림(윙크하며 손 흔드는 모습)
- 닫은 버전 기억 (기기에만 저장)
- 문구 다국어(ko, en, ja, zh, es)
- 시험: 버전 판단, 닫은 버전 기억, 실패 시 통과
