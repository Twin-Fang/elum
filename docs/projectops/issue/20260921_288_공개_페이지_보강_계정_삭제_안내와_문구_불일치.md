📝 현재 문제점
---

스토어 심사(#286)에 필요한 공개 페이지를 점검했습니다. 이미 `gh-pages` 브랜치로 게시된 페이지가 둘 있습니다.

| 페이지 | 주소 | 상태 |
| --- | --- | --- |
| 도움말(지원) | `index.html` | 있음. FAQ 7개와 문의 이메일 |
| 개인정보처리방침 | `privacy.html` | 있음. 위탁, 보호책임자, 시행일까지 적혀 있음 |
| 계정·데이터 삭제 안내 | 없음 | **Play 데이터 보안이 요구하는 전용 주소가 없음** |
| 이용약관 | 없음 | 필수는 아님 |

점검하면서 아래를 찾았습니다.

**1. 지원 페이지가 사실과 다른 말을 합니다**

- 지원 FAQ: "적은 내용이 그대로 밖으로 나가나요? → 아니요. ... **원문은 따로 보관하지 않아요.**"
- 처리방침 5항: "원문은 보호자가 나중에 내용을 확인하고 고칠 수 있도록 **이룸 서버에 보관**되며, 외부로 나가지 않습니다."
- 서버 코드 확인 결과 `Routine.rawInputText`가 `nullable = false`인 TEXT 컬럼입니다. **원문은 저장됩니다.** 처리방침이 맞고 지원 페이지가 틀렸습니다.
- 같은 사이트의 두 페이지가 서로 다른 말을 하고 있고, 그중 하나가 개인정보 처리에 관한 사실과 다릅니다.

**2. 게시된 방침과 앱 안에서 보여주는 동의 문서가 다릅니다**

- 앱은 동의 화면에서 서버가 관리하는 문서를 보여줍니다(#278, `server/src/main/resources/consent/privacy.txt`).
- 게시본에는 있는데 앱 문서에는 없는 것: 처리 위탁(Google LLC, Gemini API), 개인정보 보호책임자, 시행일, 파기 절차, 제3자 제공 조항.
- 심사에서 "게시된 방침과 앱 안 문구가 다르다"는 지적이 나오는 지점입니다. #278 커밋에서도 같은 이유로 문구를 기계로 떠냈습니다.

**3. 국외 이전 고지가 없습니다**

- 게시본 5항은 Google LLC(Gemini API)를 **위탁**으로만 적었습니다. 받는 곳이 국외이므로 국외 이전 고지 항목(이전되는 항목, 국가, 시기와 방법, 받는 자, 이용 목적, 보유 기간, 거부 방법)이 따로 필요한지 확인해야 합니다.

**4. 사실과 다른 수집 항목이 적혀 있습니다**

- 게시본 1항 `계정` 줄에 "아이디, 비밀번호"가 있습니다. 앱은 소셜 로그인만 지원하고 자체 아이디·비밀번호 로그인이 없습니다.

**5. 용어가 저장소 규칙과 다릅니다**

- 게시본은 `당사자`, `아동`, `강화물`을 씁니다. 규칙은 `이룸이`, `보상`입니다. 법적 효력이 있는 문장은 함부로 바꾸지 않되, 바꿀 수 있는 곳은 맞춥니다.

🛠️ 해결 방안 / 제안 기능
---

- **계정·데이터 삭제 안내 페이지를 새로 만듭니다.** Play 데이터 보안 선언에 넣을 전용 주소가 필요합니다. 앱 이름, 앱 안에서 삭제하는 경로(설정 → 회원 탈퇴), 이메일로 요청하는 방법, **지워지는 데이터와 남는 데이터(AI 호출 기록)**, 처리 기간을 적습니다.
- **지원 FAQ의 원문 보관 설명을 사실대로 고칩니다.** 원문을 서버에 보관하되 외부로 내보내지 않는다는 것, 탈퇴하면 함께 지워진다는 것을 적습니다.
- **게시본과 앱 안 문서를 맞춥니다.** 원본을 어디에 둘지 먼저 정합니다. #278로 서버가 원본을 들고 있으므로, 게시 페이지가 서버 문서를 그대로 보여주는 구조로 가면 두 곳이 어긋나지 않습니다. 정적 페이지를 유지한다면 갱신 절차를 문서로 남깁니다.
- **국외 이전 고지를 추가할지 확인받고 반영합니다.** 법적 문구이므로 근거를 남기고 확인을 받습니다.
- **수집 항목에서 아이디·비밀번호 줄을 사실에 맞게 고칩니다.**
- 이용약관 페이지도 함께 게시할지 정합니다. 두 스토어 모두 필수는 아닙니다.
