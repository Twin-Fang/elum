🚀[기능개선][클라][배포] iOS 심사 제출이 이미 올라간 빌드를 재사용하지 못하고 중복 업로드로 실패한다
===

📝 현재 문제점
---

- push 배포(store_only)가 끝난 뒤 `workflow_dispatch store_submit` 으로 심사를 넣으면 실패한다.
  Fastfile `pilot` 이 같은 빌드번호(version_code 213)를 다시 업로드하려다 altool 이 거부한다.
  `ENTITY_ERROR.ATTRIBUTE.INVALID.DUPLICATE — The bundle version must be higher than the previously uploaded version: '44402'`
  (2026-09-29, v2.1.1, run 36566714255)
- 9/24·9/25 에는 됐다. push 직후 dispatch 를 쏴서 concurrency 가 push 실행을 업로드 전에 취소했기 때문이다.
  코드 회귀가 아니라 "push 실행이 끝난 뒤에는 심사 제출이 항상 실패한다"는 원래 있던 구멍이다.
- 테스트 빌드 번호는 `이슈번호 + 2자리 횟수`(#444 → 44402)라 스토어 번호(version_code)보다 훨씬 커서,
  같은 버전에 테스트 빌드가 먼저 올라가면 스토어 빌드도 같은 이유로 막힌다.

🛠️ 해결 방안 / 제안 기능
---

- `pilot` 업로드가 중복 빌드 오류로 실패하고, 심사 준비·제출 모드(store_prepare / store_submit)이면
  업로드를 건너뛰고 `deliver` 단계로 넘어간다. `deliver` 가 `build_number` 로 이미 올라간 빌드를 고른다.
- store_only 에서는 예전처럼 실패시킨다(같은 번호를 두 번 올리려는 건 오류이므로).
- 중복이 아닌 다른 업로드 오류는 그대로 실패시킨다.

⚙️ 작업 내용
---

- `client/ios/fastlane/Fastfile` deploy lane 의 `pilot` 호출을 중복 빌드 오류만 걸러 내는 rescue 로 감싼다.
- 로그에 어떤 이유로 업로드를 건너뛰었는지 남긴다.
