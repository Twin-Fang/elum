**이룸이 휴대폰에서 로그인하기 전에 처음 보는 화면**인데 시안 흔적이 없다. 보호자에게 받은 여섯 글자 연결 암호를 넣는 화면이다 (#205). 개발 쪽이 PIN 화면 박스를 흉내 내 만들었다.

> 이 요청서는 정답을 드리는 게 아니다. 지금 앱 모습과 디자이너가 보통 안 그리게 되는 상태를 **재료로** 모았다. 모양, 문구, 위치 모두 바꿔도 된다. 개발 쪽 추천은 근거와 함께 한 줄씩만 적었다.

![link](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/undesigned_20260925-114504_board_g2_link.png)

### 지금 동작

- 영문과 숫자가 섞여 있어 PIN처럼 숫자패드가 아니라 **시스템 키보드**를 쓴다.
- 여섯 칸을 다 채우면 **바로 확인**한다 (확인 버튼이 없다). 확인 중에는 뒤로가기를 숨기고 스피너를 띄운다.
- 맞으면 이룸이 홈으로 가고, 틀리면 칸을 비우고 다시 넣게 한다.

### 꼭 지켜야 하는 것

- **이룸이가 보는 화면이다.** 틀렸을 때 빨간 테두리, 경고 아이콘을 쓰지 않는다. 원칙 문서가 이 화면을 콕 집어 적어 두었다: "PIN 틀림, 코드 틀림 → 한 번 흔들고 멎는다(440ms), 빨간 테두리 ❌, 경고 아이콘 ❌" (`08-design-principles.md` §6).
- 연결 암호 6칸은 **PIN 화면 박스를 재사용**하기로 되어 있다 (§5-5).
- 용어: 화면에서는 `연결 암호` (2026-09-18 온보딩 합의 #228에 따라 보호자 쪽 화면은 `코드`를 쓴다. 두 화면이 같은 말을 쓸지 정해 주면 좋겠다).
- 터치 영역 64 이상, 글자 20 이상 (이룸이 화면 규칙).

🎯 기대 결과
---

- 처음 / 입력 중 / 확인 중 / 틀림 / 인터넷 끊김 다섯 상태의 시안이 나온다.

📋 참고 자료
---

### 디자이너가 정해 주면 좋은 것

1. **안내 상자**를 둘지. 이룸이가 읽기 어려우면 보호자가 옆에서 넣어 주는 경우가 많을 것이다. 그림(보호자 휴대폰 화면 예시)으로 바꾸는 것도 방법이다.
2. **틀렸을 때** 모양. 흔들림 + 짧은 문구가 원칙이다.
3. **인터넷이 끊겼을 때** 모양. 지금은 틀렸을 때와 같은 빨간 칸이라 이룸이가 **암호를 틀린 줄 안다.**
4. 여섯 칸을 다 채우면 **바로 보낼지, 확인 버튼을 둘지.**
5. `연결 암호` / `코드` 중 무엇으로 부를지.

### 문구 후보

| 자리 | 지금 | 후보 |
|---|---|---|
| 제목 | 보호자에게 연결 암호를 받아주세요 | ① 보호자 휴대폰에 나온 글자를 넣어 주세요 ② 연결 암호를 넣어 주세요 |
| 틀림 | 암호가 맞지 않아요 | 다시 한번 넣어 볼까요? (틀렸다는 말 대신) |
| 인터넷 | 연결하지 못했어요. 인터넷을 확인해주세요 (E-NET) | 인터넷이 연결되면 다시 해 주세요 (코드는 작게 따로) |

**개발 쪽 추천 (정답 아님)**: 틀림과 인터넷 끊김을 **다른 모양**으로 그린다. 틀림은 칸이 흔들리고, 인터넷 끊김은 칸은 그대로 두고 아래에 안내 한 줄을 둔다.
