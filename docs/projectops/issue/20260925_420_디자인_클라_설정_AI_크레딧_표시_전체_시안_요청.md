🖌️ 요청 내용
---

보호자가 AI로 일과를 만들 때 쓰는 **주간 AI 크레딧**이 앱 **일곱 군데**에 나온다. **모두 시안 없이 개발 쪽이 임시로 만든 모양이다** (#407). 모양, 문구, 위치, 쓸지 말지까지 자유롭게 바꿔도 된다.

> 이 요청서는 정답을 드리는 게 아니다. 지금 앱 모습, 디자이너가 보통 안 그리게 되는 상태(적음, 0, 실패, 불러오는 중), 문구 후보, 다른 표현 아이디어를 **재료로** 모았다. 개발 쪽 추천은 근거와 함께 한 줄씩만 적었다.

### 크레딧이 뭔가 (디자인에 필요한 만큼만)

- 보호자 계정마다 **매주 50개**(운영 설정값, 관리자에서 바꾼다), 월요일 0시에 다시 채워진다. 남은 것은 넘어가지 않는다.
- AI가 일과 글을 만들면 **1개**, AI 그림이 들어간 카드 **1장마다 1개**를 쓴다. 예: 카드 4장 일과 = 5개.
- **1개라도 남아 있을 때 시작한 일과는 그림이 많아도 끝까지 만든다.** 대신 남은 것보다 많이 쓰면 잔액은 **0**이 된다 (빚으로 넘어가지 않는다).
- 0이면 새 AI 일과를 **시작할 수 없다**. 만든 일과 보기와 글 직접 고치기는 계속 된다.
- 운영자가 특정 보호자에게 **추가 지급**할 수 있다.

### 실측 검수 결과 (2026-09-25, Android 에뮬레이터 · 운영 서버 · QA 계정)

처음 올린 캡처는 위젯 렌더(가짜 데이터)였다. 실기기로 다시 밟아 **틀린 곳을 본문에서 고쳤다.** 아래가 실제 앱 모습이다 (관리자에서 QA 계정 잔액을 3 → 0 → +20 으로 조정, 일과 생성 1회).

![real](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/realqa_20260925-135245_real_credit.png)

- 주간 지급량은 **50개**다 (운영 설정). 처음 본문의 "100개"는 틀렸다.
- 크레딧이 보이는 곳은 **7군데**다. 보호자 홈의 **운영 공지 팝업**(`[ 이룸 베타 서비스 오픈 안내 ]` · 매주 월요일 크레딧 50개…)이 빠져 있었다. 이 공지 문구는 관리자 화면에서 바뀐다.
- 잔액 3에서 일과를 만들면 `AI 그림 7장 · 3크레딧 사용 · 0 남음`이 나온다. 필요한 양은 8인데 3만 빠지고 0이 된다. 초과 사용을 따로 알려주지 않는다.
- 잔액 0 홈 팝업은 이 폭(1080)에서 한 줄로 들어간다. 처음 적은 "`있어 / 요` 한 글자가 떨어진다"는 좁은 렌더에서만 생긴 것이다.
- 적음 상태 안내는 실기기 폭에서 `크 / 레딧`처럼 단어 중간에서 줄이 바뀐다.
- 추가 지급을 받으면 `20 / 50 크레딧 남음` + `+ 추가 20`이 된다. 주간분은 다 썼고 남은 20은 전부 추가분인데, **합계 40으로 읽힌다.**

### 꼭 지켜야 하는 것

- **구매, 충전, 업그레이드, 요금제처럼 보이는 요소를 넣지 않는다.** 지금은 무료 운영이다 (App Store 심사와도 걸린다).
- **모델 이름, 토큰 수, 금액(달러)은 보여주지 않는다.**
- "1개라도 남았을 때 시작하면 끝까지 만든다 / 0이면 시작할 수 없다" 두 문장의 뜻이 **모든 곳에서 같게** 읽혀야 한다.
- 보호자 화면에만 나온다. 이룸이 화면에는 없다.
- 실패 화면에는 **추적용 코드**(`E-CREDIT`, `AI_CREDIT_...` 같은 것)가 어딘가에 있어야 한다. 제보를 받았을 때 원인을 찾는 유일한 단서다. 보여주는 방식은 바꿔도 된다.
- 말투는 해요체, 능동형, 긍정형이다 (`docs/08-design-principles.md`). 용어표상 사용자에게 `서버`라는 말은 쓰지 않는다.

- 크레딧 일곱 군데의 시안이 나오고, 개발 쪽이 임시 화면을 시안으로 바꾼다.
- 특히 **적음, 0, 초과 사용, 불러오는 중, 실패** 상태까지 모양이 정해진다.

### 1. 문구 후보

지금 문구는 개발 쪽이 쓴 것이다. 수동형("~돼도", "~만들어지고")과 긴 문장이 많다. 후보는 참고용이다.

| 자리 | 지금 | 후보 | 이유 |
|---|---|---|---|
| A 제목 | 이번 주 AI 생성 | ① 이번 주 AI 크레딧 ② 이번 주 남은 크레딧 | 무엇을 세는지 제목에 드러나지 않는다 |
| A 숫자 | 72 / 100 크레딧 남음 | ① 72개 남았어요 (100개 중) ② 72 / 100 | "남음"이 명사형이라 딱딱하다 |
| A 적음 | 그림이 여러 장 생성돼도 이번 일과는 끝까지 만들어지고 크레딧은 0이 될 수 있어요 | ① 조금 남았어요. 시작한 일과는 끝까지 만들어요 ② 부족해도 이번 일과는 끝까지 만들어요 | 수동형 두 번, 한 문장이 너무 길다 |
| A 0 | 이번 주 크레딧을 모두 사용했어요 / 만든 일과 보기와 직접 고치기는 계속 할 수 있어요 | ① 이번 주 크레딧을 다 썼어요 / 만든 일과는 계속 보고 고칠 수 있어요 | 짧게 |
| A 초기화 | 9월 28일(월) 0시에 다시 채워져요 | ① 9월 28일(월) 0시에 50개로 채워 드려요 ② 월요일 0시에 다시 50개 | 수동형, 몇 개로 채워지는지 없다 |
| A 실패 | 사용량을 불러오지 못했어요 | ① 크레딧을 불러오지 못했어요 | "사용량"과 "크레딧"이 섞여 있다 |
| B 제목 | AI 크레딧은 이렇게 줄어요 | ① 크레딧은 이렇게 써요 | 능동형 |
| B 본문 | 3문장 (5줄, 가운데 정렬) | 표나 목록: `일과 글 1개` · `그림 1장마다 1개` · `월요일 0시에 50개` | 숫자를 문장 속에서 찾아야 한다 |
| C | 이번 주 크레딧을 모두 사용했어요 / 9월 28일(월) 0시부터 다시 만들 수 있어요 | (뜻은 좋다) | 좁은 폭에서 마지막 한 글자가 떨어질 수 있다 (1080 폭 실기기는 한 줄) |
| D | 크레딧이 7개 남았어요. 그림이 여러 장 생성돼도 이번 일과는 끝까지 만들어지고 크레딧은 0이 될 수 있어요 | ① 크레딧이 7개 남았어요. 부족해도 이번 일과는 끝까지 만들어요 | A 적음과 같은 문제 |
| E | AI 그림 4장 · 5크레딧 사용 · 67 남음 | ① 크레딧 5개를 썼어요 · 67개 남았어요 ② 그림 4장 · 5개 사용 · 67개 남음 | 단위가 섞여 있다 (5크레딧 / 67) |
| F (크레딧 다 씀) | 이번 주 크레딧을 모두 사용했어요. 월요일 0시에 다시 채워져요. | ① 이번 주 크레딧을 다 썼어요. 9월 28일(월)부터 다시 만들 수 있어요 | C와 같은 말로 맞춘다 |

**단위 이름 자체도 골라 주면 좋겠다.** `크레딧`은 50대 보호자에게 낯선 말일 수 있다. 후보는 `크레딧` / `개` (AI 만들기 72개 남음) / `회`. 단, 글 1개와 그림 1장을 모두 1로 세기 때문에 `회`(횟수)는 뜻이 어긋날 수 있다.

### 2. 표현, UI 요소 아이디어

| 무엇 | 지금 | 다른 안 |
|---|---|---|
| 남은 양 | 가로 막대 | 원형 링 · 10칸짜리 칸 (배터리처럼) · 숫자만 |
| 위치 | 설정 맨 위 카드 | 홈 `새로운 일과 만들기` 버튼 옆 작은 배지 · 둘 다 |
| 쓰는 법 설명 | `?` → 가운데 팝업 | 카드 안 펼치기(아코디언) · 바텀시트 · 카드 아래 작은 글씨로 항상 |
| 적음 경고 | 버튼 위 주황 띠 | 버튼 바로 위 한 줄 캡션 · 버튼 누를 때 확인 팝업 · 설정 카드만 |
| 초과 사용 알림 | 사용량 줄에 `0 남음`만 | 줄을 주황으로 강조 · 저장 뒤 토스트 한 번 · 알리지 않음 |

위치 아이디어를 풀어 쓰면 다음과 같다.

| 안 | 설정 | 홈 |
|---|---|---|
| 지금 | 맨 위 카드 (막대 + 숫자) | 없음 |
| 홈 배지 | 없애거나 작게 | `새로운 일과 만들기` 버튼 안이나 옆에 `72개 남음` |
| 둘 다 | 맨 위 카드 유지 | 버튼 옆 작은 배지 |

**개발 쪽 추천 (정답 아님)**
- 위치는 **"둘 다"**를 추천한다. 크레딧을 확인하려고 설정까지 들어가는 보호자는 드물다. 잔액이 필요한 순간은 만들기 직전이다.
- 초과 사용은 **사용량 줄 강조**를 추천한다. 토스트는 금방 사라져 다시 볼 수 없다.

### 3. 디자이너가 정해 주면 좋은 것

1. 단위 이름 (`크레딧` / `개` / 그 밖의 말)
2. 설정 카드의 큰 숫자 크기. 원래 37이었는데 설정 목록 폭(361)에 맞추느라 개발 쪽에서 32로 줄였다
3. D(만들기 직전 띠)와 E(사용량 줄)를 **둘 다 둘지**. 시안에 없던 요소다
4. 초과 사용(남은 것보다 많이 써서 0이 됨)을 알릴지, 어떻게 알릴지
5. 실패 화면에서 추적 코드를 보여주는 모양 (지금은 `AI_CREDIT_INSUFFICIENT` 원문이 버튼 아래에 그대로 보인다)
6. 홈에서 `새로운 일과 만들기`를 누른 뒤 잔액을 확인하는 동안(최대 3초)의 모양. 지금은 아무 반응이 없어 멈춘 것처럼 보인다
7. B 안내를 팝업으로 둘지, 다른 방식으로 바꿀지
8. 크레딧 기능이 꺼져 있을 때 자리까지 없애는 지금 방식이 괜찮은지
9. **추가 지급 표기.** 주간분을 다 쓰고 추가분만 남았을 때 `20 / 50 + 추가 20`이 합계 40으로 읽힌다
10. 운영 공지 팝업(G)과 설정 카드·안내 팝업의 설명이 서로 같은 말을 하도록 (공지는 관리자 문구)

💡 추가 요청 사항
---

**개발 쪽이 따로 고칠 것** (디자인과 별개로, 시안을 기다리지 않는다)
- 흐름 도중 잔액이 0이 되면 D 띠가 "끝까지 만들어져요"라고 안내하지만, 실제로는 `카드 만들기`에서 막힌다. 안내가 사실과 반대다.
- 이미 다른 일과를 만드는 중이면 홈에서 미리 막지 않고, 실패 화면(F)에서야 알게 된다.
- 다시 채워지는 시각에 시간대 정보가 없어, 해외 시간대 휴대폰에서는 날짜가 어긋날 수 있다.

이 셋은 시안과 무관하게 먼저 고칠 수 있다. 다만 첫 번째(D 띠 안내)는 시안에서 D를 어떻게 할지에 따라 모양이 바뀔 수 있다.
