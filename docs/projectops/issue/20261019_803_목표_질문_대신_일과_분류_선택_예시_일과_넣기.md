📝 현재 문제점
---

- 실증 1차(#780 3-3절)에서 온보딩 "도움 목표"는 보호자가 4개를 다 체크하게 돼 의미가 없다는 의견이 나왔다
- 처음 쓰는 보호자는 앱을 어떻게 쓰는지 모른다. 온보딩을 마친 보호자 홈은 일과 0개인 빈 화면이다
- 보호자: "예시 일과가 몇 개 들어 있으면 어떻게 쓰는지, 무슨 느낌인지 알 수 있을 것 같다"

🛠️ 해결 방안 / 제안 기능
---

- 온보딩의 목표 화면 자리를 **"어떤 일과부터 해 볼까요?"** 분류 선택 화면으로 바꾼다 (여러 개 선택, 건너뛰기 가능)
- 분류 4개: 아침·저녁 준비 / 학교·공부 / 집안일·스스로 하기 / 밖에서 해 보기
- 온보딩을 마치면 고른 분류마다 **예시 일과 2개가 실제 일과로** 들어간다
  - 누르면 카드가 보이고 고칠 수 있다. 이룸이 기기에도 바로 보인다
  - 홈에서 작은 `예시` 표시만 붙고 나머지는 일반 일과와 같다
  - 그림은 앱에 이미 있는 픽토그램을 쓴다. AI·크레딧을 쓰지 않는다
  - 다음 날부터는 다른 일과처럼 `지난 일과`로 내려간다
- 튜토리얼이 아니다. 안내 말풍선, 미리보기 화면은 만들지 않는다

⚙️ 작업 내용
---

- 서버: 예시 일과 원본(분류, 문장 ko/en, 픽토그램), 예시 일과 생성 API, `예시` 표시 컬럼, 보유 일과 한도에서 예시 제외, 두 번 불려도 한 벌만 생성
- 클라: 분류 선택 화면(목표 화면 교체), 온보딩 완료 시 예시 생성 요청, 실패해도 온보딩은 계속(에러 코드 안내, 1회 재시도), 홈 `예시` 표시
- 목표(`supportGoals`)는 묻지 않고 빈 값으로 보낸다. 서버 필드와 AI 프롬프트는 그대로 둔다

설계: `docs/superpowers/specs/2026-10-19-onboarding-example-routines-design.md`

하지 않는 것: 홈 "예시에서 더 고르기" 시트, 스타일별 그림, 요일 반복(#782), 일과 묶기(#781)
