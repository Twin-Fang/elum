- 합의된 핵심 정책은 **잔액이 1 이상인 시점에 시작한 AI 일과는, 생성된 행동카드와 그림이 잔액보다 많아도 끝까지 완성하고 최종 잔액을 0으로 만든다**는 것이다. 시작 시 잔액이 0이면 새 AI 일과는 시작할 수 없다. 이 정책을 구현·화면·공지에서 동일하게 안내해야 한다.

## 출시 정책: 한 개의 주간 AI 크레딧

- 회원 계정 단위로 매주 **100크레딧**을 제공한다. 모든 신규·기존 회원에게 동일하게 적용하고, 정책 시작 전 과거 AI 호출은 소급 차감하지 않는다.
- 한국 시각 월요일 00:00에 100으로 초기화한다. 미사용분은 이월하지 않는다. 운영자가 총량과 적용 시작일을 바꿀 수 있다. 총량 변경은 기본적으로 다음 주기부터 적용하며, 회원별 수동 조정은 즉시 반영한다.
- 사용자에게는 모델명·토큰 수·달러 비용을 노출하지 않는다. 모델별 실제 비용은 관리자 화면에서 비교한다. 제공자가 내부적으로 바뀌거나 FLUX→OpenAI 대체 호출이 일어나더라도 **동일한 사용자 행동의 크레딧 단가는 진행 중에 바뀌지 않는다**.
- 무료 출시에서는 구매, 충전 버튼, Pro 혜택·결제 화면을 노출하지 않는다. 기존 Free/Pro 권한 뼈대는 유지하되, 이번 무료 회원 정책을 안내하는 화면에서 구매 가능한 플랜처럼 보이게 하지 않는다.
- 기존 Free의 하루·주간 일과 생성 횟수 설정이 이 크레딧과 동시에 별도로 막지 않게 한다. 짧은 시간 연속 요청 제한과 서비스 전체 하루 AI 비용 상한은 계속 유지한다. 전체 비용 상한이 이미 도달했다면 시작 전에 별도 이유를 안내하되, **이미 시작한 일과는 중간에 중단하지 않는다**.

## 차감표

| 결과 또는 행동 | 기본 차감 | 확정 기준 |
| --- | ---: | --- |
| AI가 일과 글과 행동카드 구성을 만들고 일과 저장까지 성공 | 1 | 저장된 새 일과 1건당 |
| 새 AI 그림을 카드에 적용 | 1 | 카드에 실제 적용된 새 그림 1장당. 최초 일과·수동 카드 추가·다시 생성 모두 동일 |
| 추가 질문, 모델 재시도, 제공자 대체 호출 | 0 추가 | 위의 최종 결과물에 포함. 내부 실제 비용만 별도 기록 |
| 제목·본문 직접 입력·수정, 기존 그림 재사용, 일과 보기 | 0 | AI 생성 결과물이 새로 없으면 차감하지 않음 |
| AI 그림 실패·저장 실패·그림 생성 전에 삭제 | 0 | 결과에 적용되지 않은 그림의 예약 크레딧 반환 |
| 이미 성공한 일과·그림을 나중에 삭제 | 반환 없음 | 사용자가 지워도 이미 발생한 생성 비용은 되돌아오지 않음 |

예: 카드와 AI 그림 4장이 완성된 일과는 5크레딧, 8장이면 9크레딧이다. 원가와 사용자 크레딧은 별도 장부다. 운영 실측과 제공자별 차이는 #373을 기준으로 관리자 화면에서 확인한다.

## 잔액 부족과 생성 완료 보장

1. 최종 AI 일과 생성 요청을 서버가 받는 시점에 **사용 가능 잔액이 1 이상**이어야 시작할 수 있다. 0이면 생성 전에 막는다. 질문을 보는 단계가 일과 완료나 크레딧 차감으로 오인되지 않게 한다.
2. 시작에 성공하면 글 생성 뒤 행동카드가 최대 10장으로 확정되고 그림을 생성한다. 중간에 잔액이 떨어져도 그림을 건너뛰거나 일과를 취소하지 않는다. 잔액 1에서 카드·그림 8장이 나와도 8장 모두 시도하고 일과를 저장한다.
3. 완료 후 실제로 적용된 결과만 확정 차감한다. 계산된 사용량이 보유량을 넘으면 **잔액은 0**, 마이너스 잔액·다음 주기로 넘기는 빚은 없다. 이 초과분은 관리자 기록에 남겨 정책 효과를 확인할 수 있게 한다.
4. 0에서 새 일과를 **추가로 1회 허용하지 않는다**. 이슈 본문의 ‘끝까지’는 잔액이 1 이상일 때 시작된 그 일과에만 적용된다.
5. 일과 전체가 실패하거나 저장되지 않으면 그 작업의 예약·차감을 취소한다. 그림 몇 장만 실패해도 성공한 일과 글과 실제 적용된 그림만 센다.
6. 수동으로 카드의 글만 추가·편집하는 일은 잔액 0에도 허용한다. AI 그림을 별도로 요청할 때는 설정된 그림 1장 차감량 이상의 잔액이 있어야 하며, 수동 카드 그림에는 일과 생성의 초과 허용을 적용하지 않는다. 현재 설명 입력만으로 비동기 그림이 자동 생성되는 동작을 명시적인 그림 생성 선택과 일치시킨다.
7. 동일 요청의 재전송·중복 탭은 하나의 생성 작업으로 처리한다. 회원의 두 동시 요청이 모두 ‘잔액 1’을 보고 새로 시작하지 않도록 시작 허용·예약을 원자적으로 처리한다.

## 장부와 관리자 제어

- 회원·주기별 지급/사용/예약/환급/수동 조정과 작업 식별자를 보존한다. 사용자용 사용 내역 화면은 이번 범위에 없지만, 나중에 조회할 수 있도록 작업 종류, 최종 결과, 시간, 크레딧 증감, 정책 버전을 지금부터 남긴다.
- 크레딧 장부는 `ai_call_log` 집계와 분리한다. 한 그림을 얻기 위한 복수 모델 호출은 관리자 비용에는 모두 기록하되 회원에게는 적용된 그림 한 장으로 센다. 관리자에서 작업 단위 크레딧과 모델별 실제 비용을 대조할 수 있어야 한다.
- 관리자는 주간 지급량, 일과 글·그림 생성 차감량, 정책 활성화·적용일, 회원별 추가 지급/차감/한도 조정, 전체 비용 상한을 조절한다. 변경 전에 영향값과 적용 시점을 보여준다. 변경자·시각·사유를 남기고 이미 확정된 거래를 소급 재계산하지 않는다. 진행 중인 작업은 시작 시점 정책을 사용한다.
- 관리자 화면은 주간 회원별 `지급 / 사용 / 예약 / 남음`, 초과 허용 건수와 크레딧, 모델별 실제 USD 비용, 크레딧당 평균 원가, 오류·환급 건수를 제공한다. 비용 로그·장부 중 하나가 기록되지 못하면 조용히 정상으로 보이지 않게 운영 경고를 남긴다.
- 크레딧 합계, 예약 만료·복구, 주간 초기화, 관리자 조정은 여러 서버 인스턴스와 동시 요청에도 일관돼야 한다. 앱은 서버 값을 기준으로 잔액을 갱신한다.
