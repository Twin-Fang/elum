📝 현재 문제점
---

- 아동의 카드 완료 상태가 기기에는 메모리에만 있고, 서버 반영은 요청 단위로 즉시 전송됩니다. 인터넷이 끊기면 체크가 남지 않고, 앱을 다시 열면 사라집니다.
- 서버 API가 "다음 단계 하나를 완료해라" 형태라 요청 하나가 실패하면 뒤따르는 요청이 연쇄로 거부됩니다. 오프라인 후 재전송에 취약한 구조입니다.
- 보호자와 아동이 같은 기기를 쓰는 서비스 특성상, 화면 표시에는 서버가 필요 없는데도 서버 성공 여부에 화면이 흔들립니다.

🛠️ 해결 방안 / 제안 기능
---

- 기기 로컬 저장소를 아동 화면의 진실로 삼습니다. 탭하면 즉시 디스크에 기록되어 재시작·오프라인에서도 유지됩니다.
- 변경 사항은 순서가 보장되는 전송 대기열(outbox)에 쌓고, 온라인이 되면 백그라운드에서 순서대로 서버에 반영합니다. 실패는 재시도합니다.
- 서버에는 "이 일과의 완료 집합은 이것이다"를 통째로 받아 맞추는 멱등 엔드포인트를 추가합니다. 순서 규칙은 화면에서 지키고, 서버는 최종 상태를 받아들입니다.
- 이 구조는 향후 "단계별 독립 수행 기록"(전문가 자문 반영 예정)의 기반이 됩니다.

⚙️ 작업 내용
---

- 클라이언트: 완료 상태 로컬 영속화, 전송 대기열, 온라인 복귀 시 동기화 워커
- 서버: 완료 집합 일괄 반영 엔드포인트(멱등) 및 별 집계 정합성 처리
- 충돌 정책 정의(같은 일과를 여러 기기에서 만질 때)
- 설계 문서 작성 후 구현
