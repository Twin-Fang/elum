---

앱을 켤 때 서버 상태를 보고 **앱 전체를 덮는 화면**이 세 가지 있는데, 셋 다 **시안이 없다.**
지금 앱에 들어간 화면은 개발 쪽에서 임시로 만든 것이다. **문구도 개발 쪽에서 임의로 넣었다.** 문구와 모양 모두 자유롭게 바꿔도 된다.

| 화면 | 언제 뜨나 | 지금 상태 |
|---|---|---|
| ① 강제 업데이트 | 앱 버전이 관리자가 정한 **최소 버전**보다 낮을 때 | 임시 화면이 있다 |
| ② 권장 업데이트 | **최신 버전**보다 낮지만 아직 쓸 수는 있을 때 | **화면이 없다** (서버 설정과 판단 로직만 있다) |
| ③ 점검 | 관리자가 **점검 모드**를 켰을 때 | 임시 화면이 있다 |

### 화면마다 꼭 있어야 하는 것

**① 강제 업데이트**
- 닫기, 뒤로가기, 건너뛰기가 **없다**. 업데이트하기 전에는 앱을 쓸 수 없다.
- 누를 것은 **`업데이트하러 가기` 하나**다. 누르면 App Store나 Play 스토어의 이룸 화면이 열린다.
- 스토어에서 돌아오면 앱이 알아서 다시 확인한다. 그래서 `업데이트했어요` 같은 버튼은 따로 두지 않는다.
- 스토어를 열지 못하면 팝업으로 알린다. 팝업에는 에러 코드(`E-UPDATE-STORE`)가 들어간다 (위 두 번째 캡처).
- 보호자 휴대폰과 이룸이 휴대폰에 **똑같이 뜬다.** 이룸이가 혼자 업데이트하기 어려울 수 있다는 점을 고려해 주면 좋겠다.

**② 권장 업데이트 (새로 필요)**
- **닫고 계속 쓸 수 있어야 한다** (`나중에`).
- `나중에`를 누르면 같은 버전에서는 다시 띄우지 않는 것을 제안한다.
- 어느 화면에 띄울지(앱 시작할 때, 보호자 홈만 등)도 함께 정해 주면 좋겠다.

**③ 점검**
- 닫을 수 없다. 누를 것은 `다시 확인하기` 하나다. 앱을 다시 열어도 알아서 다시 확인한다.
- **설명 문구는 관리자 화면에서 바꾼다.** 한 줄에서 여러 줄까지 들어갈 수 있으니 길이가 달라져도 버티는 모양이면 좋겠다.

**공통**
- 이룸이도 보는 화면이다. 저장소 규칙상 **빨강이나 경고 아이콘을 쓰지 않고**, 누를 것은 되도록 하나만 두며, 버튼 높이는 64 이상이다.
- 말투는 해요체, 능동형, 긍정형이다 (`docs/08-design-principles.md`).

🎯 기대 결과
---

- 세 화면의 시안이 나와서 개발 쪽이 임시 화면을 시안으로 바꾼다.
- 권장 업데이트는 시안이 나오면 새로 만든다.
