🗒️ 설명
---

이룸이 전용 휴대폰에서 `elum://invite?code=…` 링크를 열면 "이 휴대폰에서는 초대를 받을 수 없어요 / 보호자 휴대폰에서 열어주세요" 토스트가 떠야 한다(#578). 앱을 완전히 종료한 뒤 링크를 열면 토스트가 뜨지만, **앱이 이미 켜져 있을 때 링크를 열면 토스트가 뜨지 않는다.** 메신저에서 링크를 누르는 경우는 대부분 앱이 켜진 상태라 실사용에서 놓친다.

🔄 재현 방법
---

1. 이룸이 전용 휴대폰(연결 완료, 홈이 열린 상태)에서 앱을 켜 둔다.
2. `xcrun simctl openurl <udid> "elum://invite?code=ZZZZZZ"` (가짜 코드).
3. 토스트가 뜨지 않는다. 같은 링크를 네 번 열고 연속 캡처 13장을 봤지만 모두 토스트 없음.
4. 앱을 종료하고 같은 링크를 열면 토스트가 뜬다.

원인 단서(확정 아님)
- 코드상 켜진 앱 경로는 `InviteLinkHost.didPushRouteInformation` → `InviteLinkIntake.accept` → `onElumiDeviceRejected`로 이어진다. 단위 테스트는 이 경로를 통과한다.
- 종료 후 경로는 라우터 redirect로 들어온다. 이룸이 휴대폰에서는 redirect가 `onInviteLink`를 부르지 않으므로, 이때 토스트는 host 경로가 만든 것으로 보인다. 켜진 앱에서만 host까지 링크가 오지 않을 수 있다.
- iOS `Info.plist`에 `FlutterDeeplinkingEnabled`가 없고, `AppDelegate`의 `open url`이 네이버 SDK를 거쳐 `super`로 넘긴다.
- 보호자 폰에서도 켜진 앱에서 링크가 입력 화면을 여는지 같이 확인이 필요하다(같은 경로).
