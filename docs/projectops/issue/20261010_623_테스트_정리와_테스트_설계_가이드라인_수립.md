📝 현재 문제점
---

- 클라이언트 테스트 파일이 278개로 늘어 전체 실행이 오래 걸리고 무겁다.
- 결함을 잡지 못하는 단언이 많다. 화면 문구를 그대로 베낀 단언은 문구만 바꿔도 깨지고, 실제 결함은 잡지 못한다. 서버 계약 단언과 한 테스트 안에 섞여 있어 골라내기도 어렵다.
- 문구를 ARB로 옮길 때 쓰던 연결 확인 테스트(`test/l10n/*_wiring_test.dart`, 파일 하나가 1300줄대)가 작업이 끝난 뒤에도 남아 매번 돈다.
- `client/CLAUDE.md` §6에는 "언제 테스트를 쓰는가"만 있고, "무엇을 단언하는가", "언제 퇴역시키는가"가 없다. 그래서 테스트가 계속 쌓이기만 한다.

🛠️ 해결 방안 / 제안 기능
---

- 파일별 실행 시간을 재고, 전체 테스트 파일을 가치 기준으로 분류한다.
- 결함을 잡지 못하는 테스트와 중복 테스트를 지운다. 섞인 파일은 계약 단언만 남긴다.
- 느린 테스트는 태그로 분리해서, 평소에는 빠른 테스트만 돌린다.
- 유의미한 테스트를 설계하는 가이드라인을 문서에 넣는다. 다룰 내용은 무엇을 단언하는가, 층 선택, 퇴역 규칙, 실행 예산이다.
