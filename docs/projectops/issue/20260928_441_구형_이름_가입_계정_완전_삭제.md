📝 현재 문제점
---

- 중간 심사 이전 APK는 이룸이 이름만 입력하면 고정 자격증명으로 계정을 생성하는 임시 가입 흐름을 사용했다.
- 현재 운영 서비스는 소셜 로그인과 필수 약관 동의를 사용하므로, 구형 흐름에서 만들어진 시험용 계정이 운영 데이터에 남아 있으면 회원 통계와 운영 점검 결과가 왜곡된다.
- 운영 DB 조회 결과, 현재 앱의 소셜 인증 연결이 없는 구형 비밀번호 가입 계정 89건을 확인했다. 이 중 69건은 이름 가입 APK의 고정 자격증명과 직접 일치하고, 20건은 과거 수동/E2E 비밀번호 가입 계정이다.
- 서버에는 구형 비밀번호 회원가입과 로그인 API가 남아 있어, 데이터만 정리하면 구형 APK가 계정을 다시 만들 수 있다.
- 개인정보와 인증정보 보호를 위해 이슈에는 계정명, 회원 식별자, 비밀번호 변환값, DB 접속정보를 기록하지 않는다.

🛠️ 해결 방안 / 제안 기능
---

- 현재 앱에서 생성될 수 없는 비밀번호 가입 계정이면서 소셜 인증 연결이 없는 계정만 삭제 대상으로 고정한다.
- 운영 중인 소셜 로그인 계정 6건은 삭제 대상에서 제외한다.
- 관련 프로필, 일과, 세션, 연결, 구독 데이터를 계정 관계에 맞춰 정리하고 운영 통계용 기록은 회원 식별자를 분리한다.
- 전체 작업을 단일 트랜잭션으로 실행해 일부만 삭제되는 상태를 방지한다.
- 작업 전후 전체 회원 수, 대상 계정 잔존 수, 소셜 로그인 계정 수를 비교해 검증한다.
- 운영 환경에서 구형 비밀번호 회원가입과 로그인을 차단해 재생성을 막는다.
- 완료 보고에는 집계값과 검증 결과만 기록하고 개인 식별값은 남기지 않는다.
