📝 현재 문제점
---

이룸이 휴대폰에서 로그인하기 전에 처음 보는 **연결 코드 입력 화면**의 시안이 새로 나왔다. 지금 화면은 시안이 없던 때 개발이 PIN 화면 박스를 흉내 내 만든 것이다 (#423 시안 요청).

- 디자이너가 새 섹션 `온보딩_이룸이`(Figma `이룸` 파일 `1274:8035`)에 두 프레임을 그렸다.
  - `1274:7909` 코드연결: 여섯 칸이 비어 있고 `시작하기`가 꺼져 있다.
  - `1274:7988` 코드연결_입력: 여섯 칸이 `5 5 5  5 5 5`로 찼고 `시작하기`가 켜져 있다.
- 같은 섹션에 약관(`1274:7740`), 역할 선택(`1274:7522`), 로그인(`1274:7537`), 스플래시(`1274:7554`)도 새로 그려졌다. 이 이슈는 코드 입력 두 프레임만 다룬다.

![시안](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/design1002_20261002-001730_issue_link_code.png)

🛠️ 해결 방안 / 제안 기능
---

시안 값 그대로 옮긴다. 현재 화면(`link_enter_screen.dart`)과 대조해 어긋난 곳만 고친다.

| 요소 | 시안 값 |
|---|---|
| 배경 | `#F7F2EF` |
| 뒤로가기 | x16, y79, 40×40 |
| 제목 | `보호자에게서 받은 코드를 / 입력해주세요`, 28pt, 800, `#242634`, x24, y131 |
| 안내 | `코드는 보호자 휴대폰의 / 설정 → 이룸이 휴대폰 연결하기에 있어요`, 16pt, 400, `#898B98`, x24, y211, `설정 → 이룸이 휴대폰 연결하기`에 밑줄 |
| 코드 칸 | 여섯 개, 48×64, 모서리 8, 흰색, 선 1px `#EFEFEF`, y339 |
| 칸 x 좌표 | 37, 89, 141 / 205, 257, 309 (세 칸씩 묶고 가운데만 16 벌어짐) |
| 입력한 글자 | 40pt, 800, `#242634`, y353 |
| 시작하기(꺼짐) | 360×66, 모서리 18, `#818393`, 글자 흰색 50%, x16, y675 |
| 시작하기(켜짐) | 같은 크기, `#242634`, 글자 흰색 |

- 여섯 칸을 다 채우면 시작하기가 켜진다. 지금은 다 채우면 바로 확인하는데, 시안에 버튼이 있으므로 **버튼을 눌러 확인하는 흐름인지 디자이너 확인이 필요하다.**
- 틀렸을 때는 빨간 테두리와 경고 아이콘을 쓰지 않고 한 번 흔들고 멎는다 (원칙 문서 `08-design-principles`, #423).

⚙️ 작업 내용
---

- 코드 입력 화면을 시안 좌표와 색으로 맞춘다
- 시안 대조 테스트에 `1274:7909`, `1274:7988` 추가
- 칸이 비었을 때와 찼을 때 시작하기가 꺼지고 켜지는 위젯 테스트

확인이 필요한 것
---

- 다 채우면 자동 확인(지금)인지, 시작하기를 눌러 확인(시안)인지
- 칸 사이 간격이 세 칸씩 묶이는 것이 의도인지 (영문·숫자 여섯 글자를 세 글자씩 끊어 읽게 하려는 뜻으로 보인다)
