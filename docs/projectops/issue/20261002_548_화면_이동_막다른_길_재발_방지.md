📝 현재 문제점
---

- #542 에서 이룸이 휴대폰이 로그아웃 뒤 연결 코드 화면에 갇혔다. 화면 이동 규칙(라우터 가드)과 화면을 쌓는 코드가 따로 만들어져 서로 충돌한 결함이었다.
- 같은 종류의 결함을 테스트가 잡지 못하는 구조다.
  - 화면 이동을 다루는 테스트 파일 75개가 가드 없는 가짜 라우터를 쓴다. 실제 앱 라우터(`createRouter`)를 쓰는 파일은 7개뿐이다.
  - 공통 뼈대(`ElumScaffold`) 뒤로가기를 쓰는 화면 28곳 중 20곳 이상이 `context.pop()` 만 부른다. 이 화면이 `go` 로 바로 열리면(앱 재시작, 상태 전환) 돌아갈 곳이 없어 go_router 가 오류를 던지고, 출시 빌드에서는 버튼이 반응하지 않는 것처럼 보인다.
  - 로그아웃, 탈퇴, 세션 만료, 연결 끊김처럼 계정 상태가 바뀌는 경로를 한 번에 확인하는 테스트가 없다. 한쪽을 고쳐도 대칭 경로는 아무도 보지 않는다.

🛠️ 해결 방안 / 제안 기능
---

1. **뒤로가기 안전망**: 돌아갈 화면이 없으면 지금 상태의 홈(앱을 켰을 때 가는 곳과 같은 규칙)으로 보낸다. 직접 만든 뒤로가기 동작이 있는 화면은 그대로 둔다. 뒤로가기에 `context.pop()` 만 쓰면 실패하는 검사 테스트를 함께 넣는다.
2. **모든 상태 조합 라우터 검사**: 로그인 여부, 이룸이 휴대폰 여부, 역할, 온보딩 완료의 24가지 조합과 등록된 모든 화면 경로에 대해 이동 규칙이 실제 화면으로 보내는지, 다시 튕기지 않는지, 홈과 깔아 두는 화면이 막히지 않는지 확인한다. 새 화면은 자동으로 검사 대상이 된다.
3. **나가는 경로 표 테스트**: 보호자와 이룸이의 로그아웃, 탈퇴, 세션 만료, 연결 끊김, 재시작 경로마다 도착 화면, 뒤로가기 결과, 재시작 결과를 실제 앱 라우터로 확인한다.
4. **규칙 문서**: 라우터 동작 테스트는 실제 라우터로, 뒤로가기는 안전망 함수로 한다는 규칙을 클라이언트 문서에 남긴다.
