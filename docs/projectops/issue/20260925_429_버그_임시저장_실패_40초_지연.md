인터넷이 끊긴 상태에서 **임시저장**에 들어가면, 요청은 **0.02초 만에 실패**하는데 화면은 **약 35~42초 동안 로딩**만 보여 준다. 그 뒤에야 `임시저장을 불러오지 못했어요`가 뜬다. 원칙 ⑤ "못 불러옴 → 빈 화면·무한 로딩 금지"와 어긋난다.

**원인 (추정 · 근거 있음)** Riverpod 3의 **실패 provider 자동 재시도**
- `flutter_riverpod 3.3.2`. `draftRoutinesProvider`(`routine_repository.dart:753`)에 `retry` 설정이 없다.
- 앱의 `FutureProvider` 11개 중 `retry: null`로 끈 것은 `creditSummaryProvider` **하나뿐**이다. 주석에 이유가 이미 적혀 있다: "뒤에서 몰래 재시도하면 실패 화면이 로딩으로 깜빡이고 요청이 쌓인다". `ProviderScope`에도 전역 설정이 없다.
- 로그상 요청은 **한 번**(13:24:35.442 시작 → .463 `AppFailure(offline)`)만 나갔다. 화면만 약 40초 뒤에 실패로 바뀌었다. 재시도 간격을 늘려 가는 기본 동작의 누적 시간과 맞는다.

같은 조건에서 **보호자 홈 지난 일과**는 12초 안에 실패 화면이 떴다. provider마다 다르게 동작하니 **FutureProvider 전체를 점검**해야 한다.

🔄 재현 방법
---

1. 보호자 로그인 상태에서 비행기 모드
2. 설정 → 임시저장
3. 로딩 표시가 30초 넘게 이어지다가 약 40초에 실패 화면으로 바뀐다
4. `adb logcat | grep getMyRoutines` → 요청은 들어가자마자 한 번 실패
