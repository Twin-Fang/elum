📝 현재 문제점
---

설정의 **임시저장** 목록에는 항목을 지우는 방법이 없다 (`draft_routines_screen.dart`에 삭제나 밀기 코드가 없다). 만들다 만 일과가 계속 쌓이기만 한다. 디자이너가 **밀어서 삭제**를 그렸다.

- Figma `이룸` 파일 `1274:9262` (`설정_임시저장_삭제`): 둘째 줄을 왼쪽으로 밀면 빨간 휴지통 버튼이 나온다.
- 보호자 홈 일과 목록의 밀어서 삭제(`931:4179`, `RoutineSwipeActions`)와 같은 모양이다.
- 시안에는 **지우기 전에 확인하는 팝업이 없다.** 일과 삭제(`931:4879`)는 `일과를 삭제하실건가요?` 팝업을 거치는데, 임시저장은 그리지 않았다.

![시안](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/design1002_20261002-001735_issue_draft_delete.png)

🛠️ 해결 방안 / 제안 기능
---

- 임시저장 줄을 왼쪽으로 밀면 휴지통 버튼이 나온다. 보호자 홈의 `RoutineSwipeActions`를 재사용한다.
- 휴지통을 누르면 **바로 지우지 않고 확인 팝업을 먼저 띄운다.** 일과 삭제 팝업(`ElumDialog`, 빨간 휴지통 아이콘, `취소`와 `삭제`)과 같은 모양을 쓴다. 문구는 `임시저장을 삭제하실건가요?`로 한다 (시안 없음, 아래 확인 사항).
- 지우는 중에는 줄을 잠그고, 실패하면 줄을 그대로 두고 에러 코드를 보여준다 (재시도 가능).
- 마지막 한 줄을 지우면 빈 상태 화면으로 바뀐다.
- 서버에는 임시저장 삭제 API 가 이미 있다 (#150, 닫힘). 클라 작업만 한다. 클라가 이 API 를 이미 부르는 저장소 함수가 있는지 먼저 찾는다.

⚙️ 작업 내용
---

- 임시저장 줄에 밀어서 삭제 연결
- 삭제 확인 팝업, 삭제 호출, 실패 처리
- 시안 대조 테스트에 `1274:9262` 추가, 삭제 확인 취소 성공 실패 위젯 테스트
- 홈의 밀어서 삭제와 같은 위젯을 쓰므로 두 곳이 어긋나지 않는지 확인

확인이 필요한 것
---

- 확인 팝업 문구와 시안: 시안에 없어서 일과 삭제 팝업 모양을 빌린다. 디자이너 확인이 필요하다.
- 사용자 요청(2026-10-02): 삭제를 눌렀을 때 바로 지워지면 안 되고 팝업이 떠야 한다.
