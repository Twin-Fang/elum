📝 현재 문제점
---

배포가 **비공개 테스트 트랙까지 가지 않습니다.** `client/android/fastlane/Fastfile.playstore`의
`deploy_internal` 레인이 `track: 'internal'`로만 올리고, 그 다음 단계는 `internal → production`
승급뿐입니다. 비공개 테스트(Alpha)를 거치는 경로가 아예 없습니다.

```ruby
upload_to_play_store(
  track: 'internal',   # ← 여기서 끝난다
  ...
)
```

배포 모드 셋(`store_only` / `store_prepare` / `store_submit`) 어느 것도 비공개 테스트를
건드리지 않습니다. 그래서 새 빌드를 테스터에게 주려면 **사람이 Play Console에 들어가
Alpha 트랙에 새 버전을 만들고, 라이브러리에서 번들을 고르고, 출시 노트를 쓰고, 검토에
전송**해야 합니다.

**실측 (2026-09-22)**

| 트랙 | 올라간 버전 | 시각 |
|---|---|---|
| 내부 테스트 | 179 (1.27.0) | 09-22 04:35 — CI 자동 |
| 비공개 테스트 Alpha | 158 (1.24.1) | 09-21 23:15 — 손으로 올림 |

**21개 버전이 벌어져 있었습니다.** 테스터 기기 16대가 두 달 전 코드가 아니라 하루 전
코드를 돌리고 있었지만, 그 사이 배포가 계속 나가는데도 자동으로 따라가지 않으니 손을
놓는 순간 다시 벌어집니다.

**왜 지금 문제인가** — Play 프로덕션 액세스 조건인 **테스터 12명 · 14일**이 2026-09-22에
시작됐습니다(#286). 이 기간 내내 최신 빌드를 Alpha에 올려야 하는데, 지금 구조로는 배포할
때마다 사람이 콘솔을 열어야 하고 한 번이라도 빠뜨리면 테스터가 옛 앱을 테스트합니다.

🛠️ 해결 방안 / 제안 기능
---

`upload_to_play_store`에 **`track_promote_to: 'alpha'`를 더해** internal에 올린 그 번들을
그대로 비공개 테스트로 승급시킵니다. 번들을 두 번 올리지 않습니다.

Play API에서 닫힌 트랙의 기본 이름이 `alpha`이고, 이 앱의 트랙 이름도 `비공개 테스트 - Alpha`라
그대로 맞습니다.

**설계 결정**

| 결정 | 선택 | 근거 |
|---|---|---|
| 방식 | 업로드 후 `internal → alpha` 승급 | 번들 재업로드 불필요. 기존 `promote_internal_to_production`과 같은 모양이라 읽기 쉽다 |
| 적용 범위 | `deploy_internal` 레인 전체 (모드 무관) | 비공개 테스트는 14일간 끊기면 안 된다. 모드별로 가르면 언젠가 빠뜨린다 |
| 출시 상태 | `completed` | 테스터에게 바로 제공. `draft`면 사람이 또 눌러야 해서 자동화의 뜻이 없다 |
| 끄는 방법 | 환경변수 `PROMOTE_TO_CLOSED_TESTING` (기본 켜짐) | 14일이 끝나면 불필요해진다. 그때 워크플로를 다시 고치지 않게 |

**실패 경로** (정상 경로만 만들지 않는다)

| 상황 | 요구 |
|---|---|
| Alpha 승급 실패 | **internal 배포는 성공으로 남긴다.** 승급은 부가 단계이고, 여기서 죽으면 배포 전체가 실패로 보인다. 실패는 로그에 분명히 남기고 레인은 계속 진행한다 |
| 서비스 계정 권한 부족 | 원인을 알 수 있는 메시지를 남긴다. `internal`은 되는데 `alpha`가 403이면 트랙 권한 문제다 |
| 트랙이 아직 없음 | 비공개 테스트 트랙을 한 번도 만들지 않은 레포에서는 승급이 실패한다. 이 경우도 배포를 막지 않는다 |
| 같은 버전 코드 재승급 | 이미 Alpha에 있는 번들을 다시 승급하면 오류가 난다. 로그로 구분되게 남긴다 |

**즉시 반영이 아니라는 점을 로그에 적는다** — Alpha 릴리스는 **매번 구글 검토를 탑니다.**
(첫 건 실측: 제출 22:28 → 게시 23:15, 47분. 구글 안내는 7일 이내이고 더 걸릴 수 있음)
검토 도는 동안 테스터는 이전 버전을 계속 쓰므로 끊기지는 않습니다.
