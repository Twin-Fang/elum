🧩 시험 대상
---

서울 ABA연구소 한상민 소장님을 통해 모은 테스터 보호자 7명에게 보낼 **실증 설문(구글 폼) 「이룸(ELUM) 서비스 사용 경험 설문조사」**

- 1주 원격 사용 뒤 보호자에게 받는 설문이다. 사용량이 적었던 점을 숨기지 않고 "왜 덜 썼는지"를 고칠 것으로 바꾸는 것이 목표다.
- 이 설문 결과로 고칠 것을 정하고, 고친 버전을 동천학교(초등부) 실증에서 다시 확인하는 순환의 첫 단계다.

📋 테스트 시나리오
---

1. 대회 심사기준(5항목)으로 현재 폼과 수정안을 예측 채점했다 (심사위원 페르소나 4명: 장애 현장 전문가, 특수교육 학계, 기술 전문가, 시민평가단)
2. 2025 본선 실증보고서 8건의 설문 방식과 대조했다
3. 수정안을 팀 결정에 맞춰 다듬은 뒤 폼에 반영했다
4. 반영 결과를 편집 화면에서 다시 읽어 전 문항을 확인했다

### 채점 결과 (진단 지표, 실제 점수 예측 아님)

| 항목 (10점 평균) | 현재 폼 | 수정안 |
| --- | :-: | :-: |
| 적용가능성 | 5.5 | 6.3 |
| 필요성 | 4.8 | 6.0 |
| 기대효과 | 4.5 | 5.3 |
| 완성도 | 3.3 | 4.5 |
| 참신성 | 2.0 | 2.5 |
| **총점 (100)** | **39.9** | **49.2** |

4명 공통 결함은 두 가지였다.
- 얼마나 썼는지를 묻지 않아, 적게 쓴 사람과 많이 쓴 사람의 만족도를 구분할 수 없다
- 처음 쓸 때 막힌 점과 덜 쓴 이유를 묻지 않는다

### 팀 결정

- 대상 표기는 "발달장애 아동", 장애 정도는 "경증 / 중증" 그대로
- 문항 수는 중도 이탈을 줄이려고 20개로 제한 (추가 후보 17개 중 6개만 반영)
- 설문 안에서 보고서·발표 활용을 언급하지 않는다. 인용 동의 문항도 넣지 않는다
- 동의 문항은 법적 필수 항목만: 수집 항목, 민감정보, 이용 목적, 보관 기간(2026년 12월 31일), 거부 권리, 법정대리인

### 반영 내용 (6섹션, 20문항: 필수 15, 선택 5)

| 구분 | 내용 |
| --- | --- |
| 새로 추가 (7) | 개인정보 수집·이용 동의(거부 시 바로 제출), 일주일 사용 일수, 이룸 전 가장 힘들었던 점, 카드를 볼 때 필요한 도움 정도, 말로 알려 주는 횟수 변화, 처음 설치와 연결, 덜 쓴 이유 |
| 수정 (7) | 안내 문구 2곳("실증 결과 분석" > "사용 경험 분석"), 이중질문 정리, "긍적적" 오타와 "특별히 없었다" 보기, 사용 편리성 척도 방향 통일(1 어려웠다 ~ 5 쉬웠다), 서술형 2개 필수 해제 |
| 묶음 (1) | 기능별 만족도 4문항 > 객관식 그리드 1개 |
| 삭제 (6) | AI 행동 단계 적절성(그리드와 중복), 기능별 만족도 개별 4문항, 빈 섹션 7 |

### 반영 방법과 확인

- 폼 편집기는 문항을 하나씩 펼쳐야 해서 화면 클릭으로는 20여 곳을 안전하게 고치기 어려웠다. 그래서 **Google Apps Script(FormApp)** 로 수정 내용을 코드로 만들어 한 번에 실행했다.
- 문항은 순서가 아니라 **제목으로 찾아** 고쳤다. 기존 응답이 있으면 척도 방향을 바꾸지 않도록 막았다. 실행 결과 기존 응답은 0건이었다.
- 빈 섹션 7은 제목이 실제로 "제목 없는 섹션"이라는 글자로 저장돼 있어 첫 실행에서 빠졌다. 삭제 전용 함수로 다시 실행했다. 이때 실행 함수 선택이 이전 함수로 남아 있으면 실행을 멈추게 해서 문항이 두 번 추가되는 것을 막았다.
- 반영 후 편집 화면을 새로 고쳐 전 문항을 다시 읽어 확인했다 ("6 중 N 섹션", 20문항).
