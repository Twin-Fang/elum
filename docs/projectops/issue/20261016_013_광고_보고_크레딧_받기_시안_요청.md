🖌️ 요청 내용
---

**광고 보고 크레딧 받기** 화면(제안 · 광고 보는 중 · 결과)의 시안을 요청해요. 지금은 시안 없이 임시로 만든 팝업 하나뿐이에요.

| | 지금 |
| --- | --- |
| 제안하는 곳 | 홈 `새로운 일과 만들기`가 크레딧 부족으로 막혔을 때의 팝업 하나뿐이에요 |
| 설정 크레딧 카드 | 새 시안(`1532:7501`)대로 구현됨. 광고로 가는 길이 없어요 |
| 여러 번 보기 | 한 번 볼 때마다 크레딧 2(서버 설정)를 받고, 하루 횟수가 남아 있으면 또 볼 수 있어요. 팝업은 한 번 보면 끝나요 |
| 사용 내역 | 광고로 받은 크레딧 줄이 들어갈 예정이에요 (내역 화면 #658 · 디자인 #685) |
| 운영 상태 | 운영은 지금 광고 보상이 꺼져 있다고 전달받았어요(제가 확인하지는 못했어요). 켜기 전에 시안이 필요해요 |

**왜 필요한가요** 크레딧이 모자란 보호자가 광고로 채울 수 있다는 걸 막힌 순간에만 알 수 있고, 평소 길이 없어요. 또 여러 번 볼 수 있는 것, 횟수를 다 쓴 것, 실패했을 때의 모습이 정해져 있지 않아요.

**꼭 지킬 것**
- 구매·플랜 표시는 두지 않아요 (`ai_credit_card.dart` 주석)
- 해요체 · 이룸이 · 휴대폰. 아이·기기·서버는 쓰지 않아요 (CLAUDE.md 용어 규칙)
- 실패에는 에러 코드를 보여줘요 (`E-AD-LOAD` `E-AD-SKIP` `E-AD-WAIT`)
- 광고임이 분명히 보여야 해요
- 크레딧은 서버가 지급을 확인한 뒤에만 `받았어요`로 알려요 (`ad_reward_flow.dart`)
- 지급량·횟수는 서버 설정이라 자릿수가 바뀌어도 안 깨져야 해요 (2 → 120, 5 → 10)
- 탭 영역 48×48 이상, 설명 14 이상, 글자 200%에서도 안 깨져요 (`docs/08-design-principles.md`)
- 한 화면에는 하나의 행동만 담아요
- 광고는 일과 만들기 흐름 안 · 이룸이 화면 · 보상 연출에는 두지 않아요 (`credit_blocked_dialog.dart` 설계 §2)
- 광고 관련 법 · 스토어 정책 문구는 이 요청서에서 정하지 않았어요

- 광고를 제안하는 자리(아래 A · B · A+B · C 중 고르거나 새 안)

- 시안이 나오면 개발이 고른 안대로 팝업과 설정 줄을 고쳐요

### 제안 자리 대안
**개발 쪽 추천은 A+B예요.** 막힌 순간이 가장 자연스럽고, 평소에도 길이 있어야 해서예요. 전부 바꿔도 돼요.

![대안 A+B](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/brief_ad_20261016-201626_alt_ab_both.png)

| 안 | 모양 | 장점 | 약점 | 개발 영향 |
|---|---|---|---|---|
| 현재 (최소) | 막힌 팝업의 임시 모양 그대로 | 변경 없음 | 시안 없음 · 평소 길 없음 · 횟수 표시 없음 | 없음 |
| A | 막힌 팝업만 시안으로 정리 (예: 오늘 횟수 한 줄) | 가장 자연스러운 순간 | 막혀야만 발견돼요 | 팝업 문구 · 모양 |
| B | 설정 크레딧 카드 아래 `광고 보고 크레딧 받기` 줄 | 막히기 전에도 길이 있어요 | 설정까지 들어가야 보여요 | 줄 하나 + 흐름 호출 |
| **A+B (추천)** | A와 B 둘 다 | 막힌 순간 + 평소 | 문구를 두 곳에서 맞춰야 해요 | A + B (흐름 코드는 공유) |
| C | 사용 내역 화면 맨 아래 (비추천) | 내역과 한곳 | 내역 화면이 아직 없어요 · 줄어든 이유를 보러 온 사람에게 광고 버튼이 먼저 보여요 · 한 화면에 행동 둘 | 내역 화면(#658) 선행 |

B의 줄을 다 받은 날에는 이렇게 바뀌어요: ![B 소진](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/brief_ad_20261016-201630_alt_b_settings_done.png)

C는 그림 없이 와이어로 드려요.
```
┌──────────────────────────────────┐
│ 크레딧 사용 내역                 │
├──────────────────────────────────┤
│오늘                              │
├──────────────────────────────────┤
│광고를 보고 받았어요    +2        │
│일과 글 만들기          -5        │
├──────────────────────────────────┤
│    [ 광고 보고 크레딧 받기 ]     │
│       광고 (오늘 5번 남음)       │
└──────────────────────────────────┘
  C안: 내역 화면 맨 아래 버튼 (그림 없는 와이어, 내역 화면은 아직 없음)
```

### 문구 (굵은 글씨가 개발 쪽 첫째 후보예요. 고르는 건 디자이너예요)

| 제안 문장 | 광고를 끝까지 보면 크레딧 {N}개를 받아요 | **그대로** / 광고 한 편을 끝까지 보면 크레딧 {N}개가 채워져요 / 광고를 끝까지 보면 크레딧 {N}개를 받아요 (광고예요) | 광고임이 보이는지 |
| 제안 버튼 | 광고 보고 더 만들기 | **광고 보고 받기** / 광고 보고 더 만들기 / 광고 보기 | 렌더에서 두 줄로 꺾였어요 |

| 지급 성공 제목 | 크레딧 {N}개를 받았어요 | **그대로** / 크레딧 {N}개가 채워졌어요 / 광고 보고 크레딧 {N}개를 받았어요 | 받은 근거를 넣을지 |

| 오늘 횟수 소진 | 오늘은 광고로 받을 수 있는 크레딧을 모두 받았어요. 내일 다시 해주세요 | **…내일 0시부터 다시 받을 수 있어요** / 오늘 받을 수 있는 크레딧을 다 받았어요 / 내일 0시에 다시 받을 수 있어요 | 시각을 말에 넣을지 (서버 기준 한국 시각 0시) |

| 내역의 광고 줄 | 없음 | **광고를 보고 받았어요** / 광고 보상 / 광고 보고 받은 크레딧 | #685와 같은 말 |

💡 추가 요청 사항
---

- 대기 팝업(준비 중 · 확인 중)은 닫을 수 없어요. 약 20초까지 걸릴 수 있어서, 기다리는 동안의 모습(진행 표시 · 문구)을 정해 주세요.
- 광고 시청은 끝났는데 확인이 늦으면 `설정에서 확인`이라고 안내해요. 지금 설정 카드에는 광고로 받는 중이라는 표시가 없어요. 필요한지 봐 주세요.
- 오늘 횟수 소진 때 `내일 0시`를 말해도 되는지 봐 주세요. 서버는 한국 시각 0시 기준이고 휴대폰 시간대가 다를 수 있어요(개발이 확인).
- 서버가 꺼 둔 경우 지금은 광고 안내가 아예 없어요. 그대로 둘지 정해 주세요.
- 관련 시안 요청: #685(크레딧 사용 내역 화면), #420(AI 크레딧 표시). 합칠지는 정해 주세요.
- 법 · 결제 문구는 없어요.
