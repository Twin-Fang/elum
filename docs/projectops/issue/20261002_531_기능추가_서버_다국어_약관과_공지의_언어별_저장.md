📝 현재 문제점
---

- 약관(`consent_document`)은 약관 키 하나에 본문 하나라 언어 구분이 없고, 동의 기록에도 어느 언어로 동의했는지 남지 않는다.
- 공지(`app_notice`)는 제목, 본문, 버튼 문구가 한 벌뿐이고 어느 나라 사용자에게 보일지 지정할 수 없다.
- 관리자 약관·공지 화면과 외부 게시 페이지(개인정보방침, 삭제 안내)가 단일 언어다.

🛠️ 해결 방안 / 제안 기능
---

- 약관과 개인정보방침은 **한국 기준 한 벌**이고 언어별로는 번역본만 둔다. 국가별 법 본문은 만들지 않는다. 동의할 때 약관 버전과 **동의한 언어**를 함께 기록한다. 그 언어의 약관이 게시되지 않았으면 영어로 대체하지 않고 가입을 막는다(읽을 수 없는 언어로 동의를 받지 않는다).
- 공지는 언어별 번역을 달고, **대상 국가를 지정**할 수 있게 한다(비우면 전체). 국가는 앱이 보내는 휴대폰 지역 설정(`X-Elum-Region`)으로 판정하고, 국가 미상에게는 전체 대상 공지만 보인다. 헤더가 없는 기존 앱은 한국으로 본다.
- 관리자 화면에 언어별 입력과 대상 국가 입력을 더한다. 공지는 한국어 필수, 나머지는 선택이다.
- 외부 게시 페이지 일치 검사를 언어별로 확장한다. 법적 문구는 임의로 바꾸지 않고, 한국어 본문은 그대로 두며 다른 언어는 법무 확인 후 채운다.

⚙️ 작업 내용
---

- [ ] 서버 약관: 언어 열, 조회, 시드, 동의 언어 기록(4개 Task)
- [ ] 서버 공지: 번역 행과 대상 국가, 노출 규칙(국가 미상 처리 포함)(2개 Task)
- [ ] 관리자 화면: 약관, 공지, 이력 화면의 언어와 대상 국가 입력(3개 Task)
- [ ] 클라이언트 동의 화면: 번들은 한국어만, 다른 언어는 서버 캐시가 없으면 "약관을 불러오지 못했어요"와 재시도 버튼(빈 화면과 무한 로딩 금지)
- [ ] 외부 게시 페이지 일치 검사 워크플로 언어별 확장
- [ ] 통과 조건: 서버·앱 테스트 전체 통과, 한국어 시드 결과가 현재와 같음(해시 비교)
