📝 현재 문제점
---

앱이 쓰는 **대기·연출 시간값 다섯 개가 앱 안에 박혀 있습니다.** 값 하나를 바꾸려면 앱을 다시 빌드해 스토어 심사를 받아야 합니다.

| 값 | 지금 어디에 | 지금 값 |
|---|---|---|
| 서버 연결 대기 | `client/.env` | 10초 |
| 서버 응답 대기 | `client/.env` | 60초 |
| 카드 만들기 최대 대기 | `client/.env` | 45초 |
| 약관 불러오기 대기 | `app_config.dart` 상수 (#278) | 3초 |
| 민감정보 검사 최소 연출 | `client/.env` | 1.5초 |

`.env`는 빌드할 때 앱 안에 함께 담깁니다. 그래서 설치된 앱에서는 바꿀 방법이 없습니다.

**이게 지금 문제가 되는 이유가 있습니다.**

- 심사 제출을 앞두고 있습니다(#286). 심사 중에 값을 고치면 **심사를 처음부터 다시** 받습니다.
- 운영 중 AI 응답이 느려져 대기 시간을 늘려야 할 때, 릴리스 한 번을 기다려야 합니다. 그동안 사용자는 카드 만들기가 실패하는 화면을 봅니다.
- 반대로 대기를 줄여야 할 때도 같습니다. 서버가 죽었는데 앱이 60초를 기다리면 사용자는 앱이 멈춘 줄 압니다.
- 관리자 화면에는 이미 설정 서른네 개가 있습니다(#248). 앱 시간값만 이 체계 밖에 있습니다.

🛠️ 해결 방안 / 제안 기능
---

**서버가 값을 주고 관리자 화면에서 고칩니다.** 앱 코드에는 기본값만 남깁니다.

- 전달 통로는 **이미 있는 `/api/app/status`** 를 씁니다(#279). 앱이 시작할 때 어차피 부르는 엔드포인트라 왕복이 늘지 않고, 인증도 필요 없습니다.
- 앱은 **세 단으로** 값을 고릅니다. 서버에서 받은 값 → 지난번에 받아 저장해 둔 값 → 코드 기본값. 서버를 못 봐도 앱은 그대로 돕니다.
- 저장해 둔 값은 **앱이 뜰 때 바로** 적용합니다. 서버에 닿기 전 첫 요청부터 관리자가 고친 값으로 돕니다.
- **범위를 서버와 앱 양쪽에서 막습니다.** 대기 시간에 0이나 음수가 들어가면 "끝없이 기다리기"가 됩니다. 관리자가 오타 한 번 내면 앱 전체가 멈추므로 한쪽만 막아서는 안 됩니다.
- 서버 기본값과 앱 코드 기본값을 **같은 값으로 맞춥니다.** 서버를 못 본 앱과 본 앱이 다르게 동작하면 제보를 받아도 어느 쪽인지 알 수 없습니다.

**실패 경로**

| 상황 | 앱의 동작 |
|---|---|
| 서버가 `client` 를 주지 않음 (옛 서버) | 지금 쓰던 값 그대로. 아무것도 바뀌지 않습니다 |
| 형식이 통째로 다름 | 통째로 버리고 지금 값 유지 |
| 한 항목만 범위 밖 | **그 항목만** 기본값. 나머지는 받습니다 |
| 저장 실패 (디스크 가득 등) | 이번 실행은 새 값으로 돕니다. 다음에 또 받으면 됩니다 |
| 관리자가 범위 밖 값을 저장 | 서버가 `E-CFG-001` 로 거절. 화면에 에러 코드를 보여줍니다 |
| 설정을 읽지 못함 | 서버가 기본값을 내려줍니다. 앱은 정상 동작합니다 |
