카드 제목과 설명을 고치는 화면이다. **디자이너가 키보드 가림 문제로 확정하지 못한 채 남아**, 개발 쪽이 바텀시트로 정했다 (#77). 나중에 이룸이 화면에서도 같은 시트를 쓸 예정이다.

> 이 요청서는 정답을 드리는 게 아니다. 지금 앱 모습과 디자이너가 보통 안 그리게 되는 상태를 **재료로** 모았다. 모양, 문구, 위치 모두 바꿔도 된다. 개발 쪽 추천은 근거와 함께 한 줄씩만 적었다.

### 지금 동작

- 카드 확인, 일과 편집에서 `이 카드 수정하기`를 누르면 아래에서 시트가 올라온다.
- 입력칸을 누르면 **시트가 키보드 위에 붙어** 입력칸이 가려지지 않는다.
- `저장하기`를 눌러야 반영되고, 바깥을 누르면 닫힌다 (바뀐 게 버려진다).

### 실측 검수 결과 (2026-09-25, Android 에뮬레이터)

![real](https://github.com/Twin-Fang/elum/releases/download/qa-evidence/realqa_20260925-135247_real_sheet.png)

처음 본문의 두 가지는 **틀려서 지웠다.** "키보드가 올라오면 뒤 `저장하기`가 비쳐 버튼이 둘로 보인다"는 위젯 렌더에 가림막이 안 그려져 생긴 착시였다. 실기기는 **뒤 화면을 이미 어둡게 가린다.** "설명이 `입어 / 요`로 한 글자만 넘어간다"는 가짜 문구 이야기였다.

### 보이는 문제

- 바깥을 눌러 닫으면 고친 내용이 조용히 사라진다. 물어볼지 정해야 한다 (원칙 ④ "되돌릴 수 있다고 먼저 말한다").

### 디자이너가 정해 주면 좋은 것

1. **바텀시트 / 전체 화면 편집** 중 무엇으로 할지. 원래 고민했던 키보드 가림 문제는 지금 방식으로 해결돼 있다.
2. 지금처럼 뒤 화면을 **어둡게 가린 채** 둘지 (실기기에서 이미 그렇게 동작한다)
3. 저장하지 않고 닫을 때 **확인을 물을지.**
4. 제목, 설명 글자 수 한도를 보여줄지.
5. 이룸이 화면에서 쓸 때 달라져야 할 것 (글자 크기 20 이상, 터치 64 이상).

**개발 쪽 추천 (정답 아님)**: 바텀시트를 유지한다. 키보드 가림은 이미 풀려 있고, 남은 결정은 "저장하지 않고 닫을 때 물을지"다.
