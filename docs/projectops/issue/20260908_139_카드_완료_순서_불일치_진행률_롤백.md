🗒️ 설명
---

- 아동 모드에서 카드를 전부 체크해 진행률이 100%로 보인 뒤, 앱을 다시 열면 진행률이 57%로 되돌아갑니다.
- 원인은 클라이언트와 서버의 완료 규칙 불일치입니다. 서버는 "이전 단계가 미완료면 완료를 거부(409)"하고 "마지막에 완료한 단계만 취소 허용"하지만, 클라이언트는 어떤 순서로든 체크·해제를 허용하고 서버의 거부 응답을 조용히 삼킵니다.
- 그 결과 화면(로컬 메모리)에는 7/7이 남고 서버에는 4/7만 저장됩니다. 로컬 상태는 메모리에만 있어 재시작·재조회 시 사라지고, 서버 값(57%)이 드러납니다.

🔄 재현 방법
---

1. 보호자 모드에서 일과 생성 후 승인 → 아동 모드 진입
2. 카드 1~3번 체크 → 4번 체크 후 곧바로 한 번 더 탭(체크 해제)
3. 5번 카드로 넘겨 체크 (서버 409, 화면은 체크됨) → 4번으로 돌아가 다시 체크 → 6, 7번 체크
4. 홈에서 진행률 100% 확인 → 앱 종료 후 재실행 → 57%로 표시

관련 코드
- `client/lib/features/child/application/child_routine_notifier.dart` — 순서 무관 낙관적 토글, 동기화 unawaited
- `client/lib/features/child/data/step_progress_repository.dart` — 실패를 debugPrint로만 남기고 흡수
- `server/.../RoutineService.completeStep` / `cancelStep` — 순서 규칙 강제

함께 보고된 "아동 모드에 두 번째 일과가 안 보임"은 버그가 아닙니다. 해당 일과는 보호자 승인(confirm) 전 상태라 서버가 아동 화면에서 의도적으로 제외합니다(서비스 원칙 3). 오늘 로그 기준 일과 생성 3회, 승인 1회.

✅ 예상 동작
---

- 화면의 체크 상태와 서버 저장 상태가 항상 일치해야 합니다.
- 서버가 거부한 체크는 화면에서도 되돌아가야 하고, 순서상 아직 체크할 수 없는 카드는 눌러도 체크되지 않아야 합니다.
- 동기화 요청은 탭 순서대로 서버에 도달해야 합니다.
