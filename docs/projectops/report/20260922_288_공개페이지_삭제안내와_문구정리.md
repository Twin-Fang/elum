# 계정 삭제 안내 추가와 게시 문구 불일치 정리

## 개요

공개 페이지에 **계정·데이터 삭제 안내**를 새로 만들고, **사실과 다른 고지**를 고쳤다. 그리고 같은 일이 다시 나지 않도록 게시본과 서버 동의 문서가 어긋나면 잡는 검사를 붙였다.

## 무엇이 틀려 있었나

### 1. 지원 페이지가 사실과 다른 말을 했다 — 가장 위험했다

> 적은 내용이 그대로 밖으로 나가나요? → 아니요. … **원문은 따로 보관하지 않아요.**

서버 `Routine.rawInputText`는 `nullable = false` 필수 컬럼이다. **원문은 저장된다.** 개인정보처리방침은 "이룸 서버에 보관되며 외부로 나가지 않습니다"라고 맞게 적고 있었다.

**같은 사이트의 두 페이지가 개인정보 처리에 대해 서로 다른 말을 했고, 그중 하나가 사실과 달랐다.**

### 2. 삭제 안내 전용 주소가 없었다

Play 데이터 보안 선언이 요구하는 주소에 **도움말 페이지 주소**를 대신 넣어 두고 있었다.

### 3. 앱에 없는 것을 수집한다고 적었다

방침 수집 항목에 `아이디, 비밀번호`가 있었다. 소셜 로그인만 지원해 자체 로그인이 없다.

### 4. 같은 것을 두 이름으로 불렀다

서버 동의 문서는 `이룸이`, 게시본은 `당사자`.

## 변경 사항

### 게시 페이지 (`gh-pages`)

- `delete.html` **신설** — 앱 안 삭제 경로, 메일 요청 방법, **지워지는 것과 남는 것**, 처리 기간
- `index.html` — 원문 보관 설명을 사실대로 정정, 탈퇴 FAQ에서 삭제 안내로 연결
- `privacy.html` — `아이디, 비밀번호` 줄 삭제, `강화물` → `보상`, `당사자` → `이룸이`
- 세 페이지의 네비게이션·푸터를 서로 연결

### 저장소

- `tool/check_public_pages.py` **신설** — 게시본과 서버 문서 대조 검사

### Play 콘솔

- 데이터 보안의 `계정 URL 삭제`를 `https://twin-fang.github.io/elum/delete.html`로 교체 (**저장만 함** — 아래 주의사항)

## 주요 구현 내용

### 원본을 한 곳으로 합치지 않은 이유

방침이 두 곳에 산다 — 게시 페이지와 서버 동의 문서. **한쪽만 고쳐져 어긋난 것이 이번 문제의 뿌리다.**

게시 페이지가 서버 문서를 읽어 그리면 원본이 하나가 되어 다시는 안 어긋난다. 그래도 **정적 페이지를 유지하기로 했다** — 심사관이 보는 페이지가 서버 장애에 걸리면 안 된다. 방침을 못 여는 것은 방침이 조금 다른 것보다 나쁘다.

대신 **사람이 두 곳을 눈으로 맞추는 일은 반드시 빠지므로** 값으로 묻는 검사를 뒀다.

| 검사 | 무엇을 막나 |
|---|---|
| 사실과 다른 고지가 남았는가 | 이번 같은 원문 보관 설명 |
| 앱에 없는 것을 수집한다고 적었는가 | 아이디·비밀번호 |
| 서버 문서의 국외 이전·보호책임자를 게시본도 말하는가 | 한쪽만 갱신 |
| 위탁 제공자가 양쪽에 같이 적혀 있는가 | 보내는 곳과 알린 곳이 다른 것 |
| 삭제 안내가 스토어 요구를 담았는가 | 페이지 유실·내용 누락 |

### 남는 데이터를 분명히 적은 이유

Play는 "삭제되거나 보관되는 데이터 유형 및 추가 보관 기간"을 요구한다. 두루뭉술하게 "다 지워집니다"라고 적으면 AI 호출 기록이 남는 것과 어긋난다.

그래서 **남는 것을 따로 적고**, 그것이 계정과 이어지지 않으며 보호자가 적은 내용이 들어 있지 않다는 것을 함께 적었다.

### `당사자`를 한 곳만 남긴 이유

첫 문장의 `발달장애 당사자`는 그대로 두고 *(이하 "이룸이")* 정의만 붙였다. 누구를 위한 서비스인지 밝히는 문장이고, 여기서 `당사자`는 법적으로 통용되는 표현이라 지우면 뜻이 좁아진다. 법정대리인 조항의 `만 14세 미만 아동`도 법률 용어라 손대지 않았다.

## 검증

**고치기 전 게시본에 검사기를 돌려 세 건을 실제로 잡는 것을 확인했다.**

```
⚠️  delete.html 가 없다 — 스토어 선언이 이 주소를 가리킨다
⚠️  index.html 이 '원문은 따로 보관하지 않아요'라고 적고 있다 — 서버는 원문을 저장한다
⚠️  privacy.html 에 '아이디, 비밀번호' 가 있다 — 자체 로그인이 없다
종료코드 1
```

게시 후 같은 검사가 통과한다. 주소도 실측했다 — `/delete.html`이 404에서 200이 됐다.

## 주의사항

### Play 콘솔 변경은 저장만 했다 — 일부러다

데이터 보안의 삭제 URL을 바꾸고 저장했지만 **검토 전송은 하지 않았다.** 전송하려니 이 경고가 떴다.

> 9월 22일부터 계속 진행 중인 검토가 있습니다. 지금 전송하면 검토가 취소되었다가 다시 시작되어 대기 시간이 늘어납니다.

비공개 테스트 릴리스가 검토 중이라, 전송하면 그 검토가 취소·재시작된다. 테스터가 새 빌드를 받는 것이 늦어지고 14일 시계에도 영향이 있다.

**다음 배포 때 함께 나가도록 두기로 했다.** 그때까지 스토어에는 옛 삭제 URL(도움말 주소)이 남는다. 프로덕션 심사는 아직 멀어(14일 조건 D+0) 지금 당장 문제가 되지 않는다.

### 검사기가 아직 자동으로 돌지 않는다

`tool/check_public_pages.py`는 손으로 돌려야 한다. **돌지 않는 검사는 없는 것과 같다.** `gh-pages` push와 서버 동의 문서 변경에 걸리는 워크플로를 붙이는 것이 남았다.

### 이용약관 페이지는 만들지 않았다

두 스토어 모두 필수가 아니다. 앱 안에는 동의 문서로 있다. 필요해지면 그때 만든다.

### 휴대폰 브라우저로 직접 열어보지는 않았다

`curl`로 상태 코드와 본문만 확인했다. 레이아웃이 좁은 화면에서 깨지지 않는지는 실제 기기에서 한 번 봐야 한다.
