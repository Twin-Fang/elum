## 구현 보고서: 연결 암호 실패 횟수가 저장되지 않던 문제

### 무엇이 문제였나
- 이미 쓴 연결 암호를 7번 넣어도 `failed_attempts`가 0이었다. `redeem()`이 실패 때 던지는 `CustomException`으로 실패 횟수 증가와 5회째 폐기가 함께 롤백됐다.

### 바꾼 것
- `DeviceLinkService.redeem()`에 `@Transactional(noRollbackFor = CustomException.class)`를 걸었다. 초대 코드와 같은 방식이다.

### 왜 안전한가
- 예외를 던지는 지점 앞에서는 실패 횟수 말고 쓰는 것이 없다. 성공 경로(연결 표시, 토큰 발급)에는 `CustomException`이 없어 반쪽 커밋이 생기지 않는다.

### 검증
- 서버 테스트 통과.
- **운영 실측**: 배포 후 쓴 암호를 2번 넣자 `failed_attempts` 0 → 2.

### 주의사항
- `redeem()` 안에서 예외 앞에 다른 쓰기를 더하면 그 쓰기도 커밋된다. 넣을 때는 이 전제를 다시 본다.
