## 구현 보고서: 비밀암호 없이 보호자 화면이 열리던 문제

### 무엇이 문제였나
- 새 휴대폰에서 보호자로 로그인한 뒤 비밀암호 만들기를 건너뛰고 앱을 다시 켜면 암호 없이 보호자 홈이 열렸다.
- 원인: "암호를 만들어야 한다" 표시(`guardianPinSetupPending`)가 로그인 때 메모리에만 세워져 재시작하면 사라졌다.
- 만들기 화면의 뒤로가기는 화면만 로그인으로 보내고 세션은 남겼다.

### 바꾼 것
- 앱 시작 때 이 휴대폰에 보호자 잠금이 있는지 읽어(`main.dart` → `startupLockMissingProvider`), 세션이 있는 보호자 휴대폰인데 잠금이 없으면 암호 만들기를 다시 세운다(`restoreGuardianPinRequirement`).
- 만들기 화면의 뒤로가기는 실제로 로그아웃까지 한다(`pin_change_screen.dart`). 서버 로그아웃은 그 세션 하나만 끊으므로 같은 계정의 다른 휴대폰은 영향이 없다.

### 왜 이 방식인가
- 잠금은 보안 저장소에 있어 읽기가 비동기다. 라우터 가드는 동기라서 시작할 때 한 번 읽어 넣는다.
- 저장 키·API는 바꾸지 않았다. 업데이트한 사용자는 잠금이 그대로 옮겨져 영향이 없고, 잠금이 정말 없는 경우만 한 번 만들고 들어간다.

### 검증
- 새 테스트 3건, 비밀암호 관련 테스트 59건 통과.

### 주의사항
- 잠금 읽기가 실패하면(기록이 깨짐) 막지 않고 기존 동작으로 둔다. 막으면 사용자가 앱에 들어갈 수 없게 된다.
- 이룸이 화면 전환은 가드 대상이 아니다. 보호자 화면으로 돌아올 때 암호가 필요하다.
