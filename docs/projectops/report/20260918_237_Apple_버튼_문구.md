# Apple 버튼 문구가 애플 승인 문구가 아니다 — 심사 전 결정 필요

## 개요

**B안(셋 다 맞추기)으로 처리했다.**

<img src="https://github.com/Twin-Fang/elum/releases/download/qa-evidence/i237_20260918-190818_login_providers.png" width="320">

| 제공자 | 전 | 후 |
| --- | --- | --- |
| 카카오 | `카카오로 시작하기` | **`카카오로 계속하기`** |
| 네이버 | `네이버로 시작하기` | **`네이버로 계속하기`** |
| Apple | `Apple로 시작하기` 🔴 | **`Apple로 계속하기`** ✅ |

## 왜 셋을 다 바꿨나

애플은 버튼 문구를 **세 가지로만** 허용한다.

```
Apple로 로그인 · Apple로 계속하기 · Apple로 가입
```

`Apple로 시작하기`는 여기 없다. 애플만 바꾸면(A안) 규격은 지키지만
**세 버튼의 문구가 어긋나 목록으로 읽히지 않는다.**

```
카카오로 시작하기
네이버로 시작하기
Apple로 계속하기     ← 혼자 다르다
```

셋 중 `계속하기`를 고른 이유 — **로그인과 가입을 가리지 않는 말**이다. 이룸은
소셜 로그인 하나로 가입과 로그인을 함께 처리하므로 `로그인`이나 `가입`은
한쪽만 가리켜 맞지 않다.

## 진행 중 문구도 통일했다

같은 화면에서 셋이 제각각이었다.

| 제공자 | 전 | 후 |
| --- | --- | --- |
| 카카오 | `연결하고 있어요` | **`연결하고 있어요`** |
| 네이버 | `연결 중...` | **`연결하고 있어요`** |
| Apple | `연결 중...` | **`연결하고 있어요`** |

`연결 중...`은 명사형이라 **해요체·능동형 규칙**(루트 `CLAUDE.md`)에 어긋난다.
문구를 건드리는 김에 함께 맞췄다.

## 회귀 방지

문구가 다시 `시작하기`로 돌아가면 심사에서 걸린다. 테스트로 고정했다.

```dart
testWidgets('애플이 승인한 문구를 쓴다 (이슈 #237)', (tester) async {
  expect(find.textContaining('로 시작하기'), findsNothing);
  expect(find.text('카카오로 계속하기'), findsOneWidget);
  expect(find.text('네이버로 계속하기'), findsOneWidget);
});
```

## 주의사항

- **문구를 임의로 바꾸지 않는다.** 애플이 허용하는 셋 밖으로 나가면 심사에서
  지적받는다. `login_screen.dart` 주석에 근거를 남겼다.
- 애플 버튼은 규격 위젯(`SignInWithAppleButton`)이 아니라 직접 그린다 (#230).
  **검정 배경 · 흰 사과 심볼 · 최소 높이 · 승인 문구**를 코드가 직접 지켜야 한다.
- 시안 문구(`~로 시작하기`)와 달라졌다. **디자이너에게 알려야 한다** — 심사 규격이
  이유라 되돌릴 수 없는 변경이다.
