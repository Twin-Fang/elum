# 홈, 일과, 보상 화면을 최신 시안으로 전체 반영

## 개요

디자이너가 새로 정리한 시안 섹션 `이룸이 휴대폰_이룸이모드`(1197:6774)에 맞춰 이룸이 화면 9장(홈, 홈_아무것도X 2종, 일과 진행, 일과 진행_완료, 별, 보상 루미·포포·루루)을 고쳤다. 화면마다 Figma 덤프와 시안 PNG를 함께 보고, **덤프와 PNG가 다른 곳은 PNG를 기준**으로 삼았다. 커밋은 caafbfa이고 푸시 전이다.

## 변경 사항

- `child_home_screen.dart`: 오른쪽 위 캐릭터 얼굴 버튼을 톱니(24×24 @ 345,86)로 바꿨다. 누르면 기존 비밀암호 화면을 연다. 누를 자리는 48로 넓히고 바깥 여백과 간격에서 그만큼 빼, 그림이 시안 자리에 그대로 선다. 별 배지는 x271로 옮겼다.

## 주요 구현 내용

**PNG가 기준인 이유.** Figma 덤프는 글자 구간별 색을 주지 않는다. 일과 진행 보상 칩은 덤프상 검정 한 색이지만 PNG는 "다하면"이 회색, 보상이 민트다. 픽셀 색을 직접 재서 밝은 화면(#74757D / #40BBA6)과 어두운 화면(흰색 / #55CFBA)을 각각 반영했다.

**공용 링은 보호자 홈 시안과 대조해 분리했다.** 이룸이 홈의 체크가 굵어 처음엔 공용 위젯을 바꿨다. 그런데 보호자 홈 시안(931:3896)의 체크는 가늘고 작아서, 옵션(`boldCheck`)으로 분리했다.

**보상 화면 간격은 서로 물려 있다.** 바닥 그림자 y를 올리면 별 묶음 높이가 줄어 아래 글자가 함께 올라간다. 캐릭터·그림자를 옮긴 뒤 제목 간격을 다시 보정했다.

**검증.** 앱 테스트 1203건이 통과했고 analyze는 0건이다. 시안 PNG와 앱 렌더를 픽셀로 맞댔다.

| 화면 | 시안 대비 다른 픽셀 |
|---|---|
| 홈 | 2.96% (로고·별 배지·톱니 자리는 픽셀 단위로 같다) |
| 홈_아무것도X 루루 / 포포 | 1.39% / 1.66% |
| 일과 진행 | 8.09% (카드 그림이 시험에서는 대체 일러스트라 남는 차이) |
| 보상 루미 / 포포 / 루루 | 3.8% / 4.4% / 3.6% (글자 렌더링과 별 후광) |

## 주의사항

- **톱니의 동작은 임시다.** 시안에 동작이 없어 기존 비밀암호 화면을 연다. 디자이너(예람) 답을 받으면 다시 정한다.
- **보상 칩의 대비.** 어두운 보상 화면의 반투명 칩은 시안대로 그렸다. 대비가 낮아 보이는 것이 의도인지 확인이 필요하다.
- **보호자 모드 변환 화면**은 새 섹션에 프레임이 없어 옛 섹션(309:2837) 기준 그대로 뒀다.
- **옆 카드 구분.** 옆 카드를 같은 크기·선명도로 그려 "지금 카드"가 덜 두드러진다. 시안대로다. 헷갈린다는 반응이 있으면 디자이너와 다시 논의한다.
- **일과 진행에서 보상이 없는 일과**는 칩 자리(48)를 비워 두어 카드가 오르내리지 않는다. 시안에 보상 없는 경우가 없어 정한 것이다.
- **실기기 확인은 못 했다.** 에뮬레이터에 새 빌드를 설치해 앱이 뜨는 것까지만 봤다. 홈 이후 화면은 운영 서버의 QA 계정과 일과 생성(AI 비용)이 필요해 시안 PNG 대조와 테스트로 갈음했다.
