# 인터넷이 끊기면 임시저장이 실패를 약 40초 늦게 보여준다: 자동 재시도

## 개요
인터넷이 끊긴 채 임시저장에 들어가면, 요청은 0.02초 만에 실패했는데 화면은 약 35~42초 동안 로딩만 보여 줬다. 원인은 Riverpod 3의 **실패 provider 기본 자동 재시도**였다. 앱 전체 `ProviderScope`에서 재시도를 껐다. 커밋은 `0c2b927`(develop 푸시, main 미반영)이다.

## 변경 사항
- `core/state/provider_retry.dart`(신규): `elumProviderRetry`는 늘 `null`을 돌려준다. 즉 재시도하지 않는다.
- `main.dart`: `ProviderScope(retry: elumProviderRetry, …)`.

## 왜 전역으로 껐나
FutureProvider 11개 중 재시도를 끈 것은 크레딧 하나뿐이었다. 재시도에 기대는 provider는 없었다. 실패 화면에는 모두 `다시 시도`가 있으니 다시 부를지는 사용자가 정한다. 저절로 재시도가 꼭 필요한 provider가 생기면 **그 provider에만** `retry:`를 준다.

## 검증
| 항목 | 결과 |
|---|---|
| `provider_retry_test` — 앱 설정 | 실패 직후 0.1초에 실패 화면이 뜬다 |
| `provider_retry_test` — Riverpod 기본값(대조군) | 같은 순간에 아직 실패 화면이 없다. 원인을 고정해 둔다 |
| Android 비행기 모드 실측 | 2초 안에 `임시저장을 불러오지 못했어요 · 다시 시도 (E-NET-OFFLINE)` |
| 전체 | 1185 통과, analyze 0건 |

기존 테스트가 이 결함을 못 잡은 이유: `pumpAndSettle()`이 가상 시간을 끝까지 돌려 재시도 대기를 가렸다.

## 주의사항
- 이 설정은 **모든 provider**에 걸린다. 일시적 오류를 조용히 넘기던 곳이 있었다면 이제 실패 화면이 바로 보인다. 11개를 전수 확인했지만 새 provider를 만들 때도 이 점을 기억해야 한다.
