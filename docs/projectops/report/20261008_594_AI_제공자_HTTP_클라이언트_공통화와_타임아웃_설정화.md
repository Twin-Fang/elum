# AI 제공자 HTTP 클라이언트 공통화와 타임아웃 설정화

## 개요
OpenAI 텍스트, OpenAI 이미지, FLUX 클라이언트가 RestClient를 만드는 코드를 각자 복사해 쓰고 있었습니다. 이것을 `AiRestClientFactory` 하나로 모았습니다. 코드에 박혀 있던 타임아웃(연결 10초, 읽기 120초)은 `ai.http` 설정으로 옮겼고, **키가 없으면 지금과 같은 값을 씁니다.** 운영 AI 동작(제공자 선택·폴백·재시도)은 바꾸지 않았습니다.

## 변경 사항

### 신규
- `common/infrastructure/properties/AiHttpProperties.java`: `ai.http.connect-timeout-millis`와 `read-timeout-millis`를 받습니다. 값이 없거나 0 이하이면 10,000ms / 120,000ms로 보정합니다.
- `ai/infrastructure/client/AiRestClientFactory.java`: `create(baseUrl)`로 RestClient를 만듭니다. baseUrl이 null이면 기준 주소 없이 만듭니다(FLUX 결과 이미지 다운로드용).

### 수정
- `OpenAiTextClient.java`, `OpenAiImageClient.java`, `FluxImageClient.java`: 자체 `buildRestClient()`를 지우고 팩토리를 씁니다. 필드 초기화가 주입받은 팩토리에 의존하게 돼서 `@RequiredArgsConstructor` 대신 명시적 생성자로 바꿨습니다.
- `FluxImageClientTest.java`: 생성자 인자가 늘어난 것에 맞췄습니다.
- `AiHttpPropertiesTest.java` (신규): 기본값이 이전 하드코딩과 같은지, 보정 규칙이 맞는지 확인합니다.

| 클라이언트 | 이전 | 이후 기본값 |
|---|---|---|
| OpenAI 텍스트·이미지 | 연결 10초 / 읽기 120초 | 10,000ms / 120,000ms |
| FLUX(요청·다운로드) | 연결 10초 / 읽기 120초 | 10,000ms / 120,000ms |

## 주요 구현 내용
- 요청 팩토리는 이전 그대로 `SimpleClientHttpRequestFactory`입니다. Gemini·로컬 LLM이 쓰는 `JdkClientHttpRequestFactory`로 통일하면 연결 방식이 바뀌어 동작이 달라질 수 있어서 바꾸지 않았습니다.
- `@ConfigurationPropertiesScan`이 있어 새 properties가 자동으로 등록됩니다. yml에 키를 추가하지 않아도 기동됩니다.

## 검증
- 서버 테스트 1545건 통과
- 로컬 Postgres로 리허설 통합 테스트 27건을 돌려, 실제 컨텍스트에서 새 빈이 붙는 것을 확인했습니다.
- 실제 AI 호출은 하지 않았습니다. 비용이 들기 때문입니다.

## 주의사항
- 세 클라이언트가 같은 타임아웃 쌍을 공유합니다. 제공자별로 다르게 하려면 properties를 나눠야 합니다.
- 텍스트 AI는 선택한 제공자가 실패하면 대체 경로(폴백) 없이 바로 실패합니다. 재시도와 서킷브레이커도 없습니다. 운영 동작이 바뀌는 일이라 이번 범위에서 뺐고, 하려면 따로 결정이 필요합니다.
