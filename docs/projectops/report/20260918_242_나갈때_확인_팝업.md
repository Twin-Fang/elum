# 만들다 나갈 때 확인 팝업 — warn 톤이 없어 함께 만든다

## 개요

일과를 만들다 중간에 나가면 **아무 말 없이 사라지던 것**을 막았다.
그러려면 팝업 무게가 하나 더 필요했다.

<img src="https://github.com/Twin-Fang/elum/releases/download/qa-evidence/i241_242_20260918-214849_dialog_tones.png" width="320">

## 1. warn 톤을 더했다

`ElumDialog`에 무게가 셋뿐이었다.

| 톤 | 색 | 쓰임 |
| --- | --- | --- |
| `primary` | 민트 | 주 동작 (확인) |
| `neutral` | 회색 | 취소·닫기 |
| `danger` | 빨강 #BB3F38 | **되돌릴 수 없는 파괴** (회원탈퇴) |
| **`warn`** 🆕 | **주황 #F5A524** | **지금 나가면 잃는다** |

나가기는 그 사이다. 만들던 것이 사라지지만 계정이 날아가는 건 아니다.
`danger`를 쓰면 빨간 경고가 겁을 주고, `primary`를 쓰면 대수롭지 않아 보인다.

> **아동도 보는 화면이라 빨강·경고 아이콘을 함부로 쓰지 않는다**
> (client/CLAUDE.md). warn은 그 선을 지키는 중간 톤이다.

아이콘 `dialogWarn`도 같은 이유로 **붉지 않은 주황 원**이다.

## 2. 나갈 때 팝업

```
        ⚠️
  만들던 일과가 사라져요

  [ 계속 만들기 ]  [ 나가기 ]
      neutral         warn
```

**되돌아가는 쪽을 먼저 둔다** — 실수로 누르는 일이 잦다.
바깥을 눌러 닫으면 null이고, 그때도 **나가지 않는 쪽**으로 해석한다.

### 어디서 뜨나

| 화면 | 묻나 | 왜 |
| --- | :-: | --- |
| 일과 입력 (빈 상태) | ❌ | 잃을 게 없다 |
| 일과 입력 (글을 썼다) | ✅ | |
| AI 질문 | ✅ | |
| 보상 정하기 | ✅ | 앞서 만든 답까지 사라진다 |
| 카드 검토 | ✅ | **AI가 30초 걸려 만든 카드다** |
| 보상 고치기(검토에서 진입) | ❌ | 되돌아갈 곳이 검토 화면이다 |

### 🔴 시스템 뒤로가기도 잡는다

화면 안의 `<`와 `⌂`만 막으면 **제스처로 그냥 빠져나간다.**
`PopScope(canPop: !confirmExit)`로 함께 잡았다 — 약관 화면이 쓰던 방식과 같다.

### 문구는 한 함수에 둔다

`confirmLeaveRoutineFlow()`.

일과 입력 화면만 `RoutineFlowScaffold`를 쓰지 않아 스캐폴드 안에만 두면
그 화면에서 다른 문구를 쓰게 된다. **화면마다 따로 쓰면 문구가 어긋난다.**

## 검증

| 항목 | 결과 |
| --- | --- |
| `flutter analyze` | **error·warning 0건** |
| `flutter test` | **542건 전부 통과** (신규 5건) |
| 골든 | 세 무게를 나란히 — 잘못 고르면 눈에 띈다 |

신규 테스트가 고정하는 것.

- 홈을 누르면 확인을 먼저 묻는다
- `계속 만들기`면 화면에 남는다
- `나가기`면 홈으로 간다
- **잃을 것이 없으면 묻지 않는다**
- `warn`과 `danger`는 다른 색이다

## 주의사항

- **팝업을 띄우는 조건을 늘릴 때 `confirmExit`만 켜면 된다.** 스캐폴드가 뒤로가기·홈·
  시스템 제스처를 한 번에 잡는다.
- 저장 후에는 화면을 떠나므로 묻지 않는다. 카드 검토에서 `저장하기`를 누르면
  그대로 나간다 — 이미 남았기 때문이다.
- **실기기 확인은 아직 못 했다.** 골든으로 색과 배치만 확인했다.
