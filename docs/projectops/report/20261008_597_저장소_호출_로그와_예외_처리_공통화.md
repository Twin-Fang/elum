# 저장소 호출 로그와 예외 처리 공통화

## 개요
저장소 호출마다 반복되던 틀(호출 로그 → try → 완료 로그 → catch → 실패 로그)을 `guarded`·`logged` 두 함수로 모았습니다. 회원·연결·크레딧·광고 보상·공지 저장소에 적용했습니다. `features/*/data`에 흩어져 있던 `debugPrint`는 `AppLogger`로 통일했습니다. 각 메서드가 호출부에 돌려주던 값은 바꾸지 않았습니다.

## 변경 사항

### 신규
- `core/network/guarded_call.dart`
  - `guarded<T>(repo, op, body, {describe})`: 예외를 `Attempt.failed(AppFailure.of(e))`로 바꿔 돌려줍니다.
  - `logged<T>(repo, op, body, {describe})`: 같은 로그를 남기고 예외는 그대로 다시 던집니다.
  - `describe`는 완료 로그에 남길 요약입니다. 값 자체가 아니라 건수·상태만 넘깁니다.
- `test/core/network/guarded_call_test.dart`: 6건

### 적용
- `guardian/data/member_repository.dart`
  - `createProfile`·`update*`는 `guarded`를 씁니다.
  - `getMyInfo`는 null을 돌려주는 동작을 유지했습니다.
- `link/data/device_link_repository.dart`: `issue`·`statusResult`
- `credit/data/credit_repository.dart`, `ad_reward_repository.dart`: `logged` 뒤에 기존대로 `AppFailure`로 바꿔 던집니다.
- `notice/data/notice_repository.dart`: 빈 피드를 돌려주는 동작과 `E-NOTICE` 에러 로그를 유지했습니다.
- `debugPrint` 26곳을 `AppLogger`로 바꿨습니다. 대상은 음성, 카드 캐시, 사진 고르기, 카드 그림, 카드 저장소입니다.

## 주요 구현 내용
- **호출부가 받는 값을 바꾸지 않는 것이 기준이었습니다.** 원래 방식은 세 가지(다시 던짐 / 실패 값 / null)였고, 메서드마다 쓰던 방식을 그대로 썼습니다. 상태 코드에 따라 갈라지는 메서드(`revoke`·`redeem` 등)는 건드리지 않았습니다.
- `AppLogger.error`는 시각을 붙여 `debugPrint`로 찍기만 합니다. 외부로 보내지 않으므로 레벨을 바꿔도 운영에 영향이 없습니다.
- 크레딧 완료 로그의 요약 문구는 `AppLogger` 호출 밖으로 나오면서 한글 검사기에 잡혔습니다. 로그 전용이라 검사기가 인정하는 `l10n-ignore` 표식을 붙였습니다.
