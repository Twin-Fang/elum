## 🔴 이슈의 전제가 사실과 달랐다 — 시스템 키보드는 이미 쓰고 있었다

이슈는 **"가장 큰 변화 — 커스텀 숫자패드가 아니라 시스템 키보드다"** 라고 적었다.
코드를 열어보니 **이미 시스템 키보드다.**

```dart
// pin_keypad.dart — PinInputField
TextField(
  keyboardType: TextInputType.number,   // OS 숫자 키패드
  ...
)
// 화면에는 PinDots로 자릿수만 그린다
```

`pin_keypad.dart`라는 **파일 이름이 오해를 부른 것으로 보인다.** 이 파일에는 키패드가
없고 "키패드를 띄우는 숨은 입력칸"과 "점"만 있다.

따라서 오버플로·플랫폼 차이 검토는 필요 없었고, 남은 것은 **문구 셋과 CTA 규칙**뿐이라
가벼운 작업이 됐다.

## 변경 사항

| CTA 문구 | `맞춤 설정하기` | **`시작하기`** |
| CTA 노출 | 항상 보임 (비활성) | **다 맞춰 넣어야 나타남** |

## 🔴 눌리지 않는 버튼은 알려주는 게 없다

시안에는 입력 중에 **버튼이 아예 없다.**

전에는 비활성 버튼을 깔아 뒀는데, 그러면 네 자리를 넣고도 "이걸 눌러야 하나" 하고
멈춘다. 두 번 맞춰 넣으면 그때 나타나므로 **나타나는 것 자체가 다 됐다는 신호**가 된다.

```dart
bottomButton: _canConfirm
    ? ElumButton(label: '시작하기', onPressed: _onComplete)
    : null,
```

## 용어 — `보호자모드`로 되돌렸다

`보호자 화면`은 #196에서 한 번 바꿨던 말이다. **시안을 따르기로 합의했다**
(이슈 #228 — 기기만 휴대폰으로 바꾸고 코드·모드는 시안대로). 근거는 루트 `CLAUDE.md`
용어 규칙에 있다.

> `한번`도 시안 그대로다. 맞춤법으로는 `한 번 더`(횟수)가 맞지만 같은 합의를 따랐다.
> 바꾸려면 디자이너와 함께 정하는 편이 낫다.

## 주의사항

- **불일치 경로는 그대로다** — 재입력만 비우고 1단계 암호는 살린다. 시안에 그 화면이
  없어 기존 동작을 유지했다.
- 2단계가 맞으면 키보드를 내려 CTA를 드러낸다. 키보드를 띄워두면 버튼이 그 뒤에 숨어
  **실기기에서 실제로 막혔던 적이 있다.**
