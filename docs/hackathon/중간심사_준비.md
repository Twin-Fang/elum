## 2. 발표자료(PPT) 목차안

대회가 요구하는 **6개 필수 항목**을 모두 채우되, 순서는 설득 흐름에 맞춘다.

| # | 슬라이드 | 내용 | 대응 심사항목 |
| --- | --- | --- | --- |
| 1 | 표지 | [룸룸] 이룸 · 분야 1 디지털 포용 | — |
| 2 | **기획의도 및 필요성** | 발달장애인 일과 수행의 어려움 · 보호자의 반복 설명 부담 | 필요성 |
| 3 | 사용자 정의 | **행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인** + 보호자 | 필요성 |
| 4 | **국내·외 유사 사례 비교** | 종이 그림카드 · 일정관리 앱 · **전년도 수상작 토닥이** 대비 차이 | **참신성** ★ |
| 5 | 개발물 설명 ① | 메뉴 구조도 | 완성도 |
| 6 | 개발물 설명 ② | 플로우차트 (일과 입력 → DLP → 카드 생성 → 승인 → 수행 → 보상) | 완성도 |
| 7 | 개발물 설명 ③ | 메인화면 + 주요 기능 스크린샷 | 완성도 |
| 8 | **핵심기술 ①** | AI 행동 카드 생성 — 자연어 한 문장을 행동 단계로 분해 (과제분석 자동화) | 참신성·적용가능성 |
| 9 | **핵심기술 ②** | **AI DLP Gateway** — 전송 전/후 비교 화면 | 참신성 ★ |
| 10 | 장애와 개발물의 연관성 | **ABA의 과제분석·연쇄·강화** 구조와 앱 기능의 1:1 대응 | 적용가능성 ★ |
| 11 | **전문기관 자문 반영** | 서울 ABA연구소 자문 → 강화(보상) 기능 추가 · 단계 수 가변화 | 적용가능성 |
| 12 | 상용화 전략 | 활용 방안 · 제약 사항과 해결방안 | 기대효과 |
| 13 | 리스크 해결방안 | AI 실패 fallback · 개인정보 · 오탐 · 보호자 입력 부담 | 적용가능성 |
| 14 | 기대효과 | 보호자 개입 감소 → 자립 지원 · 수행률 데이터 | 기대효과 |

### 10장이 가장 중요하다

> 심사위원 5명 중 **3명이 장애인 전문가**다. 기술이 아니라 **"이 앱이 행동중재 이론과 어떻게 연결되는가"** 를
> 본다. 과제분석(Task Analysis) → 카드 분해, 연쇄(Chaining) → 카드 순서 수행, 강화(Reinforcement) → 보상 설정
> 이 대응 관계를 한 장으로 보여주면 **"현장을 아는 팀"** 이라는 신호가 된다.

### 9장은 기술 전문가 2명을 위한 장이다

입력문이 DLP를 거쳐 실제로 바뀌는 **전/후 비교 화면**을 그대로 넣는다.
이미 구현되어 있으므로 스크린샷만 있으면 된다 (`dlp_screen.dart`).

## 3. 발표 시간 배분 (10분 + 질의 5분)

| 시간 | 내용 |
| --- | --- |
| 0:00~1:30 | 문제 — "학교 갈 준비해"에 숨은 단계들, 보호자의 반복 설명 |
| 1:30~2:30 | 유사 사례 비교 (**토닥이 포함**) 및 차이 |
| 2:30~5:30 | **시연** — 일과 입력 → DLP → 카드 생성 → 보호자 승인 → 아동 수행 → 보상 |
| 5:30~7:00 | 핵심 기술 2가지 (카드 생성 · DLP) |
| 7:00~8:30 | ABA 이론 연결 + 전문기관 자문 반영 |
| 8:30~10:00 | 상용화·리스크·기대효과 |

> ⏱️ **시간 초과는 감점이다.** 시연은 반드시 **녹화 영상**으로 한다 —
> 현장에서 실시간 시연하다 네트워크·AI 응답 지연이 나면 배점이 날아간다.

## 5. 중간심사에서 반드시 해야 할 일

> **중간심사 점수는 최종 순위에 반영되지 않는다.**
> 목적은 점수가 아니라 **피드백을 정확히 받아오는 것**이다.

- 심사위원 지적을 **그대로 받아 적는다** (요약하지 말고 표현 그대로)
- 애매한 지적은 **질의응답 시간에 되물어 구체화**한다
- 돌아와서 [반영계획](../meetings/20260913_서울ABA연구소_1차자문/반영계획.md)과 같은 형식으로 정리한다
- 최종 발표는 **"지적 → 반영 결과"** 를 1:1로 보여주는 구성으로 만든다 (전년도 수상팀이 쓴 방식)
