제출 마감과 심사 기준이 개발 우선순위를 결정하므로, 기능을 정하기 전에 이 문서를 먼저 본다.

| 대회명 | 2026년 장애인 분야 해커톤 대회 「장애 플러스 기술」 — 장애인을 위한 APP 개발 공모전 |
| 주최·주관 | 한국장애인재단 |
| 후원 | 과학기술정보통신부 · 보건복지부 |

### 발표자료(PPT) 필수 포함 항목

```text
1) APP 기획의도 및 필요성
2) 국내·외 유사 사례 비교 및 차이점        ← 전년도 수상작 '토닥이' 대응 필수
3) 개발물에 대한 설명
   · APP 시연 영상 및 이미지
   · 플로우차트
   · 메뉴 구조도
   · 메인화면 + 기본서비스 + 주요서비스 설명
   · 장애와 개발물의 연관성
4) 상용화 전략 (활용 방안, 제약 사항과 해결방안)
5) 리스크 해결방안
6) 기대효과
```

> 📌 **시연 영상·이미지는 "선택"이지만 사실상 필수다.** 미제출 상태에서 발표 중 PPT 영상이 안 돌아가면
> 대체할 수단이 없다. 현장 네트워크·기기 환경을 신뢰할 수 없으므로 반드시 함께 낸다.

## 4. 실증 (필수 요건) ⚠️

> **"개발 진행 시 각 팀별 최소 1회의 개별적·자율적 실증이 필수적으로 진행되어야 하며,
> 본선 대회(최종심사) 발표 시 실증 관련 내용이 반드시 포함되어야 함"**

형식·방법·인원·기간은 자유지만 **하지 않으면 안 된다.** 실증보고서에 들어갈 항목은 다음과 같다.

| 항목 | 준비해야 하는 것 |
| --- | --- |
| 참여자 모집 | 모집방법 · 선정기준 · 인원 · **동의 방법** |
| 참여자 기본정보 | 성별 / 연령 / 장애유형 / 장애정도 — **표로, 익명 처리** |
| 실증 진행 내용 | 진행방식(대면·비대면·원격) · 실증도구 · 기간 및 횟수 · 평가·피드백 방법 |
| 실증 결과 | **정량**(설문 점수·만족도) + **정성**(참여자 발언·개선 의견) |
| 개선사항 반영현황 | 피드백 반영 전/후 비교 |
| 실증 진행 사진 | **최소 3장** · 얼굴 모자이크 또는 비노출 촬영 |

> 🔗 **[서울 ABA연구소 1차 자문](../meetings/20260913_서울ABA연구소_1차자문/)이 실증의 출발점이다.**
> 자문에서 나온 "보호자용·자녀용 앱 설치 후 실사용 테스트"가 곧 이 실증에 해당한다.
> 참여자 모집·동의 절차를 연구소와 협의해 두면 실증보고서의 모집 항목이 그대로 채워진다.

> ⚠️ **실증 참여자 정보와 앱 수집 정보를 혼동하지 않는다.**
> 실증보고서에는 참여자의 장애유형·장애정도를 적어야 하지만, 이는 **대회 제출 문서용으로 별도 동의를 받아
> 수집하는 정보**다. ELUM 앱은 여전히 진단명·장애유형을 수집하지 않는다
> ([서비스 원칙 1번](../README.md)). 발표에서 이 구분을 명확히 해야 원칙과 모순되어 보이지 않는다.

## 5. 심사 기준

### 중간심사 (100점 · 심사위원 5명 — 장애인 전문가 3 + 기술 전문가 2)

| 평가항목 | 배점 | 평가기준 |
| --- | ---: | --- |
| 적용가능성 | 20 | 실제로 실현 가능한가 · 장애 현장에서 적용 가능성이 높은가 |
| 참신성 | 20 | **기존 APP 대비 차별성** · 독창적이고 새로운가 |
| 필요성 | 20 | 실제 장애인에게 얼마나 활용·필요할 것인가 · 장애계 이슈의 해결책인가 |
| 완성도 | 20 | 제안 내용이 얼마나 충실히 구현되었는가 |
| 기대효과 | 20 | 사회적 영향력 · 장애인의 삶에 미치는 영향 |

> **중간심사 점수는 최종 순위에 반영되지 않는다.** 그러나 여기서 받은 피드백을
> 최종 발표에서 어떻게 반영했는지를 보여줘야 하므로, **피드백을 정확히 받아 적는 것이 중간심사의 진짜 목적**이다.

### 본선 (100점 = 심사위원 70 + 시민평가단 30)

같은 5개 항목, 항목별 **심사위원 14점 + 시민평가단 6점**.

**시민평가단 30점**은 장애인 단체·기관 종사자, 사회복지 종사자, 학계 전문가, **장애인 당사자와 가족**,
대학(원)생, 비장애인 10명으로 구성된다. 현장에서 발표만 듣고 채점한다.

> 📌 **시민평가단은 코드를 보지 않는다.** DLP·아키텍처 같은 기술적 깊이는 심사위원 70점에 작용하고,
> "이 앱이 우리 아이에게 실제로 도움이 되겠는가"가 시민평가단 30점을 가른다.
> 발표는 두 청중을 동시에 설득해야 한다.

## 7. 반드시 피해야 할 것 (탈락·환수 사유)

### 참가 및 심사과정 제외 기준

해당되면 **심사 제외 · 입상 취소 · 상금 전액 환수**된다.

| # | 기준 | 내용 |
| --- | --- | --- |
| ① | 동시·중복 제출 | 같은 해 타 대회·공모전에 동일·유사 아이디어를 **동시에 제출**한 경우 |
| ② | 기존 개발물 재출품 | 이전에 타 대회·공모전에 참가해 **이미 개발이 진행된** 아이디어를 제출한 경우 |
| ③ | 수상 개발물 제출 | 동일·유사 아이디어로 **이미 타 대회에서 입상**한 경우 |
| ④ | 법률 위반 | 특허법·실용신안법·저작권법·디자인보호법·부정경쟁방지법 등 위반 |

### 중도포기·탈락

- 본선 전 중도포기 시 **실증진행비 30만원 전액 환수**
- **개발 진척도가 다른 팀에 비해 현저히 떨어지거나 불성실하다고 판단되면 탈락** + 전액 환수

### 팀 구성 변경

부득이한 사유로 팀장·팀원이 바뀌면 담당자에게 구두로 알리고 **[별첨 2] 변경 신청서**로 사무국 승인을 받는다.
임의 진행 시 선정 취소 등 불이익.
