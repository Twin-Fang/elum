# 1. 🚫 절대 쓰지 말아야 할 표현

| 쓰면 안 되는 말 | 왜 | 대신 |
| --- | --- | --- |
| **"ABA 기반 치료 앱"** | ELUM은 임상 ABA 중재로 검증된 적이 없다. 치료를 표방하면 근거를 요구받는다 | **"ABA 및 특수교육에서 활용되는 과제분석·강화·연쇄 원리를 참고한 일상생활 자립 지원 서비스"** |
| **"개별화교육계획(IEP)을 자동 생성한다"** | IEP는 교사·보호자·관련 인력이 참여해 수립하는 **제도화된 교육 계획**이다. 앱이 만들 수 있는 것이 아니다 | **"사용자의 개별 수행 수준에 맞춘 행동 단계 개인화"** |
| **"발달장애에는 ADHD도 포함된다"** | 국내 법률상 발달장애인은 **지적장애·자폐성장애** 중심이다. 신경발달장애(ADHD·학습장애 포함)와 범주가 다르다 | **"신경발달장애 범주에는 ADHD 등이 포함되지만, 국내 법률상 발달장애인 범주와는 구분된다"** |
| **"지적장애 1급 / 2급 / 3급"** | 장애등급제는 **폐지**됐다. 옛 기준이다 | 등급 대신 **기능 기준** — 글 이해 / 그림 이해 / 순서 이해 / 스마트폰 조작 / 독립 수행 여부 |
| **"셀프 모델링"** (사용자 얼굴을 캐릭터에 반영) | 학술 용어 **Video Self-Modeling**은 *자신이 목표 행동을 수행하는 영상*을 보는 중재다. 얼굴 반영과는 다르다 | **"사용자 모습을 반영한 개인화 시각자료"** / "자기참조형 시각자료" |
| **"발달장애인은 지연 강화가 안 된다"** | 개인차가 크다. 전체로 일반화하면 부정확하고 당사자를 단순화한다 | **"일부 발달장애인은 장기간 지연된 결과보다 행동과 가까운 시점의 명확한 강화에서 행동-결과 관계를 이해하기 쉬울 수 있다"** |
| **"발달장애인은 사진만 이해하고 그림은 못 이해한다"** | 개인차가 크다 | **"추상화 수준이 높아질수록 이해가 어려운 사용자가 있을 수 있어, 사용자 수준에 맞는 시각자료를 제공한다"** |
| **"AI가 아이의 일과를 교정한다"** | 앱이 행동을 바꾸는 주체가 아니다 | **"보호자·지도자가 구성한 일상 행동 지원 구조를 디지털로 확장한다"** |

> ⚠️ **금지 표현은 대부분 "과장"에서 나온다.** 더 크게 말하려다 근거 없는 주장이 되고,
> 장애인 전문가 심사위원에게는 그게 가장 먼저 보인다.

# 2. ✅ 발표에서 쓸 핵심 문장

### 서비스 한 줄 정의 (권장)

> **보호자가 입력한 일상 과제를 AI가 과제분석(Task Analysis) 방식의 작은 행동 단계로 구조화하고,
> 보호자가 사용자의 실제 수행 수준에 따라 이를 개별화한 뒤,
> 강화와 순차적 행동 지원을 통해 독립 수행을 돕는 서비스**

### 이론 연결 (심사위원 3명이 보는 지점)

```text
응용행동분석(ABA)
│
├─ 강화(Reinforcement)        → 보호자가 설정하는 보상, 수행 중 지속 노출
│   ├─ 사회적 강화             → 캐릭터 칭찬 반응
│   ├─ 즉각 강화               → "오늘 받을 수 있는 것" 안내
│   └─ 지연 강화
│
├─ 과제분석(Task Analysis)     → AI가 한 문장을 행동 단계로 분해   ★ 핵심 차별점
│
└─ 연쇄(Chaining)              → 카드를 순서대로 수행
    ├─ Forward Chaining
    ├─ Backward Chaining       → 향후 개인화 확장 여지
    └─ Total Task
```

### 서비스 흐름을 전문 개념으로 옮기면

```text
보호자가 자연어로 일과 입력
      ↓ AI
과제분석 초안 생성 (Task Analysis)
      ↓ 보호자
개별화 — 이미 혼자 하는 단계 삭제, 어려운 단계 추가·세분화
      ↓
행동 시퀀스 제시 (Chaining)
      ↓
단계별 수행 + 강화물 상기 (Reinforcement)
      ↓
보호자 지원 감소 → 독립적인 일과 수행
```

# 3. 용어 정의 (물어보면 답할 수 있어야 하는 것)

| 용어 | 한 줄 정의 |
| --- | --- |
| **강화(Reinforcement)** | 어떤 행동 뒤에 특정 결과가 주어져 **그 행동의 미래 발생 가능성이 증가**하는 것. 단순히 "상을 준다"가 아니다 |
| **강화물(Reinforcer)** | 행동 뒤에 제공되어 그 행동을 증가시키는 자극. **사람마다 다르다** — 그래서 보호자가 설정한다 |
| **과제분석(Task Analysis)** | 복잡한 행동을 수행 가능한 작은 단계로 분해하는 것 |
| **연쇄(Chaining)** | 나눈 단계들을 순서대로 연결해 하나의 기술로 완성하는 절차 |
| **Backward Chaining** | 마지막 단계부터 독립 수행 범위를 넓혀 가는 방식 |
| **생활연령 / 발달연령** | 출생일 기준 나이 / 특정 영역의 수행 수준을 연령 등가로 표현한 것. **둘은 다르다** |
| **행동 시퀀스** | 여러 행동이 일정 순서로 연결된 구조. 단순 스케줄(09:00 학교)과 구분된다 |

> 💡 **강화의 정의를 정확히 아는 게 중요하다.** "학교에 가서 김밥을 줬다"만으로는 강화가 아니다.
> **그 뒤 학교 가는 행동이 실제로 늘어야** 강화라고 할 수 있다.
> 질의응답에서 이 구분을 말할 수 있으면 전문가 심사위원에게 신뢰를 준다.

# 4. 우리 서비스가 "일정 관리 앱"이 아닌 이유

```text
스케줄(Schedule)              행동 시퀀스(Sequence)
─────────────                ────────────────────
09:00 학교                    가방 챙기기 → 신발 신기
12:00 점심                    → 집 나가기 → 버스 타기
16:00 귀가                    → 학교 도착
```

ELUM은 **Schedule Management가 아니라 Sequential Routine / Task Support**다.
"캘린더가 없다"는 질문을 받으면 이 구분으로 답한다.

# 5. 아직 반영하지 않은 개념 (확장 여지)

| 개념 | ELUM 적용 가능성 |
| --- | --- |
| **Backward Chaining** | 마지막 단계부터 독립 수행하게 하는 모드. 단계별 "혼자 할 수 있음" 체크와 연결 가능 |
| **Total Task Teaching** | 전체를 매번 수행하되 필요한 단계에서만 도움. 현재 구조와 가장 가깝다 |
| **기능별 프로필** | 발달연령 숫자 하나가 아니라 **글 읽기 / 그림 이해 / 순서 이해 / 스마트폰 조작**을 각각 받는 방식 |
| **시각자료 수준 선택** | 실제 사진 / 사실적 이미지 / 카툰 중 선택 |

> 이 표는 **"앞으로 무엇을 할 것인가"** 질문에 대한 답이기도 하다.
> 근거 없는 확장이 아니라 **전문 개념에 기반한 로드맵**으로 제시할 수 있다.
