## A-1 · A-2 — Secret을 확인할 필요가 없어졌다

`client/lib/core/config/app_config.dart`에서 세 플래그가 전부 **빌드 종류로 먼저 막힙니다.**

```dart
static const String _buildFlavor =
    String.fromEnvironment('ELUM_BUILD', defaultValue: 'prod');
static bool get isDevBuild => _buildFlavor == 'dev';

static bool get useMock       => (kDebugMode || isDevBuild) && _bool('ELUM_USE_MOCK', true);
static bool get showDevTools  => (kDebugMode || isDevBuild) && _bool('ELUM_SHOW_DEV_TOOLS', false);
static bool       skipOnboarding = (kDebugMode || isDevBuild) && _bool('ELUM_SKIP_ONBOARDING', false);
```

제출용 APK는 `--release`에 `ELUM_BUILD`를 주지 않으므로 `kDebugMode = false`,
`isDevBuild = false`입니다. **`&&` 왼쪽에서 이미 false라 `.env` 값은 읽히지도 않습니다.**

| 빌드 | 명령 | mock · 개발도구 · 온보딩 건너뛰기 |
| --- | --- | --- |
| 제출용 | `./scripts/build-apk.sh submit` | **무조건 꺼짐** (Secret 값과 무관) |
| 개발용 | `./scripts/build-apk.sh dev` | `.env` 값을 따름 |

> 📌 **발견 사항** — 릴리스 워크플로우(`PROJECT-COMMON-RELEASE-CHANGELOG.yaml`)에는
> 다른 워크플로우와 달리 devFlag를 false로 덮어쓰는 안전장치 스텝이 **없습니다.**
> 지금은 위 코드가 막아주므로 실제 피해는 없지만, `app_config.dart`의 `&&` 조건을
> 누가 되돌리면 그날로 구멍이 됩니다. **제출용 APK는 워크플로우 산출물이 아니라
> `scripts/build-apk.sh submit`으로 만듭니다.**

# 5. ④ 시연 영상 — 가장 오래 걸린다

| 항목 | 내용 |
| --- | --- |
| 길이 | 2분 30초 |
| 녹화 | **실기기** 화면 녹화 (에뮬레이터 X) |
| 자막 | **필수** — 현장 스피커를 신뢰할 수 없다 |
| 나레이션 | 없음 — 발표자가 직접 설명하며 재생 |
| 강조 | 카드 생성 순간 · 캐릭터 일관 삽화에서 2초 정지 |
| 개인정보 | 실명·실제 학교명 입력 금지 (데모 페르소나 `하늘이`) |
| 백업 | 주요 장면 **스크린샷 5~6장**을 PPT에 별도 삽입 |

## 시나리오 — 장면별 대본은 [시연영상 촬영대본](./제출물/시연영상_촬영대본.md)에 있다

```
① 문제 제시 → ② 일과 입력(음성) → ③ AI 되묻기 → ④ 카드 생성
→ ⑤ 캐릭터 일관성 → ⑥ 보호자 수정 → ⑦ 아이에게 보내기
→ ⑧ 카드 수행 → ⑨ 완료·별 → ⑩ 보호자가 진행률 확인
```

> ⚠️ **보상 설정 화면은 이 영상에 넣지 않는다.**
> 서버(#148~150)는 완료됐지만 **앱 화면은 디자인(#145~147) 대기 중**이라
> 9/16 녹화 시점에 없다. 없는 기능을 있는 것처럼 찍으면 최종심사에서 확인받는다.
>
> 발표에서는 이렇게 말한다 —
> *"서버는 지난주에 만들었고, 화면은 이번 주에 붙입니다.
> 최종 발표 때 완성된 모습으로 보여드리겠습니다."*
