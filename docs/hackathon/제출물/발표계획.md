# 2. 이 발표의 목적

> **중간심사 점수는 최종 순위에 반영되지 않습니다.**

목적은 **피드백을 정확히 받아오는 것**입니다.
전년도 수상작 토닥이는 중간심사에서 *"타겟 명확화가 필요하다"* 는 지적을 받고
구조를 바꿔 보건복지부장관상을 받았습니다.

## 그래서 이렇게 합니다

| 할 것 | 하지 말 것 |
| --- | --- |
| 지적을 **그대로 받아 적는다** (요약하지 않고) | 변명하거나 방어하지 않는다 |
| 애매한 지적은 **질의 시간에 되묻는다** | "네 알겠습니다"로 넘기지 않는다 |
| 마지막 장에서 **먼저 고민을 꺼낸다** | 완벽한 척하지 않는다 |

# 3. 발표 첫 30초 (가장 중요)

```
"이룸은 '학교 갈 준비해' 한 마디를
 아이가 따라 할 수 있는 순서로 바꿔주는 앱입니다.

 그 한 마디에는 옷 입기, 가방 챙기기, 신발 신기처럼
 여덟 단계가 숨어 있습니다.

 지금까지 이걸 머릿속에서 쪼개온 사람은 보호자였습니다.
 저희는 그 일을 AI가 대신하게 만들었습니다."
```

**기능을 나열하지 않습니다.** 무엇을 만들었는지보다 **무엇을 푸는지**가 먼저입니다.

# 4. 전문가 자문을 말하는 방식

```
"지난주 서울 ABA연구소 한상민 소장님께 자문을 받았습니다.

 가장 크게 남은 말씀은 이것이었습니다.
 '기분이 나쁘면 폰을 던지지, 속으로 다스리는 게 아니다.'

 저희 추천 일과에 '마음 다스리기' 같은 항목이 있었는데,
 눈으로 확인할 수 없는 건 카드가 될 수 없다는 지적이었습니다.
 그날 바로 전부 걷어냈습니다.

 소견을 긍정적으로 검토해 현재도 반영·수정 중입니다."
```

> 💡 **"검토 후 수정 중"이 정확한 표현입니다.** 다 했다고 하면 확인을 요구받습니다.

| 질문 | 답 |

| **작년 토닥이와 뭐가 다른가요?** | "토닥이는 정해진 일정을 보여줍니다. 이룸은 그 일정을 만들어내는 앞단을 다룹니다." |
| **AI가 잘못된 카드를 만들면?** | "출력 검증 → 위험 문장 검수 → **보호자 승인 게이트** 3중입니다. AI 결과는 초안으로 다룹니다." |
| **실제 발달장애인에게 테스트했나요?** | "9월 13일 서울 ABA연구소 자문을 받았고, 10월에 연구소 협력으로 실증을 진행합니다." |
| **아동만 쓸 수 있나요?** | "아닙니다. 연령이 아니라 기능 수준 기준입니다. 지적장애인 중위연령이 33.8세입니다." |
| **보호자가 설정을 복잡해하면?** | "온보딩은 네 단계뿐이고 보상 설정도 건너뛸 수 있습니다. 개별화는 설정이 아니라 **편집**으로 합니다." |
| **수익 모델은?** | "보호자에게 직접 과금하지 않습니다. 기관 라이선스와 기업용을 우선으로 봅니다." |
| **개인정보는?** | "진단명·장애유형을 수집하지 않고, 입력 원문을 보관하지 않습니다." |
| **AI 비용은 감당되나요?** | "지난 일과 재사용으로 재호출을 줄입니다. 매일 같은 준비는 탭 한 번으로 끝납니다." |
| **ADHD도 대상인가요?** | "국내 법률상 발달장애인은 지적장애·자폐성장애입니다. 다만 순서 유지에 어려움이 있는 경우 같은 구조가 쓰일 수 있습니다." |

> ⚠️ **마지막 질문의 답을 틀리면 안 됩니다.** 법률상 범주와 의학적 범주를 구분해 말합니다.

# 6. 시연 영상 — 현장 실시간 시연은 하지 않습니다

| 항목 | 기준 |
| --- | --- |
| 길이 | 2분 30초 |
| 녹화 | **실기기** (에뮬레이터는 의심을 삽니다) |
| 자막 | **필수** — 현장 스피커를 신뢰할 수 없습니다 |
| 나레이션 | 없음 — 발표자가 직접 설명하며 재생 |
| 강조 | 카드 생성 순간 · 캐릭터 일관 삽화에서 2초 정지 |
| 백업 | 주요 장면 스크린샷 5~6장을 PPT에 별도 삽입 |

> 네트워크·AI 응답 지연으로 배점이 날아가는 건 막아야 합니다.
