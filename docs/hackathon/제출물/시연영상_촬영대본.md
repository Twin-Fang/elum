# 1. 장면 구성 (150초)

## ① 문제 제시 — 8초

| | |
| --- | --- |
| **화면** | 보호자 홈 (오늘 일과가 비어 있는 상태) |
| **조작** | 없음. 화면만 |
| **자막** | `"학교 갈 준비해"` **한 마디에 8단계가 숨어 있습니다** |

> 첫 8초는 **앱을 보여주지 않고 문제를 보여줍니다.** 기능부터 나오면 심사위원은
> "또 일정 앱이구나"로 분류합니다.

## ② 일과 입력 — 15초

| | |
| --- | --- |
| **화면** | 일과 입력 |
| **조작** | `+` → 입력창에 **말로** 입력 (마이크 버튼 사용) |
| **입력 내용** | **"내일 비가 온대. 학교 갈 준비를 해야 해"** |
| **자막** | 평소 말하듯 입력합니다 · 단계를 나눌 필요가 없습니다 |

> **반드시 음성으로 입력합니다.** 보호자는 바쁩니다. 타이핑 장면은 이 앱의 강점을
> 보여주지 못합니다. 음성 인식이 틀리면 그 테이크는 버리고 다시 찍습니다.

## ③ 되묻기 — 20초

| | |
| --- | --- |
| **화면** | 준비 중 → 추가 질문 |
| **조작** | 선택지 중 **"우산"** 탭 → 다음 |
| **자막** | 비 오는 날 무엇이 필요한지 **되묻습니다** |

> ⭐ **이 장면이 이 영상에서 가장 중요합니다.** 다른 앱은 입력한 대로 쪼개기만 합니다.
> 이룸은 **상황에 따라 달라지는 준비물을 되묻습니다.** 편집에서 이 구간만
> 0.5초 정지 + 화살표 강조를 넣습니다.

## ④ 카드 생성 — 12초

| | |
| --- | --- |
| **화면** | 카드 만드는 중 → 카드 검토 |
| **조작** | 없음. 카드가 채워지는 것만 |
| **자막** | 8개 행동 카드가 만들어집니다 |
| **편집** | **로딩이 8초를 넘으면 2배속.** 12초를 넘으면 컷 |

## ⑤ 캐릭터 일관성 — 12초

| | |
| --- | --- |
| **화면** | 카드 검토 화면을 **천천히** 스크롤 |
| **조작** | 위에서 아래로 한 번, 되돌아오지 않습니다 |
| **자막** | 아이가 고른 캐릭터가 **모든 그림에 똑같이** 나옵니다 |

> ⭐ 두 번째로 중요한 장면입니다. **여러 장의 그림에 같은 캐릭터가 있다는 사실**이
> 한눈에 보여야 합니다. 스크롤이 빠르면 아무도 못 알아봅니다.

## ⑥ 보호자가 고친다 — 15초

| | |
| --- | --- |
| **화면** | 카드 검토 |
| **조작** | 카드 하나를 탭 → 문장 수정 → 저장 |
| **자막** | AI가 만든 것을 **보호자가 확인하고 고칩니다** · 승인 전에는 아이에게 보이지 않습니다 |

> AI 신뢰성 질문은 반드시 나옵니다. **영상에서 미리 답해둡니다.**

## ⑦ 아이에게 보내기 → 모드 전환 — 10초

| | |
| --- | --- |
| **화면** | 검토 → 모드 전환 PIN |
| **조작** | `아이에게 보내기` → PIN 입력 |
| **자막** | 아이 화면으로 넘어갑니다 · **PIN이 있어야 보호자 화면으로 돌아옵니다** |

## ⑧ 아이가 수행한다 — 35초

| | |
| --- | --- |
| **화면** | 아동 홈 → 일과 상세 |
| **조작** | 일과 탭 → 카드 1번 완료 → 2번 완료 → **3번에서 음성 재생 버튼** → 완료 |
| **자막** | 그림 한 장 · 짧은 문장 한 줄 · 읽어주는 음성 |
| **소리** | **TTS가 나오는 구간은 소리를 살립니다.** 나머지는 무음 |

> 3장만 보여주고 나머지는 편집에서 빠르게 넘깁니다. 8장을 다 보여주면 지루합니다.
> **음성 재생은 반드시 넣습니다** — 글을 못 읽는 사용자를 위한 기능이라는 근거입니다.

## ⑨ 완료 — 15초

| | |
| --- | --- |
| **화면** | 다 했어요 → 별 → 보상 화면 |
| **조작** | 마지막 카드 완료 |
| **자막** | 해낸 것을 바로 알려줍니다 |

## ⑩ 보호자가 확인한다 — 8초

| | |
| --- | --- |
| **화면** | 모드 전환 → 보호자 홈 (진행률 표시) |
| **조작** | PIN → 홈 |
| **자막** | 보호자는 **어디까지 했는지** 확인합니다 |

> 마지막을 아이 화면이 아니라 **보호자 화면으로 닫습니다.** 이 앱이 누구의 문제를
> 푸는지를 마지막 프레임에 남깁니다.

# 2. 편집 규칙

| | |
| --- | --- |
| **자막** | **전 구간 필수.** 현장 스피커를 신뢰할 수 없습니다 |
| **자막 위치** | 화면 **하단 1/5**. UI를 가리지 않게 |
| **자막 길이** | 한 줄 **20자 이내**, 한 번에 두 줄까지 |
| **나레이션** | 넣지 않습니다. 발표자가 직접 말하며 재생합니다 |
| **배경음** | 넣지 않거나 아주 작게. TTS 구간과 겹치면 안 됩니다 |
| **로딩** | 2배속 또는 컷. **AI를 기다리는 장면은 감점 요인입니다** |
| **강조** | ③ 되묻기 · ⑤ 캐릭터 일관성 두 곳만. 세 곳 넘기면 강조가 죽습니다 |
| **길이** | **2분 30초 ± 10초.** 3분 넘으면 발표 시간이 무너집니다 |

# 3. 영상이 안 될 때를 대비합니다

현장에서 영상이 재생되지 않는 사고는 실제로 일어납니다.

- [ ] 영상을 PPT에 **삽입**합니다 (링크 ❌)
- [ ] 주요 장면 **스크린샷 6장**을 별도 슬라이드로 준비합니다
      → ② 입력 / ③ 되묻기 / ⑤ 캐릭터 일관 / ⑥ 수정 / ⑧ 수행 / ⑩ 보호자 확인
- [ ] USB와 메일 양쪽에 백업합니다
- [ ] **실기기에 APK를 설치해 가져갑니다** — 최악의 경우 직접 보여줍니다

# 4. 지금 영상에 넣을 수 없는 것

**보상(강화) 설정 화면은 아직 앱에 없습니다.** 서버는 만들었지만 화면이 남았습니다.

| | |
| --- | --- |
| 서버 | ✅ 완료 (보상 저장·조회 API) |
| 앱 화면 | ⏳ 디자인 확정 후 구현 (#151·#152) |

**영상에 억지로 넣지 않습니다.** 대신 발표에서 이렇게 말합니다.

```
"자문에서 가장 크게 지적받은 것이 보상이었습니다.
 서버는 지난주에 만들었고, 화면은 이번 주에 붙입니다.
 최종 발표 때 완성된 모습으로 보여드리겠습니다."
```

없는 기능을 있는 것처럼 보여주면 최종심사에서 반드시 확인받습니다.
**지금 없는 것은 없다고 말하는 편이 안전합니다.**
