# 본선 PPT 설계 — 점수표에서 거꾸로 만든다

> 대상: 본선(최종심사) 발표 · **10분 발표 + 질의응답 5분 · 시간 초과 시 감점**
> 제출: 2026-10-28(수) 이메일 · 발표: 11/2 ~ 11/13 중 1일
> 근거: [활동안내자료.pdf 6쪽](../raw/활동안내자료.pdf) 심사기준 · [수상전략](../수상전략.md) · [표현 가이드](../발표_표현가이드.md)
>
> 🔴 = 아직 레포에 근거가 없어 **팀이 채워야 하는 칸**. 비워 둔 채로 슬라이드를 만들지 않는다.

# 1. 점수표를 슬라이드로 옮기기

| 항목 (심사위원 14 + 시민 6) | 심사위원이 묻는 것 | 이 항목의 점수가 되는 슬라이드 |
| --- | --- | --- |
| **적용가능성** | ① 실현 가능한가 ② 장애 현장에서 쓸 수 있는가 | **실증(S8·S9)** · 현장 기관 · 운영 방식 |
| **참신성** | ① 기존 앱과 뭐가 다른가 ② 독창적인가 | **비교표(S6)** · 과제분석 자동화(S7) |
| **필요성** | 실제 장애인에게 얼마나 필요한가 | **규모·보호자 부담(S2·S3)** · 당사자 목소리 |
| **완성도** | 말한 것이 실제로 구현됐는가 | **시연 영상(S5)** · 피드백 반영(S10) · 출시 상태 |
| **기대효과** | 사회적 영향력이 있는가 | **효과 숫자(S11)** · 상용화·로드맵(S12) |

> 🎯 **본선은 "무엇을 만들었나"가 아니라 "써 봤더니 어땠나"를 묻는다.**
> 중간심사는 기획을 봤고, 본선은 실증 결과가 들어와야 한다(공고가 필수로 못 박았다).
> 적용가능성 20점과 필요성 20점은 실증 슬라이드가 거의 혼자 가져간다.

## 청중이 둘이다

| | 심사위원 5명 (70점) | 시민평가단 10명 (30점) |
| --- | --- | --- |
| 구성 | 장애인 전문가 3 · 기술 전문가 2 | 당사자·가족·복지 종사자·학계·대학생 |
| 보는 것 | 근거·이론 정합성·구현 | **발표만 듣고** 심사표에 적는다. 코드는 못 본다 |
| 먹히는 것 | 출처 있는 숫자, 전문 개념 매핑, 실증 수치 | 당사자의 말, 장면, 쉬운 말 |
| 설계 원칙 | 슬라이드 아래쪽에 **근거를 작게** 깐다 | 슬라이드 위쪽은 **한 문장·한 장면** |

한 장에 두 청중을 모두 담는 방식: **큰 글씨 한 문장(시민) + 하단 작은 근거 줄(심사위원).**

# 2. 10분 배분

| 구간 | 시간 | 슬라이드 | 주로 따는 점수 |
| --- | ---: | --- | --- |
| 여는 말 | 0:30 | S1 표지 · 한 줄 정의 | 전체 첫인상 |
| 문제 | 1:15 | S2 규모 · S3 보호자의 하루 | 필요성 |
| 해결 + 시연 | 2:30 | S4 흐름 · S5 시연 영상 | 완성도 · 참신성 |
| 왜 다른가 | 1:15 | S6 비교 · S7 이론 매핑 | 참신성 |
| 실증 | 2:00 | S8 실증 개요 · S9 결과 | **적용가능성 · 필요성** |
| 피드백 반영 | 0:45 | S10 지적 → 반영 | 완성도 · 적용가능성 |
| 효과·확장 | 1:15 | S11 효과 · S12 상용화·로드맵 | 기대효과 |
| 닫는 말 | 0:30 | S13 한 문장 · QR | 기대효과 |
| **합계** | **10:00** | 13장 + 부록 | |

> ⏱️ 시연 영상은 **2분 이내**로 편집한다. 중간심사 때 시연에 3분을 쓰면 실증이 들어갈 자리가 없다.
> 영상이 실패하면 점수가 날아가므로 **PPT 안에 내장 + 같은 영상을 별도 파일로 대기**한다.

# 3. 장별 설계

각 장은 **한 장 한 메시지**다. `헤드라인`은 청중이 기억할 한 문장이다.

## S1 — 표지 · 한 줄 정의 (0:30)

| | |
| --- | --- |
| 헤드라인 | **"보호자가 하던 말을, 이룸이가 따라 할 수 있는 순서로 바꿔 줍니다"** |
| 화면 | 팀명·앱 이름·로고. 아래에 한 줄 정의 1개 |
| 근거 줄 | 서비스 한 줄 정의(표현 가이드 2장)를 작은 글씨로 |
| 메모 | 기능 나열로 시작하지 않는다. 무엇을 푸는 앱인지 먼저 던진다 |

## S2 — 규모 (0:35) · 필요성

| | |
| --- | --- |
| 헤드라인 | 숫자 **한 개**를 크게. (예: 지적장애인 중위연령 33.8세 → "절반 이상이 성인입니다") |
| 화면 | 연도별 추이 표 1개 **또는** 응답률 표 1개. 뉴스 클리핑 1장 |
| 근거 줄 | **출처와 연도 필수** — 보건복지부 · 한국장애인개발원 등 ([통계자료](../통계자료.md)) |
| 🔴 | 통계 5종의 출처 URL·연도 최종 확인 |

## S3 — 보호자의 하루 (0:40) · 필요성

| | |
| --- | --- |
| 헤드라인 | **"'준비해' 한 마디에는 여덟 단계가 들어 있습니다"** — 예시는 **'출근 준비'와 '등교 준비'를 나란히** |
| 화면 | 한 문장이 8개 카드로 쪼개지는 그림. 성인 일과와 어린이 일과를 **함께** 보인다. 보호자가 매일 아침 이걸 머릿속에서 한다 |
| 주의 | **예시가 하나뿐이면 심사위원이 대상을 그 하나로 읽는다.** 중간심사에서 "비 오는 날 학교 가요" 한 장으로 "어린이 대상이죠?"를 받았다 |
| 당사자 목소리 | 🔴 **보호자 인터뷰 따옴표 1~2개를 그대로.** 요약하지 않는다 |
| 메모 | 시민평가단 중 보호자·가족이 가장 먼저 반응하는 자리 |

## S4 — 흐름 한 장 (0:30) · 완성도

```
보호자가 말로 입력 → AI가 카드 초안 → 보호자가 고치고 승인 → 이룸이가 한 장씩 따라 하고 → 별과 보상
```

| | |
| --- | --- |
| 헤드라인 | **"만드는 건 AI, 정하는 건 보호자"** |
| 근거 줄 | 서비스 원칙 3 — AI 생성 결과는 **보호자 승인 후에만** 이룸이 화면에 나간다 |

## S5 — 시연 영상 (2:00) · 완성도

| | |
| --- | --- |
| 헤드라인 | 없음. **영상이 말한다** |
| 구성 | 입력 → 카드 생성 → 보호자 수정 → 이룸이 수행 → 완료(팡파르·별) → 보상 |
| 규칙 | 실제 앱 화면만. 목업·합성 금지. 마지막은 **완료 순간**으로 끝낸다 |
| 🔴 | **중간심사 이후 추가된 것**(보상 설정·햅틱·다국어·이어서 만들기 등)이 영상에 보이는지 점검 |
| 안전망 | 영상 실패 시 → 스크린샷 4장 슬라이드를 바로 뒤에 숨겨 둔다 |

## S6 — 비교 (0:45) · 참신성

| 대상 | 한계 한 줄 | 이룸 |
| --- | --- | --- |
| 종이 그림카드 | 상황마다 새로 만들어야 한다 | 말로 입력하면 만들어진다 |
| 일정 앱 | 일정만 알려주고 **단계로 쪼개지 않는다** | 행동 단계로 분해 |
| 해외 앱 (Choiceworks 등) | 카드를 **사람이 직접** 만든다 | AI가 초안 |
| 토닥이 (2025 수상작) | 정해진 일정을 보여준다. 만드는 앞단이 없다 | 일정을 **만들어 내는** 앞단 |
| 범용 LLM | 카드·수행 흐름·보호자 승인이 없다 | 승인 구조 + 수행 화면 |

> ⚠️ 경쟁 서비스는 **이름을 대고** 한계를 짚는다. 폄하하지 않고 "어디까지 하고 어디부터 비는가"로 쓴다.
> 토닥이를 직접 언급하는 것은 **심사위원이 이미 아는 수상작**이라 숨기는 쪽이 더 불리하다.

## S7 — 이론 매핑 (0:30) · 참신성 · 전문가 3명 겨냥

```
한 문장을 단계로 분해   → 과제분석(Task Analysis)    ★ 핵심 차별점
카드를 순서대로 수행    → 연쇄(Chaining)
보호자가 정한 보상      → 강화(Reinforcement)
보호자의 카드 수정      → 개별화
```

| | |
| --- | --- |
| 헤드라인 | **"보호자가 매일 머릿속으로 하던 과제분석을 AI로 옮겼습니다"** |
| 금지 | "ABA 기반 **치료** 앱" · "IEP 자동 생성" · "앱을 쓰면 자립한다" ([표현 가이드 1장](../발표_표현가이드.md)) |
| 말하는 방법 | "ABA 및 특수교육에서 활용되는 과제분석·강화·연쇄 원리를 **참고한** 생활 지원 서비스" |

## S8 — 실증 개요 (0:50) · 적용가능성 🔴

| 칸 | 채울 값 |
| --- | --- |
| 누가 | **실사용자 9명** 설문 확보 · 🔴 보호자/이룸이 구분 · 연령대·지원 수준(익명) |
| 어디서 | 🔴 기관명 또는 "가정" · 연결 경로(서울 ABA연구소 등) |
| 언제·몇 번 | 🔴 기간 · 횟수 · **설문 안내 메일을 10/12에 발송**(추가 응답 대기 중) |
| 어떻게 | 🔴 대면/원격 · 사용한 일과 · 측정 방법 |
| 동의 | 🔴 동의 방법 한 줄 (보호자 동의, 사진 비노출) |

> 📌 **실증 참여자 정보 ≠ 앱 수집 정보.** 실증보고서에는 장애유형·정도를 적지만 대회 제출용으로 별도 동의를 받은 것이다.
> 앱은 진단명을 수집하지 않는다(서비스 원칙 1). 이 구분을 **발표 중 한 문장으로** 말한다.

## S9 — 실증 결과 (1:10) · 적용가능성 · 필요성 🔴

| | |
| --- | --- |
| 헤드라인 | **숫자 하나 + 말 하나.** 예: "보호자 도움 없이 끝낸 단계 □ → □ %" + 보호자 한마디 |
| 정량 | 🔴 리커트 5점 평균 3~4개 (이해도 · 따라 하기 · 계속 쓰고 싶은가) |
| 정성 | 🔴 보호자·당사자 발언 **원문 인용** 2개 |
| 지표 주의 | "수행률 100%"를 쓰지 않는다. **"보호자 도움 없이 수행한 단계 비율"**로 쓴다(자문 지적) |
| 한계 | **작은 표본이면 작다고 먼저 말한다.** "N명이라 일반화하지 않는다. 다음 단계는 □" |

> 실증 결과가 좋지 않아도 된다. **지적받은 것을 고친 흔적**(S10)이 점수가 된다.
> 숨긴 한계를 질의응답에서 들키는 것이 가장 크게 깎인다.

## S10 — 지적 → 반영 (0:45) · 완성도 · 적용가능성

중간심사 심사의견 7개를 **전부 다룬다.** 받아들인 것은 화면으로, 받아들이지 않은 것은 **이유와 근거를 붙여** 보인다.
"안 했다"가 아니라 **"검토했고, 이 근거로 이렇게 판단했다"**가 되어야 한다.

| # | 심사위원 지적 (요지) | 판단 | 우리의 답 · 근거 |
| :-: | --- | :-: | --- |
| 1 | 보호자가 찍은 **실제 사진** 옵션. 그림 스타일은 바꾸지 말 것 | ✅ 반영 | 카드마다 **직접 찍은 사진**을 넣을 수 있다(카드 수정 → 사진 올리기). 그림 방식은 기본 그림·만화·실사 중에 고르고 캐릭터는 일관 유지 |
| 4 | AI 단계를 보호자가 **추가·삭제·수정** 유지·강화 | ✅ 반영 | 카드 수정·추가 시트, 순서 바꾸기, 지우기 확인(#444·#471·#497) |
| 6 | **실시간 등록**(평가 피드백용) | ✅ 반영 | 이룸이 수행 → 보호자 화면에 **30초 안에 반영**. 완료 상태를 보호자가 바로 본다 |
| 2 | **사회적·관계적 강화** 설계 | ⛔ 취지상 비수용 | 자문: *즉시 눈앞의 보상*이 효과적이고, 사회적·관계적 강화는 **앱으로 해결하기 어렵다.** 앱은 보호자가 정한 보상을 **상기**하고, 관계적 강화는 보호자가 오프라인에서 한다 |
| 3 | 행동 단계에 **활동의 목적**도 제시 | ⛔ 취지상 비수용 | 좋은 중재의 핵심은 **개별화**이고 그 판단은 보호자의 몫이다. 앱이 "왜 해야 하는지"의 방향을 미리 정하지 않는다. 일과 이름 자체를 보호자가 정한다 |
| 5 | **최종 결과 사진**으로 수행 확인 | ⛔ 취지상 비수용 | 보호자의 일상에 녹아드는 **간편함**이 앱의 취지다. 사진 절차는 부담을 늘린다. 원문 비저장 원칙(서비스 원칙 5)과도 맞지 않는다 |
| 7 | **타겟 구체화** · 중증도별 실증 | 🎯 구체화 | 대상을 □로 한정(아래). 실증 9명 설문으로 **경향**을 확인한다(S8·S9) |

### 🔴 대상 한정 문구 — 정하고 가야 하는 것

초안: **"자폐성장애·지적장애가 있는 어린이"**.

> ⚠️ **이 한정은 팀이 이미 합의한 것과 부딪힌다.** 9/13 자문 이후 팀은 대상을 *"어린이"에서 "발달장애인"으로 넓혔다.*
> - 지적장애인 중위연령 33.8세 — 절반 이상이 성인이다 (S2의 숫자와 충돌)
> - 자문 지적: *"회사 다니는 아들에게 '학교에 가요'가 뜬다"* → 성인 일과를 추가했다
> - 프로젝트 용어 규칙: 연령으로 나누지 않고, 성인 당사자도 쓰는 앱이다
>
> 어린이로 줄이면 위 세 가지를 슬라이드에서 스스로 지워야 한다. 심사위원이 중간심사 PPT와 대조하면 **"오히려 후퇴"**로 읽을 수 있다.
>
> **권장:** 연령이 아니라 **기능 기준**으로 구체화한다. 표현 가이드가 이미 정리해 둔 방식이다.
> **"자폐성·지적 발달장애인 중, 그림 카드와 순서를 이해하고 스마트폰을 조작할 수 있는 사람"**
> 이러면 "구체화하라"에 답하면서 성인 일과 근거도 지킨다. 어린이를 **주 사용 사례**로 두는 건 가능하다.

### 이 장을 말하는 방법

1. **✅ 3개는 전/후 화면 한 쌍.** 먼저 보여 준다.
2. **⛔ 3개는 "그 지적이 틀렸다"가 아니라 "자문과 취지가 달랐다"로.**
   - 말하기 구조: *지적 → 우리가 검토한 근거(자문) → 대신 한 것.*
   - 예(강화): "사회적 강화는 중요합니다. 다만 앱이 아니라 보호자가 오프라인에서 할 일이라는 자문을 받았고, 앱은 **눈앞의 보상을 상기**시키는 데 집중했습니다."
3. **전문가 3명이 있다.** "소장님이 그렇게 말했다"만으로 닫지 않고 **ABA 근거 한 줄**을 붙인다.
   (*일부 발달장애인은 지연된 결과보다 행동과 가까운 시점의 명확한 강화에서 행동-결과 관계를 이해하기 쉬울 수 있다* — 표현 가이드 1장 문장)
4. 근거 출처는 **"행동중재 전문기관 소장 자문(2026-09-13)"**으로 쓴다. 실명을 슬라이드에 넣을지는 소장님 동의를 확인한 뒤 정한다.

### 질의응답에서 나올 것

| 예상 질문 | 답의 뼈대 |
| --- | --- |
| "사회적 강화를 빼면 칭찬은 어떻게 하나요?" | 캐릭터의 칭찬·별·팡파르는 **즉각적인 반응** 연출이다. 관계적 강화는 보호자의 몫으로 남겨 둔다 |
| "결과를 확인하지 않으면 수행했는지 어떻게 아나요?" | 이룸이가 단계마다 직접 체크하고, 보호자는 완료 상태를 30초 안에 본다. **"보호자 도움 없이 한 단계"**를 센다 |
| "그냥 체크만 다 누르면 어떡하나요?" | 체크는 이룸이의 **자기 점검**이고 보상을 주는 사람은 **보호자**다. 보호자가 완료를 30초 안에 보고 곁에서 확인한 뒤 보상한다. 그래서 체크만으로는 보상으로 이어지지 않는다. 지표도 "수행률"이 아니라 **"보호자 도움 없이 수행한 단계 비율"** |
| "실시간 등록이라고 했는데 그건 동기화 아닌가요?" | 지적의 의도(평가 피드백용 즉시 확인)에 **이룸이 수행 → 보호자 반영**으로 답했다. 보호자가 현장 사건을 직접 기록하는 기능은 아니다 — **이 한계를 먼저 말한다** |

> ⚠️ **#6은 해석이 갈린다.** 지적 원문은 "이야기 생성에 **더하여** 실시간 등록 기능"이다.
> 30초 동기화는 *보호자가 이룸이의 수행을 거의 실시간으로 본다*는 점에서 답이 되지만,
> *보호자가 즉석에서 일과를 등록한다*는 뜻이었다면 답이 아니다. 후자라면 "반영"이 아니라 "부분 반영"으로 쓴다.

# 6. 이 설계에서 일부러 하지 않은 것

- **기능 목록 슬라이드를 만들지 않는다.** 중간심사 이후 늘어난 것(다국어·진동·광고 등)을 나열하면 시간만 쓴다. 심사표에 대응 항목이 없다.
- **기술 아키텍처를 본문에 넣지 않는다.** 시민평가단은 못 읽는다. 기술 전문가 질문은 부록 A3으로 받는다.
- **"AI DLP로 가려 준다"를 말하지 않는다.** 서비스 원칙 2: DLP는 POC로 끝냈고 보호자 입력은 가공 없이 AI로 간다.
