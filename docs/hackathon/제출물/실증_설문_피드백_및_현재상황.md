### 1-3. 순환 구조 (보고서·PPT의 뼈대)

```
① 테스터 설문 (원격 1주)        → 고칠 것 확정
② 고쳐서 스토어 배포 (v□, 날짜)
③ 특수학교 실증                  → 고친 버전 확인 + 새 피드백
④ 다시 반영                      → 보고서 5장 · PPT S13
```

2025 토닥이(실증 → 반영 → 재실증 2회 순환, 미반영 3건 사유 공개)와 같은 구조다. 근거로 인정받으려면 아래 세 가지가 필요하다.

1. **회차마다 버전과 날짜를 기록한다.** "설문에서 나온 □ → v□(10/□ 배포)에서 고침 → 학교에서 확인"이 한 줄로 이어져야 완성도 상한(`improvement-is-plan`, 5점)이 풀린다.
2. **학교 실증 전에 스토어 배포를 끝낸다.** 고친 버전을 학교에서 써야 "고쳐서 다시 확인했다"가 성립한다.
3. **같은 척도를 쓴다.** 설문 E(도움 정도)와 학교 관찰지의 선택지를 똑같이 맞춘다.

### 4명 공통 결함

1. **얼마나 썼는지를 묻지 않는다.** 사용량이 적었는데 사용 일수를 묻지 않으면, 하루 써 본 사람의 "매우 도움 됐다"와 매일 쓴 사람의 답을 구분할 수 없다. 학계 심사위원은 이 점 하나로 결과 전체를 믿지 않는다.
2. **처음 쓸 때의 어려움과 안 쓴 이유를 묻지 않는다.** "아리송했다"는 말이 이미 나왔는데 설문에 그 질문이 없다. 이 답이 완성도 점수의 재료(고칠 것)다.

그 밖: 긍정 보기만 있는 체크박스(유도 문항) · "반복 설명하거나 직접 도와주는"(이중질문) · 난이도 문항만 반대인 척도 방향 · 서술형까지 전부 필수.

## 5. 스토리라인과 슬라이드 연결

약점(사용량이 적었음)을 숨기지 않고 이야기의 전환점으로 쓴다.

```
① 원격 1주 (보호자 7명 설문)
   "써 보니 □명이 처음 연결에서 막혔다"              ← A · H · I
② 그래서 직접 찾아갔다 (10/20 가정 대면)
   "아리송했다"는 말을 따라 어디서 막혔는지 봤다      ← 관찰지 (E와 같은 척도)
③ 고쳤다 (v□, 10/□ 스토어 배포)
   전후 화면                                          ← 완성도 상한 해제
④ 학교에서 다시 확인했다 (동천학교 초등부)
   "중증·경증별로 도움 없이 어디까지"                ← 피드백 7
⑤ 숫자로 정리
   "써 본 □명 중 □명이 말로 알려 주는 횟수가 줄었다" ← C · F (분모 + 표본 한계)
```

| PPT 슬라이드 | 설문 문항 |
| --- | --- |
| S2 문제 | C, D (보호자 원문) |
| S11 실증 개요 | 참여자 표 + A, B |
| **S12 실증 결과** | E (보호자 응답 vs 팀 관찰), F, G |
| **S13 실증 → 고친 것** | H, I, 서술형 → 배포 버전 |
| S14 리스크 | K, L ("AI가 틀리면 보호자가 이렇게 고쳤다") |
| S15 기대효과 | F, P, 재사용 (분모 + 한계 한 줄) |

결과를 쓸 때:
- 7명이라 퍼센트·평균만 쓰지 않는다. **"7명 중 □명"**처럼 분모를 붙인다.
- 나이 폭이 넓으니(만 4~15세) 결과를 나이·장애정도별로 나누는 것 자체가 피드백 7의 답이 된다.
- 사용 기간 중 안내 문자를 보낸 것도 실증 방법이니 보고서에 횟수를 적는다.
- F 같은 사용 전 비교 응답은 **보호자 회상**이라는 한계를 한 줄로 적는다.
