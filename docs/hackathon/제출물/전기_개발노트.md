## 1. 주요 개발 내용

제안한 기획 내용을 기준으로 **디자인 · 서버 · 클라이언트**를 함께 개발했다.
핵심은 보호자가 자연어로 입력한 일과를 AI가 행동 카드로 바꾸고,
보호자가 검토·승인한 카드만 사용자 화면에 전달하는 흐름을 완성하는 것이었다.

### 1-1. AI 행동 카드 생성 (서버 · AI)

보호자가 입력한 한 문장을 **수행 가능한 행동 단계로 분해**하는 파이프라인을 구현했다.

- 자연어 입력 → 행동 단계 추출 → 단계별 카드 생성
- 생활 맥락이 부족하면 AI가 보호자에게 **추가 질문**을 먼저 한다
  (예: *"비 오는 날 평소와 다르게 챙겨야 하는 물건이 있나요?"*)
- 단계마다 **사용자가 고른 캐릭터가 동일하게 등장하는 삽화**를 생성
- 생성 실패 시 단계별 대체 경로를 두어 화면이 비지 않도록 처리

카드 생성 규칙은 **관찰 가능한 행동만** 담도록 제한했다.
"마음을 다스려요" 같은 수행 확인이 불가능한 표현은 생성하지 않는다.

### 1-2. 보상(강화) 기능 (서버 · 클라이언트 · 디자인)

전문기관 자문에서 가장 크게 지적받은 부분이다. 일과를 알려주는 것만으로는 행동이
일어나지 않으며, **무엇을 위해 하는지**가 함께 있어야 한다는 지적이었다.

설계는 이렇게 정리했다.

- **보호자**: 일과 생성 중 *"다 하면 무엇을 할 수 있나요?"* 로 보상 설정
  (프리셋 선택 + 직접 입력, 건너뛰기 가능, 이후 수정 가능)
- **사용자**: 시작 화면 배너 → **수행 중 상단 고정 노출** → 완료 화면
- 최근 사용한 보상을 다시 제시해 두 번째 일과부터는 선택 한 번으로 끝나게 했다

**앱이 보상을 결정하지 않는다.** 정하는 것도 실제로 주는 것도 보호자이며,
앱은 약속을 기억하고 적절한 시점에 보여주는 역할만 한다.

**현재 진행 상황** — 자문 이후 착수해 서버와 데이터 처리를 먼저 완성했다.

| 영역 | 상태 |
| --- | --- |
| 서버 — 보상 저장·조회·재사용 API | 완료 |
| 클라이언트 — 데이터 처리 및 보상 미설정 시 노출 차단 | 완료 |
| 화면 디자인 · 화면 구현 | 진행 중 |

보상을 정하지 않은 보호자에게 빈 보상 영역이 보이지 않도록 하는 규칙은
**테스트로 고정**해 두었다. 화면을 붙이는 과정에서 이 원칙이 흐트러지지 않게 하기 위해서다.

### 1-3. 보호자 검토·승인 흐름 (클라이언트 · 서버)

AI가 만든 카드는 **보호자가 승인하기 전까지 사용자 화면에 나타나지 않는다.**

- 카드 검토 화면에서 문구 수정·단계 삭제
- 승인하지 않은 일과는 **임시저장** 상태로 보관하고, 이어서 수정할 수 있다
- 지난 일과를 **다시 하기** 한 번으로 오늘 일과로 재사용 (AI 재호출 없음)
- 승인한 날이 곧 그 일과를 수행하는 날이 되도록 처리

### 1-4. 사용자(아동·성인) 수행 화면 (디자인 · 클라이언트)

- 카드 한 장에 **행동 하나** — 큰 그림 + 짧은 문장 + 음성 안내 + 준비물 체크
- 완료할 때마다 진행률이 차오르고 별 보상으로 이어진다
- 할 일이 없는 날, 모두 마친 날의 화면을 각각 따로 구성했다

### 1-5. 오프라인 동작 보장 (클라이언트 · 서버)

사용자가 쓰는 화면이 통신 상태에 영향을 받지 않도록 **오프라인 우선** 구조로 만들었다.

- 완료 기록을 기기에 먼저 저장하고 서버 전송은 대기열로 분리
- 앱 시작·복귀·온라인 전환 시 자동 재전송
- 네트워크 실패 시 마지막 성공 응답을 사용해 화면을 유지

> 카드를 누르는 순간 화면이 멈추거나 되돌아가면 수행 자체가 중단된다.
> 통신 상태와 무관하게 **사용자 화면은 항상 즉시 반응**해야 한다는 판단이었다.

### 1-6. 추천 일과 (서버)

일과를 처음 만드는 보호자가 무엇을 입력해야 할지 막막하지 않도록
상황별 추천 일과를 제공한다. 항목을 넣을 때 두 가지를 기준으로 삼았다.

1. **눈으로 "했다/안 했다"를 확인할 수 있는 행동만** 넣는다
2. **아동·학교 전제를 두지 않는다** — 출근·주간보호센터 등 성인 일과를 함께 제공

### 1-7. 운영 도구 (서버)

- 관리자 콘솔에서 **AI 프롬프트를 실시간 편집·테스트**할 수 있게 했다
- AI 호출 로그·토큰 사용량 모니터링
- 회원 활동 추적 및 운영 조치

프롬프트를 코드가 아니라 운영에서 고칠 수 있게 한 것이,
자문 내용을 당일에 반영할 수 있었던 이유다.

### 1-8. 전문기관 자문 반영 (전 영역)

**서울 ABA연구소 한상민 소장님**께 서비스 전반에 대한 자문을 받고 설계에 반영했다.
상세 내용은 아래 2장에 정리했다.

## 2. 제안서(중간심사) 대비 변경사항 및 사유

### ① 서비스 대상 재정의

| | 내용 |
| --- | --- |
| **변경 전** | 7~12세 발달장애 아동 |
| **변경 후** | **행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인** |

**사유** — 자문에서 *"생활연령과 발달연령은 다르다"* 는 지적을 받았다.
통계로도 지적장애인의 중위연령은 33.8세로(보건복지부, 2024년 등록장애인 현황)
**절반 이상이 성인**이다. 연령으로 대상을 한정하면 실제 사용자를 배제하게 된다.

판단 기준을 연령에서 **기능 수준**으로 바꿨다 —
스마트폰 사용 가능 여부, 시각정보 이해 여부, 행동 순서 이해 여부.

### ② 강화(보상) 기능 신규 추가

**변경 전** — 계획에 없던 기능. 앱 내 별(⭐) 보상만 존재했다.
**변경 후** — 보호자가 일과별 보상을 설정하고, 아동이 수행하는 내내 화면에 노출한다.

**사유** — 자문의 핵심 지적이었다.
*"버스를 타세요, 내리세요처럼 순서만 알려줘도 그 행동을 하기 싫으면 하지 않는다."*

앱 내 별은 화면 안의 연출이고, 실제로 행동을 유발하는 것은 **보호자가 정한 현실의 보상**이다.
행동 카드만으로는 수행 동기가 생기지 않는다는 지적을 받아들여 기능을 추가했다.

### ③ 행동 카드 단계 수 고정 해제

**변경 전** — 데모 기준 카드 5개 고정
**변경 후** — 사용자별 가변

**사유** — 같은 "학교 가기"라도 사용자마다 어려워하는 지점이 다르다.
버스 타기·내리기 두 단계만 필요한 사용자에게 이미 혼자 하는 단계까지 카드로 보여줄 필요가 없다.
과제분석은 개인별로 구성되어야 한다는 자문 내용을 반영했다.

### ④ 추천 일과 개편

**변경 전** — 추천 50개가 전부 아동·학교 전제. 내면 조절 항목 포함
**변경 후** — 내면 조절 항목 제거, 성인 일과 추가 (총 58개)

**사유** — 위 1-2 참조. 자문 중 실제로 발견된 문제였다.

## 3. 기타 이슈 및 보고 사항

### 3-1. 개발 과정의 이슈

**AI 생성 결과의 신뢰 문제** — 추천 목록만 고쳐서는 부족했다.
보호자가 직접 "속상할 때"라고 입력하면 AI가 다시 내면 조절 카드를 만들기 때문에,
프롬프트 단계에서 **관찰 가능한 행동으로 변환하는 규칙**을 추가했다.

**테스트에 원칙을 심었다** — 추천 일과 검증 테스트를 개수 확인에서
*"내면 조절 표현이 포함되지 않는다"* 는 검증으로 바꿨다.
자문에서 받은 원칙이 사람의 기억이 아니라 **테스트로 지켜지도록** 했다.

### 3-2. 향후 계획

| 단계 | 내용 |
| --- | --- |
| 1 | 보상 기능 사용자 화면 마무리 · 일과 목록 정리 |
| 2 | 보호자 계정과 사용자 프로필 분리, 기기 연결 구조 개편 |
| 3 | **실증 — 서울 ABA연구소 협력 (10월)** |
| 4 | 실증 피드백 반영 및 최종 개발물 제출 |

보호자와 사용자가 **각자의 기기**를 쓰는 형태를 준비하고 있다.
현재는 한 기기에서 모드를 전환하는 구조라, 실증 전까지 계정과 기기 연결 구조를 개편한다.

### 3-3. 실증 계획

서울 ABA연구소와 협력해 실제 발달장애인과 보호자를 대상으로 실증을 진행한다.
보호자용·사용자용 화면을 각자의 기기에 설치해 사용하는 형태를 준비하고 있으며,
이를 위해 계정·기기 연결 구조를 실증 전까지 개편할 예정이다.

정량 지표로는 **일과 수행률**(전체 단계 대비 완료 단계)을 기록하고,
정성 평가로는 보호자·사용자 대상 설문과 인터뷰를 함께 진행한다.
