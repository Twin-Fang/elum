# 1. 메뉴 구조도

이룸은 **하나의 앱 안에 보호자 모드와 아동 모드**가 들어 있습니다.
두 모드는 **PIN으로만** 전환되며, 아동은 보호자 화면으로 넘어갈 수 없습니다.

```mermaid
flowchart TD
    ROOT(["이룸"]) --> ONB["온보딩"]
    ROOT --> GUARD["보호자 모드"]
    ROOT --> CHILD["아동 모드"]
    ROOT --> SWITCH["모드 전환 · PIN"]

    subgraph onb_group ["처음 한 번만"]
        ONB --> O1["이름 입력"]
        O1 --> O2["지원 목표 선택"]
        O2 --> O3["캐릭터 선택"]
        O3 --> O4["보호자 PIN 설정"]
        O4 --> O5["첫 카드 안내"]
    end

    subgraph guard_group ["보호자 모드"]
        GUARD --> G1["홈 · 오늘 일과 · 추천 일과"]
        G1 --> G2["일과 입력 (말 또는 글)"]
        G2 --> G3["준비 중"]
        G3 --> G4["추가 질문 답하기"]
        G4 --> G5["카드 만드는 중"]
        G5 --> G6["카드 확인 · 수정 · 보상 설정"]
        G6 --> G7["아이에게 보내기"]
    end

    subgraph child_group ["아동 모드"]
        CHILD --> C1["홈 · 오늘 할 일"]
        C1 --> C2["카드 한 장씩 수행"]
        C2 --> C3["완료 · 별 받기"]
        C3 --> C4["보상 화면"]
        C1 --> C5["모은 별 보기"]
    end

    SWITCH --> GUARD
    SWITCH --> CHILD
```

## 화면 목록

| 구분 | 화면 | 경로 |
| --- | --- | --- |
| 공통 | 시작 화면 | `/` |
| 온보딩 | 이름 · 목표 · 캐릭터 · PIN · 첫 카드 안내 | `/onboarding/*` |
| 보호자 | 홈 | `/guardian` |
| 보호자 | 일과 입력 | `/guardian/routine/input` |
| 보호자 | 준비 중 (민감정보 처리 · 질문 준비) | `/guardian/routine/masking` |
| 보호자 | 추가 질문 | `/guardian/routine/question` |
| 보호자 | 카드 만드는 중 | `/guardian/routine/generating` |
| 보호자 | 카드 확인 · 수정 | `/guardian/routine/review` |
| 아동 | 홈 | `/child` |
| 아동 | 일과 수행 (카드 넘기기) | `/child/routine` |
| 아동 | 모은 별 | `/child/stars` |
| 아동 | 보상 | `/child/reward` |
| 공통 | 모드 전환 (PIN) | `/mode-switch` |

> **아동 모드에는 나가는 문이 없습니다.** 보호자 모드로 돌아가려면 PIN이 필요합니다.
> 아이가 실수로 설정을 바꾸거나 카드를 지우는 일을 구조로 막았습니다.

# 2. 전체 흐름 — 한 장으로

```mermaid
flowchart TD
    A(["앱 실행"]) --> B{"온보딩 했나?"}
    B -->|아니오| C["이름·목표·캐릭터·PIN 설정"]
    C --> D["보호자 홈"]
    B -->|예| E{"저장된 로그인 정보 있나?"}
    E -->|없음| C
    E -->|있음| D

    D --> F["일과 입력"]
    F --> G["AI가 행동 단계로 나눔"]
    G --> H["보호자가 확인·수정"]
    H --> I{"보낼까?"}
    I -->|수정 요청| G
    I -->|보내기| J["아이 화면에 표시"]

    J --> K["아이가 카드를 하나씩 수행"]
    K --> L["단계마다 별"]
    L --> M{"다 했나?"}
    M -->|아니오| K
    M -->|예| N["보상 화면 · 보호자에게 기록 전달"]
    N --> O(["끝"])
```

> **AI가 만든 카드는 보호자 승인 전에는 아이에게 보이지 않습니다.**
> 위 그림의 `H → I` 가 그 관문입니다.

# 3. 일과 만들기 — 보호자

```mermaid
flowchart TD
    A(["일과 입력 화면"]) --> B["평소 말하듯 입력<br/>예: 내일 비 온대. 학교 갈 준비해야 해"]
    B --> C["민감정보를 유형 태그로 치환"]
    C --> D["AI가 되물을 것이 있는지 판단"]
    D --> E{"물어볼 게 있나?"}
    E -->|있음| F["선택지로 질문<br/>예: 우산·우비·여벌 양말"]
    F --> G["AI가 행동 단계로 분해"]
    E -->|없음| G
    G --> H["단계마다 그림 생성<br/>고른 캐릭터가 모든 그림에 등장"]
    H --> I["카드 확인 화면"]
    I --> J{"보호자 판단"}
    J -->|문장 고치기| K["단계 직접 수정"]
    K --> I
    J -->|단계 지우기| L["단계 삭제"]
    L --> I
    J -->|보상 정하기| M["간식·영상·놀이·산책 중 선택<br/>또는 직접 입력"]
    M --> I
    J -->|나중에| N["임시저장"]
    J -->|보내기| O["아이 화면에 표시"]
    O --> P(["완료"])
```

**실패해도 화면은 멈추지 않습니다.**

| 어디서 실패 | 어떻게 되나 |
| --- | --- |
| AI 응답 없음·지연 | 미리 준비한 기본 카드로 대체하고 안내 문구를 띄웁니다 |
| 그림 생성 실패 | 기본 삽화로 대체합니다. 카드는 그대로 씁니다 |
| 네트워크 끊김 | 입력한 내용을 지우지 않고 재시도 버튼을 보여줍니다 |

# 4. 일과 수행 — 아동

```mermaid
flowchart TD
    A(["아이 홈"]) --> B["오늘 할 일 목록"]
    B --> C["일과 선택"]
    C --> D{"보상이 정해져 있나?"}
    D -->|있음| E["다 하면 무엇을 할 수 있는지 먼저 보여줌"]
    D -->|없음| F["첫 카드"]
    E --> F
    F --> G["그림 한 장 · 짧은 문장 · 읽어주는 음성"]
    G --> H{"다 했어요?"}
    H -->|아직| I["다시 듣기 · 그대로 머무름"]
    I --> G
    H -->|했어요| J["별 하나"]
    J --> K{"남은 카드 있나?"}
    K -->|있음| L["다음 카드"]
    L --> G
    K -->|없음| M["다 했어요 화면"]
    M --> N["보상 화면"]
    N --> O(["보호자 기록에 반영"])
```

> **보상을 일과 시작 전에 먼저 보여줍니다.** 다 끝난 뒤에만 알려주면
> 수행하는 동안 무엇을 위해 하는지 알 수 없기 때문입니다.

# 5. 오프라인에서도 끊기지 않습니다

아이가 쓰는 순간에 인터넷이 끊길 수 있습니다. 그때도 일과는 진행돼야 합니다.

```mermaid
flowchart TD
    A(["카드 완료 탭"]) --> B["기기에 먼저 기록"]
    B --> C["화면에 즉시 별 표시"]
    C --> D{"서버에 보낼 수 있나?"}
    D -->|가능| E["서버에 전송"]
    D -->|불가| F["대기열에 저장"]
    F --> G["연결되면 다시 전송"]
    G --> E
    E --> H{"기기와 서버가 다르면?"}
    H -->|다름| I["기기 기록을 정답으로 삼음"]
    H -->|같음| J["그대로 유지"]
    I --> K(["보호자 화면에 반영"])
    J --> K
```

**기기가 진실입니다.** 아이가 눈앞에서 한 행동이 서버 기록보다 우선합니다.
네트워크 때문에 "했는데 안 한 것으로 표시되는" 일은 없어야 하기 때문입니다.

# 6. 일과의 상태

```mermaid
flowchart TD
    A(["보호자가 입력"]) --> B["검토 대기<br/>PENDING_REVIEW"]
    B --> C{"보호자 판단"}
    C -->|수정 요청| B
    C -->|삭제| D(["삭제"])
    C -->|보내기| E["진행 중<br/>CONFIRMED"]
    E --> F["아이가 단계를 하나씩 완료"]
    F --> G{"전부 완료?"}
    G -->|아니오| F
    G -->|예| H["완료<br/>COMPLETED"]
    H --> I["지난 일과에 보관"]
    I --> J{"다시 쓸까?"}
    J -->|복제| B
    J -->|그대로 둠| K(["기록으로 남음"])
```

> **지난 일과를 지우지 않고 접어둡니다.** 수행률 추이를 보려면 원본이 필요하고,
> 매일 같은 준비는 복제 한 번으로 끝나기 때문입니다.

# 7. 시스템 구성

```mermaid
flowchart TD
    subgraph app_group ["앱 (Flutter · Android/iOS)"]
        A1["보호자 모드"]
        A2["아동 모드"]
        A3["기기 저장소<br/>오프라인 기록·대기열"]
    end

    subgraph server_group ["서버 (Spring Boot)"]
        B1["인증"]
        B2["일과 · 카드"]
        B3["민감정보 처리"]
        B4["관리자 페이지"]
    end

    subgraph ai_group ["외부 AI"]
        C1["문장 → 행동 단계"]
        C2["단계 → 그림"]
        C3["문장 → 음성"]
    end

    A1 --> B2
    A2 --> B2
    A2 --> A3
    A3 --> B2
    B2 --> B3
    B3 --> C1
    B3 --> C2
    A2 --> C3
    B1 --> B2
    B4 --> B2
```

**보호자가 쓴 문장은 그대로 AI에 가지 않습니다.** `B3`에서 이름·장소 같은 정보를
유형 태그로 바꾼 뒤 최소한만 보냅니다. 원문은 로그에도 남기지 않습니다.

# 8. 서버가 제공하는 기능

| 묶음 | 하는 일 |
| --- | --- |
| 인증 | 가입 · 로그인 |
| 일과 만들기 | 자연어 입력 받기 · 되물을 질문 만들기 · 행동 단계로 분해 |

| 일과 관리 | 아이에게 보내기 · 복제 · 삭제 |
