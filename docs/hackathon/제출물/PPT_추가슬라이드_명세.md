## 각 칸에 들어갈 문구

### ① 👥 인구는 늘고 있다

```
전체 장애인 중 발달장애 비율

    7.0%  →  9.4%
    2010     2020

전체 등록장애인은 263만 명에서 정체 상태입니다.
발달장애만 계속 늘고 있습니다.
```

### ② 💰 지원은 커지고 있다

```
발달장애인 관련 정부 예산

    2조 8천억 원  (＋15.9%)
    2027년 정부안

· 복지부 발달장애인 지원   4,880억 → 5,721억
· 성인 주간활동서비스      1.5만 명 → 2만 명
                          → 2030년 3만 명
```

### ③ 🏠 그런데 집은 남는다

```
발달장애인              약 25만 명
주간활동서비스 대상        2만 명   (8%)
최중증 통합돌봄 대상       2,760명  (1.1%)

그리고 주간활동서비스는 낮 시간, 기관에서의 활동입니다.
```

### 맨 아래 한 줄 (가장 크게 강조)

```
아침에 옷을 입고 가방을 챙기는 일은 어떤 제도도 대신해 주지 않습니다.
```

> "발달장애인은 계속 늘고 있습니다. 전체 장애인 수는 263만 명에서 거의 멈춰 있는데,

> 그런데 그건 **낮 시간에, 기관에서** 일어나는 일입니다.
> 25만 명 중 2만 명이 대상이고, 최중증 통합돌봄은 2,760명입니다.
>
> 아침에 옷을 입고 가방을 챙기는 일은 여전히 보호자가 매일 반복합니다."

# 슬라이드 B — 국내·외 유사 사례 비교

**들어갈 위치: 슬라이드 A 바로 뒤 (기존 4장 「ABA 설계」 앞)**

> ⚠️ **이 장이 참신성 20점을 가릅니다.**
> AI로 일정을 만들어주는 앱은 해외에 이미 있습니다. *"세계 최초"* 는 쓰지 않습니다.
>
> 다만 **싸움터를 "한국어"가 아니라 "무엇이 자동인가"로 옮깁니다.**
> "한국어라서 다르다"고 하면 *"번역하면 되지 않나요?"* 한 마디에 무너집니다.
>
> **두 앱이 정확히 양 끝입니다.**
> Tiimo는 **자동으로 만들어주지만 발달장애를 보지 않고**,
> Choiceworks는 **발달장애를 보지만 보호자가 전부 만들어야** 합니다.
> 이룸은 그 사이에 있습니다.

## 제목

```
개발물 / 차별점                                       ← 작게, 회색

자동으로 만들거나, 발달장애를 고려하거나 — 둘 다는 없었습니다   ← 크게, 검정 볼드
```

> 제목이 길면 **"둘 다는 없었습니다"** 만 남기고 앞부분을 작게 처리해도 됩니다.

## 발표자가 할 말 (참고용, 화면에는 안 들어감)

> "먼저 솔직하게 말씀드리면, **비슷한 앱은 이미 있습니다.**
> 저희도 **두 개를 직접 설치해서 써봤습니다.**
>
> 하나는 **Tiimo**입니다. 올해 App Store 올해의 앱입니다.
> AI가 일정을 만들어줍니다. 그런데 써보니 **일정과 할 일 목록**이었습니다.
> 단계마다의 그림이 없고, 읽어주는 음성이 없고, 보상도 없습니다.
> 스토어 소개에도 **ADHD**를 대상으로 적고 있습니다.
>
> 다른 하나는 **Choiceworks**입니다. 이건 발달장애를 위한 앱이 맞습니다.
> 그림 순서표도 있고 음성도 넣을 수 있습니다.
> 그런데 **그 사진과 음성을 보호자가 하나씩 전부 넣어야 합니다.**

>
> 정리하면 이렇습니다.
> **자동으로 만들어주는 쪽은 발달장애를 보지 않고,
> 발달장애를 보는 쪽은 보호자가 전부 만들어야 합니다.**

## 들어갈 문구

| | 무엇이 달라지나 |
| --- | --- |
| **보호자** | 매일 아침 반복하던 설명을 앱이 대신합니다. 카드를 손으로 만들지 않아도 됩니다 |
| **당사자** | 다음에 무엇을 하는지, 다 하면 무엇이 있는지 스스로 확인하며 일과를 이어갑니다 |
| **기관·지도자** | 이용자별 과제분석을 매번 새로 만들지 않고, 수행률을 기록으로 남깁니다 |

### 정량 목표 (이 장에서 가장 크게)

```
10단계짜리 일과를, 보호자 도움 없이 10단계까지.
```

> 📌 **이것이 기대효과이자 측정 지표입니다.**
> 자문에서 받은 정의 그대로입니다 —
> *"전체가 10단계가 있는데 10단계 중에 **얘가 오늘 자기의 힘으로 몇 단계까지 하는가.**"*
> *"각 단계별로 **독립적으로 수행할 수 있으면 그게 퍼센트에 포함되는 거예요.**"*
>
> 상담·치료 현장에서 실제로 쓰는 방식이라, 심사위원이 **바로 알아듣는 지표**입니다.
> "편리해집니다" 같은 말보다 훨씬 강합니다.

### 실증 (한 줄만)

```
10월, 서울 ABA연구소와 함께 실제 사용자에게 확인합니다.
```

### 확장 (아주 작게)

```
순서를 유지하기 어려운 다른 이용자에게도 같은 구조가 쓰일 수 있습니다.
```

## 디자인 요청

| | |
| --- | --- |
| **구조** | 3열 균등. 기존 3장(보호자/아동 2칸)과 같은 카드 톤 |
| **정량 목표** | `10단계 → 보호자 도움 없이 10단계` 가 **이 장에서 가장 큽니다.** 숫자 두 개가 눈에 박히게 |
| **실증 줄** | 민트, 한 줄. **여기까지만 씁니다** — 인원·기간·측정 방법을 화면에 적지 마세요 |
| **확장 줄** | **작게.** 크게 쓰면 "대상이 흐릿한 팀"이 됩니다 |
| **주의** | ⚠️ **"ADHD·학습장애로 확장"이라고 쓰지 마세요.** 국내 법률상 발달장애인은 지적·자폐성뿐입니다. 위 문장 그대로 씁니다 |

> ⚠️ **실증 계획을 화면에 자세히 적지 않습니다.**
> 중간심사 시점에 아직 하지 않은 일입니다. 인원·기간·측정 방법을 적으면
> *"몇 명입니까"* · *"대조군은요"* 가 바로 나오는데 답할 수 없습니다.
> **한 줄로 두고, 물어보실 때만 답합니다.**

## 발표자가 할 말 (화면에는 안 들어감)

> "보호자는 매일 아침 반복하던 설명을 덜어냅니다.
> 당사자는 다음에 무엇을 하는지, 다 하면 무엇이 있는지 스스로 확인합니다.
> 기관은 이용자별 과제분석을 매번 새로 만들지 않아도 됩니다.
>
> 저희가 보는 숫자는 하나입니다.
> **10단계짜리 일과를, 보호자 도움 없이 10단계까지 해내는 것.**
> 상담 현장에서 실제로 쓰는 방식입니다. 완료 여부가 아니라
> **자기 힘으로 몇 단계까지 갔는지**를 셉니다.
>
> **10월에 서울 ABA연구소와 함께 실제 사용자에게 확인합니다.**"

### 📌 물어보실 때만 답하는 것

심사위원이 *"효과를 어떻게 확인하실 건가요?"* 라고 물으면:

> "**혼자 해낸 단계의 비율**을 봅니다.
> 완료율만 보면 보호자가 옆에서 다 시켜도 100%가 나옵니다.
> 보호자 도움 없이 해낸 단계를 따로 세야 의미가 있다고 보고 있습니다.
>
> 여기에 보호자·지도자 인터뷰를 함께 봅니다.
> 숫자로는 **어떤 일과에서 되고 어떤 일과에서 안 되는지**를 알 수 없어서입니다."

*"인원은 몇 명입니까?"* 라고 물으면:

> "**연구소에서 대상자 모집을 맡아주시기로 했습니다.**
> 연령과 장애 유형·정도를 다양하게 구성한 예비조사를 제안받았고, 규모와 일정은 협의 중입니다.
> 통계를 낼 규모라기보다 **실제로 쓸 만한지 확인하는 조사**로 보고 있습니다."

> 💡 **이 답이 이 장에서 가장 강한 카드입니다.** "실증 계획이 있습니다"와
> **"전문기관이 대상자를 모아주기로 했습니다"** 는 무게가 다릅니다.
> 다만 구두 약속이므로 화면에는 쓰지 않고, 물어보실 때만 답합니다.

> 💡 **과장하지 않습니다.** 자문에서 *"앱만으로 자립이 만들어지지 않는다.
> 오프라인에서 보호자·지도자가 구조를 먼저 만들고, 앱은 보호자가 없을 때 상기시키는 역할"* 이라는
> 말씀을 들었습니다. **"앱이 자립을 만들었다"고 말하면 그 자리에서 무너집니다.**
