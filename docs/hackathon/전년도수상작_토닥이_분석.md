# 전년도 수상작 '토닥이' 분석과 ELUM 차별화 전략

> **왜 이 문서가 필요한가** — 2025년 **보건복지부장관상** 수상작 `토닥이`(팀 따숨)는
> **발달장애인의 일상 안정과 예측 가능성**을 다룬 앱이다. ELUM과 대상·문제의식이 상당 부분 겹친다.
> 이 팀이 올해 OT에서 특강까지 했으므로 **심사위원과 참가팀 모두가 토닥이를 알고 있다.**
>
> 심사 항목 **참신성(20점)의 기준이 "기존 개발된 APP과 비교 시 차별성을 갖고 있는가"** 이고,
> 발표자료 필수 항목에 **"국내·외 유사 사례 비교 및 차이점"** 이 있다.
> 즉 **토닥이를 언급하지 않는 것은 선택지가 아니다.** 먼저 꺼내서 차이를 정리해 보여줘야 한다.

## 1. 토닥이 요약

| 항목 | 내용 |
| --- | --- |
| 팀 / 앱 | 따숨 / **토닥이(todak)** |
| 수상 | 2025년 보건복지부장관상 (자립생활 지원 분야) |
| 한 줄 | 발달장애인의 **일상 안정과 예측 가능성**을 높이는 서비스 |
| 사용자 | **발달장애인 근로자** + **고용기업 관리자** (2인 구조) |
| 근거 데이터 | 국내 발달장애인 약 25만명(보건복지부, 2023) · 보호자 73% 돌봄피로·정보부족(한국장애인개발원, 2022) |
| 실증 | 한국자폐인사랑협회 부산지부 · 발달장애인 고용기업 **브라보비버** 부산지부 |
| 핵심 문장 | *"예측 가능한 하루가 발달장애인의 안정이 된다"* |

### 기능 구성

| 기능 | 내용 |
| --- | --- |
| 1. 사용자 일정 관리 | 주간 시간표 · 월간 캘린더 · 일정 추가/수정/삭제 · 알림(소리·진동 개별 설정) · TTS 전체 읽기 |
| 2. 상황 기반 안정 행동 추천 | 감정 선택 → 상황 선택 → **RAG + Gemini로 안정 행동 3가지 추천** → 단계별 설명 → 행동 후 감정 재확인 → **칭찬 스티커** |
| 3. 관리자 모드 | 직원 일정·주의사항·감정 상태 통합 관리 · 안전수칙 **열람 여부 확인** · 감정 변화 그래프 · 푸시 알림 |

**위험·금지 행동 필터링**을 별도로 두고(주머니에 손, 뛰기, 칼, 지게차 등 금지 행동 목록),
기업 관리자·대표의 검증을 거친 대체 행동을 제시한다.

## 2. 겹치는 부분 (정면으로 인정하고 시작해야 하는 지점)

| 겹침 | 토닥이 | ELUM |
| --- | --- | --- |
| 대상 | 발달장애인 | 발달장애인 |
| 문제의식 | 일과의 예측 가능성 | 일과의 순서 이해·수행 |
| 형태 | 일과를 화면으로 보여주고 상기 | 행동 카드로 보여주고 상기 |
| 표현 | 그림 + 음성(TTS) | 이미지 + 음성(TTS) |
| 보상 | 칭찬 스티커 | 별 ⭐ |
| AI | RAG + Gemini 행동 추천 | LLM 행동 카드 생성 |
| 2인 구조 | 근로자 ↔ 관리자 | 아동 ↔ 보호자 |

> 이 표를 그대로 발표에 쓰는 것이 오히려 안전하다. **"비슷한데요?"를 심사위원이 먼저 말하게 두면 안 된다.**

## 3. 결정적 차이 — 이 4개가 ELUM의 참신성이다

### ① 일과를 사람이 입력하느냐, AI가 분해하느냐 ★ 가장 큰 차이

```text
토닥이 : 관리자/사용자가 "회사 근무 09:00~18:00" 을 직접 등록  → 일정 관리
ELUM  : 보호자가 "내일 비가 온대. 학교 갈 준비를 해야 해" 라고 말하면
        AI가 옷 입기 → 가방 챙기기 → 우비 입기 → … 로 자동 분해  → 과제분석 자동화
```

토닥이의 일정은 **이미 정해진 일정을 보여주는 캘린더**다.
ELUM은 **"학교 갈 준비"라는 한 덩어리를 수행 가능한 단위로 쪼개는 일**을 AI가 대신한다.
ABA의 **과제분석(Task Analysis)** 을 자동화한 것이고, 이건 토닥이에 없다.

> 서울 ABA연구소 자문에서 확인된 개념이다 — [1차 자문 회의록 4-7](../meetings/20260913_서울ABA연구소_1차자문/#4-7-이론적-근거--과제분석과-연쇄)

### ② 캐릭터 일관성 있는 AI 삽화 생성 ★ 시각적으로 가장 강한 차이

토닥이는 **이모지·픽토그램·사용자 얼굴 사진**을 쓴다. 이룸은 카드마다
**아이가 고른 캐릭터가 동일하게 등장하는 삽화를 실시간 생성**한다.

종이 그림카드·픽토그램과 가장 뚜렷하게 갈리는 지점이고, 발표 화면에서 바로 전달된다 —
**시민평가단 30점**에 작용하는 차별점이다.

> 🔕 **AI DLP는 이번 대회 발표에서 다루지 않는다** (2026-09-13 내부 회의 결정 10).
> 기능은 구현되어 있으나 이 대회는 보안 분야가 아니며, 앞세우면 "장애 서비스"가 아니라
> "보안 서비스"로 들린다. 개인정보 처리는 **리스크 해결방안 슬라이드에서 한 줄로만** 언급한다.

### ③ 진단명 없는 개인화

토닥이는 페르소나에 **"장애 유형: 경도 발달장애"** 를 명시하고 사용자 특성을 상세히 입력받는다.
ELUM은 **진단명·장애유형을 묻지 않고**, 보호자가 고른 `supportGoals`(도움 목표)만으로 개인화한다.

> 최소 수집으로 개인화한다는 설계는 그 자체로 장애 서비스에 대한 태도 차이다.

### ④ AI 생성 결과의 보호자 승인 게이트

AI가 만든 카드는 **보호자가 검토·수정·승인하기 전에는 아동 화면에 뜨지 않는다.**
입력 보호(DLP) + 출력 승인의 **이중 안전 구조**는 LLM 기반 장애 서비스에서 드문 설계다.

## 4. 배울 점 — 그대로 따라 해야 하는 것

수상팀의 자료는 **"어떻게 하면 이 대회에서 점수를 받는가"의 모범답안**이다. 아래 5가지는 그대로 가져온다.

| # | 토닥이가 한 것 | ELUM이 할 것 |
| --- | --- | --- |
| 1 | **실증 협력기관 확보** (자폐인사랑협회·브라보비버) 후 "기관 검증을 거쳤다"고 명시 | **서울 ABA연구소** 자문·실증으로 동일 구조 확보 |
| 2 | **중간심사 지적 → 반영 결과**를 슬라이드에서 1:1로 보여줌 | 중간심사 피드백을 그대로 받아적고 최종 발표를 같은 형식으로 구성 |
| 3 | 관리자용·사용자용 **설문지 2종** 제작 (리커트 5점 + 자유서술 4문항) | 보호자용·아동용 설문 2종 제작 — 실증보고서의 정량 데이터가 여기서 나온다 |
| 4 | **효과 측정 구조를 앱에 내장** (행동 전 감정 → 행동 → 행동 후 감정) | **수행률**이 그 역할 — 자문 P1 "행동 수행률 리포트"와 정확히 일치 |
| 5 | 금지·위험 행동 목록을 **현장 전문가에게 검증**받음 | AI 카드 출력 검수 기준(위험 문장·의료적 판단 금지)을 ABA연구소에 검증 요청 |

> 특히 **2번**이 중요하다. 토닥이는 중간심사에서 *"구체적인 타겟 명확화가 필요하다"* 는 지적을 받고
> 타겟을 '발달장애인 근로자'로 확정한 뒤 **관리자 모드를 새로 추가**했다.
> 지적을 받아들여 구조를 바꾼 것이 최종 수상으로 이어졌다.

### 토닥이가 받은 지적 3가지 (우리도 받을 가능성이 높다)

| 중간심사 지적 | 토닥이의 반영 | ELUM에 대입하면 |
| --- | --- | --- |
| "구체적인 **타겟 명확화**가 필요하다" | 발달장애인 **근로자**로 확정 | ⚠️ ELUM도 동일 지적 예상 — 자문에서 이미 "연령이 아니라 기능 수준"으로 재정의했다 |
| "일정표에 **그림·픽토그램·사진**, 장소와 사람(지원인) 정보를 추가하라" | 본인 얼굴 사진 입력 | ELUM은 이미 이미지 기반 · **셀프 모델링**(자문 4-9)이 같은 방향 |
| "**효과 측정**(우울·고립지표 등) 기능이 필요하다" | 행동 전/후 감정 비교 구조 | ELUM은 **수행률 추이**로 대응 (자문 4-11) |

### 실증에서 나온 피드백 (사용자 입력 부담 문제)

- *"보호자가 서술형으로 길게 작성해야 하므로 부담이 크다"* → 카테고리 선택 + 간단 자유서술로 완화
- *"'불안한가요?'는 감정 범위를 좁게 해석한다"* → **"지금 마음이 어때요?"** 로 문구 변경
- *"행동 단계 설명을 음성으로 들으면 텍스트보다 이해가 쉽고 에너지가 덜 든다"* → TTS 버튼 추가

> 첫 번째는 ELUM에도 그대로 적용된다. 자문의 **"개별화는 하되 온보딩은 최대한 가볍게"** 와 같은 지적이다.
> 보호자 입력 부담은 이 분야에서 **반복적으로 나오는 실패 지점**이다.

## 5. 발표에서 쓸 문장 (초안)

> "지난해 수상작 토닥이는 **정해진 일정을 예측 가능하게** 보여줘 발달장애인 근로자의 불안을 낮췄습니다.
> 이룸은 그 앞단을 다룹니다 — **'학교 갈 준비를 해야 해'라는 한 문장을 수행 가능한 행동 단계로 쪼개는 일**,
> 지금까지 보호자가 매일 머릿속으로 해오던 그 과제분석을 AI가 대신합니다.
> 그리고 그 단계마다 아이가 고른 캐릭터가 등장하는 그림이 함께 만들어집니다."

## 6. 남은 확인 사항 ⚠️

| # | 확인할 것 | 왜 |
| --- | --- | --- |
| 1 | **ELUM의 개발 이력이 규정 ②③에 걸리지 않는지** | 규정상 *"이전에 타 대회·공모전에 참가하여 이미 개발이 진행된 아이디어"* 는 심사 제외·상금 환수 대상이다. 레포 문서에 다른 대회명이 기재되어 있었으므로, 출품·입상 이력이 실제로 있었는지 팀 내부에서 명확히 하고 필요하면 **사무국에 먼저 문의**하는 편이 안전하다. 문서에서 표기를 지우는 것과 규정 해당 여부는 별개다 |
| 2 | 토닥이의 현재 상태 (출시 여부·서비스명 중복) | 유사 서비스 비교 슬라이드의 정확도 |
| 3 | 올해 심사위원 구성 | 작년과 겹치면 토닥이 대비 설명의 비중을 더 키운다 |
