# 다국어 지원 마스터 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 이 문서는 **순서·의존·공통 계약**만 정한다. 구현 단계(코드, 테스트, 명령)는 하위 계획 1~7에 있다. 하위 계획은 이 문서의 "공통 계약"을 그대로 쓴다. 이름을 바꾸려면 이 문서를 먼저 고친다.

**Goal:** 한국어 전용 앱을 5개 언어(ko, en, ja, zh, es)를 받을 수 있는 구조로 바꾸고, 언어를 데이터로 추가해 단계적으로 연다.

**Architecture:** 화면 언어는 OS 언어를 따르고(앱 안 선택 없음), 콘텐츠 언어는 일과가 가진다. 클라이언트는 ARB가 화면 문구의 원본이고, 서버가 내려보내는 문장(에러, 폴백 질문, 추천, 공지, 약관)은 서버가 `Accept-Language`로 골라 준다. 대체 순서는 요청 언어 → `en` → `ko`.

**Tech Stack:** Flutter(`flutter_localizations`, `intl`, `flutter gen-l10n`), Riverpod, Dio / Spring Boot(`MessageSource`, Flyway), PostgreSQL.

**Spec:** `docs/superpowers/specs/2026-10-02-multi-language-design.md`

## Global Constraints

- 지원 언어는 `ko` `en` `ja` `zh`(간체) `es` 다섯이다. RTL과 번체 중국어는 범위 밖이다.
- **앱 안에는 언어 선택 화면을 만들지 않는다.** 언어 강제 스위치는 개발자 도구(`core/dev`)에만 둔다.
- 대체 순서는 어디서든 **요청 언어 → `en` → `ko`** 이다. 단 요청 언어가 `ko` 이면 `ko` 만 본다(한국어 사용자에게 영어를 보이지 않는다).
- `Accept-Language` 헤더가 **없으면 `ko`**, 5개 밖이거나 깨진 값이면 `en` 이다. 이미 배포된 앱의 응답은 바뀌지 않는다.
- 에러 문구는 서버가 번역해 내려보내고 클라이언트는 서버 문구를 그대로 보여준다(#347). 클라이언트가 에러 코드를 번역하지 않는다.
- `ko` 화면은 **1단계 이후에도 지금과 픽셀 단위로 같다.** 기존 앱 테스트와 골든이 그대로 통과해야 한다.
- 일과의 콘텐츠 언어는 일과를 만든 요청의 화면 언어이고, 보호자가 고르지 않는다.
- 약관과 개인정보방침은 한국 기준 한 벌이고 언어별 번역본만 둔다. 국가별 법 본문은 만들지 않는다. 공지만 대상 국가를 지정할 수 있다(비우면 전체).
- 약관은 그 언어의 게시본이 있어야 그 언어를 연다. 없는 언어에서 `en` 약관으로 대체하지 않는다.
- 서비스 원칙 유지: 진단명 미수집, 보호자 승인 후 노출, 원문 로그 미저장, AI 실패 시 fallback 필수.
- 용어: `이룸이`(아이·아동 금지), 해요체·능동형·긍정형(한국어 기준). 번역 용어는 용어집(`docs/i18n/glossary.md`)을 따른다.
- 코드 주석은 간결한 한국어(WHY 중심). 커밋은 `/pro-commit`으로, 이슈 번호 연결, `Co-Authored-By` 금지, 푸시는 사용자 요청 시에만.
- AI 호출은 비용이다. 검증용으로 생성 API를 반복 호출하지 않고 언어당 가장 싼 모델로 최소 횟수만 쓴다.
- Flyway 번호는 아래 표가 임시 배정이다. 구현 시점에 `origin/develop`의 다음 빈 번호를 쓴다(번호가 겹치면 먼저 머지된 쪽이 이긴다).

### C1-2. 국가(지역) 판정

| 항목 | 값 |
| --- | --- |
| 전송 | 클라이언트가 OS 지역 코드를 요청 헤더 `X-Elum-Region` 으로 보낸다. ISO 3166-1 alpha-2 대문자(`KR`, `US`, `JP`, `ES`, `MX` 등) |

| 서버 접근자 | `com.chuseok22.elumserver.common.locale.CurrentRegion.get()` → `String`(대문자 코드) 또는 `null`(국가 미상). 요청 밖 호출은 `KR` |
| 클라이언트 전송 | `AcceptLanguageInterceptor` 가 `Accept-Language` 와 함께 `X-Elum-Region` 도 붙인다(OS 지역 코드가 없으면 헤더를 생략한다) |

### C2. 서버 언어 타입

패키지 `com.chuseok22.elumserver.common.locale`

```java
public enum AppLocale {
  KO("ko"), EN("en"), JA("ja"), ZH("zh"), ES("es");

  public String code();                         // "ko" ...
  public List<AppLocale> fallbackChain();       // KO → [KO] (한국어 요청이 영어로 새지 않는다), 그 외 → [this, EN, KO]. 중복 제거, 순서 유지
  public static AppLocale fromCode(String code);          // 정확히 일치, 없으면 Optional.empty 대신 IllegalArgumentException
  public static AppLocale fromAcceptLanguage(String header); // null/빈 값 → KO, 미지원·깨진 값 → EN
}
```

- 요청 범위 접근자: `CurrentLocale.get()` → `AppLocale` (요청마다 `Accept-Language`로 정해진다. 요청 밖 호출은 `KO`).
- 일과 생성 가능 언어: 시스템 설정 `ConfigKey.ENABLED_CONTENT_LOCALES`(CSV 문자열, 기본 `ko`). 접근자 `EnabledLocales.contains(AppLocale)`, `EnabledLocales.resolveContentLocale(AppLocale requested)` → 요청 언어가 켜져 있으면 그것, 아니면 `EN`이 켜져 있으면 `EN`, 아니면 `KO`.

| 받는 계획 | 넘기는 것 |

### C5. 일과 언어의 전달

- 서버 `Routine.language` (`AppLocale`), 응답 필드 `RoutineResponse.language` 는 `"ko"` 같은 코드 문자열이다.
- 클라이언트는 이룸이 화면에서 카드 글과 음성에 일과의 `language` 를 쓴다. 클라이언트 모델 필드 이름은 `language`(문자열 코드), 없으면 `ko`.
- 일과 생성 요청에는 언어 필드를 **추가하지 않는다.** 서버가 `Accept-Language`로 정한다.

## Review Focus

스펙이 암시하지만 개별 작업의 테스트가 놓치기 쉬운 것. 각 줄은 소유한 하위 계획의 작업에서 테스트로 고정한다.

- 헤더가 없는 요청(이미 배포된 앱)의 응답은 이전과 **바이트 단위로 같다**. (계획 2)
- `Accept-Language: zh-TW`, `zh-Hant`, `ar`, 빈 값, `*`, 품질값(`en;q=0.1, ja;q=0.9`)이 터지지 않고 정해진 언어로 떨어진다. (계획 2)
- 번역이 하나도 없는 키가 화면을 깨지 않는다(`en` → `ko` 대체). (계획 1, 2)
- 이룸이 휴대폰과 보호자 휴대폰의 언어가 다를 때 카드 글과 음성이 일과 언어를 따른다. (계획 1, 3)
- 폴백 질문·추천 목록 파일이 한 언어라도 비면 서버가 뜨지 않는다. (계획 2)
- 약관이 게시되지 않은 언어에서 가입이 막히고 재시도 안내가 나온다(빈 화면·무한 로딩 금지). (계획 4)
- 번역 문자열이 길어도(스페인어) 고정 폭 위젯에서 넘치지 않는다. (계획 1, 5)
- 번역 파일 간 키·자리표시자 불일치를 CI가 잡는다. (계획 5)

```
7 법무 검토 ─────────────────────────────────────────────▶ (출시 차단, 언어별)
1 클라 i18n 기반 ──┐
2 서버 언어 기반 ──┼─▶ 3 AI 다국어 ──┐
                   └─▶ 4 약관·공지 ──┼─▶ 5 번역·품질 ─▶ 언어별 출시 (en → es → ja → zh)
6 네이티브·스토어 ───────────────────┘
```

| 단계 | 계획 | 선행 | 사용자 영향 |
| --- | --- | --- | --- |
| 0 | 7. 법무 검토 시작 | 없음 | 없음 |
| 1 | 1. 클라 i18n 기반, 2. 서버 언어 기반 | 없음(서로 독립) | 없음 (`ko` 동작 불변) |
| 2 | 3. AI 다국어, 4. 약관·공지 | 2 (3은 1의 TTS 부분도) | 없음 (`ko` 동작 불변) |
| 3 | 5. 번역·품질, 6. 네이티브·스토어 | 1 (5), 없음 (6) | 없음 |
| 4 | 언어별 출시 | 위 전부 + 7 | `en` 부터 |

언어를 여는 조건(스펙 5장)은 언어마다 확인한다: 번역 파일 완성, 약관 게시, AI 프롬프트 행 검증, 법무 확인.
