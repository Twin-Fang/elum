# 무료 AI 크레딧 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 회원별 주간 AI 크레딧 장부(예약·정산·반환·멱등)를 서버에 만들고, 일과 생성·수동 카드 그림에 연결하고, 관리자 운영 화면과 보호자 설정 카드를 붙인다.

**Architecture:** `credit/` 도메인에 계정(잠금 지점)·적립 묶음·작업·원장·정책 버전 표를 둔다. 모든 증감은 계정 행 `FOR UPDATE` 안에서 일어나 여러 서버에서도 일관된다. 일과 생성은 시작 때 예약, 저장 트랜잭션에서 정산, 실패 시 반환한다.

**Tech Stack:** Spring Boot 3 / JPA / PostgreSQL / Flyway / Thymeleaf+daisyUI(관리자) · Flutter / Riverpod / dio / Freezed.

**Spec:** `docs/superpowers/specs/2026-09-24-ai-credit-design.md` — 모든 태스크는 스펙을 함께 읽는다.

## Global Constraints

- 서버 패키지: `com.chuseok22.elumserver.credit.{core,application.{controller,dto.request,dto.response,service},infrastructure.{entity,repository}}`.
- 엔티티는 `BaseEntity` 상속, id 는 UUID 문자열(기존 엔티티와 같은 방식).
- 예외는 `CustomException(ErrorCode.X)` 만. 새 ErrorCode 는 `GlobalExceptionHandler`/`ExceptionHandlerCoverageTest` 규칙을 따른다.
- REST 엔드포인트는 `@LogMonitoring` + `*ControllerDocs` 인터페이스. 요청 DTO 에 `jakarta.validation.constraints` 금지.
- 마이그레이션 파일은 `V26__create_ai_credit.sql` 하나, `IF NOT EXISTS`·`ON CONFLICT DO NOTHING`, 추가 전용(`MigrationRollbackContractTest`).
- 시간: `LocalDateTime` + 주입 `Clock`(기본 `Clock.systemDefaultZone()`, 운영 TZ=Asia/Seoul). 주기 시작 = 그 주 월요일 00:00, period_key = `YYYY-Www`(ISO 주).
- 화면 문구: 해요체·능동형, "아이"·"기기"·"서버" 금지. 에러 문구는 스펙 표 그대로.
- 주석: 간결한 한국어, WHY 중심.
- 앱: 하드코딩 색·글꼴·간격 금지(토큰), 새 색 토큰은 AppColors 5곳, 300줄 넘는 파일 분리, TDD.
- **커밋·푸시하지 않는다**(오케스트레이터가 `/pro-commit` 으로 한다). `git add -A`·`git stash`·`git checkout .` 금지.

## Review Focus

1. 잔액 1 에서 그림 8장 일과 → 차감 1, overage 8, 잔액 0, 일과는 저장됨 (Task S2·S3 테스트).

5. 크레딧 조회 실패 시 앱이 0 을 그리지 않고 실패 상태 + 재시도 (Task C2).

### Task S2: 예약·정산·반환·만료

**Files:**

**Interfaces:**
- Consumes: S1 전부.
- Produces:
  - `CreditReservation reserve(String memberId, CreditJobKind kind, String requestKey, boolean allowOverage)` — 크레딧 꺼짐이면 `CreditReservation.disabled()`. 결과 `record CreditReservation(String jobId, Outcome outcome, String routineId)`, `Outcome { RESERVED, ALREADY_SETTLED, DISABLED }`. 진행 중 → `CustomException(AI_CREDIT_JOB_IN_PROGRESS)`, 부족 → `AI_CREDIT_INSUFFICIENT`, 동결 → `AI_CREDIT_ACCOUNT_FROZEN`, DB 예외 → `AI_CREDIT_UNAVAILABLE`. 예약량 = ROUTINE_CREATE 는 `costOf(ROUTINE_TEXT)`, CARD_IMAGE 는 `costOf(CARD_IMAGE)`. 사용 가능 < 예약량이면 부족.
  - `CreditSettlement settle(String jobId, int cardCount, int imageCount, String routineId, String stepId)` — `@Transactional(propagation = MANDATORY)` 아님: 기본 REQUIRED(호출자 트랜잭션에 참여). 청구 = 스냅샷 단가로 계산(ROUTINE_CREATE: text + image×n, CARD_IMAGE: image×n). 차감 = min(청구, available+reserved). 만료 임박 grant 부터 CONSUME 원장. 나머지 overage + OVERAGE 원장(delta 0, reason 에 수량). `record CreditSettlement(int charged, int overage, int balanceAfter)`. 이미 SETTLED 면 그대로 반환(멱등).
  - `void release(String jobId, String reason)` — REQUIRES_NEW, RESERVED 일 때만 RELEASED + RELEASE 원장. 예외 삼키지 말고 error 로그 후 무시(호출자 흐름 보호).
  - `int expireStale(String memberId)` — TTL 지난 RESERVED → EXPIRED + RELEASE 원장. `balance` 조회·reserve 전에 호출.
- [ ] Step 1: 테스트 — (a) 잔액 1, ROUTINE_CREATE 예약 → RESERVED, available 0; (b) 잔액 0 → INSUFFICIENT; (c) 같은 키 RESERVED → IN_PROGRESS, SETTLED → ALREADY_SETTLED + routineId; (d) settle 잔액 1·그림 8 → charged 1, overage 8, balanceAfter 0; (e) 잔액 100·그림 4 → charged 5, balanceAfter 95; (f) WEEKLY 2 + BONUS 무기한 10, 청구 5 → WEEKLY 0, BONUS 7; (g) CARD_IMAGE allowOverage=false, 잔액 0 → INSUFFICIENT; (h) release → RELEASED, 잔액 원복; (i) TTL 16분 지난 RESERVED → EXPIRED; (j) 정책 꺼짐 → DISABLED, 원장 없음; (k) 동결 → FROZEN.
