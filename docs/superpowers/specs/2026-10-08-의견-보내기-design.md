# 의견 보내기 설계

보호자가 앱 안에서 의견을 적어 보내고, 원하면 앱 상태 기록(최근 로그)을 함께 보낸다.
관리자는 관리자 화면에서 목록과 상세를 본다.

- 디자인 요청: #604 (시안은 아직 없다. 시안 없이 먼저 구현하고, 모양은 시안이 나오면 바꾼다)
- 와이어 참고: #604 본문의 A안(새 화면)

## 1. 이해한 것

| 구분 | 내용 |
|---|---|
| 목적 | 사용 중 문제와 의견을 앱 안에서 받는다. 앱 상태 기록이 오면 재현이 쉽다 |
| 대상 | 보호자 화면만. 이룸이 휴대폰 설정에는 넣지 않는다 |
| 합의 | 체크 문구는 "앱 상태 기록 보내기", 기본 켜짐, 개인정보 경고 문구는 넣지 않는다 |
| 성공 기준 | 보호자가 글을 보내면 관리자 화면에 글과 기록이 보인다. 실패해도 적은 글이 남는다 |
| 가정 | 설정 줄은 약관과 앱 버전 사이에 둔다. 위치는 시안이 나오면 바뀔 수 있다 |

## 2. 범위

**한다**
- 서버: 의견 저장 API, 테이블, 관리자 목록·상세·삭제
- 클라: 설정 줄, 의견 화면, 앱 로그 메모리 버퍼, 전송

**하지 않는다**
- 답변 기능, 푸시 알림, 상태(처리중·완료) 관리
- 이룸이 휴대폰 설정의 줄
- 로그 마스킹. 마스킹은 하지 않으므로 화면에서 "가린다"고 말하지 않는다
- 이미지·파일 첨부

작업은 두 이슈로 나눈다. 서버가 먼저다.

1. `⚙️[기능추가][서버][의견] 의견 보내기 저장과 관리자 조회`
2. `⚙️[기능추가][클라][의견] 설정에서 의견 보내기와 앱 상태 기록 전송`

## 3. 서버

### API

`POST /api/feedback` (보호자 인증. 기존 `/api/**` 규칙의 `GUARDIAN` 권한만 통과한다)

| 필드 | 타입 | 규칙 |
|---|---|---|
| `message` | string | 필수. 공백만이면 거절. 최대 2000자 |
| `appLog` | string | 선택. 최대 64KB. 없으면 로그 없이 저장 |
| `appVersion` | string | 선택. 최대 32자 |
| `os` | string | 선택. 최대 64자 |

응답은 `{ "id": "..." }`다. 컨트롤러는 `FeedbackController` + `FeedbackControllerDocs`로 나누고 `@LogMonitoring`을 붙인다. 로그 파라미터는 남기지 않는다(`logParameters=false`). 의견 원문이 서버 로그에 들어가면 안 된다.

요청 DTO에는 validation 어노테이션을 쓰지 않는다(`server/CLAUDE.md`). 길이·공백 검사는 서비스에서 하고 `CustomException`으로 던진다.

### 에러 코드

| 코드 | 상태 | 쓰임 |
|---|---|---|
| `FEEDBACK_MESSAGE_EMPTY` | 400 | 글이 비었다 |
| `FEEDBACK_MESSAGE_TOO_LONG` | 400 | 2000자 초과 |
| `FEEDBACK_LOG_TOO_LARGE` | 400 | 로그 64KB 초과 |
| `FEEDBACK_RATE_LIMITED` | 429 | 한 회원이 하루 20건을 넘었다 |
| `FEEDBACK_NOT_FOUND` | 404 | 관리자 상세·삭제에서 id가 없다 |

`messages_{ko,en,ja,es,zh}.properties`에 모두 등록하고, 클라 `server_error_code.dart`에도 같은 이름을 넣는다. ko 문구는 `ErrorMessagesStartupGuard`가 기동 시 검사한다.

### 저장

테이블 `feedback`. `BaseEntity`를 상속한다(UUID 문자열 id, `created_at`, `updated_at`). 마이그레이션은 `V34__create_feedback.sql`이다.

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `member_id` | varchar(255), not null | 외래키는 걸지 않는다(기존 관례). 인덱스를 둔다 |
| `message` | text, not null | |
| `app_log` | text, null | |
| `app_version` | varchar(32), null | |
| `os` | varchar(64), null | |

### 관리자

- 사이드바에 "의견 관리" 한 줄 추가 (`admin-layout.html`)
- `GET /admin/feedback` 최신순 목록. 한 줄에 날짜, 회원 id 앞자리, 글 앞 40자, 로그 여부
- `GET /admin/feedback/{id}` 상세. 글 전체, 앱 버전·OS, 로그는 접어서 보여 준다
- `POST /admin/feedback/{id}/delete` 삭제
- 새 컨트롤러가 `AdminViewExceptionHandler`의 대상 목록에 들어가야 하는지 구현 때 확인한다

### 보관

의견과 로그는 관리자가 삭제할 때까지 보관한다. 자동 삭제는 하지 않는다.

## 4. 클라이언트

### 진입

- 보호자 설정 화면의 `약관 및 개인정보처리방침`과 `AppInfoTile` 사이에 `의견 보내기` 줄(`SettingsTile`)을 둔다. 임시 시안이므로 코드 주석에 그렇게 적는다.
- 라우트는 `/guardian/settings/feedback`이다. `/guardian` 접두라 보호자·세션 가드를 자동으로 받는다.

### 화면 (`FeedbackScreen`)

위치는 `features/feedback/presentation/`이다. data·application 분리는 `features/notice`를 본보기로 삼는다.

- 여러 줄 입력창. `ElumTextField`는 한 줄 전용이라 같은 모양의 입력창을 새로 만든다. 글자 상한은 서버와 같은 2000자다.
- 체크박스 "앱 상태 기록 보내기". 기본 켜짐. 앱에 체크박스 컴포넌트가 없어 새로 만든다. 임시 시안이다.
- 하단 `보내기` 버튼(`ElumButton`).
- `ElumScaffold`는 키보드가 올라와도 하단 버튼을 올려 주지 않고 키보드가 버튼을 가린다. 이 화면은 `viewInsetsOf`로 버튼을 키보드 위에 올린다.

### 전송

- 보내는 값: 글, 로그(체크 켜졌을 때만), 앱 버전(`AppStatusRepository.currentVersion()`), OS(`Platform.operatingSystem` + 버전)
- 저장소 `FeedbackRepository`는 `guarded`로 감싸고 실패 코드는 `E-FEEDBACK`로 둔다. 요청 본문은 로그에 남기지 않는다.

### 앱 로그 버퍼

기존 `DevLogBuffer`는 개발자 도구를 켠 빌드에서만 설치되고 "정식 출시 전 제거 대상"이라 재사용하지 않는다.

- 새 `AppLogBuffer`를 `core/logger/`에 둔다. `AppLogger._log`가 한 줄을 만들 때 버퍼에도 추가한다.
- 메모리 링버퍼, 최근 200줄, 합계 50KB 상한. 디스크에 쓰지 않는다. 앱을 끄면 사라진다.
- 일반 빌드의 `AppLogger`는 값을 100자에서 자르고 목록은 개수만 남기므로, 로그에 들어가는 원문이 적다.
- 보낼 때 마지막 N줄을 합쳐 상한 안으로 자른다.

### 문구

ko와 en을 함께 추가한다(`arb_parity_test`가 두 언어의 키를 맞춘다). 문구는 해요체, "이룸이", "휴대폰" 규칙을 따른다. 후보는 #604를 따른다.

| 자리 | 문구 |
|---|---|
| 설정 줄 | 의견 보내기 |
| 입력창 안내 | 불편했던 점을 편하게 적어 주세요 |
| 체크 | 앱 상태 기록 보내기 |
| 버튼 | 보내기 |
| 성공 토스트 | 의견을 보냈어요 |
| 실패 팝업 제목 | 의견을 보내지 못했어요 |

## 5. 실패 경로

| 상황 | 동작 |
|---|---|
| 글이 비었다 | `보내기` 비활성. 서버도 `FEEDBACK_MESSAGE_EMPTY`로 막는다 |
| 글이 2000자를 넘는다 | 입력창이 2000자에서 멈춘다 |
| 전송 중 | 버튼에 로딩, 입력 잠금. 중복 전송을 막는다 |
| 네트워크 실패·타임아웃 | `showFailure` 팝업 + 에러 코드. 적은 글과 체크 상태는 그대로 둔다. 다시 누르면 재전송한다 |
| 서버가 거절 (`RATE_LIMITED` 등) | 서버가 준 문구와 코드를 팝업으로 보여 준다. 글은 그대로 둔다 |
| 로그가 비었다 | 로그 없이 글만 보낸다. 오류로 막지 않는다 |
| 로그가 64KB를 넘는다 | 클라가 먼저 50KB로 자르므로 거의 없다. 서버가 거절하면 위와 같이 처리한다 |
| 보낸 직후 화면을 벗어남 | 성공 토스트를 화면 이동 전에 `showElumToastOn(messenger, ...)`로 띄운다 |
| 목록이 0건 (관리자) | 빈 상태 문구를 보여 준다 |
| 응답 형식이 다르다 | 파싱 실패를 잡아 실패 팝업으로 보낸다. 앱이 죽지 않는다 |

## 6. 서비스 원칙 점검

| 원칙 | 판단 |
|---|---|
| 진단명·장애 유형을 수집하지 않는다 | 자유 글이라 사용자가 적을 수는 있다. 서버가 따로 수집하지 않고 관리자 화면에만 보인다 |
| 원문을 감사 로그·로컬에 저장하지 않는다 | 로그는 메모리뿐이다. 의견 글은 서버 로그에 남지 않게 `@LogMonitoring`의 파라미터 로그를 끈다 |
| AI | 이 기능은 AI를 쓰지 않는다 |
| 데모는 어떤 실패에서도 끝까지 진행 | 실패해도 화면은 살아 있고 글이 남는다 |

## 7. 테스트

**서버**
- 서비스: 빈 글, 2000자 초과, 로그 64KB 초과, 하루 20건 초과, 정상 저장
- 컨트롤러: 인증 없음 401, 이룸이 권한 403
- 로컬 DB 통합 테스트로 마이그레이션과 저장·조회 확인
- 관리자 목록·상세·삭제

**클라**
- `AppLogBuffer`: 상한(줄·바이트), 오래된 줄이 먼저 빠짐
- 의견 화면: 빈 글에서 버튼 비활성, 전송 성공 후 토스트와 이동, 실패 시 글 보존과 에러 코드 노출, 체크를 끄면 로그가 안 감
- 키보드: `showKeyboard`로 올린 상태에서 버튼이 키보드 위에 있다
- 라우터: `/guardian/settings/feedback` 가드(`router_elumi_guard_test` 계열에 이룸이 차단 케이스 추가)
- 한글 리터럴 검사 0줄, ARB ko·en 키 일치

## 8. 확인이 필요한 것

사용자 확인 대상이다.

1. **심사 위험.** 설정 화면 코드에 `문의하기`를 App Store 심사 기간에는 두지 않기로 한 기록이 있다(#312, 2026-09-23). 앱 안 의견 창구는 성격이 비슷하다. 심사에서 문제가 되면 줄을 숨길 수 있게 서버 시스템 설정으로 끌 수 있는 스위치를 둘지, 지금은 넣지 않고 문제가 되면 코드를 고칠지 정해야 한다. 이 설계는 **스위치 없이** 간다.
2. **약관·개인정보처리방침.** 의견 글과 앱 상태 기록을 수집·보관(로그 보관)한다는 내용이 법적 문구에 들어가야 하는지 확인이 필요하다. 문구는 임의로 바꾸지 않는다. 약관은 네 곳에 산다(운영 DB는 배포로 덮이지 않는다).
3. **하루 20건 제한.** 숫자는 임의 값이다. 바꿔도 된다.
