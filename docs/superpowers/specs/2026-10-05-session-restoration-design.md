# #560 재설치 인증과 휴대폰 비밀암호 설계

2026-10-05 사용자 합의 및 구현 승인. 실기기 검증은 사용자가 수행하며 코드 검증·커밋·푸시·배포는 개발 담당이 수행한다.

## 정책

- 완전 삭제 후 재설치는 반드시 로그인 화면부터 시작한다. iOS Keychain에 남은 토큰은 세션 복원의 근거가 아니다.
- 일반 재시작·업데이트·iOS 앱 정리하기(데이터 유지)는 로그인·마지막 화면·오프라인 상태를 유지한다.
- 로그인 후 기존 회원의 약관과 프로필은 기존 `/api/member/me`에서 복원한다. 기존 프로필이 있으면 역할·이름 온보딩을 반복하지 않는다.
- 보호자 비밀암호는 계정 비밀번호가 아니라 이 휴대폰의 보호자 화면 잠금이다. 서버 저장·휴대폰 간 동기화 없이 오프라인에서도 검증·변경한다.
- 새 설치의 기존 보호자 로그인은 기존 프로필을 복원한 뒤 이 휴대폰 암호만 새로 설정한다. 연결한 이룸이 휴대폰은 보호자 로그인 권한을 얻지 않는다.
- 일과·진행 기록의 기존 오프라인 큐와 온라인 동기화 동작은 유지한다. 갱신 중 네트워크 오류만으로 로그아웃하지 않는다.

## 원인

`SecureTokenStore.load`는 Keychain 토큰만 복원하고, 라우터는 SharedPreferences의 역할·온보딩 정보로 목적지를 결정한다. 삭제 후 토큰만 남으면 미완료 온보딩으로 오인한다. 비밀암호는 현재 SharedPreferences 평문이며 저장 실패가 묻히고, 회원 조회 실패를 약관 미동의로 취급한다.

## 설치 경계

iOS Application Support의 백업 제외 파일, Android noBackupFilesDir의 파일에 무작위 설치 식별자를 원자적으로 저장한다. OS 저장소 읽기 오류와 파일 부재를 구분한다. 토큰에 설치 식별자를 결합하고 불일치·누락이면 남은 토큰을 사용하지 않는다. 새 식별자 생성은 기존 식별자가 없는 경우뿐이다. 보안 저장소 실패는 E-INSTALL 표시와 재시도로 시작을 막으며 인증·잠금 화면을 열지 않는다.

기존 정상 설치의 업데이트는 강제로 로그아웃시키지 않는다. 설치 결합이 아직 없는 레거시 토큰에 한해 완성된 로컬 프로필·역할 상태가 일관되게 남아 있으면 일회적으로 새 설치 식별자에 결합한다. 로컬 상태가 없는 재설치는 잔존 토큰을 차단한다. 이미 설치 결합이 있는 토큰의 불일치는 레거시 이전으로 우회하지 않는다. 구버전 데이터 전체가 OS 백업에서 복원된 경우는 최초 이전의 한계이며 구현 보고서에 명시한다. 기존 로컬 프로필·진행 큐는 같은 회원 재로그인일 때 보존하고 다른 회원이면 초기화한다. 회원 식별자가 없는 캐시는 재로그인 시 다른 계정에 상속하지 않는다.

## 로컬 잠금

비밀암호 인터페이스는 존재 확인·검증·설정으로 나눈다. 원문 읽기 API를 호출부에서 제거하고 무작위 salt와 PBKDF2-HMAC-SHA256(600,000회, 256bit) verifier를 secure storage에 저장한다. 읽기·쓰기 실패를 호출부에 전달한다. 평문 레거시 PIN은 설치와 계정 경계가 유효할 때만 일회 이전 후 SharedPreferences에서 제거한다. 프로필 전환은 휴대폰 PIN을 지우지 않는다. 로그아웃·탈퇴·새 설치는 PIN을 초기화한다. 기존 PIN 없이 보호자 화면에서 생성하기를 허용하려면 방금 보호자 로그인했다는 세션 내 증거가 필요하다. 화면 전환으로 이룸이가 직접 PIN을 생성해서 보호자 화면에 진입하는 우회는 금지한다. 잘못된 입력 5회는 5분 제한하며 secure storage에 기록해 재실행으로 우회하지 못한다.

## 로그인 복원과 실패

회원 조회 응답의 필수 필드·프로필 정보를 검증한다. 조회 실패·5xx·오프라인은 약관/온보딩 미완료가 아니라 로그인 실패/재시도이며, 미완성 세션으로 라우터가 홈을 열지 않도록 정리한다. 신규 회원만 동의→역할→프로필 생성 경로를 탄다. 기존 계정은 현재 프로필의 id·이름·목표·캐릭터·그림 방식을 복원하고 마지막 화면을 보호자로 지정한다. 성공한 신규 보호자 로그인에서 PIN이 없으면 PIN 생성 화면을 거쳐 기존 홈으로 이동한다.

401 갱신 요청을 동시에 묶는 기존 제어를 유지한다. 갱신 서버에서 확정된 401은 세션 종료, 타임아웃·오프라인·5xx는 기존 세션과 오프라인 진행 기록 보존이다. 재시도는 한 번만 한다. 계정 전환 도중 오래된 응답이 새 계정 토큰을 덮어쓰지 못하도록 저장 전 세션 식별을 확인한다.

## 검증과 배포

Dart 저장소·라우터·로그인·PIN·오프라인 회귀 테스트, flutter analyze, 전체 flutter test, 네이티브 컴파일 가능한 범위 확인. 실기기 삭제/재설치·Apple 로그인은 사용자가 검증한다. develop 최신 변경을 통합하고 main 전용 버전 커밋을 반영한 뒤 projectops 릴리스 PR로 배포한다. 서버 API 신규 추가는 필요 없으며 PIN 서버 스키마도 추가하지 않는다.

## 이전 판정과 권한 경계

레거시 이전은 토큰에 결합 값이 한 번도 기록되지 않은 경우만 가능하다. 로컬 완료 프로필(이름/id 및 완료 상태)과 보호자/연결 상태가 일관되어야 하며, 누락·충돌이면 자동 복원하지 않는다. 이 검사와 JWT의 회원 id 힌트는 캐시 보존 판단만 담당한다. 보호자/이룸이 권한은 서버가 검증한 토큰과 연결 상태로 결정하며 SharedPreferences 값을 보안 권한으로 사용하지 않는다. 구버전 최초 이전의 OS 전체 백업 복원은 완전 삭제 후 App Store 재설치와 별도 사례이며, 토큰만으로 완전 구분할 수 없다는 한계를 숨기지 않는다. 새 버전 토큰은 설치 결합으로 이를 차단한다.

PIN 생성 권한은 URL query나 `createOnly` boolean만으로 부여하지 않는다. 인증 조정자가 성공한 보호자 로그인 이후 메모리에 발급한 일회 허가를 생성 화면에서 소비한다. 실패·취소·로그아웃·다른 계정 전환·앱 재시작 때 허가는 소멸한다. 정상 설치에서 PIN이 갑자기 없어지면 재인증한 뒤 설정하며 이룸이 화면에서 임의 설정 후 보호자 진입은 금지한다.

## 구현 전 검증 게이트

1. 설치 경계 구현과 재시작/재설치/레거시 이전/실패 테스트.
2. PIN 저장소 및 계정·설치 scope, 영속 오답 제한, 실패 UI 테스트.
3. 회원 복원·PIN 생성 허가·계정 전환·갱신 동시성과 임시 오류 테스트.
4. 통합 analyze/test/네이티브 컴파일과 독립 리뷰 후 코드 커밋·푸시.
5. 사용자의 실기기 검증은 별도이며 코드 검증만으로 실기기 통과라고 기록하지 않는다.

현재 요청은 설계 문서를 우선 커밋·푸시하는 단계다. 구현 도중 파일은 설계 커밋에 포함하지 않으며 설계 문서 푸시를 제품 수정·배포 완료로 표현하지 않는다.
