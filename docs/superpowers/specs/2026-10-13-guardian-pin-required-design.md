# 보호자 암호 만들기를 건너뛸 수 없게 한다 (#630)

## 결함
새 휴대폰에서 기존 보호자로 로그인하면 암호 만들기(`/guardian/settings/pin?from=login`)로 간다.
여기서 뒤로가기를 누르면 화면은 로그인인데 세션은 남았고, 앱을 다시 켜면 잠금 없이 보호자 홈이 열렸다.

원인 둘.
1. `guardianPinSetupPending` 이 로그인 때 메모리에만 서서 재시작 후 false.
2. 만들기 화면의 뒤로가기가 `context.go(login)` 만 해서 세션을 정리하지 않았다.

## 설계
- 시작 시 `main` 이 `hasPin()` 을 읽어 `startupLockMissingProvider` 로 주입하고,
  `AuthRepository.restoreGuardianPinRequirement` 가 (세션 있음 · 이룸이 휴대폰 아님 · 온보딩 완료 ·
  역할이 elumi 아님 · 잠금 없음)이면 대기 표시와 일회 허가를 세운다. 기존 경로 가드가 보호자 화면을 만들기로 돌린다.
- 만들기 화면의 뒤로가기는 `logout()` 후 로그인으로 간다. 화면과 세션이 항상 일치한다.
- 저장 키·에러 코드·API 는 바꾸지 않는다.

## 행복 경로
로그인 → 만들기 → 저장 → 보호자 홈. 중간에 앱을 꺼도 다음 시작에 만들기로 돌아온다.
뒤로가기 → 로그아웃 → 로그인 화면, 재시작해도 로그인 화면.

## 실패 경로
- 잠금 기록이 깨져 `hasPin` 이 던짐: 로그만 남기고 기존 동작(강제하지 않음). 새로 덮어쓰지 않는다.
- 로그아웃 중 서버/로컬 정리가 던짐: 로그만 남기고 로그인으로 나간다. 남은 세션은 다음 시작에 만들기로 돌아온다(막다른 길 없음).
- 옛 사용자가 PIN 없이 쓰던 경우: 한 번 만들고 들어가면 끝난다. 이룸이 휴대폰·역할 미정은 대상 제외.
- 재설치: 설치 표식이 바뀌면 토큰·잠금이 함께 폐기돼 세션이 없으므로 로그인 흐름을 탄다.
