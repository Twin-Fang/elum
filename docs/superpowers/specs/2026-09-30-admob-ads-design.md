# AdMob 광고 설계 (#281)

2026-09-30 · 상태: 사용자 승인 대기(spec 검토) · 관련: #278(개인정보처리방침), #368(비용 상한), #407(주간 크레딧)

## 1. 목표와 배경

Free 요금제가 기본이고 일과 생성마다 AI 비용(평균 약 40원)이 든다. 광고 수입으로 이 비용을 메운다.
**허용된 화면 안에서 광고 수익을 최대로** 잡되, 이룸이 화면은 건드리지 않는다.

성공 기준.

- 보호자 홈·임시저장·설정에 배너, 홈 목록에 네이티브, 크레딧 소진 시 보상형이 뜬다.
- 이룸이 화면·일과 만들기 흐름·보상 연출에는 광고 코드가 닿지 않는다(테스트로 잠금).
- 광고가 실패·차단돼도 빈 자리가 남지 않고 앱은 그대로 동작한다.
- 개발·테스트 빌드는 실제 광고 단위를 절대 쓰지 않는다.

## 2. 화면별 배치 (허용 / 금지)

| 화면 | 광고 | 형식 |
|---|---|---|
| 보호자 홈 | ⭕ | 하단 고정 적응형 배너 + (목록 한가운데 배너는 디자인을 해쳐 뺐다) + '지난 일과' 목록 사이 네이티브 1개(#465) |
| 임시저장 목록 | ⭕ | 하단 고정 배너 |
| 설정 | ❌ | 맨 아래 `회원탈퇴` 줄과 가까워 광고를 잘못 누르면 되돌릴 수 없는 동작으로 이어진다. 시안에서 간격이 정해지면 다시 검토 |
| 크레딧 소진 안내(일과 만들기 진입 전) | ⭕ | 보상형(선택형, "광고 보고 더 만들기") |
| 일과 만들기 흐름(입력·로딩·질문·카드확인·보상설정) | ❌ | 만들다 끊긴다 |
| 이룸이 모드 전체 | ❌ | 절대 금지 |
| 보상·완료 연출 | ❌ | 해냈다는 순간을 덮지 않는다 |
| 비밀암호 변경·온보딩·연결 | ❌ | 입력 화면 |

전면·앱 오픈 광고는 넣지 않는다(흐름 중단·오클릭 정지 위험, #281 결정).

## 3. 구성

```
lib/core/ads/
  ad_config.dart        광고 단위 ID·앱 ID 해석. 디버그·프로필·테스트 빌드는 Google 공식 테스트 ID로 고정
  ad_gate.dart          adsEnabledProvider(지금은 항상 true, 이후 FREE/PRO_ADS_REMOVED 연결) + 서버 설정
  ad_consent.dart       ATT(iOS)·비개인화 요청 결정. 인터페이스로 분리해 테스트에서 가짜 주입
  ad_sdk.dart           SDK 초기화(지연). 보호자 화면에서 처음 광고를 그릴 때만
  banner_slot.dart      AdBannerSlot: 로드 전·실패 시 높이 0, 성공하면 그 높이만큼 본문이 줄어든다
  native_slot.dart      AdNativeSlot: 목록 항목용. 실패하면 항목 자체가 없다
  rewarded_offer.dart   보상형 로드·표시·서버 검증 흐름
```

- **겹침 방지는 구조로 한다.** `ElumScaffold`에 `bottomBanner` 슬롯을 추가하고, `bottomButton`과 함께 쓰면 assert로 막는다.
  홈은 `Scaffold.bottomNavigationBar`에 둔다. 본문 여백을 계산하지 않는다.
- **이룸이 전용 휴대폰에서는 SDK가 초기화조차 되지 않는다.** 초기화는 보호자 홈이 처음 배너를 그릴 때 지연 실행한다.
- **광고 요청에 사용자 정보를 넘기지 않는다.** 키워드·콘텐츠 URL·이룸이 이름·진단 정보 없음(서비스 원칙 1·2).
  `AdRequest`를 만드는 곳을 한 곳으로 모으고 테스트로 잠근다.

## 4. ATT · 동의

- iOS에서 보호자 홈을 처음 열 때 `notDetermined`이면 한 번만 묻는다. 이후 다시 묻지 않는다.
- 거부하면 비개인화 광고로 요청한다. Android는 ATT가 없어 기본 요청이다.
- 안내 문구(`NSUserTrackingUsageDescription`) 초안: "보호자 화면에 알맞은 광고를 보여드리는 데 사용해요. 이룸이의 정보는 사용하지 않아요." (해요체, 법적 문구 아님)
- ATT 팝업·SDK 초기화 예외는 삼키지 않고 로그를 남기며, 화면에는 아무것도 띄우지 않는다.

## 5. 광고 ID 주입 (계정 게시자 `pub-2025665624324395`, 개발자 계정)

발급된 ID 값은 #281 댓글의 표를 따른다. 코드에는 값을 넣지 않고 `.env` 키로만 다룬다.

| 키 | 용도 |
|---|---|
| `ELUM_ADMOB_IOS_APP_ID` · `ELUM_ADMOB_ANDROID_APP_ID` | 네이티브 앱 ID(빌드 타임). 비어 있으면 Google 테스트 앱 ID |
| `ELUM_ADMOB_{IOS,ANDROID}_BANNER_HOME` · `_BANNER_DRAFTS` · `_BANNER_SETTINGS` | 배너 |
| `ELUM_ADMOB_{IOS,ANDROID}_NATIVE_HOME_PAST` | 네이티브 |
| `ELUM_ADMOB_{IOS,ANDROID}_REWARDED_CREDIT` | 보상형 |

- Android는 `build.gradle.kts`의 manifestPlaceholders, iOS는 `gen_ios_secrets.sh`가 만드는 xcconfig를 `GADApplicationIdentifier`에 연결한다(소셜 로그인 키와 같은 방식).
- 앱 ID가 비면 SDK가 시작하다 죽으므로 기본값은 Google 테스트 앱 ID다.
- **`kDebugMode || isDevBuild`이면 `.env` 값과 무관하게 테스트 광고 단위만 쓴다.** 실제 ID는 릴리스 빌드에서만 읽는다.
- 새 키는 `.env.example`과 `AppConfig`를 함께 고친다(기존 규칙).

## 6. 수익 극대화 규칙

- 배너는 적응형(화면 폭 기준)으로 요청한다. 로드 실패 시 30초·60초 뒤 각 1회 재시도하고 포기한다.
- 보상형 교환 비율(광고 N번 = 생성 1회), 광고 on/off, 배치별 on/off를 **서버 시스템 설정**으로 둔다.
  기존 대기·연출 시간과 같은 패턴(관리자 화면에서 조절, 앱 재빌드 없음, 코드에는 기본값).
- 광고 1번이 생성 비용(40원)을 넘기 어려울 수 있다(추정). 처음에는 2~3번 시청에 1회로 시작하고 실제 eCPM을 보고 조정한다.
- 미디에이션(Meta·AppLovin·Pangle 등)은 실측 데이터가 쌓인 뒤 배너부터 켠다(별도 이슈).
- app-ads.txt 인증이 끝나야 게재 제한이 풀리고 단가가 유리하다.

## 7. 보상형 크레딧 흐름

1. 이번 주 크레딧이 바닥나면 홈의 "일과 만들기" 진입 시 안내가 뜬다(#407). 이 안내에 "광고 보고 더 만들기"를 둔다.
2. 사용자가 누르면 보상형 광고를 로드해 보여준다. 흐름 안이 아니라 **진입 전**에서만 제안한다.
3. 시청이 끝나면 **서버가 SSV(서버 측 검증) 콜백으로 확인한 뒤** 크레딧을 지급한다. 클라이언트 보고만으로는 지급하지 않는다.
4. 하루 지급 상한과 서비스 전체 비용 상한(#368)을 넘지 않는다. 광고 로드 실패·중도 종료는 지급하지 않고 사유를 화면에 알린다.

실패 경로: 광고 없음(no fill)·오프라인·SSV 지연이면 "지금은 광고를 불러올 수 없어요. 다음 주에 다시 만들 수 있어요" 안내 후 원래 화면으로 돌아간다. 크레딧 소진 안내 자체는 항상 뜬다.

## 8. 테스트

- 위젯 테스트에서는 SDK를 띄우지 않고 로더를 가짜로 주입한다. 시안 대조 골든에는 광고 슬롯이 접힌 상태로 남는다.
- 로드 전·실패 시 높이 0 / 성공 시 본문이 줄어듦 / `bottomButton`과 함께 쓰면 assert.
- 이룸이·일과 만들기·보상 화면에 `AdBannerSlot`·`AdNativeSlot`이 없음(위젯 테스트 + `lib/features/child/`·일과 만들기 화면이 `core/ads`를 import하지 않는 소스 스캔 테스트).
- 디버그·테스트 빌드에서 실제 ID가 선택되지 않음.
- ATT 거부 시 비개인화 요청, `AdRequest`에 사용자 정보가 없음.
- 실기기: Android 에뮬레이터·iOS 시뮬레이터에서 테스트 광고 확인. 실제 광고는 누르지 않는다.

## 9. 스토어·약관 (코드 밖 작업, 제출 전 필수)

| 위치 | 할 일 |
|---|---|
| App Store Connect 앱 개인정보 | 광고 식별자·제품 상호작용·광고 데이터·충돌·성능 데이터 신고, 서드파티 광고 목적, ATT 허용 시 추적 표시 |
| App Store 심사 메모 | 광고 위치와 이룸이 화면 제외 명시, 아동 카테고리 아님 확인 |
| Play Console | 광고 포함 "예", 광고 ID 선언, 데이터 보안(기기 ID·앱 활동·진단, 광고 목적, 제3자 공유), 타겟층이 아동 아님 |
| 개인정보처리방침 | Google AdMob 이용 고지: 광고 식별자, 제공받는 자·국외 이전, 목적, 거부·재설정 방법(#278) |
| 이용약관 | 광고 게재 고지, 보상형 광고 시청과 크레딧 지급 조건(지급 시점·소멸·부정 이용 회수) |
| 앱 안 약관 문서 | 네 곳에 산다(운영 DB는 배포로 덮이지 않음). 관리자 화면 갱신이 마지막 단계 |

법적 문구는 초안 확정 전 검토를 받는다. 개인정보처리방침·ASC 라벨은 코드로 처리하지 않는다.

## 10. 단계

1. **기반 + 배너**(#281): SDK·네이티브 설정·ATT·게이트·테스트 ID 강제·`AdBannerSlot`·세 화면 배치
2. 네이티브(홈 지난 일과): 디자이너 협의 필요
3. 보상형 크레딧: 서버 SSV·지급 API·상한·설정 + 클라 UI(디자인 요청 선행)
4. 스토어·약관 갱신, app-ads.txt 호스팅
5. 미디에이션·Pro 연동(`FREE/PRO_ADS_REMOVED`)

## 11. 시안에 없는 것 (디자이너 협의)

시안에 광고 자리·보상형 안내 UI가 없다. 하단 배너 배치, 네이티브 카드 모양, "광고 보고 더 만들기" 안내와 광고 시청 전후 화면은
`/pro-design-brief`로 디자이너에게 요청한다. 시안이 나오기 전 코드는 임시 배치이며, 시안과 다르면 시안을 따른다.

## 12. 열린 결정

- 광고 콘텐츠 등급 제한(권장 PG)
- app-ads.txt 호스팅 방식((A) `Twin-Fang/twin-fang.github.io` 저장소 신설 권장)
