# 크레딧 꾸러미 관리자 화면 설계

상태: 초안 (승인 전, 구현 금지) · 작성 2026-11-17

## 배경과 의도

크레딧 꾸러미(50/100/150) 판매를 App Store와 Google Play 모두 승인받아 운영 중이다(2026-11-17 운영 DB·App Store Connect 실측).
그런데 이 판매를 다루는 설정이 관리자 `AI 설정` 화면의 「AI 크레딧」 그룹에 흩어져 있어, 운영자가 한눈에 보거나 안전하게 바꾸기 어렵다.

**운영자가 하고 싶은 일**: "지금 스토어별로 뭐가 팔리고 있나" 보기, 판매 켜고 끄기, 상품 구성 바꾸기, 잘못 설정한 것 미리 알기.

## 현재 구조 (코드·운영 실측)

| 항목 | 위치 | 비고 |
|---|---|---|
| 판매 스위치 3개 | 설정 `CREDIT_PACK_SALE_ENABLED` / `_APPLE_` / `_GOOGLE_` | 전체 스위치 켜짐 OR 스토어 스위치 켜짐이면 판매 (`CreditPackCatalog.isSaleEnabled`) |
| 상품 목록 | 설정 `CREDIT_PACK_PRODUCTS` | `상품ID:개수` 쉼표 문자열을 손으로 편집 |
| 인기 상품 | 설정 `CREDIT_PACK_POPULAR_PRODUCT_ID` | 목록에 없으면 표시 안 됨 |
| 크레딧 화면 | `/admin/credits/*` | 개요, 회원별, 작업 탐색, 구매·환불, 정책. 꾸러미 판매 설정은 없음 |
| 설정 저장 | `SystemConfigService.update(key, value, actor, reason)` | 값 검사, 사유, 변경 이력, 30초 안에 전 서버 반영 |

운영 현재값: Apple·Google 스위치 켜짐, 전체 스위치 꺼짐, 상품 50/100/150, 인기 `elum_credit_100`. 구매 0건.

## 목표 / 하지 않는 것

**목표**
- 크레딧 화면에 `꾸러미` 탭을 더해 판매 현황, 스위치, 상품 구성을 한 곳에서 본다
- 판매 스위치와 상품을 안전하게(사유, 확인 창, 이력) 바꾼다
- 흔한 설정 실수를 화면이 먼저 경고한다

**하지 않는 것**
- 가격 관리 (가격은 스토어가 갖고 서버는 모른다)
- 스토어에 상품 만들기·수정 (App Store Connect, Play Console에서만)
- 스토어에 등록된 상품 ID와 설정이 같은지 서버가 자동 대조 (스토어 조회 API를 새로 붙이지 않는다. 화면에 "스토어 등록 ID와 직접 맞춰 보세요" 안내만 둔다)
- 새 DB 테이블, 설정 원본 이중화

**실패해서는 안 되는 것(안티골)**: 이 화면이 설정을 잘못 저장해서 운영 판매가 의도치 않게 켜지거나 꺼지는 일.

## 검토한 안

| 안 | 내용 | 판단 |
|---|---|---|
| **A (추천)** | 크레딧 화면에 `꾸러미` 탭을 새로 만들고, 저장은 기존 설정 키와 `SystemConfigService.update` 를 그대로 쓴다 | 설정 원본이 하나로 유지돼 `AI 설정` 화면에서 바꿔도 이 화면에 반영된다. 이력·검증·반영 시간 그대로. 새 저장소 없음 |
| B | `AI 설정` 그룹에 크레딧 화면으로 가는 링크만 추가 | 가장 싸지만 "한눈에 보기·점검"이 안 풀린다 |
| C | 꾸러미 전용 테이블과 엔티티로 관리 | 설정과 원본이 둘이 되고 마이그레이션이 필요해 과하다 |

## 설계 (안 A)

### 화면 `/admin/credits/packs` (탭 이름 `꾸러미`, 구매·환불 탭 옆)

```
[개요] [회원별] [작업 탐색] [꾸러미] [구매·환불] [정책]

판매 현황
  App Store    ● 판매 중   [끄기]      iOS 2.101.0 이상 앱에만 적용
  Google Play  ● 판매 중   [끄기]
  전체 스위치  꺼짐 (켜면 두 스토어와 옛 앱까지 모두 판매)

꾸러미 상품 (3개)                              [상품 편집]
  상품 ID             크레딧   인기
  elum_credit_50        50
  elum_credit_100      100     ★
  elum_credit_150      150
  스토어에 등록한 상품 ID와 같아야 구매가 적립돼요.

점검
  ✓ 인기 상품이 목록에 있어요
  ✓ 판매 중인 스토어가 있고 상품이 1개 이상이에요
  ! 환불 재확인(STORE_REFUND_RECHECK_ENABLED)이 꺼져 있어요   <- 해당될 때만

최근 7일  구매 0건 · 환불 0건          최근 변경 이력 5건 (누가·언제·사유)
```

### 동작
1. **스위치 켜기/끄기**: 확인 창(돈이 걸린 기능) + 사유 필수(200자 이내) > `update(스토어 스위치 키, "true"|"false", 관리자 이름, 사유)`. 끌 때 안내문 "이미 산 크레딧은 그대로 쓸 수 있어요"
2. **상품 편집**: 행 추가·삭제·순서·인기 선택 > 저장 시 `상품ID:개수` 문자열로 직렬화해 `CREDIT_PACK_PRODUCTS`, `CREDIT_PACK_POPULAR_PRODUCT_ID` 를 함께 저장. 값 검사는 기존 `CreditPackListFormat` 과 `SystemConfigValueValidator` 를 쓴다(중복 ID, 개수 0 이하, 형식 오류 거절)
3. **점검 규칙**(읽기 전용 표시): 목록 비어 있음, 판매 켜졌는데 상품 0개, 인기 상품이 목록에 없음, 상품 ID 중복, 환불 재확인 꺼짐
4. 이력은 기존 설정 이력을 키로 걸러 5건 표시, 구매·환불 건수는 기존 구매 조회 서비스로 집계

### 실패 경로 (화면이 깨지지 않게)
| 상황 | 동작 |
|---|---|
| 설정 읽기 실패 | 칸마다 독립 실패, 그 칸에 안내와 코드 `E-ADMIN-CREDIT-PACKS-칸이름`. 나머지 칸은 정상 표시 |
| 저장 값 검사 실패 | 입력값을 그대로 두고 사유 표시 (`E-CFG-001` 기존 형식) |
| 사유 비었거나 200자 초과 | 저장 안 하고 사유 입력 안내 (`ADMIN-CREDIT-PACKS-REASON`) |
| 상품 편집 중 다른 곳에서 설정 변경 | 저장 시 이력에 전후 값이 남고, 마지막 저장이 이긴다(설정 화면과 같은 규칙) |
| 구매·이력 집계 실패 | 그 줄만 `확인 못 했어요` 로 대체 |

## 구조 (server 규칙 준수)
- `admin/application/controller/AdminCreditPackController` (`/admin/credits/packs`), 템플릿 `admin/credits-packs.html`, `fragments/credit-nav.html` 에 탭 한 줄
- `admin/application/service/AdminCreditPackService`: 화면 데이터 조립과 저장 (다른 도메인 repository 를 직접 쓰지 않고 `SystemConfigService`, `CreditPackCatalog`, `CreditPurchaseAdminQueryService` 를 거친다)
- 점검 규칙은 부수효과 없는 순수 클래스 하나(`CreditPackHealthCheck`)로 분리해 단위 테스트
- 새 `ErrorCode` 는 만들지 않는다(화면 안내 코드 문자열만 사용). 클라이언트(앱) 변경 없음

## 테스트 (결함 하나를 겨누는 것만)
| 막을 결함 | 층 |
|---|---|
| 상품 편집 직렬화가 잘못돼 판매 목록이 깨진다 | 단위: 직렬화 > 기존 `CreditPackListFormat.parse` 왕복 |
| 점검 규칙이 위험 설정을 놓친다 (빈 목록, 인기 누락, 중복) | 단위: `CreditPackHealthCheck` |
| 탭 화면이 렌더링 중 깨진다 | 템플릿 테스트(`AdminCreditPurchasesTemplateTest` 패턴) |
| 사유 없이 판매가 바뀐다 | 컨트롤러 테스트: 사유 없으면 `update` 호출 안 함 |

실행은 관련 클래스만 지정한다. 마지막에 실제 운영형 화면을 `/pro-launch` 로 캡처(라이트·다크)해 이슈에 첨부한다.

## 결정 필요 (승인 때 확인)
1. **전체 스위치(`CREDIT_PACK_SALE_ENABLED`)를 이 화면에서 바꿀 수 있게 할지** (내 선택: 읽기 전용 표시 + 켜져 있으면 경고만. 스토어별 스위치를 우회해 한꺼번에 팔리게 되는 실수가 크다)
2. **상품 편집을 이 화면에서 허용할지** (내 선택: 허용. 상품 ID 오타가 구매 미적립으로 이어지므로 저장 전 미리보기 한 줄을 보여 준다)
