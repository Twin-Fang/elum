# 다국어(5개 언어) 지원 구조 설계

- 이슈: [#521](https://github.com/Twin-Fang/elum/issues/521)
- 작성일: 2026-10-02
- 상태: 설계 합의 완료, 스펙 검토 대기
- 기준 코드: `origin/develop` (`0164a36a`)

## 1. 목적과 범위

앱이 한국어 전용이다. 해외 출시를 위해 **언어를 추가할 때 코드가 아니라 데이터를 추가하는 구조**로 바꾼다.

| 항목 | 값 |
| --- | --- |
| 지원 언어 | `ko` `en` `ja` `zh`(간체) `es` |
| 제외 | RTL 언어, 번체 중국어 |
| 대상 | 클라이언트 문구, 서버 응답, AI 생성물, 약관·공지, 네이티브, 스토어 문구 |
| 번역하지 않는 것 | 관리자 화면 대부분, 로그, 시스템 설정 문구(운영자는 한국어를 쓴다) |

**서비스 원칙은 모든 언어에서 그대로 지킨다.** 진단명 미수집, AI 결과는 보호자 승인 후 노출, 원문 로그 미저장, AI 실패 시 fallback.

### 이 설계가 풀지 않는 것

- 번역 문구 자체와 용어집 내용 (별도 작업)
- 법무 판단 (국외 이전, 연령 동의, GDPR·APPI). 설계는 결과를 담을 자리만 만든다.
- 결제·가격 표기 (아직 구현이 없다)

## 2. 현재 상태 (감사 결과)

수치는 줄 단위 정규식 집계라 ±10% 오차가 있다(추정).

| 영역 | 현황 |
| --- | --- |
| 클라 문구 | 사용자 노출 한글 약 836줄. `intl`, ARB, `supportedLocales`, locale 설정이 없다. |
| 클라 로직 | 조사 처리 9곳, 숫자 단위 34곳, 날짜 직접 조립 5곳 이상, 어절 줄바꿈(`keepWords`)은 한글 전용 |
| 폰트 | Pretendard, TmoneyRoundWind 모두 한글·라틴 위주로 추정. `fontFamilyFallback` 없음 |
| 음성 | TTS가 `ko-KR` 고정. 서버 음성은 `voice='F1'` 고정, 500자 제한 |
| 테스트 | `find.text` 한글 의존 1,391건(94파일), 골든·시안 PNG 123장 |
| 서버 응답 | ErrorCode 104개가 코드와 한글 문장을 함께 내려보낸다. `Accept-Language` 처리 없음 |
| 서버 생성 문장 | AI 폴백 질문(`RoutineAiPipeline`), 추천 목록 58개(`RoutineSuggestionCatalog`) |
| AI | `prompt_template`에 언어 열 없음. 출력 언어 지정 없음. `NicknamePlaceholder`는 한국어 조사 전용. 이미지 프롬프트 언어는 KO/EN만 있고 관리자 설정으로 고른다 |
| DB 콘텐츠 | `consent_document`, `app_notice`, `prompt_template` 모두 언어 열 없음 |
| 사용자 정보 | `Member`, `Profile`에 언어 정보 없음 |
| 네이티브 | iOS 권한 문구·앱 이름, Android 앱 이름이 한국어 고정. 심사 노트에 "Korean-only" 명시 |
| 스토어 | 문구 한국어 단일본, `DELIVER_LOCALES` 기본값 `ko` |
| 유리한 점 | 픽토그램(811개) 라벨이 영어라 언어와 무관하다. 약관은 이미 서버 관리 + 번들 기본값 구조다. 서버가 에러 코드를 이미 내려준다. |

## 3. 핵심 개념: 언어는 세 종류

이 앱은 보호자 휴대폰과 이룸이 휴대폰이 따로라서 언어가 하나가 아니다.

| 언어 | 정하는 것 | 정하는 주체 | 저장 위치 |
| --- | --- | --- | --- |
| **화면 언어** | 버튼, 메뉴, 에러 문구 | 그 휴대폰의 OS 언어 | 기기(OS) |
| **콘텐츠 언어** | AI가 만든 카드 글, 음성 | 일과를 만든 보호자 휴대폰의 화면 언어 | 일과(`Routine`) |
| **법적 문서 언어** | 약관, 개인정보방침 | 동의 시점의 화면 언어 | 동의 기록 |

## 4. 설계

### 4.1 화면 언어 선택

**앱 안에는 언어 선택 화면을 만들지 않는다.** OS 언어를 따른다.

결정 근거 (2026-10-02 합의)

- Apple과 Google 모두 OS 언어 추종과 OS의 앱별 언어 설정을 권장한다.
- 앱 안 변경을 만들면 즉시 반영, 로그인 전 선택 UI, 저장·복원, 서버 동기화가 모두 따라온다.
- 이룸이 당사자와 보호자에게는 휴대폰 언어가 곧 앱 언어인 쪽이 예측 가능하다.
- 약관 동의 화면도 휴대폰 언어로 정해져서 로그인 전 선택 UI가 필요 없다.

동작

1. 휴대폰 언어가 5개 중 하나면 그 언어를 쓴다.
2. 5개 밖이면 `en`을 쓴다 (번체 중국어 포함).
3. 사용자가 바꾸고 싶으면 OS의 **앱별 언어 설정**을 쓴다. 5개 언어가 그 목록에 뜨도록 네이티브 설정을 등록한다.
4. QA와 시연을 위한 **언어 강제 스위치**는 개발자 도구(`core/dev`)에만 둔다. 릴리스 빌드에는 없다.

알려진 한계

- Android 12 이하에는 OS의 앱별 언어가 없다. 이 기기에서는 휴대폰 언어를 바꿔야 앱 언어가 바뀐다.
- 휴대폰은 영어인데 앱만 한국어로 쓰고 싶은 사용자는 설정 앱까지 가야 한다.
- 사용자 요청이 쌓이면 앱 안 선택을 나중에 추가한다. 이 설계는 그것을 막지 않는다.

실패 경로

| 상황 | 동작 |
| --- | --- |
| 번역 키 하나가 빠짐 | 그 문구만 `en`, 그다음 `ko`로 대체한다. 화면은 깨지지 않는다. |
| 번역 파일 로드 실패 | 번들의 `ko` 기본값으로 떨어진다. |

### 4.2 콘텐츠 언어

**일과가 자기 언어를 들고 있다.**

- 보호자가 일과를 만들 때 **보호자 휴대폰의 화면 언어**가 그 일과의 콘텐츠 언어가 되어 `Routine`에 저장된다. 보호자가 고를 수 없다.
- AI는 그 언어로 단계 글을 쓴다. 보호자가 다른 언어로 입력해도 출력은 일과 언어에 맞춘다.
- 이룸이 휴대폰은 버튼과 메뉴는 **자기 OS 언어**로, 카드 글과 음성은 **일과 언어**로 보여준다.
- 기존 일과는 모두 `ko`로 간주하고 마이그레이션에서 기본값을 채운다.

음성(TTS)

- 일과 언어로 읽는다. 기기 음성이 그 언어를 지원하지 않으면 서버 음성으로 대체한다.
- 서버 음성도 안 되면 글만 보여준다. 화면은 깨지지 않는다.

이 앱만의 위험

| 지점 | 문제 | 방향 |
| --- | --- | --- |
| 호칭 치환 | `이룸이` 같은 자리표시를 한국어 조사로 복원하는 방식은 다른 언어에서 성립하지 않는다 | 언어별로 따로 설계한다 (AI 하위 프로젝트) |
| 이미지 프롬프트 | 한국어를 영어 한 줄로 바꾸는 단계가 있다 | 일과 언어를 입력으로 넘겨 어떤 언어든 영어로 맞춘다 |
| 픽토그램 | 라벨이 영어다 | 언어와 무관해서 그대로 쓴다 |

> 확장 여지: 보호자가 일과마다 콘텐츠 언어를 고르게 하는 것은 이번 범위에서 제외한다. 일과에 언어 필드가 이미 있으므로 나중에 열기만 하면 된다.

### 4.3 서버와 데이터

**원칙:** 화면 문구의 원본은 클라이언트 번역 파일이다. 서버가 만드는 문장은 서버 쪽 언어별 데이터다. 서버는 `Accept-Language`로 언어를 안다.

| 대상 | 방식 |
| --- | --- |
| 에러 응답(104개) | 서버는 에러 코드를 계속 내려보내고 클라이언트가 코드를 번역한다. 서버 문장은 대체용으로 남긴다. |
| 서버 생성 문장(AI 폴백 질문, 추천 목록) | 서버 리소스 파일에 언어별로 둔다. 코드와 함께 배포된다. |
| 공지(`app_notice`) | 공지 하나에 언어별 번역 행을 단다(제목, 본문, 버튼 문구) |
| AI 프롬프트(`prompt_template`) | 키에 언어를 더한다. 기존 행은 모두 `ko`로 간주한다. |
| 약관(`consent_document`) | 4.4 참고 |
| 시스템 설정 문구, 관리자 화면, 로그 | 번역하지 않는다 |

**대체 순서:** 요청 언어 → `en` → `ko`. 어디서든 같다.

**사용자 정보:** `Member`, `Profile`에는 언어를 저장하지 않는다. 화면 언어는 기기가, 콘텐츠 언어는 일과가 갖는다.

**기존 앱과의 호환**

- 이미 배포된 앱은 `Accept-Language`를 보내지 않고 서버의 한국어 에러 문장을 그대로 띄운다.
- 헤더가 없으면 항상 `ko`로 응답하고 기존 응답 형식을 바꾸지 않는다. 새 앱보다 서버를 먼저 배포해도 안전하다.
- 새 앱이 모르는 에러 코드를 받으면 서버 문장을 보여주고, 그것도 없으면 "문제가 발생했어요" + 에러 코드를 보여준다.

**실패 경로**

| 상황 | 동작 |
| --- | --- |
| 요청 언어의 번역 행이 없음 | 대체 순서를 따른다. 하나도 없으면 `ko`(번들·시드 기본값)다. |
| `Accept-Language`가 5개 밖이거나 깨진 값 | `en`으로 응답한다. |
| 어떤 언어의 AI 폴백 질문 파일이 비어 있음 | 시작 시 검증해서 서버가 뜨지 않게 한다. AI가 실패하는 순간에 문구도 없는 일을 막는다. |

### 4.4 약관과 동의 기록

- 약관 키 구조를 **(약관 키, 언어)** 한 쌍으로 바꾼다. 수정 이력(`ConsentDocumentHistory`)에도 언어를 기록한다.
- 동의할 때 약관 버전과 **동의한 언어**를 함께 저장한다. 어떤 사용자가 어떤 언어의 어떤 버전에 동의했는지 증명할 수 있다. 이 기록은 서비스 원칙 5(원문 저장 금지)와 무관하다.
- **오프라인 대비:** 앱 번들 기본값은 `ko`와 `en` 두 벌만 둔다. 다른 언어는 서버에서 받은 캐시가 없으면 "약관을 불러오지 못했어요" + 재시도 버튼을 보여준다. 읽을 수 없는 언어의 약관으로 동의받지 않고, 빈 화면이나 무한 로딩도 만들지 않는다.
- **외부 게시 페이지:** 개인정보방침과 삭제 페이지의 언어별 게시본이 필요하다. 서버 약관과 게시본의 일치를 검사하는 워크플로(`PROJECT-ELUM-PUBLIC-PAGES-CHECK`)를 언어별로 확장한다.
- **언어와 법역은 다르다.** 스페인어는 스페인과 멕시코가, 영어는 미국과 영국이 법이 다르다. 이번 설계는 약관 단위를 언어로만 둔다. 법무 검토에서 지역 축이 필요하다고 나오면 키 구조를 확장한다. 지금 미리 만들지 않는다.

### 4.5 관리자 화면

| 화면 | 영향 | 내용 |
| --- | --- | --- |
| 공지(`notice-edit`, `notices`) | 바뀜 | 언어별 제목, 본문, 버튼 문구 입력. 목록에 언어별 채움 상태(✓/−)를 보여준다. |
| 약관(`consent-edit`, `consents`, `consent-history`) | 바뀜 | 약관 키와 언어마다 본문과 버전 이력이 따로 있다. |
| 프롬프트(`prompts`, `prompt-history`) | 바뀜 | 키와 언어 조합으로 편집한다. 기존 한국어 프롬프트는 `ko` 행이 된다. |
| 일과 상세(`routines`, `routine-detail`) | 조금 | 일과 언어를 표시한다. |
| 회원, 크레딧, 모니터링, 로그, 설정 | 안 바뀜 | 운영자용 한국어 그대로 |

규칙

- **공지:** `ko`는 필수, 나머지 4개 언어는 선택이다. 빠진 언어는 대체 순서(`en` → `ko`)로 보여준다.
- **약관:** 언어마다 **법무 확인을 거쳐 게시한 약관이 있어야** 그 언어를 가입 가능한 언어로 연다. 약관이 없는 언어에서는 `en`으로 대체하지 않는다. 동의는 읽을 수 있는 언어로 받아야 성립한다.
- **프롬프트:** 그 언어의 행이 없거나 검증되지 않았으면 관리자가 그 언어를 "일과를 만들 수 있는 언어" 목록에 **켤 수 없다**(5장). 목록 밖 언어의 휴대폰에서 만든 일과는 `en`으로 처리하므로, 검증되지 않은 언어로 AI가 글을 쓰는 일은 생기지 않는다.

주의할 점

- `notice-preview.js`는 클라이언트 `keepWords`와 같은 줄바꿈 규칙을 쓴다고 주석에 적혀 있다. 클라이언트의 일본어·중국어 줄바꿈 규칙이 바뀌면 관리자 미리보기도 같이 바꾼다.
- 관리자 폰트는 한글·라틴 위주의 subset이다. 일본어·중국어 본문은 미리보기에서 시스템 폰트로 보인다. 미리보기가 글자 모양까지 같지 않다는 점을 운영자가 알아야 한다.

## 5. 단계적 출시

**순서:** 구조(`ko`만, 사용자에게 변화 없음) → `en` → `es` → `ja` → `zh`. 법무 검토는 처음부터 병렬로 진행한다.

| 단계 | 내용 | 이유 |
| --- | --- | --- |
| 0. 구조 | 번역 기반, 서버 언어 처리, 일과 언어 필드. 동작은 지금과 같다. | 사용자 영향이 없고, `ko` 불변을 테스트로 증명할 수 있다. |
| 1. `en` | 첫 번째 추가 언어 | 레이아웃·폰트 부담이 가장 작다. 구조가 맞는지 검증한다. |
| 2. `es` | 번역 파일과 프롬프트 행 추가 | 글이 길어지는 언어라 넘침 검사를 시험한다. |
| 3. `ja` | 폰트와 줄바꿈 규칙 추가 | 띄어쓰기가 없고 글리프가 필요하다. |
| 4. `zh`(간체) | 일본어와 같은 종류의 작업 | `ja`에서 만든 것을 재사용한다. |

**언어를 여는 조건** (모두 충족해야 한다)

1. 클라이언트 번역 파일이 모든 키를 채웠다.
2. 그 언어의 약관이 법무 확인을 거쳐 게시됐다.
3. 그 언어의 AI 프롬프트 행이 검증됐다.

서버는 "일과를 만들 수 있는 언어" 목록을 시스템 설정으로 가진다. 앱에 번역이 들어 있어도 이 목록에 없는 언어면 일과 생성은 `en`으로 처리한다. 새 언어를 열 때 앱 업데이트 없이 관리자 화면에서 켠다.

## 6. 검증

| 대상 | 방법 |
| --- | --- |
| `ko` 동작 불변 | 기존 앱 테스트와 골든·시안 대조가 그대로 통과해야 한다. 구조 단계의 통과 조건이다. |
| 번역 누락 | CI가 언어 간 키 일치와 자리표시(`{name}` 등) 일치를 검사한다. |
| 글 넘침 | `ko`는 시안과 픽셀로 맞춘다. 다른 언어는 "넘치거나 잘리지 않는다"만 위젯 테스트로 확인한다. |
| 서버 폴백 | 폴백 문구 파일이 비면 서버가 뜨지 않는 기동 검사를 둔다. |
| AI 품질 | 언어마다 **가장 싼 모델로 최소 횟수만** 호출해서 확인한다. 검증을 이유로 생성 API를 반복 호출하지 않는다. |

시안 대조 하네스(`figma_conformance`)는 `ko`에만 적용한다. 5개 언어의 픽셀 시안은 만들지 않는다.

## 7. 하위 프로젝트

각각 별도 이슈, 스펙, 구현 계획을 가진다. 이 문서가 상위 아키텍처다.

| # | 하위 프로젝트 | 핵심 내용 |
| --- | --- | --- |
| 1 | 클라 i18n 기반 | `intl`·ARB 도입, 문구 추출(`ko` 불변), 조사·단위·날짜를 ICU로, 폰트 fallback, 언어별 줄바꿈, 개발자 도구 언어 스위치, `Accept-Language` 전송 |
| 2 | 서버 언어 기반 | `Accept-Language` 처리, 에러 응답 호환 유지, 서버 생성 문장의 언어별 리소스, 일과 언어 필드와 마이그레이션 |
| 3 | AI 다국어 | `prompt_template` 언어 차원, 출력 언어 지정, 호칭 치환 재설계, 이미지 프롬프트, 음성 언어 |
| 4 | 약관과 공지 | 키 구조 변경, 동의 언어 기록, 공지 번역 행, 관리자 편집 화면, 게시 페이지 검사 확장 |
| 5 | 번역과 품질 | 용어집, 번역 작업, 번역 누락 CI, 넘침 검사, 시안 대조 범위 조정 |
| 6 | 네이티브와 스토어 | iOS 권한 문구·앱 이름, Android 앱 이름·앱별 언어 등록, fastlane 로케일, 스토어 문구 |
| 7 | 법무 검토 | 국외 이전 동의, 연령 동의 기준, GDPR·APPI. 코드 작업이 아니다. 1~6과 병렬이며 출시 차단 항목이다. |

권장 순서: 7을 먼저 시작하고, 1 → 2 → (3, 4 병렬) → 5·6 → 언어별 출시.

## 8. 열린 질문

설계 확정 전에 정해야 하거나, 하위 프로젝트에서 정할 것.

## 9. 위험

| 위험 | 대응 |
| --- | --- |
| 번역 추출 중 한국어 문구가 달라짐 | `ko` 불변을 기존 테스트와 골든으로 증명하는 것을 0단계 통과 조건으로 둔다 |
| 문구 어조 붕괴(해요체, `이룸이`, 용어표) | 언어별 용어집과 어조 가이드를 먼저 만들고 번역 검수에 쓴다 |
| 폴백 문구 누락 | 서버 기동 검사로 막는다 |
| 읽지 못하는 언어의 약관으로 동의받음 | 약관이 게시된 언어만 가입 가능한 언어로 연다 |
| 오래된 문서가 현재 사실과 다름 | `docs/05-ai-dlp-gateway.md`가 "로컬 LLM이라 외부 전송 없음"으로 적혀 있으나 DLP는 #377에서 폐기됐다. 법무 검토 전에 문서를 현재 사실에 맞춘다. |
| 한 언어에서 구조 결함이 발견되면 전 언어가 흔들림 | 단계적 출시로 `ko`와 `en`에서 먼저 발견한다 |

## 10. 참고한 합의

- 언어 5개: ko, en, ja, zh(간체), es (2026-10-02)
- 앱 안 언어 선택은 만들지 않는다 (2026-10-02)
- 콘텐츠 언어는 보호자 휴대폰 화면 언어로 고정하고 일과마다 고르지 않는다 (2026-10-02)
- 관리자 규칙: 공지는 `ko` 필수, 약관은 언어별 게시가 있어야 그 언어를 연다 (2026-10-02)
- 시안 대조는 `ko`만 픽셀로 맞춘다 (제안 후 별도 반대 없음)
