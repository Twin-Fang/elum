## 문제

1. 카드확인 하단이 알약 칩 하나(`이 카드 수정하기`)뿐이다. 순서 변경·카드 추가 진입점이 없다.
2. 카드 수정 시트는 시안 없이 만든 것이다(#77). 이제 시안이 있다.
3. 서버에는 카드 추가(`POST /steps`)와 순서 변경(`PATCH /steps/order`)이 있으나
   카드확인 화면에서 쓰지 않는다. 앱에는 `addStep`이 없다.
4. 머리·보상 줄·저장 버튼·상단 `임시저장`이 시안과 다르다.

## 상태와 저장 (핵심)

**서버 순서 API 는 전체 카드를 요구한다** — `steps.size() != stepIds.size()` 면 400
(`RoutineService.reorderSteps`). 그런데 카드 X 로 뺀 카드는 `저장하기` 때까지 서버에 남는다(#405).
순서를 바로 보내면 늘 실패한다.

→ **순서는 로컬에만 두고 `저장하기`에서 함께 보낸다.** 뺀 카드 규칙과 같다.

```
save(): 1) 뺀 카드 deleteStep  2) reorderSteps(화면에 남은 카드 id 순서)  3) 임시저장이면 confirm
```

- 2단계는 **순서가 바뀐 경우에만** 보낸다(원래 순서와 같으면 호출하지 않는다).
- 어느 단계든 실패하면 다음으로 가지 않고 화면에 남는다(`showFailure`, 서버가 준 코드가 있으면 그것, 없으면 E-CONFIRM). 성공한 삭제는 기억에서 지워 다시 누를 때 남은 것만 보낸다(기존 동작). 실패한 순서는 `_orderDirty` 가 남아 다시 누르면 다시 보낸다.
- `이미 저장한 일과`(PENDING_REVIEW 아님)는 3단계를 건너뛴다(기존 동작). 1·2단계는 그대로 한다.
- 나가기 팝업의 `뺀 카드는 저장하기를 눌러야 빠져요` 문구에 순서도 포함할지는 구현 때 문구만 조정한다(법적 문구 아님).

**카드 추가는 즉시 서버로 간다.** 새 카드는 서버가 준 id 가 있어야 순서·수정이 가능하다.
성공하면 응답 일과의 단계 목록에서 새 카드를 뽑아 **로컬 목록 맨 뒤**에 붙이고 그 카드로 넘어간다.
나가기 없이 앱을 끄면 추가한 카드는 임시저장 일과에 남는다(서버 상태이므로).

## 실패·엣지 (설계에 함께 적는다)

| 상황 | 동작 |
|---|---|
| 카드 추가 서버 실패 | 시트를 닫지 않고 `showFailure`(제목 `카드를 추가하지 못했어요`, 서버 코드가 없으면 `E-STEP-ADD`). 입력은 남긴다. 시트가 `onSubmit` 결과(true/false)로 닫을지 정한다 |
| 순서 저장 실패 | 승인하지 않고 화면에 남는다. 서버 코드가 있으면 그것이, 없으면 E-CONFIRM 이 뜬다 (별도 코드를 만들지 않았다 — 저장하기 실패 하나로 다룬다) |
| 그림 없는 카드 | `CardImage` 가 그림을 못 받으면 캐릭터 일러스트로 대신한다(기존 동작). 새 카드도 같은 자리에 캐릭터가 선다 — 확인함 |
| 추가 응답에 새 카드가 없음 | 목록에 붙이지 않고 실패로 본다(파싱 방어, `!` 금지) |
| 카드가 1장 | 순서 변경 버튼은 켜 두되 옮길 것이 없다. 진입은 막지 않는다 |
| 순서 모드 중 저장·홈·임시저장 | 모드에서는 이 버튼들이 없다. 시스템 뒤로만 모드를 닫는다 |
| 수정 시트 저장 실패 | 기존 `E-STEP` 그대로 |
