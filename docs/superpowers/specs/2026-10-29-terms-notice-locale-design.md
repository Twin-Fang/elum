## 3. 약관

### 3.1 저장

- `consent_document.locale VARCHAR(8) NOT NULL DEFAULT 'ko'`, 유니크 `(consent_key)` → `(consent_key, locale)`.
- `consent_document_history.locale` 같은 규칙, 이력 조회는 (키, 언어)로.
- 시드(`ConsentDocumentInitializer`)는 `ko` 만 만든다. 다른 언어 본문 파일이 들어와도 배포 한 번에 자동 게시되지 않게 한다.

### 3.2 조회와 대체 (fallback)

`GET /api/consents/documents` 는 `Accept-Language` 로 고른 언어(`CurrentLocale`)의 **게시본**을 준다.

- 게시본 = 그 언어에 **필수 4종**(이용약관·개인정보·국외 이전·나이 확인)이 모두 있는 상태. 일부만 있으면 필수가 빠진 동의 화면이 뜨므로 게시로 보지 않는다.
- 요청 언어 게시본이 없으면 **`ko` 로 대체**한다. 영어로는 대체하지 않는다(#521·#531: 법무 확인 안 된 번역으로 동의받지 않음. `ko` 는 원본이다).
- 응답 본문에 `locale`(실제로 준 언어)과 `isFallbackLocale`(요청 언어가 아니라 대체했는지)을 더하고 `Content-Language` 헤더를 붙인다. 기존 필드는 그대로라 옛 앱은 모른 채 읽는다.

**검토한 안**

| 안 | 판단 |
|---|---|
| A. 요청 언어가 없으면 빈 목록·400 으로 가입을 막는다 (원 계획) | 안 고름. 지금 영어 휴대폰 사용자는 한국어 약관으로 가입하고 있다. 이걸 막으면 운영 중인 가입이 끊기는 **새 제품 결정**이 되고, 언어별 출시 게이트(#528)가 정할 일이다 |
| B. `ko` 로 대체하고 대체 사실을 응답에 표시 | **고름**. 지금 동작과 같고, 앱·게이트가 이 표시로 나중에 막을 수 있다 |
| C. `en` → `ko` 순 대체 (서버 공통 대체 순서) | 안 고름. 약관은 번역본이 법무 확인을 거쳐야 하므로 공통 순서를 따르지 않는다 |

### 3.3 동의 기록

- `member.consent_locale VARCHAR(8)` NULL 허용. 이미 동의한 회원은 그때 한국어 약관밖에 없었으므로 `consented_at IS NOT NULL` 인 행을 `ko` 로 채운다.
- `POST /api/member/consents` 에 선택 필드 `consentLocale` 을 더한다. 없으면 요청 헤더 언어를 쓴다.
- 기록하는 값은 **그 요청 언어로 서버가 실제로 내주는 게시본의 언어**다(3.2 와 같은 판정). 지금은 언제나 `ko`. 앱이 `en` 을 보내도 `en` 게시본이 없으면 `ko` 로 남는다 — 사용자가 본 것은 한국어 약관이기 때문이다.
- 모르는 코드(`fr`, 빈 값)는 없는 것으로 보고 헤더를 따른다. 기록이 목적이라 가입을 막지 않는다.
- 탈퇴 계정을 되살릴 때(`clearConsents`) 언어도 비운다.
- 응답 `MemberConsentResponse` 에 `consentLocale` 을 더한다.

## 4. 공지 대상 국가

- `app_notice.target_countries VARCHAR(255)` NULL 허용. 쉼표 구분 ISO 3166-1 alpha-2 대문자(`KR,JP`). 비면 전체.
- 판정 규칙 한 곳: `notice/core/NoticeTargetCountries` (다듬기 + 포함 판정).
  - 입력: 공백·쉼표로 나눔, 빈 조각 무시, **두 글자 대문자만** 받음(소문자·세 글자는 거절 — 몰래 고치면 화면 값과 저장 값이 달라진다), 중복 제거, 255자 안. 걸리면 `NOTICE_TARGET_COUNTRIES_INVALID` 로 아무것도 저장하지 않는다.
  - 노출: 대상이 비면 모두에게. 대상이 있으면 요청 국가가 그 안에 있을 때만. **국가 미상(`null`)에게는 대상 지정 공지를 보이지 않는다.**
- 노출 순서: 게시 중 → 언어 → 플랫폼 → **국가** → 최대 5장. 다른 나라 공지가 5장 자리를 차지하지 않게 자르기 전에 거른다.
- 같은 판정을 쓰는 곳 3곳: 홈 팝업(`NoticeService.publishedFor`), 공지 탭(`NoticeHistoryService.history`), 안 읽음 표시(`hasUnseenNotice`). 국가는 서비스가 요청 컨텍스트를 읽지 않고 컨트롤러·호출부가 `CurrentRegion.get()` 으로 넘긴다(비동기·시험에서 값이 흐르지 않게, 언어 인자와 같은 방식).
- 공지 응답 `Vary` 에 `X-Elum-Region` 을 더한다(60초 캐시가 한국 응답을 일본 요청에 주지 않게).
- 응답 본문에 대상 국가를 내보내지 않는다(앱은 몰라도 된다, 응답 모양 불변).
- 관리자: 편집 화면에 "대상 국가" 칸, 목록에 대상 국가 표시.

## 5. 호환성과 되돌리기

| 상황 | 결과 |
|---|---|
| 헤더 없는 옛 앱의 약관 조회 | `ko` (헤더 없음 = `ko`). 기존 필드 값 동일, 새 필드 2개만 더해짐 |
| 옛 앱의 동의 | `consentLocale` 없음 → 헤더 → `ko` 기록 |
| 옛 앱의 공지 | 헤더 없음 = `KR`. 대상이 빈 기존 공지는 전과 같이 나옴 |
| 옛 서버 이미지로 되돌림 | 새 열은 모두 DEFAULT 또는 NULL 허용이라 옛 서버가 모른 채 읽고 쓴다. 단 ① `ko` 가 아닌 약관 행이 생긴 뒤면 옛 `findByConsentKey` 가 여러 행을 만나 터지므로 되돌리기 전에 `delete from consent_document where locale <> 'ko'` ② 대상 국가가 지정된 공지는 옛 서버가 모두에게 보이므로 먼저 끈다. 지금은 둘 다 0건 |
| Flyway | V58 은 더하고 푸는 것만 한다(지우는 열·표 없음). 옛 유니크 이름은 V21 이 `uk_consent_document_key` 로 지었지만 로컬(ddl-auto) 환경을 위해 이름 대신 모양(`consent_key` 한 칸 유니크)으로 찾아 지운다 (V36 과 같은 방식) |

## 6. 실패 경로

| 상황 | 처리 |
|---|---|
| 요청 언어 약관 없음 | `ko` 대체, `isFallbackLocale=true`, 오류 아님 |
| `ko` 필수 약관도 일부 없음(시드 실패) | 지금처럼 있는 문서만 준다(앱은 형식 검사 후 번들 기본값으로 떨어짐). `isFallbackLocale` 은 요청 언어 ≠ 준 언어일 때만 true |
| 동의 요청의 `consentLocale` 이 모르는 값 | 헤더 언어로 판정, 가입 진행 |
| 관리자가 대상 국가를 `kr`, `KOR`, `K1` 로 입력 | 400 + 입력값 그대로 다시 그림 + 오류 코드 표시, 저장 안 함 |
| 지역 헤더가 깨짐 | 국가 미상 → 대상 없는 공지만 |

## 7. 시험 (결함 하나씩)

| 시험 | 깨지면 생기는 문제 |
|---|---|
| 헤더 없는 약관 조회 → `ko`, 대체 아님 | 옛 앱이 다른 응답을 받는다 |
| `en` 게시본 없음 → `ko` 대체 + `isFallbackLocale` | 영어 사용자에게 빈 약관 또는 표시 없이 한국어 |
| `en` 필수 4종 중 일부만 있음 → `ko` 대체 | 필수 항목이 빠진 동의 화면 |
| 동의 시 기록 언어 = 실제 준 언어(`en` 요청이라도 `ko`) | 본 적 없는 언어로 동의했다는 기록 |
| 동의 요청에 언어 없음·모르는 값 → 헤더 → `ko` | 옛 앱 가입 실패 |
| 국가 미상에게 대상 지정 공지가 안 샘 | 다른 나라 공지 노출 |
| 다른 나라 공지가 5장 자리를 차지하지 않음 | 보여야 할 공지가 빠짐 |
| 대상 국가 형식 검사(소문자·세 글자 거절, 중복 제거) | 저장 값과 화면 값 불일치 |
| `Vary` 에 `X-Elum-Region` | 캐시가 국가를 섞음 |
| V58 계약(기본값 `ko`, 유니크 교체, 지우는 것 없음) | 운영 기동 실패·되돌리기 불가 |

## 8. 하지 않는 것

- 약관·개인정보처리방침·동의 문구(법적 문구) 수정, 다른 언어 본문 추가
- 그 언어 약관이 없을 때 가입 차단(언어별 출시 게이트 #528 에서 결정)
- 앱 코드 변경, 외부 게시 페이지 검사 확장
- 원 계획의 `app_notice_translation` 번역 표 (#673 의 공지당 언어 하나 모델을 유지)
