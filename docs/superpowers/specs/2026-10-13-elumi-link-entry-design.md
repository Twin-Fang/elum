# 이룸이 휴대폰 입구 — 로그인 없이 연결 암호 넣기

## 문제

이룸이 휴대폰은 소셜 로그인 → 약관 → 역할 선택 `이룸이`를 거쳐야 연결 암호 화면에 닿는다.
온보딩을 마친 계정으로 로그인하면 역할 선택을 건너뛰어 부모·교사 계정으로는 이룸이 휴대폰을
만들 수 없다. 연결이 끊긴 이룸이 휴대폰은 뒤로가기가 로그인 화면으로 간다.

## 결정

로그인 화면 하단(소셜 버튼 아래 여백)에 밑줄 링크 `이룸이 휴대폰이에요 · 연결 암호 넣기`를 둔다.
온보딩 이름 화면의 `초대 코드가 있어요`와 같은 부품(`AppPressable` + `linkLater` 밑줄)이다.
누르면 `push(/link/enter)` 로 로그인 없이 연결 암호 화면을 연다.

## 행복 경로

1. 로그인 화면에서 링크를 누른다 → 연결 암호 화면 (스택 `[로그인, 연결]`).
2. 여섯 자를 넣고 시작하기 → `redeem` 이 토큰과 `isElumiDevice=true` 를 저장한다.
3. `go(/child)`. 가드는 표식이 있으면 역할·온보딩 검사를 건너뛰므로 이룸이 홈이 열린다.
4. 이후 앱을 켜면 `resolveDestination` 이 `/child`.

## 실패 경로

| 상황 | 동작 |
|---|---|
| 암호 틀림·만료·시도 초과·오프라인·기타 | 기존 연결 암호 화면 그대로 (흔들림 + 에러 코드 `E-LINK` 등) |
| 가드 | `/link/enter` 는 세션이 필요한 경로가 아니라 세션 없이 열린다 (변경 없음) |
| 로그인 진행 중 | 링크는 눌리지 않는다 (소셜 로그인과 겹치지 않는다) |
| 연결 화면 뒤로가기 | push 로 열었으므로 로그인 화면으로 돌아온다 (입구가 거기 있다) |
| 연결이 끊긴 이룸이 휴대폰 | 표식(`isElumiDevice`)은 남고 `연결이 끊어졌어요` 안내가 선다. 뒤로가기는 로그인으로 가지만 입구 링크로 돌아올 수 있다. 앱을 다시 켜면 `resolveDestination` 이 연결 화면으로 보낸다 |
| 이룸이 표식이 있는 채 소셜 로그인 성공 | 기존 규칙대로 표식을 내리고 보호자로 전환 (변경 없음) |

## 약관

연결 암호는 로그인한 보호자가 만든다. 약관은 그 보호자 계정이 받았다. 기존 `역할 선택 이룸이`
경로도 약관은 같은 계정에서 받은 뒤이므로 이룸이 휴대폰에서는 약관을 받지 않는다. 같은 구조다.
