# 이룸 서버를 내 NAS 로 이사 — 2단계: 무감지 전환

관련 이슈: #1052(배포 장애) · #831(앱 주소 원격 전환) · #936(1단계 미러) · 1단계 설계 `2026-10-21-server-move-to-my-nas-design.md`

## 왜

- 2026-11-04 운영 API 가 2시간 넘게 502 였다. 친구 NAS 의 nginx 가 없는 blue 를 가리켰는데, 그 서버는 SSH 로 들어갈 수 없어 원인을 끝까지 볼 수 없었다 (#1052).
- 운영을 내 NAS(SUH-PROJECT)로 옮긴다. 다음 릴리스부터 앱은 `api.elum.suhsaechan.kr` 를 쓰게 된다.
- **일반 사용자는 이사를 눈치채지 못해야 한다.** 데이터는 한 건도 다르면 안 된다.

## 목표 · 하지 않는 것 · 실패로 보는 것

**목표**

1. DB 와 파일(그림·음성)이 친구 서버와 **완전히 같은 상태**에서 넘어간다.
2. 사용자 입장에서 보이는 것은 앱 업데이트 한 번, 새벽 몇 분의 점검 화면, 앱이 한 번 다시 뜨는 것뿐이다. 로그아웃·데이터 유실·알림 중복은 없다.
3. 내 NAS 표준(Traefik blue/green)에 맞춰 배포한다. 친구 서버 방식을 그대로 옮기지 않는다.
4. 전환 전까지 친구 서버도 안정적으로 돈다 (#1052 결함 수정).

**하지 않는 것**

- MinIO 전환 (전환이 끝난 뒤 별도)
- 실시간 DB 복제 (친구 PostgreSQL 설정 변경이 필요)
- 친구 서버 즉시 종료 (구버전 앱 안내용으로 남긴다)
- 운영 서버에 쓰기가 일어나는 시험. 운영에는 **읽기만** 한다. 쓰기 시험은 내 NAS 에서만 한다

**실패로 보는 것 (기능이 돌아도 실패)**

- 전환 뒤 한 명이라도 로그아웃되거나 데이터가 사라진다
- 두 서버가 동시에 쓰기를 받아 DB 가 갈라진다
- 같은 예약 알림이 두 서버에서 두 번 간다
- 전환 전 준비 작업이 운영 사용자에게 보인다 (점검 화면·오류·속도 저하)

## 확인한 사실 (2026-11-04)

| 항목 | 친구 서버(운영) | 내 NAS |
|---|---|---|
| DB | PostgreSQL 17.10, 14MB, Flyway V59 | 미러 `elum-postgres`(17), 10/21 사본 Flyway V52 |
| 건수 예 | 가입자 45 · 일과 135 · 단계 651 | 39 · 82 · 379 |
| 서버 이미지 | `chuseok22/elum-back:main` (친구 Docker Hub, 운영 설정을 이미지 안에 넣어 빌드) | 같은 이미지 10/21 빌드 |
| 파일 | `/volume1/project/elum/server` → `/app` | 음성만 다시 만든 111MB, **그림 없음** |
| 프록시 | DSM nginx → 8085/8086 직결, 배포가 DSM 생성 파일을 덮어씀 | DSM → 8085 직결(미러). 다른 서비스는 전부 DSM → Traefik(8079) |
| 기타 | — | Traefik v3.0(`traefik-network`, docker 라벨), MinIO 가동 중, 메모리 여유 약 3.5GB, 미러 서버 약 540MB |

코드에서 확인한 것.

- 앱은 `/api/app/status` 로 **점검 > 업데이트 필요** 순서로 화면을 막는다. 상태 조회가 실패하면 막지 않는다 (`app_status_gate.dart`).
- 점검 중 서버가 열어 두는 곳 3개: 앱 상태, 약관 읽기, **토큰 갱신** (`MaintenanceModeFilter`).
- 토큰 갱신은 리프레시 토큰을 회전한다. 앱은 갱신이 401 이면 로그아웃하고, 503·네트워크 오류면 토큰을 유지한다 (`auth_repository.dart`).
- 앱 주소는 `AppConfig.apiBaseUrl` = 개발자 도구 지정 주소 > `.env` 기본 주소. Dio 는 시작 때 이 값으로 만든다. 개발자 도구는 주소를 바꾼 뒤 앱을 안에서 다시 띄운다 (`dev_tools_server.dart`).
- 앱에 옛 도메인이 박힌 곳: `.env` 기본 주소, `AppConfig.productionApiBaseUrl`(운영 서버 판단 `isProductionApiServer` 가 이 값과 비교), iOS `applinks:api.elum.chuseok22.com`, Android 앱 링크 호스트 (`/s/` 공유 링크).
- 앱의 공유·초대 링크 주소와 라우터가 받는 링크 호스트는 `AppConfig.apiBaseUrl` 에서 나온다 (`app_router.dart`, `invite_link_host.dart`, `talk_detail_actions.dart`, `talk_link_share_screen.dart`). 주소가 바뀌면 옛 도메인 링크를 라우터가 못 받는다.
- 서버에 옛 도메인이 박힌 곳: 이야기 공유 링크 기준 주소, 신고 메일 관리자 링크, 장애 알림 관리자 링크(`ELUM_INCIDENT_ALERT_ADMIN_BASE_URL`), OpenAPI 서버 주소 (`application.yml` 환경변수로 바꿀 수 있음).
- 서버는 Redis 를 쓰지 않는다. 공유 상태(로그인 시도 횟수 등)는 메모리(`InMemorySharedStateStore`)라 옮길 것이 없다. 미러의 `elum-redis` 는 쓰이지 않는다.
- 시스템 설정은 DB(`system_config`)에 있고 서버가 30초 캐시한다 (`SystemConfigService`). DB 를 복사하면 설정도 같이 넘어간다.
- 광고 보상 콜백 `/api/ads/ssv` 는 `/api/**` 아래라 점검 중 503 이다.
- 예약 작업 밖에서 도는 배경 작업: 음성 만들기 대기열(`RoutineStepSpeechQueue`), 알림·신고 메일 비동기 리스너.
- 서버가 디스크에 쓰는 파일 4종: 카드 그림(`RoutineProperties`), 이야기 그림(`data/talk-images`), 공지 그림(`NoticeProperties`), 음성(`data/routine-speech`).
- 관리자 화면은 세션 로그인(CSRF), 기존 로그 다운로드 API 가 경로 보호·감사 기록 구조를 이미 갖고 있다 (`AdminLogApiController`).

## [A] 친구 서버 배포 안정화 (#1052)

`PROJECT-SPRING-CICD.yaml` 을 고친다. 전환 날까지 친구 서버가 계속 운영이고, 이 워크플로로 [B][C] 서버 코드가 나가기 때문이다.

1. **동시 실행 금지**: `concurrency` 그룹 하나, 진행 중 실행은 취소하지 않고 다음 실행이 기다린다.
2. **활성 색 판단을 실제 컨테이너와 교차 확인**: nginx 설정의 포트(conf 색)와 실행 중 컨테이너를 같이 본다.

   | conf 색 컨테이너 | 반대 색 컨테이너 | 판단 | 새로 띄울 색 |
   |---|---|---|---|
   | 실행 중 | 무관 | 정상 | 반대 색 |
   | 없음 | 실행 중 | **어긋남** (오늘 장애) | conf 색 (nginx 가 이미 가리키는 쪽을 살린다, 실행 중인 반대 색은 새 색이 통과할 때까지 건드리지 않음) |
   | 없음 | 없음 | 둘 다 없음 | conf 색 |
   | 포트를 못 찾음 / 8085·8086 이 아님 | — | 중단 (기존 동작) | — |

   어긋남을 찾으면 로그에 남기고 배포 결과 알림에 표시한다.
3. **전환 검증 실패 시 되돌림**: nginx 전환 뒤 도메인 검증이 실패하면 경고로 넘기지 않는다. nginx 백업 복원 > reload > 새 컨테이너 제거 > 옛 컨테이너 유지 > 실패로 끝낸다. 검증은 NAS 안에서 `--resolve 도메인:443:127.0.0.1` 로 nginx 경로를 직접 확인한다 (공인 IP 되돌아오기(hairpin)에 의존하지 않음).
4. **옛 컨테이너 정리는 검증 통과 뒤에만**.
5. **배포 결과에 `현재 nginx 포트` · `실행 중 컨테이너`를 한 줄로 남긴다** (다음 장애 때 배포 로그만으로 상태를 안다).

**외부 감시** (새 워크플로): 10분마다 `https://api.elum.chuseok22.com/healthz` 와 `https://api.elum.suhsaechan.kr/healthz` 를 확인한다. 실패하면 60초 뒤 한 번 더 보고, 그래도 실패하면 장애 알림 Discord 웹훅으로 보낸다. 실행 사이에 상태를 저장하지 않으므로 장애가 이어지는 동안 10분마다 알림이 가고, 회복 알림은 없다 (구현 단순화, 내 판단). GitHub 예약 실행은 몇 분씩 늦을 수 있어 감지 지연 10~20분을 받아들인다.

## [B] 서버: 파일 내보내기 API · 이전 잠금

운영 릴리스에 함께 나간다. 둘 다 시스템 설정으로 켜고 끄며 **기본값은 꺼짐**이다.

### B-1. 파일 내보내기 API (임시, 전환 끝나면 제거)

친구 NAS 에 SSH 가 없어 그림을 받을 길이 없다. 관리자 전용 API 로 받는다.

- 설정 `MIGRATION_FILE_EXPORT_ENABLED` (그룹: 앱 제어 또는 운영, 기본 false). 꺼져 있으면 두 API 모두 404.
- `GET /admin/migration/api/files?area={area}` → 파일 목록: 상대 경로, 크기, SHA-256, 수정 시각, 합계(개수·바이트)
- `GET /admin/migration/api/files/download?area={area}&path={상대경로}` → 파일 그대로
- `area` 4개만 허용: `routine-images`, `talk-images`, `notice-images`, `routine-speech`. 각 area 의 기준 폴더는 해당 저장소 설정값에서 읽는다 (하드코딩 금지).
- 경로 보호: 정규화 후 기준 폴더 안인지 확인, 일반 파일만, 심볼릭 링크 거부.
- 감사 기록: 목록 조회마다 1건 (`MIGRATION_FILES_LISTED`, area·개수). 파일별 다운로드는 감사 기록에 넣지 않고 애플리케이션 로그만 남긴다 (수백 건이 감사 화면을 덮지 않게).
- 읽기 전용. 파일을 바꾸거나 지우는 코드는 없다.
- 부하: 목록 조회는 파일 전체 해시를 계산한다. 전체 수백 MB 수준이라 수 초~수십 초. 내려받기 스크립트는 한 번에 한 파일씩 받는다.

### B-2. 이전 잠금 (`MIGRATION_LOCK`)

전환 순간부터 친구 서버를 **쓰기 불가 + 안내 전용**으로 만든다. 한 번 켜면 친구 서버는 끝까지 이 상태로 남는다.

켜지면.

| 대상 | 동작 | 이유 |
|---|---|---|
| `/api/**` (앱 상태·약관 읽기·광고 보상 콜백 제외) | 503 `MAINTENANCE_MODE` | 쓰기를 서버가 막는다. 같은 오류 코드라 앱이 기존대로 상태를 다시 묻는다 |
| 토큰 갱신 | **503** (점검 모드와 달리 열지 않음) | 덤프 뒤 토큰이 회전되면 그 사람은 내 서버에서 401 > 로그아웃된다. 503 이면 앱이 토큰을 유지한다 |
| 광고 보상 콜백 `/api/ads/ssv` | `APP_API_BASE_URL` 이 있으면 새 서버 같은 경로·같은 쿼리로 전달하고 그 응답을 그대로 돌려준다. 없으면 503 | AdMob 콘솔 주소를 바꾸기 전까지 들어오는 보상을 잃지 않는다. 서명은 쿼리에 있어 새 서버가 그대로 검증한다 |
| 예약 작업 (`@Scheduled` 전부) | 건너뜀 | 알림 중복·덤프 뒤 쓰기 방지 |
| 배경 작업 (음성 대기열, 알림·메일 비동기 리스너) | 발송기·대기열 입구에서 잠금을 확인하고 건너뜀 | 잠금 전에 쌓인 작업도 잠금 뒤에는 나가지 않게 한다 |
| 푸시·메일 발송기 | 보내지 않음 | 중복 방지 (발송 지점 한 곳에서 확인) |
| `/s/{글id}` 공유 미리보기 | 새 도메인 같은 경로로 302 (`APP_API_BASE_URL` 이 있을 때) | 밖에 퍼진 옛 링크가 최신 내용으로 열린다 |
| 앱 연결 검증 파일 | 그대로 제공 | 옛 링크가 계속 앱으로 열린다 |
| `/api/app/status` | 평소대로 (점검 값 그대로) + 새 주소 | 덮어쓰지 않는다. 점검 아님으로 바꾸면 앱이 503 과 상태 재확인을 반복한다 |
| 관리자 화면 | 그대로 | 잠금을 풀 수 있어야 한다 (전환 취소) |

- 잠금은 점검 모드와 별개 키다. 점검 모드 값은 DB 복사로 내 서버에 그대로 넘어가야 해서 섞지 않는다.
- 전환 취소가 필요하면 잠금을 끄는 것만으로 원래대로 돈다.
- 구버전 앱(주소 전환 장치 없음) 안내는 잠금이 아니라 **전환 전 최소 버전 상향**으로 끝낸다 ([E] 전환 전 조건 3).

**이전용 설정 3개(`MIGRATION_LOCK`, `MIGRATION_FILE_EXPORT_ENABLED`, `APP_API_BASE_URL`)는 DB 복사로 내 서버에도 넘어간다.** 그래서 `sync-from-source.sh --cutover` 는 복원 직후 내 DB 에서 이 3개를 기본값으로 되돌리고, 정합성 검사는 `system_config` 의 이 3개 키만 비교에서 뺀다 (설정 변경 이력 테이블도 같은 키의 행만 뺀다). 복원부터 검사 통과까지 내 서버 컨테이너는 띄우지 않는다 — 떠 있으면 서버가 DB 에 쓰는 순간 검사가 0 차이에 닿지 못한다.

## [C] 주소 전환 장치 (#831)

### 서버

- 설정 `APP_API_BASE_URL` (그룹 앱 제어, 기본 빈 값 = 전환 안 함). TTS 주소는 앱 기본값이 이미 내 서버(`ai.suhsaechan.kr`)라 이번 범위에서 뺀다 (#831 의 TTS 항목 제외).
- `/api/app/status` 응답에 `server: { apiBaseUrl }` 를 더한다 (빈 값은 null). 필드 추가만이라 구버전 앱은 무시한다.

### 앱 (다음 릴리스)

1. **주소 결정 순서** (시작 때 Dio 를 만들기 전): 개발자 도구 지정 > **서버가 지정해 저장해 둔 주소** > `.env` 기본 주소.
2. **허용 도메인 목록을 코드에 둔다**: `api.elum.chuseok22.com`, `api.elum.suhsaechan.kr`. https 만. 목록 밖 주소는 무시하고 로그만 남긴다.
3. **받으면 바로 확인 후 전환**: 상태 응답의 `apiBaseUrl` 이 지금 주소와 다르고 허용 목록에 있으면, 별도 Dio 로 새 주소의 `/api/app/status` 를 짧은 대기시간으로 부른다. 정상(200·파싱 성공)일 때만 저장하고 **그 자리에서 앱을 안에서 다시 띄운다** (개발자 도구 전환과 같은 길, 단 로그아웃하지 않고 토큰·캐시를 유지 — 같은 JWT 키·같은 DB 라 그대로 유효).
   - #831 은 "다음 실행부터"였다. 친구 서버가 잠긴 뒤에는 기다리면 사용자가 503 만 받으므로 즉시 전환으로 바꾼다. 다시 띄우는 순간에는 친구 서버가 이미 쓰기를 막고 있어 진행 중 요청이 섞일 일이 없다.
   - **상태 응답의 주소 확인은 점검·업데이트 판정보다 먼저 한다.**
4. **되돌리기**: 저장된 주소로 시작했는데 앱 상태 조회가 연결 오류로 3번 연속 실패하면(앱 실행 3번), 저장값을 지우고 기본 주소로 돌아간다. 서버가 빈 값을 주면 저장값을 지운다(다음 실행부터 기본 주소).
5. **앱 링크**: iOS associated domains 와 Android 앱 링크 호스트에 `api.elum.suhsaechan.kr` 를 **더한다** (옛 도메인 유지). 앱 라우터·초대 링크 판별은 지금 주소 하나가 아니라 **허용 도메인 목록 전체**를 받는다. 새로 만드는 링크는 지금 주소로 만든다.
6. **운영 서버 판단**: `isProductionApiServer` 를 "지금 주소가 허용 도메인 목록(운영 도메인 2개) 안인가"로 바꾼다. 상수 하나와 비교하면 전환 뒤 운영을 테스트 서버로 오인해 테스트 빌드가 운영에 테스트 계정을 만든다.
7. **개발자 도구**: 지금 주소와 출처(개발자 도구·서버 지정·기본) 표시.
8. `.env` 기본 주소는 이번 릴리스에서 **바꾸지 않는다.** 전환이 끝난 다음 릴리스에서 바꾼다.

이 릴리스가 나가도 서버 설정이 빈 값이라 사용자에게 변화가 없다.

## [D] 내 NAS: 배포와 도구

### D-1. Traefik blue/green 배포 (새 워크플로)

passQL 워크플로(`Twin-Fang/passQL` 레포 `.github/workflows/PROJECT-SPRING-SYNOLOGY-PASSQL-CICD.yaml`, 같은 NAS 에서 운영 중)를 바탕으로 elum 용을 새로 만든다.

- 실행: **수동 실행만** (전환 전까지 `main` 푸시로 돌지 않음). 입력: `mode` = `mirror` | `production`, 선택 `rollback_image_tag`.
- 이미지: 내 Docker Hub. **운영 설정·FCM 키를 이미지에 넣지 않는다** (jar 안 비밀 파일 검사). 설정은 NAS `/volume1/project/elum/server/config/` 에서 읽기 전용으로 붙인다.
- 컨테이너 `elum-back-blue|green`: `traefik-network` + `elum-net` 둘 다 연결, Host 라벨 `api.elum.suhsaechan.kr`, 헬스체크는 컨테이너 healthy + Traefik 경유 200 둘 다.
- 활성 색은 실행 중 컨테이너로 판단. 새 색이 통과하기 전에는 옛 색을 건드리지 않음. drain 표식 > 대기 > 로그 보관 > 제거.
- `mirror` 모드: FCM 키 경로를 없는 파일로, 기동 뒤 `[notification push] enabled` 가 보이면 새 컨테이너를 멈추고 실패 (지금 `run-mirror.sh` 와 같은 안전장치). `production` 모드: FCM 키 파일을 붙인다.
- Secret 은 `NAS_` 접두사로 새로 둔다 (`NAS_SERVER_*`, `NAS_APPLICATION_PROD_YML`, `NAS_FIREBASE_ADMINSDK_JSON`, `NAS_DOCKERHUB_*`). 값은 사용자가 가진 운영 설정값을 쓴다. 친구 서버용 Secret 은 건드리지 않는다.
- 운영 설정값 중 내 NAS 에 맞게 바꾸는 것: DB 주소(`elum-net` 안), 공유 링크 기준 주소·신고 메일 관리자 링크·장애 알림 관리자 링크·OpenAPI 서버 주소(새 도메인). 미러용 Redis 설정 줄과 쓰이지 않는 `elum-redis` 는 정리한다. **JWT 키·암호화 마스터키·OAuth·AI 키는 운영과 같은 값.**
- DSM 역방향 프록시 `api.elum.suhsaechan.kr` 를 8085 에서 **8079(Traefik)** 로 바꾼다. 이 시점에 미러 컨테이너를 내린다. 미러는 운영 사용자가 없으므로 언제 해도 안전하다. 바꾸기 전에 `curl -H 'Host: api.elum.suhsaechan.kr' http://localhost:8079/healthz` 로 먼저 확인한다.

### D-2. 동기화 · 검사 도구 (`server/tool/nas-mirror/`)

- `sync-from-source.sh` 를 새 컨테이너 이름에 맞춘다: 복원 동안 `elum-back-*` 를 멈추고 끝나면 다시 띄운다. 옵션 `--cutover` 일 때는 **신고 메일 끄기 등 안전 SQL 과 음성 경로 비우기를 하지 않는다** (운영 값 그대로).
- `pull-files.sh` (새): 관리자 로그인(CSRF) > area 4개 목록 > 없거나 해시가 다른 파일만 받기 > `.part` 로 받고 해시 확인 뒤 이름 바꾸기 > 원본 목록에 없는 파일은 지우지 않고 보고만. 계정은 `mirror.env`(root 전용)에 사용자가 넣는다.
- `verify-consistency.sh` (새): 운영 DB 와 내 DB 를 같은 질의로 비교해 표와 종료 코드를 낸다.
  - Flyway: 버전 목록과 checksum 전부
  - 모든 테이블: 정확한 건수, 내용 해시(행을 텍스트로 정렬해 md5, 14MB 라 충분히 빠름)
  - 파일: area 별 개수·바이트·파일별 SHA-256 (B-1 목록 ↔ 내 NAS 파일)
  - `--allow-live` 옵션(리허설용): 운영이 살아 있어 생기는 차이를 실패가 아니라 정보로 표시

## 검증 방법 (위험한 시험 금지)

- 운영 서버에는 **읽기 질의·파일 내보내기 호출만** 한다. 운영에서 잠금·점검을 켜는 시험은 하지 않는다. 그 동작은 내 NAS(미러 DB)에서 확인한다.
- 서버: 바꾼 코드만 겨누는 테스트를 고른다 — 경로 이탈 차단, 설정 꺼짐 404, 잠금 시 토큰 갱신 503·예약 작업 건너뜀, 상태 응답 필드. 전체 스위트는 배포 직전 1회.
- 앱: `flutter analyze` 와 `client/tool/check_*`. 주소 결정·허용 목록·되돌리기는 테스트 빌드로 내 NAS 를 상대로 실측 (앱 테스트는 두지 않는다, #848).
- 워크플로: [A] 수정은 친구 서버 배포가 곧 운영 배포라, 변경을 작게 하고 배포 로그로 확인한다. [D] 는 내 NAS 에서 `mirror` 모드로 반복 시험한다.
