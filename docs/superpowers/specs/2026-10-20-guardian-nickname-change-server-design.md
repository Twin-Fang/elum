# 보호자 닉네임 변경 서버 API 설계 (#851)

범위는 **서버만**이다. 클라(입구·시트)는 시안이 필요해 디자인 요청 #893 이 끝난 뒤에 따로 한다.

## 배경과 목적

- #849 에서 보호자 닉네임을 가입 때 자동 생성(형용사+명사-숫자, 예: 가파른블록-1269)하도록 했지만 바꿀 방법이 없다.
- 이야기 기능에서 닉네임이 다른 보호자에게 보이게 되면 자동 이름을 그대로 쓰기 어렵고, 사용자가 직접 고른 이름이 남에게 보이므로 **욕설·사칭·혼동 이름을 서버에서 막아야 한다.**
- 기존 `PATCH /api/member/nickname` 은 이룸이 프로필 호칭용이라 건드리지 않고 분리한다.

## 목표 / 비목표

목표
- 보호자가 자기 닉네임을 바꾸는 API 1개 (검증 · 중복 · 변경 주기 제한 · 욕설 차단)
- 한국어와 외국어(영어·일본어·중국어·스페인어, 앱 지원 5개 언어) 욕설이 닉네임에 들어가지 못한다
- 어떤 실패도 오류 코드와 사용자 문구(5개 언어)로 응답한다

비목표 (하지 않는다)
- 이미 저장된 닉네임을 다시 검사하거나 바꾸지 않는다 (자동 생성 이름은 그대로)
- 관리자 화면에서 닉네임을 고치는 기능
- 외부 욕설 판별 서비스·AI 호출 (원문을 밖으로 보내지 않는다, 비용 없음)
- 이룸이 호칭(`/api/member/nickname`) 변경
- 완벽한 욕설 탐지. 목록 기반이라 새 변형은 목록에 더해 대응한다

안티 목표: 정상 이름(예: "시발점", "Scunthorpe" 같은 단어 일부)을 마구 막아 가입자가 화를 내는 것. 아래 허용 예외 목록으로 완화한다.

## API

`PATCH /api/member/account/nickname` (새 경로. 보호자 계정 정보는 별도 엔드포인트 없이 `GET /api/member/me` 응답의 `account` 로 나가므로 변경 전용 경로를 새로 둔다. 기존 `PATCH /api/member/nickname` 은 이룸이 호칭용이라 그대로)

요청: `{ "nickname": "푸른하늘" }`
응답 200: 다른 PATCH 들과 같은 `MemberResponse`. `account` 안에 `nicknameChangeableAt`(다음에 바꿀 수 있는 시각, 제한이 없으면 null) 필드를 **더한다**. 필드 추가뿐이라 기존 GET 응답을 읽는 클라는 무시하면 되고 깨지지 않는다.

동작 순서: 정규화 > 현재와 같으면 그대로 200(변경 없음, 주기 소모 없음) > 형식 검증 > 예약어·욕설 검사 > 변경 주기 확인 > 중복 확인 > 저장

## 규칙

| 항목 | 값 (내 판단, 근거: 자동 생성 닉네임이 9~13자라 비슷한 길이를 허용) |
|---|---|
| 길이 | 2~16자, 앞뒤 공백 제거 후 |
| 허용 문자 | 한글 완성형(가-힣), 영문, 숫자, 하이픈(-). 공백·이모지·제어문자·보이지 않는 문자·한글 자모 단독(ㅅㅂ) 금지 |
| 정규화 | NFKC 정규화 후 영문은 소문자로 비교. 저장은 사용자가 쓴 모양 그대로(대소문자 유지) |
| 중복 | 대소문자 무시 조회(`lower(nickname)`)로 막는다. 기존 `uk_member_nickname` 은 대소문자를 구분하므로 **정확히 같은 이름의 경합**만 인덱스가 막고, 그 경우 중복 오류로 변환. 대소문자만 다른 이름의 동시 요청은 허용(드물고 피해가 작아 함수형 인덱스는 만들지 않음, 내 판단) |
| 변경 주기 | 마지막 변경 후 7일. 가입 후 첫 변경은 제한 없음(자동 생성 이름이므로). 같은 이름으로 다시 저장은 주기를 쓰지 않음 |
| 예약어 | 운영·사칭으로 읽히는 이름 금지: 관리자, 운영자, 이룸 공식, elum, admin, official, support 등 (`nickname-reserved.txt`) |

## 욕설 차단

- 위치: `member/application/service/NicknamePolicy`(형식·예약어·욕설을 한 곳에서 판정) + 단어 목록 리소스 파일(언어별 `nickname-profanity-{ko,en,ja,zh,es}.txt`).
- 비교용 문자열 만들기: NFKC > 소문자 > 하이픈·숫자·기호 제거(`시1발`, `s-h-i-t` 우회 차단) > 한글은 자모 분해해 비교(`ㅅㅂ`, `씨발` 변형 흡수).
- 판정: 정규화한 이름이 목록 단어를 **포함**하면 거절. 단, 허용 예외 목록(`nickname-profanity-allow.txt`, 예: "시발점", "assassin" 처럼 단어 일부가 우연히 겹치는 정상어)에 있으면 통과.
- 거절 사유로 **어떤 단어가 걸렸는지 응답하지 않는다** (우회 힌트가 됨). 로그에도 원문 닉네임을 남기지 않고 회원 id 와 사유 코드만 남긴다.
- 목록 출처: 직접 만든 최소 목록으로 시작한다(외부 목록은 라이선스 표기 의무가 있어 쓰지 않음). 운영 중 신고로 더한다.
- 비교용 문자열에서 숫자는 영문 글자 사이에 있을 때만 비슷한 글자로 바꿔 본다(예: `sh1t`). 한글 사이 숫자(`시1발`)는 숫자를 지워 붙인다. 정확한 변환표와 초기 단어 목록은 구현하는 쪽이 직접 만든다(내 판단). 오탐은 허용 예외 목록에 더해 고친다.
- **미결정(내 판단으로 진행, 바꿀 수 있음):** 목록은 코드와 함께 배포(재배포 필요). 관리자 화면에서 목록을 고치는 기능은 이번에 하지 않는다.

## 오류 (모두 에러 코드와 5개 언어 문구, 해요체)

| 코드 | 상태 | 문구(ko) |
|---|---|---|
| NICKNAME_INVALID_FORMAT | 400 | 닉네임은 한글, 영문, 숫자, 하이픈으로 2~16자까지 쓸 수 있어요. |
| NICKNAME_NOT_ALLOWED | 400 | 쓸 수 없는 닉네임이에요. 다른 이름을 적어 주세요. (욕설·예약어 공통, 이유는 알리지 않음) |
| NICKNAME_DUPLICATED | 409 | 다른 보호자가 이미 쓰고 있어요. 다른 이름을 적어 주세요. |
| NICKNAME_CHANGE_TOO_SOON | 429 | 닉네임은 7일에 한 번 바꿀 수 있어요. `nicknameChangeableAt` 이후에 다시 해 주세요. |

기존 오류 코드 규칙(ErrorCode enum, messages_*.properties 5개 파일, 골든 테스트 갱신)을 따른다.

## 데이터

- `member.nickname_changed_at timestamp null` 추가 (마이그레이션 번호는 **구현 시점에 develop 의 최신 V 번호 다음**으로 정한다. 다른 작업과 번호가 겹쳐 배포가 깨진 전례가 있음).
- 기존 회원은 null = 제한 없음. 백필 없음.

## 실패 경로

- DB 유니크 경합 > `DataIntegrityViolationException` 을 NICKNAME_DUPLICATED 로 변환 (500 으로 새지 않게)
- 요청 본문이 비었거나 null > NICKNAME_INVALID_FORMAT
- 계정이 탈퇴·정지 상태 > 기존 인증 흐름의 오류를 그대로 따름
- 욕설 목록 파일을 못 읽음 > 서버가 기동되지 않게 시작 시점에 검증(조용히 통과시키지 않음)

## 테스트 (한 결함씩 겨눈다)

- 정책 표 테스트: 길이 경계(1·2·16·17), 허용 문자, 우회 표기(`시1발`, `ㅅㅂ`, `s-h-i-t`), 예약어, 허용 예외
- 서비스 테스트: 중복(대소문자), 7일 이내 재변경, 같은 이름 재저장, 경합 변환
- 컨트롤러 테스트: 4개 오류 코드와 200 응답 모양
- i18n 정합(기존 ErrorMessageParityTest·골든)이 5개 언어 누락을 잡는다
- 실행은 관련 테스트만 한 번 돌린다

## 배포·호환

- 응답에 필드만 더하고 기존 API 는 바뀌지 않는다. 클라가 아직 호출하지 않으므로 서버 먼저 배포해도 안전하다.
- 앱 배포가 따로 필요 없다(서버 배포).

## 내 판단으로 정한 것 (확인 부탁)

1. 닉네임 규칙: 2~16자, 한글·영문·숫자·하이픈
2. 변경 주기 7일, 첫 변경은 제한 없음
3. 욕설 거절 시 이유를 알려 주지 않음(`NICKNAME_NOT_ALLOWED` 하나)
4. 욕설 목록은 자체 최소 목록 + 허용 예외, 관리자 편집 기능 없음
5. 대소문자 무시 중복(서비스 조회로만), 저장은 입력 모양 그대로
6. 응답은 `MemberResponse`, `account.nicknameChangeableAt` 필드 추가
