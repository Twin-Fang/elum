# 스토어 검색 노출(ASO) 전면 개선 설계

> 2026-11-13 · 상위 기준 `docs/store/store-listing.md` · 언어 규칙 `docs/store/locales/README.md`

## 왜

`이룸` 은 같은 이름 앱이 많아 이름으로는 안 찾아진다. 보호자·선생님은 `행동카드 만드는 어플`, `행동카드 생성어플`,
`발달장애 교육 어플`, `학습장애 adhd 교육어플`, `aba 학습도구`, `특수학교 교육어플` 처럼 **하고 싶은 일·대상·현장**으로 검색한다.
지금 이 검색들에서 이룸이 안 뜨거나 상단이 아니다.

원인 세 가지.
1. **검색어가 문구에 없다.** `행동카드`(붙여 씀)·`만들기`·`생성`·`ABA`·`학습도구`·`특수학교`·`치료` 가 iOS 이름·부제·키워드, Play 제목·간단한 설명에 없다.
2. **스토어에 한국어만 있다.** en·ja·zh·es 는 `docs/store/locales/` 초안으로만 있고 콘솔에 없다 → 해외 검색 0.
3. **문구가 저장소와 끊겨 있다.** iOS 배포는 `release_notes` 만, Play 는 `skip_upload_metadata: true` → 이름·키워드·설명은 손으로 고쳐야 해서 방치됐다.

## 목표 / 하지 않는 것

- 목표: 위 검색어 묶음(아래 표) 어느 조합으로 찾아도 이룸이 결과에 걸리게, 5개 언어 × 2개 스토어 문구를 검색어 중심으로 다시 쓰고 **배포 때 자동으로 올라가게** 한다.
- 하지 않는 것: ja·zh·es **앱 화면 열기**(스토어 문구만 먼저), 스크린샷 교체(#1369 로 분리), 돈이 드는 일 전부(검색 광고 등, 2026-11-14 사용자 결정으로 제외), 사이트 SEO(후속 이슈).
- 실패로 보는 것: 문구가 앱이 치료한다고 약속하는 문장이 되는 것(반려·법 위험), 콘솔 기존 값이 빈 값으로 덮이는 것.
- 한계: 순위는 설치 수·평점·유지율이 가장 크게 좌우한다. 문구는 **검색어에 걸릴 자격**을 만든다. 최상단 보장은 아니다 → 리뷰 요청 기능을 후속 이슈로 둔다(지금 앱에 `in_app_review` 없음).

## 금지어 기준 변경 (사용자 결정 2026-11-13)

`store-listing.md` 금지어는 **저장소 규칙**이었다. 앱 화면에는 그 말이 나오지 않으므로 **스토어 검색용 문구에는 쓴다.**

| 쓴다 | 쓰지 않는다 |
|---|---|
| iOS 키워드·Play 태그·검색어로: `치료` `치료실` `언어치료` `놀이치료` `특수학교` `특수교육` `아동` `특수아동` `교육` `학습` | 효과를 약속하는 문장: `치료해요` `증상이 좋아져요` `효과가 있어요` |
| 설명에서 **현장·대상 설명**으로: "특수학교·치료실·ABA 현장에서도 쓰는 행동카드" | 진단을 대신한다는 말, 의료기기처럼 읽히는 말 |

앱 화면 용어 규칙(`이룸이`·`기기` 등, 루트 CLAUDE.md)은 그대로 둔다 — 스토어 문구에만 해당하는 변경이다.

## 접근법

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 저장소 문구 → 배포 때 자동 업로드 (채택)** | 5개 언어 문구를 fastlane metadata 파일로 두고 iOS `deliver`·Play `supply` 가 함께 올린다 | 한 곳 수정 → 다음 배포에 전부 반영. 콘솔 직접 수정은 덮인다 |
| B. 문구만 쓰고 콘솔 수기 입력 | 파이프라인 그대로 | 10곳 수기, 또 어긋난다 |
| C. A + 사이트 SEO | 사이트 안내 글을 같은 검색어로 | 스토어가 먼저. C 는 후속 이슈 |

사용자가 방법을 맡김 → A 로 진행, C 는 후속 이슈.

## 설계

### 1. 문구 파일 (배포가 읽는 곳)

```
client/ios/fastlane/metadata/{ko,en-US,ja,zh-Hans,es-MX}/
  name.txt  subtitle.txt  keywords.txt  description.txt  promotional_text.txt
client/android/fastlane/metadata/android/{ko-KR,en-US,ja-JP,zh-CN,es-419}/
  title.txt  short_description.txt  full_description.txt
```

- 원본은 이 파일들이다. `docs/store/store-listing.md`·`locales/*.md` 는 기준·설명 문서로 바꾸고 문구 사본은 지운다(사본 두 벌 금지).
- iOS 설명 끝에 **구독 안내(EULA 링크) 블록을 모든 언어에** 넣는다(#1081 반려 근거).
- 글자 수 한도(이름 30·부제 30·키워드 100·간단한 설명 80·설명 4000)를 넘지 않게 검사 스크립트 `docs/store/check_store_metadata.py` 로 확인: 한도, 빈 파일, 효과 약속 문장(`치료해요|효과가 있|좋아져요` 등), 구독 블록 유무.
- iOS 키워드는 이름·부제와 겹치는 말을 빼고 100자를 꽉 채운다. 붙여 쓴 형태(`행동카드`)를 반드시 포함.

### 2. 배포 연결

- iOS Fastfile: `release_notes.txt` 를 만드는 로케일 목록을 metadata 폴더에 있는 로케일 전체로 넓힌다. 기존 파일(name 등)은 그대로 두고 release_notes 만 덧쓴다. metadata_path 가 레포 파일 위치(`APP_ROOT/ios/fastlane/metadata`)를 가리키는지 확인(지금은 `workspace/ios/...` 라 `client/` 아래 파일을 못 볼 수 있음 — 구현 때 실측).
- Play Fastfile: 본 배포 lane 의 `skip_upload_metadata: false`, `skip_upload_images/screenshots: true` 유지. 출시 노트 changelogs 경로와 충돌 없게 한다.
- App Store 이름·부제·키워드는 **새 버전 제출 때만** 바뀐다 → 다음 deploy 배포에 함께 실린다. Play 는 같은 배포에서 반영되고 구글 검토를 탄다.

### 3. 실패 경로

| 상황 | 대응 |
|---|---|
| 파일이 비었거나 한도 초과 | 검사 스크립트가 실패 → 커밋 전에 잡는다. deliver 는 빈 파일이면 그 필드를 건너뛰게 둔다 |
| 새 로케일 추가로 deliver 실패(ASC 권한·로케일 코드) | 로케일 코드는 README 표대로. 실패 시 ko 만 남기고 재배포할 수 있게 로케일 목록을 폴더 기준으로 둔다 |
| 심사에서 키워드·문구 지적 | 해당 문장만 고쳐 재제출. 효과 약속 문장은 검사로 미리 막는다 |
| Play 메타 업로드 실패 | 바이너리 업로드와 분리된 lane 에서 재시도 가능하게 |

## 남은 선택 (구현자 판단)

- es 스토어 변종: iOS `es-MX`, Play `es-419` 로 둔다(중남미 사용자 수, 초안이 중립 `tú` 문장).
- 앱 이름 현지 표기: 모든 언어 스토어 이름은 `ELUM` 를 앞에 두고 현지 검색어를 뒤에 붙인다(예: `ELUM: Visual Schedule & ABA Cards`). 기기 홈 화면 앱 이름은 바꾸지 않는다.
- 번역 문구는 원어민 검수 전이다 → 이슈에 표시하고 배포 뒤 검색 실측(각 스토어 검색 결과 캡처)을 증거로 남긴다.

## 후속 이슈

1. 사이트 SEO: 같은 검색어 묶음으로 안내 글·메타 태그 정비 (C 안)
2. 앱 안 리뷰 요청(`in_app_review`): 일과 완료 몇 회 뒤 보호자 화면에서 1회 — 순위의 가장 큰 변수
