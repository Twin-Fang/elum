# 일과 시트: 번호 고정, 카드만 옮기기, 떠 있는 버튼 (#434)

- 날짜: 2026-09-27
- 시안: `956:4084`(오늘 일과 시트), `980:4777`(지난 일과 시트), `980:5174`(보상 없음)
- 대상: `client/lib/features/guardian/presentation/widgets/routine_detail_sheet.dart`

## 문제

1. 번호 뱃지와 카드가 한 줄(`_StepRow`)로 묶여 있다. 오래 누르면 번호까지 들리고,
   끄는 동안 번호가 카드를 따라 미끄러진다. 끌고 있는 줄은 번호를 감춰 자리가 빈다.
2. `편집하기`·`일과 다시하기` 버튼을 목록 아래 칸으로 잘라 두어 목록이 버튼 위에서 끝난다.

시안은 번호(`1번`~`4번`, x=16)와 카드 묶음(`행동단계`, x=60)을 따로 그렸고,
버튼은 시트 바닥 위에 떠 있다.

## 결정 (사용자 승인)

- **번호는 자리를 뜻한다.** 왼쪽 번호 칸은 순서를 바꾸는 동안에도 움직이지 않고
  들리지도 않는다. 오른쪽 카드만 떠서 자리를 바꾼다.
- **버튼은 떠 있다.** 위치는 시안 그대로(시트 위에서 492, 바닥에서 56).
  목록은 버튼 뒤로 스크롤된다.
- **버튼 위 흐림(그라데이션)은 넣지 않는다.** 시안에 없다 — "디자인대로만 가자".

## 구조

```
Container(시트, 모서리 20, 자식 자르기)
└ Stack
  ├ Column
  │ ├ _Header (고정)
  │ └ CustomScrollView
  │   ├ SliverPadding
  │   │ └ SliverCrossAxisGroup
  │   │   ├ SliverConstrainedCrossAxis(44) → SliverList(_StepBadge)   ← 끌기와 무관
  │   │   └ SliverReorderableList(_StepCard)                           ← 카드만
  │   └ SliverPadding(아래: 버튼 56 + 66 + 여백) → _RewardRow
  └ Positioned(bottom 56, height 66) → 버튼
```

- 두 칸을 **한 스크롤 안에 나란히** 둔다. 따로 두면 같이 스크롤되지 않고, 끌면서
  가장자리에 닿았을 때의 자동 스크롤도 한쪽에서만 돈다.
- `SliverReorderableList`는 `ReorderableListView`와 달리 항목을 전역 키로 감싸 주지
  않는다. 끌기가 시작되면 카드 상태가 버려져, 손을 떼는 순간 이미 사라진 애니메이션을
  되돌리다 오류가 난다. `_StepItemKey`로 직접 감싼다.
- 보상 줄은 순서 바꾸기 대상이 아니라 스크롤 맨 아래에 따로 둔다. 보이는 모습은 같다.

## 실패 경로

- 순서 저장 실패: 기존 그대로 화면을 되돌리고 `E-STEP-ORDER` 스낵바를 띄운다.
- 단계가 많을 때: 목록이 버튼 뒤로 스크롤되고, 끝까지 내리면 보상 줄이 버튼 위에 온전히 보인다.
- 지난 일과: 손잡이가 없어 끌기가 시작되지 않는다. 번호 칸 구조는 같다.

## 검증

- 위젯 테스트: 끄는 동안 번호 위치·표시가 그대로이고 뱃지에 그림자가 없다 /
  목록 영역이 버튼 아래까지 이어진다 / 끈 카드가 실제로 자리를 옮긴다.
- 시안 대조: `956:4084`·`980:5174` 렌더는 바뀌지 않았다. `980:4777`은 목록이 버튼
  뒤로 이어지는 부분만 바뀌었다.
- 에뮬레이터: 가짜 데이터로 시트만 띄워 4단계 끌기, 8단계 스크롤, 끌며 자동 스크롤을 밟았다.
