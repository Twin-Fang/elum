# 개발자 도구: 서버 바꾸기·테스트 계정·상태 흉내 (#930)

## 왜

- 테스트를 운영 서버에서만 할 수 있다. 서버 주소가 빌드 때 `.env` 로 고정돼, 로컬 서버나 따로 만든 테스트 서버를 보려면 다시 빌드해야 한다.
- 공지처럼 모두에게 가는 기능은 운영에서 시험할 수 없다 (실제 사용자 홈에 뜬다).
- 공지 팝업·업데이트 권유·강제 업데이트·점검 화면·푸시 눌러 이동·실패 화면을 볼 방법이 없다.
- 지금 개발자 도구는 9개 항목이 묶음 없이 한 줄이고, 회원삭제는 실패해도 성공처럼 넘어간다.

## 범위

개발자 도구가 켜진 빌드에서만 (`AppConfig.showDevTools`: 디버그 또는 `APP_FLAVOR=dev` + `.env` `ELUM_SHOW_DEV_TOOLS=true`).
스토어 빌드(`apply_build_profile.sh release`)는 개발자 도구가 꺼져 있어 아래 기능이 전부 없다.
저장해 둔 서버 주소도 `showDevTools` 일 때만 읽는다 — 테스트 빌드 위에 스토어 빌드를 덮어 깔아도 운영 주소로 돈다.

## 결정

### 1. 서버 주소

- 주소 결정은 `AppConfig.apiBaseUrl` 한 곳: 개발자 도구 지정 주소 > `.env` 기본 주소.
  #831(원격 전환)은 같은 자리에 "서버가 지정한 주소"를 끼운다.
- 고를 수 있는 것: 운영(`.env` 기본), 로컬 시뮬레이터 `http://localhost:8080`, 로컬 에뮬레이터 `http://10.0.2.2:8080`, 직접 입력, 최근 쓴 주소(최대 5개).
- 바꾸는 순서: 지금 서버에 로그아웃(푸시 토큰 해제 포함, 실패해도 계속) > 시간값·약관 캐시 비움 > 주소 저장 > 앱 위젯 트리를 통째로 다시 만든다(`AppRestart`).
  ProviderScope 를 새로 만들어 Dio·repository·메모리 캐시가 모두 새 주소로 다시 생긴다. 프로세스를 죽이지 않는다.
- 운영이 아닌 서버를 보고 있으면 디버깅 버튼 아래에 서버 이름을 띄운다.
- `http` 주소: Flutter(dart:io) 연결은 OS 의 http 차단(ATS, cleartext)을 거치지 않으므로 네이티브 설정을 바꾸지 않는다. 실측으로 확인한다.

### 2. 테스트 계정

- 서버 `POST /api/auth/signup`, `POST /api/auth/login` (운영 프로파일에서는 컨트롤러가 없고, 그 밖에서도 `ELUM_AUTH_LEGACY_PASSWORD_ENABLED=true` 일 때만 열림).
- 개발자 도구 "테스트 계정": 새 계정 만들기(아이디 `test{MMddHHmmss}`, 비밀번호 자동) > 바로 로그인. 저장한 계정 목록에서 골라 로그인. 계정은 서버 주소별로 기기에 저장한다.
- 로그인 뒤 갈 곳은 소셜 로그인과 같다: 약관 > 역할 선택 > 보호자 홈(잠금 없으면 잠금 만들기).
- 운영 서버를 보고 있을 때는 메뉴를 숨긴다. 서버가 404 를 주면 "이 서버는 테스트 계정이 꺼져 있음" 과 켜는 방법을 보여준다.
- 비밀번호는 SharedPreferences 에 평문으로 둔다 — 테스트 서버의 일회용 계정이고 개발자 도구 빌드에만 있다.

### 3. 이 기기에서만 흉내 (운영에 붙어 있어도 다른 사용자 영향 없음)

| 흉내 | 방법 | 끝나는 때 |
|---|---|---|
| 앱 상태: 업데이트 권유·강제 업데이트·점검 | `appStatusProvider` 가 서버 대신 만든 값을 돌려줌. 권유는 스토어 확인을 건너뛰고 오늘 기록을 지움 | 끄기, 또는 앱 종료 |
| 공지 다시 보기 | 공지 숨김 기록 전부 지움 > 앱 다시 띄우기 | - |
| 견본 공지 | 실제 공지 팝업에 견본 3종(글만, 버튼, 긴 글) | - |
| 푸시 | 종류 7개 중 골라 실제 배너(로컬 알림) 띄우기 > 누르면 실제 이동 경로. 또는 누른 것처럼 바로 이동 | - |
| 처음 한 번 | 코치마크 전부·공지 숨김·업데이트 권유 기록 초기화 | - |
| 실패 | 요청을 일부러 실패: 네트워크 끊김·응답 지연·서버 오류 500 | 끄기, 또는 앱 종료 |

흉내 상태는 정적 값(메모리)이라 `AppRestart` 로 트리를 다시 만들어도 남고, 앱을 끄면 사라진다.
켜져 있는 흉내는 디버깅 버튼 아래 표시로 보인다.
개발자 도구 오버레이를 `AppStatusGate` 바깥으로 옮긴다 — 점검·강제 업데이트 화면에서도 버튼이 남아 흉내를 끌 수 있어야 한다.

### 4. 메뉴 정리

묶음: 서버와 계정 / 흉내 / 화면과 언어 / 기록 / 위험.
`현재 상태`는 `상태 덤프`에 이미 같은 값이 있어 뺀다. 회원삭제 실패는 시트에 에러 코드와 함께 보여주고 화면을 옮기지 않는다.

## 실패 경로

| 상황 | 동작 |
|---|---|
| 직접 입력한 주소가 `http(s)://호스트` 형식이 아님 | 저장하지 않고 입력칸 아래 사유 표시 |
| 바꾼 서버가 응답 없음 | 앱은 그대로 뜨고 각 화면의 기존 네트워크 오류 화면이 뜬다. 서버를 다시 고를 수 있다 |
| 로그아웃 요청 실패(이전 서버 꺼짐) | 로컬은 지우고 계속 진행 |
| 테스트 계정 가입·로그인 실패 | 시트에 상태 코드·서버 에러 코드 표시 |
| 알림 권한 없음 | 푸시 배너가 안 뜰 수 있다고 안내, "바로 이동" 은 그대로 됨 |

## 하지 않는 것

- 서버 쪽 시험용 푸시 발송 API, 시드 데이터 API
- 일과 리마인더 즉시 울리기 (매일 시각 기반이라 흉내 값이 적음)
- 로컬 서버 실행 스크립트·docker-compose
- 서버 주소를 앱 실행 중 무중단 교체 (트리 재생성으로 대신)
