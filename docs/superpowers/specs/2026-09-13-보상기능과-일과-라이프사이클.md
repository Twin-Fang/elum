# A. 서버 변경

## A-1. `Routine` 엔티티 — 보상 필드 추가 🔴

```java
/// 보호자가 정한 보상(강화물). 없으면 null — 건너뛰기를 허용한다.
/// 앱이 보상을 주지 않는다. 아이에게 보여주고 상기시키는 용도다.
@Column(length = 100)
private String rewardText;

/// 프리셋에서 고른 경우 그 키. 직접 입력이면 null.
/// 아동 화면에 그림을 띄우려면 키가 필요하다 — 자유 텍스트는 글자만 나온다.
@Column(length = 30)
private String rewardPresetKey;
```

**마이그레이션** `V9__add_reward_to_routine.sql`

```sql
ALTER TABLE routine ADD COLUMN reward_text VARCHAR(100);
ALTER TABLE routine ADD COLUMN reward_preset_key VARCHAR(30);
```

## A-2. 보상 프리셋 상수 🔴

| key | 라벨 | 이모지 |
| --- | --- | --- |
| `SNACK` | 좋아하는 간식 | 🍪 |
| `VIDEO` | 유튜브 10분 | 📺 |
| `PLAY` | 좋아하는 놀이 | 🧸 |
| `WALK` | 산책 | 🚶 |
| `CUSTOM` | 직접 입력 | ✏️ |

> 프리셋을 두는 이유는 **아동 화면에 그림을 띄우기 위해서**다.
> 자유 텍스트만 받으면 글자를 못 읽는 사용자에게 아무 의미가 없다.

## A-3. API 변경 🔴

| API | 변경 |
| --- | --- |
| `POST /api/routines` | 요청에 `rewardText`, `rewardPresetKey` 추가 (**선택**, null 허용) |
| `PATCH /api/routines/{id}/reward` | 🆕 보상만 수정 |
| `GET /api/routines/{id}` · `/today` | 응답에 `rewardText`, `rewardPresetKey` 포함 |
| `GET /api/routines/recent-rewards` | 🆕 최근 사용한 보상 **최대 3개** (중복 제거, 최신순) |
| `POST /api/routines/{id}/duplicate` | 🆕 같은 steps로 **오늘** 일과 생성 (**AI 호출 없음** · 날짜 파라미터 없음) |

### `duplicate` 동작 규칙

```
원본의 title · steps(title/description/ttsText/imagePath) · reward를 복사
→ 새 Routine 생성 (status = CONFIRMED, scheduledAt = 오늘 09:00 고정)
→ steps의 completed는 전부 false로 초기화
→ rawInputText/sanitizedInputText는 복사하지 않는다 (원문 미보관 원칙)
```

## A-4. 목록 조회 🔴

현재 보호자 홈이 `findAllByMemberId`로 **전부** 가져온다. 세 구간으로 나눈다.

```java
// 오늘    : status ∈ {CONFIRMED, COMPLETED} AND scheduledAt ∈ [오늘 00:00, 23:59:59] (KST)
// 준비 중  : status = PENDING_REVIEW  (승인 대기 · 아이에게 보이지 않음)
// 지난     : scheduledAt < 오늘 00:00  → 최신순 10개만
```

**`confirm()` 변경** — 승인 시 `scheduledAt`을 그날로 갱신한다.

```java
routine.setStatus(RoutineStatus.CONFIRMED);
routine.setScheduledAt(LocalDate.now().atTime(9, 0));
```

> **지난 일과를 삭제하지 않는다.** 수행률 추이(P1)의 원본 데이터이고,
> 보호자가 "이 날은 왜 안 했지"를 확인하는 근거다.

# B. 화면 명세

## B-1. 보호자 홈 `guardian_home_screen` — **수정** 🔴

### 현재
```
[헤더]
[새로운 일과 만들기 카드]
[오늘 일과]        ← 있음
[추천 일과]
```

### 변경 후
```
[헤더]
[새로운 일과 만들기 카드]

오늘                                    ← CONFIRMED/COMPLETED · scheduledAt 오늘
  ┌──────────────────────────────┐
  │ ☂️ 비 오는 날 학교 가기         │
  │ ●●●○○  3/5                   │
  │ 🍪 다 하면: 젤리 먹기          │  ← 보상 있을 때만
  └──────────────────────────────┘

준비 중                                  ← PENDING_REVIEW (승인 대기)
  ┌──────────────────────────────┐      있을 때만 표시
  │ 🏥 병원 가기                   │
  │ 아직 아이에게 보이지 않아요      │
  │                    [ 확인하기 ] │  → 카드 검토 화면
  └──────────────────────────────┘

지난 일과  ▾ (기본 접힘)                  ← scheduledAt이 오늘 이전
  ┌──────────────────────────────┐
  │ 🎒 아침 등교 준비   5/5         │
  │                   [ 다시 하기 ]│
  └──────────────────────────────┘

추천 일과                                ← 기존 유지
```

### 섹션 규칙

| 섹션 | 조건 | 표시 |
| --- | --- | --- |
| `오늘` | status ∈ {CONFIRMED, COMPLETED} AND scheduledAt = 오늘 | 항상. 0건이면 "오늘은 등록된 일과가 없어요" |
| `준비 중` | status = PENDING_REVIEW | **1건 이상일 때만** |
| `지난 일과` | scheduledAt < 오늘 00:00 | 1건 이상일 때만 · 기본 접힘 · 최근 10개 |

> **`준비 중`이 곧 "미리 만든 일과" 보관함이다.** 별도 저장 기능을 만들지 않는다.
> 날짜를 고르지 않아도 "내일 병원"을 오늘 미리 만들어 둘 수 있고,
> 승인하기 전까지는 아이 화면에 뜨지 않는다.

### 타일 공통 요소

| 요소 | 조건 |
| --- | --- |
| 보상 줄 | `rewardText != null` 일 때만 |
| 진행률 `3/5` | steps 중 completed 개수 |
| **[다시 하기]** | **지난 일과 타일에만** |
| **[확인하기]** | **준비 중 타일에만** → 카드 검토 화면으로 |

### [다시 하기] 동작

```
탭 → duplicate API 즉시 호출 (확인 시트 없음 · 날짜 묻지 않음 · AI 호출 없음)
   → 오늘 일과로 생성 (status = CONFIRMED, scheduledAt = 오늘 09:00)
   → 성공: 오늘 섹션 상단에 추가 + 토스트 "오늘 일과로 만들었어요"
   → 실패: 토스트 + 에러 코드 노출 (E-xxxx). 원본은 그대로
```

> **탭 한 번으로 끝나야 재사용 가치가 있다.** "다시 하기"의 의도가 곧 "지금 또 할래"다.
> 내일 것으로 만들고 싶으면 내일 다시 누르면 된다.

> 별도 "저장된 일과" 개념을 만들지 않는다. **지난 일과가 곧 저장소**다.

## B-2. 일과 입력 `routine_input_screen` — **변경 없음** ✅

### 날짜 UI를 만들지 않는다 (2026-09-13 회의 결정)

캘린더·날짜 피커·요일 계산을 전부 만들지 않는다. 대신 **승인 시점이 곧 그 일과를 하는 날**이 된다.

```java
// RoutineService.confirm()
routine.setStatus(RoutineStatus.CONFIRMED);
routine.setScheduledAt(LocalDate.now().atTime(9, 0));   // ← 승인한 날로 갱신
```

### 이 한 줄이 만드는 것

| 사용 패턴 | 동작 |
| --- | --- |
| 오늘 할 일 | 만들고 **바로 승인** → 아이 화면에 뜸 |
| **내일 병원** | 오늘 미리 만들고 **승인하지 않음** → `준비 중`에 대기 → **내일 승인** → 그때 아이 화면에 뜸 |
| 재사용 | `지난 일과`에서 [다시 하기] → 오늘 일과로 즉시 생성 |

> 아동 `GET /api/routines/today`는 **`PENDING_REVIEW`를 제외**한다(기존 구현).
> 승인 전 일과는 아이에게 보이지 않으므로, **승인이 곧 "오늘 할 일로 올리기"** 다.
> 날짜를 고르는 UI 없이 미리 만들어두기가 성립한다.

# C. 예외 처리 (전 화면 공통)

| 상황 | 처리 |
| --- | --- |
| 보상 미설정 | 모든 보상 UI를 **숨긴다**. 기존 별 보상만 동작 |
| `duplicate` 실패 | 토스트 + 에러 코드. 원본은 그대로 유지 |
