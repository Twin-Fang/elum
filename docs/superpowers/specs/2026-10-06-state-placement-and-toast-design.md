# 실패·빈 상태 위치 통일과 토스트 공통 호출 — 설계

- 날짜: 2026-10-06
- 관련: #422 (실패·빈 상태·토스트 시안 요청), #573 (오프라인 실패 시안 요청), #543 (토스트 임시 테마)

## 배경 · 목표

#422 검토 결과(사용자, 2026-10-06):

- 보호자용/이룸이용, 화면 전체/칸 하나처럼 **자리에 따라 모양이 다른 것은 맞다.**
- 문구(`~를 불러오지 못했어요`, `다시 불러오기`/`다시 하기`, `잠시 후 다시 해주세요`, `아직 하늘이의 일과가 없어요`)는 문제없다.
- 문제는 **놓이는 위치에 규칙이 없다**는 것, 그리고 **토스트가 커스텀 모양이 아니라 기본 모양으로 보인 적이 있다**는 것.

목표: 모양·문구·색은 그대로 두고, **위치 규칙**과 **토스트 띄우는 길**만 하나로 만든다.
시안(#422·#573)이 나오면 공통 위젯만 바꿔 한꺼번에 들어가게 한다.

## 지금 상태 (코드 조사)

| 어긋남 | 근거 |
|---|---|
| 세로 위치가 세 갈래 | 가운데(임시저장·카드 0장·카드 생성 실패) / 위에서 고정(연결 상태 80, 이룸이 바꾸기 40) / 앞 요소 바로 아래(함께하는 사람·초대 코드·오늘 일과) |
| 로딩→실패 전환 때 자리가 튐 | 연결 상태 로딩 top 120 · 실패 top 80. 오늘 일과는 로딩·빈 상태가 회색 칸, 실패만 칸 밖. 초대 코드는 작은 로딩 → 큰 그림 실패 |
| 실패 화면 복사본 | `routine_loading_screen.dart` 의 `_GenerateError` 가 `ElumErrorView` 전체 모드를 복사해 따로 그린다 |
| 토스트 호출이 제각각 | 7곳이 `ScaffoldMessenger.of`/`maybeOf` 를 섞어 직접 부르고, 앞 토스트를 지우지 않아 연달아 쌓인다 |
| 기본 모양 토스트 | 코드상 테마(`snackBarTheme`)를 우회하는 경로는 찾지 못했다 → 실기기에서 밟아 찾는다 |

## 설계

### 1. 위치 규칙 두 가지

| 종류 | 규칙 | 화면 |
|---|---|---|
| **본문 전체 상태** | 헤더 아래 남는 영역의 **세로 가운데**. 로딩·빈 상태·실패가 같은 자리. 글자가 커져 넘치면 스크롤 | 임시저장, 연결 상태, 이룸이 바꾸기, 카드 확인 0장, 카드 생성·질문 준비 실패 |
| **구역 상태** | 정상일 때 첫 줄이 놓이는 자리에, **로딩과 같은 칸** 안 | 보호자 홈 오늘·지난 일과, 추천 띠, 함께하는 사람 목록, 초대 코드 |

- 본문 전체 상태는 공통 위젯 **`ElumStateBody`**(`lib/core/widgets/`)로 만든다.
  남는 높이를 받아 가운데에 두고, 넘치면 스크롤한다. 로딩 표시도 이 위젯 안에 둬서 전환 때 자리가 같다.
- 구역 상태는 화면마다 이미 있는 칸(`_GreyTileShell` 등)을 로딩·빈 상태·실패가 함께 쓰게 맞춘다.
  오늘 일과 실패를 칸 안으로 넣는 것이 대표다.
- `_GenerateError` 는 지우고 `ElumErrorView`(전체 모드)를 쓴다. 버튼 문구(`routineLoadingRetry` 등)는
  지금 값을 그대로 넘긴다 — 문구는 바꾸지 않는다. `ElumErrorView` 에 버튼 문구 인자를 더한다.

### 2. 토스트 공통 호출

- `showElumToast(context, message)` 하나를 만든다 (`lib/core/widgets/elum_toast.dart`).
  - 루트 `ScaffoldMessenger` 를 `maybeOf` 로 잡는다 — 없으면 아무것도 하지 않는다(앱이 죽지 않는다).
  - 띄우기 전에 `hideCurrentSnackBar()` — 연달아 눌러도 쌓이지 않고 마지막 것만 보인다.
  - 모양은 테마 한 곳(`snackBarTheme`)에 그대로 둔다.
- 7곳을 이 함수로 바꾼다. 화면을 옮기기 전에 messenger 를 잡아 두던 곳은 그 순서를 지킨다
  (함수가 messenger 를 받는 형태도 둔다).
- **기본 모양 토스트 찾기**: 이 작업 전용 iOS 시뮬레이터에서 7곳을 밟아 캡처한다.
  기본 모양이 나오는 곳을 찾으면 원인을 이 작업에서 고친다. 못 찾으면 못 찾았다고 남긴다.

### 3. 그대로 두는 것

- 이룸이 홈 실패/빈 상태 (겁주지 않으려고 일부러 만든 모양, 위 고정 109)
- 모든 문구·색·그림, `snackBarTheme` 값

## 실패 경로

| 상황 | 처리 |
|---|---|
| 토스트를 띄울 messenger 가 없음 | 조용히 넘어가지 않고 debug 로그를 남기고 끝낸다. 화면은 계속 동작 |
| 화면을 옮긴 직후 토스트 | 옮기기 전에 잡은 messenger 로 띄운다 (지금 동작 유지) |
| 글자 크기가 커서 상태 내용이 영역보다 큼 | `ElumStateBody` 가 스크롤로 받는다 — 잘리지 않는다 |
| 로딩 중 실패 | 같은 자리에서 바뀐다 (위치 고정 테스트) |

## 검증

- 위젯 테스트: 화면별 로딩·빈 상태·실패의 중심 위치가 같은지, 오늘 일과 실패가 칸 안인지.
- 토스트 테스트: 연달아 두 번 부르면 하나만 보이는지, messenger 가 없어도 예외가 없는지, 테마 모양인지.
- 기존 골든·`figma_conformance` 테스트가 깨지면 위치 변경이 의도된 것인지 보고 갱신한다.
- 새 iOS 시뮬레이터 실측: 토스트 7곳 + 오프라인 상태 실패 화면 위치.
