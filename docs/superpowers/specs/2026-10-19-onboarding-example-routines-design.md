# 온보딩 예시 일과 — 목표 질문 대신 "어떤 일과부터?"

## 1. 왜

실증 1차(#780 3-3절)에서 두 가지가 나왔다.

- 온보딩 "도움 목표"(`supportGoals`)는 보호자가 4개를 다 체크해서 의미가 없다.
- 처음 쓰는 보호자는 이 앱을 어떻게 쓰는지 모른다. 예시 일과가 몇 개 들어 있으면 "이런 느낌이구나"를 바로 안다.

그래서 목표 질문을 **일과 분류 질문**으로 바꾸고, 고른 분류의 **예시 일과를 실제 일과로 넣어 준다.**
튜토리얼이 아니다. 안내 말풍선·미리보기·코치마크 없이 예시가 홈에 들어가 있을 뿐이다.

시안: `.superpowers/brainstorm/…/onboarding-template-v3.html` (1안 확정본)

## 2. 목표 · 하지 않는 것

| 목표 | |
| --- | --- |
| 목표 화면 자리에 분류 선택 화면 (여러 개 선택, 건너뛰기) | |
| 온보딩을 마치면 고른 분류마다 예시 일과 2개가 **실제 일과로** 생긴다 | 누르면 카드가 보이고, 고칠 수 있고, 이룸이 기기에 바로 보인다 |
| 예시 일과는 홈에서 작은 `예시` 표시만 붙는다 | 나머지 동작은 일반 일과와 같다 |
| AI·크레딧을 쓰지 않는다 | 고정 문장 + 기존 픽토그램 |

**하지 않는 것**

- 홈의 "예시에서 더 고르기" 시트 — 다음 이슈. 지금은 일과 만들기 화면의 `예시 일과 둘러보기`(#777)가 있다
- `supportGoals` 서버 필드·AI 프롬프트 제거 — 묻지만 않는다
- 스타일별 그림 — 만화·실사 스타일 보호자도 예시는 픽토그램. 바꾸고 싶으면 기존 카드 수정(사진·그림)으로
- 요일 반복 (#782) · 일과 묶기 (#781)
- 튜토리얼·안내 말풍선·이룸이 화면 미리보기

**실패로 보는 것** — 예시를 만들다 실패해서 온보딩이 막히거나 홈이 깨지는 것. 예시는 덤이다.

## 3. 흐름

```
이름 → [분류 선택 — 새 화면] → 캐릭터 → 그림 스타일 → 비밀암호 → 보호자 홈
                                                         └ 프로필 저장 성공 후 예시 일과 생성 요청
```

| 화면 | 내용 |
| --- | --- |
| 분류 선택 | 제목 `{호칭}와 어떤 일과부터 해 볼까요?` · 설명 `고른 분류의 예시 일과를 넣어 둘게요. 여러 개 골라도 돼요.` · 분류 카드 4개(픽토그램 + 이름 + 한 줄 예) · 오른쪽 위 `건너뛰기` · 하단 `다음`(1개 이상 골라야 활성) |
| 건너뛰기 | 분류 없이 다음 화면으로. 예시를 만들지 않는다 |
| 보호자 홈 | 예시 일과가 일반 일과처럼 나온다. 카드 오른쪽에 `예시` 표시 |
| 예시 일과 열기 | 기존 일과 상세·편집 화면 그대로 |

`건너뛰기`와 `다음` 둘 다 같은 다음 화면(캐릭터)으로 간다. 고른 분류는 온보딩 상태에 들고 있다가 완료 때 쓴다.

## 4. 분류 4개 · 예시 일과 8개

| `SCHOOL_STUDY` | 학교·공부 | 등교 준비, 숙제 |

문구 규칙: 해요체 · 한 카드 한 행동 · `아이` 금지. 영어 번역을 함께 둔다. 나머지 언어(ja·zh·es)는 en 으로 대체(기존 `RoutinePhrases` 와 같은 규칙).

## 5. 서버

### 원본

예시 일과의 **단일 원본은 서버**다. 문장·픽토그램 id·순서·분류를 서버 리소스 파일 하나(언어별 문장 포함)에 둔다.
클라는 분류 코드 4개와 분류 화면 문구만 안다.

### API

`POST /api/routines/examples` — 본문 `{ "categories": ["MORNING_EVENING", "SCHOOL_STUDY"] }`

처리: 검증 > 이미 만들었는지 확인 > 분류별 예시 일과 생성 > 생성한 일과 목록 응답

| 항목 | 결정 |
| --- | --- |
| 대상 | 요청 보호자가 담당하는 현재 이룸이 프로필 (기존 일과 생성과 같은 방식으로 찾는다) |
| 상태 | `CONFIRMED` — 이룸이 기기에 바로 보인다 (보호자 결정 2026-10-19) |
| 언어 | **실제 넣은 문장의 언어**로 저장한다. 콘텐츠 언어(`resolveContentLocale`)가 ko 면 ko 문장·`language=KO`, 그 외는 en 문장·`language=EN`. ja·zh·es 일과에 영어 글이 들어가 음성·글꼴이 어긋나는 것을 막는다 (구현자 판단) |
| 보유 한도 | 예시는 `ROUTINE_MAX_COUNT` 검사를 하지 않고 집계(`countByCreatedBy`)에서도 뺀다. 예시 때문에 첫 일과 만들기가 막히면 안 된다 (구현자 판단) |
| 음성 | 일반 `CONFIRMED` 일과처럼 단계 음성 대기열에 올린다(`RoutineCreationWriter` 선례). 크레딧 없음 |
| 선례 | AI 없이 일과를 만드는 `RoutineService.duplicate` 를 따른다. `rawInputText`(NOT NULL)는 제목으로 채운다 |
| 예정 시각 | 오늘 날짜 + 일과별 기본 시각 (§5.1). 오늘 홈에 보이고, **다음 날부터는 다른 일과처럼 `지난 일과`로 내려간다** — 예시만 따로 남기지 않는다 (보호자 결정 2026-10-19). 반복은 #782 |
| 순서 | `displayOrder` 는 기존 최대값 뒤로, 분류 순서 → 예시 순서 |
| 표시 | 새 컬럼 `routine.is_example` (boolean, 기본 false). 응답 DTO 에 `isExample` |
| 크레딧 | 쓰지 않는다. AI 호출 없음 |
| 중복 방지 | 이 프로필에 `is_example = true` 일과가 이미 있으면 아무것도 만들지 않고 200 + 빈 목록. 온보딩 재시도·재설치로 두 번 불려도 한 벌만 |
| 검증 | 빈 목록 → 400 · 모르는 분류 코드 → 400 · 중복 코드는 한 번만 |

### 5.1 기본 예정 시각 (구현자 판단으로 정함 — 바꿔도 된다)

아침 준비 07:30 · 등교 준비 08:00 · 버스 타기 10:00 · 가게에서 사기 15:00 · 숙제하기 16:00 · 장난감 정리 18:00 · 식탁 차리기 18:30 · 잠자리 준비 21:00

### 마이그레이션

`V42__add_routine_is_example.sql` — `alter table routine add column is_example boolean not null default false`
(테이블·컬럼 실제 이름은 엔티티 매핑을 따른다)

## 6. 클라이언트

| 부분 | 내용 |
| --- | --- |
| 라우트 | `Routes.onboardingGoals` 자리를 분류 화면으로 교체 (이름 화면 → 분류 → 캐릭터) |
| 상태 | 온보딩 상태에 `selectedExampleCategories` (Set). 저장소에 들고 있어 앱이 꺼져도 유지 |
| 분류 enum | `RoutineExampleCategory` (apiValue = 서버 코드). 화면 문구는 ARB |
| `supportGoals` | 화면에서 묻지 않는다. 프로필 저장 시 빈 목록을 보낸다 (서버 필드·프롬프트는 그대로) |
| 생성 호출 | 이룸이 프로필이 생기면(`pin_screen` `_save` 의 `ensureProfile` 성공) 분류가 1개 이상일 때 `POST /api/routines/examples`. 이름·캐릭터 등 `complete()` 의 개별 PATCH 실패와 무관하게 부른다 (구현자 판단) |
| 홈 | 일과 카드에 `isExample` 이면 `예시` 표시 (디자인 시스템 배지 컴포넌트) |
| 초대로 들어온 보호자 | 분류 화면을 거치지 않는다. 예시를 만들지 않는다 |

### 실패 경로

| 상황 | 동작 |
| --- | --- |
| 예시 생성 실패(네트워크·5xx·타임아웃) | 온보딩은 그대로 홈으로 간다. 홈에 한 번 `예시 일과를 넣지 못했어요 (E-코드)` 스낵바. 고른 분류는 지우지 않고, 다음 홈 진입 때 1회 재시도 후 지운다 |
| 400 (분류 코드 불일치 — 앱·서버 버전 차이) | 재시도 없이 분류를 지운다. 로그 남김 |

| 픽토그램 id 를 클라가 못 찾음 | 기존 카드 그림 폴백 규칙 그대로 |

## 8. 남는 사본

- 클라 `routine_template_catalog.dart`(#777, AI 프롬프트용 26개)와 서버 `RoutineSuggestionCatalog` 는 이번 예시 카탈로그와 **용도가 다른 별도 목록**이다. 합치지 않는다. 홈 "예시에서 더 고르기" 시트를 만들 때 정리한다.
- 서버 `pictograms/` 와 클라 `assets/pictograms/` 는 이미 두 벌이다. 새 SVG 를 그리면 양쪽에 넣는다.

## 9. 구현자에게 맡기는 것

- 분류 카드·`예시` 배지의 세부 모양(디자인 토큰·기존 컴포넌트 안에서)
- 서버 리소스 파일 형식(기존 `RoutinePhrases` 방식을 따르면 된다)
