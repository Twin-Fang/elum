# 관리자 사용 분석: 리텐션 · 가입 단계 · 최근 가입·활동 · 계정 종류 (2026-11-16)

## 왜

사장님이 알고 싶은 것: **사람이 남는지 빠지는지, 어디서 빠지는지(무엇이 문제인지), 지금 인기가 있는지.**
대시보드에는 숫자·추이만 있고 "누가 언제 무엇을 했는지" 목록이 없다. 리텐션·가입 단계는 아예 없다.
테스트·내부·스토어 심사 계정이 섞여 숫자가 부풀어 있다 (2026-11-16 기준 52명 중 9명 이상).

2026-11-16 운영 스냅샷 (조회만): 가입 52 > 일과 만듦 29 > 카드 체크 11 > 기기 연결 6 > 스토어 결제 0.
10/21 이후 가입 14명 중 다음 날 재방문 2, 7일 안 3, 2주차 1. 주간 활성 6~12명.

## 목표 / 하지 않는 것 / 실패로 보는 것

- 목표: 대시보드를 열면 최근 가입·최근 활동이 바로 보이고, `사용 분석` 화면에서 가입 단계별 이탈과 가입 주차별 리텐션을 본다. 모든 숫자는 기본으로 **일반 계정만** 센다
- 하지 않는 것: 외부 BI(Metabase 등) 연결 — 규모가 커지면 그때. 앱(클라) 변경, 새 행동 이벤트 수집, 알림 전송
- 실패로 보는 것: 실제 사용자가 자동 규칙으로 숫자에서 사라지는 것 (자동 분류 금지, 제안만), 분석 쿼리 실패로 대시보드 전체가 깨지는 것

## 1. 계정 종류

- `member.account_kind` VARCHAR(20) NOT NULL DEFAULT `NORMAL` — `NORMAL` 일반 · `INTERNAL` 내부(운영자) · `TEST` 테스트 · `STORE_REVIEW` 스토어 심사
- 함께: `account_kind_changed_at`, `account_kind_changed_by` (관리자 아이디). 바꿀 때마다 `admin_audit_log` 에 전후 값 남김
- 관리자 회원 상세에 계정 종류 선택 + 저장. 회원 목록에 종류 배지와 필터
- 마이그레이션 V77 (추가만)

## 2. 분류 제안 (자동 분류 아님)

`사용 분석` 화면의 `분류 제안` 칸: 규칙에 맞는 `NORMAL` 계정을 이유와 함께 보이고, 버튼 한 번으로 분류. 숨기기(이 계정은 일반 맞음)도 가능 — `account_kind_reviewed_at` 으로 다시 안 띄움.

규칙 (상수로 한곳):
- **스토어 심사 의심**: Apple 로그인 + 이메일 가리기(privaterelay) + 사용자 일과 0개 + 방문한 날 1일 이하 + 가입 후 7일 지남
- **내부 의심**: 관리자 메모에 `내부`·`테스트` 포함

## 3. 대시보드 추가

- 요약 한 줄: 이번 주 쓴 사람(주간 활성) · 7일 리텐션(최근 4주 가입 기준) · 이번 주 카드 체크 수 — 각 숫자는 `사용 분석`으로 링크
- **최근 가입 10명**: 가입 시각, 로그인 방법, 일과 수, 기기 연결 여부, 마지막 활동, 계정 종류 배지 > 회원 상세 링크
- **최근 활동 20줄**: 가입 · 일과 만듦 · 카드 체크(같은 일과·같은 시간대는 묶어 "카드 3장 체크") · 기기 연결 · 스토어 구매. 시각, 회원 닉네임(> 상세), 무엇. **일과 원문·제목은 보이지 않는다** (서비스 원칙 5)
- 기존 숫자(오늘 신규 가입, 신규 가입·방문 추이)도 일반 계정만. 화면에 "내부·테스트·심사 계정 제외" 작은 글씨

## 4. 새 화면 `/admin/analytics` 사용 분석 (사이드바 운영 묶음)

기간: 최근 4 / 8 / 12주 (기본 8). `모두 포함해서 보기` 켜면 계정 종류 무관.

1. **가입 단계**: 가입 > 일과 만듦(예시 일과 제외) > 카드 체크(일과 단계 completed_at) > 기기 연결(device_link.redeemed_at) > 스토어 결제(subscription APPLE_IAP/GOOGLE_IAP 또는 크레딧 구매). 기간 안 가입자 기준, 단계별 인원·비율·이전 단계 대비 비율 막대
2. **가입 주차별 리텐션 표**: 행 = 가입 주, 칸 = 1주·2주·4주 뒤 그 주에 방문한 비율(member_daily_visit). 아직 안 지난 칸 `-`, 방문 기록 시작(2026-10-21) 전 가입 주는 `기록 전`
3. **주별 추이**: 신규 가입 · 주간 활성 · 일과 만듦 · 카드 체크 (기존 추이 그래프 부품 재사용)
4. **마지막 활동 분포**: 1일 · 7일 · 30일 · 그 이상 · 없음 (이탈 규모)
5. **플랫폼**: push_device 기준 iOS · Android 회원 수
6. **분류 제안** (2절)

## 5. 구조

- 집계 SQL 은 `AdminUsageAnalyticsQueries` 한곳 (네이티브 SQL, 계정 종류 조건 한 줄로 공유) — 나중에 외부 도구로 옮길 원본
- 서비스 `AdminUsageAnalyticsService` (기존 `AdminStatsCache` 로 짧게 캐시), 컨트롤러 `AdminAnalyticsController`, 템플릿 `admin/analytics.html`, 대시보드 조각 추가
- 계정 종류 조건은 기존 `MemberStatsService` 의 가입·방문 집계에도 적용

## 실패 경로
