# 앱 공지·이벤트 팝업 — 관리자가 올리고 보호자 홈에 뜬다

> 상태: 설계 (2026-09-23). 세부 결정은 사용자가 위임했다 — "기간·문구 등 다 감안해서 너가 해줘야 해".
> 사용자가 정한 것: **보호자 홈에서만** 뜬다 · **일주일간 보지 않기 / 닫기** · 관리자 화면에서 올린다 · 관리자 화면에 **미리보기** · **게시 기간**.
> 관련: #279 (점검 모드·강제 업데이트 — `/api/app/status`) · #278 (약관을 관리자에서 관리) · #349 (팝업 부품) · #281 (이룸이 화면에는 광고를 넣지 않는다)

## 1. 왜

베타 기간에 AI 생성 한도를 걸면 보호자에게 **미리 알려야** 한다 ("베타 기간이라 하루 N개까지 만들 수 있어요").
이벤트·업데이트 안내도 같은 통로가 필요하다. 지금 앱에는 공지를 띄울 길이 없다 — 점검 모드는 앱을
통째로 막고, 강제 업데이트는 버전 안내뿐이다.

## 2. 결정

| 쟁점 | 결정 | 왜 |
|---|---|---|
| 어디에 뜨나 | **보호자 홈에서만** (사용자 결정). 이룸이 화면·로그인 전·일과 만들기 흐름 중에는 뜨지 않는다 | 이룸이 화면은 "한 화면에 행동 하나" 원칙이 있다(#281 과 같은 판단) |
| 언제 뜨나 | 앱을 켠 뒤 보호자 홈에 **처음 들어올 때 한 번**. 홈을 오갈 때마다 뜨지 않는다 | 설정에 갔다 돌아올 때마다 뜨면 방해다 |
| 여러 개면 | **한 팝업 안에서 슬라이드로 넘겨 본다** (2026-09-23 사용자가 참고 화면으로 정함 — 아래 2-1). 순서는 우선순위 높은 것 → 같으면 게시 시작이 늦은 것. 한 팝업에 최대 5장 | 팝업을 연달아 띄우지 않고 한 번에 보여준다 |
| 내용 | 슬라이드마다: 이미지(선택, **위쪽**) · 제목(필수, `**강조**` 표기 가능) · 본문(필수) · 버튼(선택: 문구 + 링크) | 참고 화면 구조 그대로. 이미지가 없으면 글만 |
| 게시 기간 | 시작·종료 일시(한국 시각). 종료를 비우면 끌 때까지. **서버가** 기간을 판단한다 | 기기 시간이 틀려도 끝난 공지가 뜨지 않게 |
| 보지 않기 | 오른쪽 위 **☐ 일주일간 보지 않기** 체크 후 ✕ 로 닫으면, 이 팝업에 있던 공지 **전부**를 숨긴다. 일수는 관리자 설정 `NOTICE_HIDE_DAYS`(기본 7, 1~30 — 7 이 아니면 "N일간 보지 않기") | 참고 화면처럼 팝업 하나에 체크박스 하나. 공지마다 일수가 다르면 한 체크박스로 설명할 수 없다 |
| 닫기 | 체크하지 않고 ✕ 로 닫으면 이번 실행에서만 닫는다. 다음에 앱을 켜면 다시 뜬다. 바깥(어두운 배경)을 눌러도 같다 | 흔한 공지 팝업 관례 |
| 고친 공지 | 관리자가 **"다시 보이게"**를 켜고 저장하면 판(revision)이 올라가, 숨긴 사람에게도 다시 뜬다. 끄고 저장하면(오타 수정 등) 숨긴 사람에게는 안 뜬다 | 내용이 크게 바뀐 이벤트는 다시 알려야 한다 |
| 대상 | 플랫폼: 전체 / iOS / Android | 스토어별 안내가 있을 수 있다. 버전·요금제 조건은 하지 않는다 |
| 관리자 미리보기 | 편집 화면 오른쪽에 **휴대폰 틀(393×852) 안에 앱 팝업과 같은 치수**로 그린다. 입력하는 대로 바로 바뀐다. 이미지도 올리기 전에 미리 본다 | 올리기 전에 앱에서 어떻게 보일지 알아야 한다 |
| 문구 도움 | 편집 화면에서 저장소 용어 규칙의 금지어(`아이`·`아동`·`기기`·`모드`·`강화`)를 입력 즉시 짚어 준다(경고일 뿐 막지 않는다). 해요체 안내 한 줄 | 화면에 나가는 모든 문구는 `docs/08-design-principles.md` 를 따른다 |

### 2-1. 모양 — 참고 화면을 휴대폰에 옮긴다

사용자가 보여준 참고(사내 웹 공지 팝업, 명세 폴더의 참고 이미지 3장): 위 절반 큰 그림, 아래 제목(일부 파란 강조)·
설명·가운데 버튼, 맨 아래 점(슬라이드 위치)과 ← →, 오른쪽 위 "☐ 다시 보지 않기"와 ✕.

```
┌──────────────────────────────┐   ← 카드: 화면 폭의 90%(최대 360), 모서리 20
│              ☐ 일주일간 보지 않기 ✕│   ← 그림 위에 얹는다(반투명 흰 알약 배경)
│                              │
│         [ 그림 16:10 ]         │   ← 이미지 없으면 이 영역을 없앤다
│                              │
├──────────────────────────────┤
│  별도 설정 없이 **하이웍스와 연동** │   ← 제목: 18, 굵게, 가운데. **…** 는 브랜드 색
│  설명 한두 줄 …               │   ← 본문: 14, 가운데, 길면 이 부분만 스크롤
│       [ 버튼 문구 ]           │   ← 선택. 없으면 자리를 없앤다
│    ←     ● ○ ○ ○     →       │   ← 한 장이면 점·화살표를 숨긴다
└──────────────────────────────┘
```

- 옆으로 밀어 넘긴다. 50대 보호자가 밀기를 모를 수 있어 ← → 화살표도 둔다(첫 장에서 ←, 끝 장에서 → 숨김).
- 강조 표기는 `**…**` 한 가지뿐이다. 짝이 안 맞으면 관리자 저장을 거부한다.

## 3. 구조

### 3-1. 서버

**표 `app_notice`**

| 컬럼 | 뜻 |
|---|---|
| `id` | UUID |
| `title` | VARCHAR(40), 필수 |
| `body` | VARCHAR(1000), 필수, 줄바꿈 유지 |
| `image_key` | 저장된 이미지 키, 선택 |
| `button_label` · `button_url` | 둘 다 있거나 둘 다 없다. URL 은 `https://` 만 |
| `platform` | `ALL` · `IOS` · `ANDROID` |
| `priority` | 정수, 클수록 먼저 (기본 0) |
| `revision` | "다시 보이게" 저장마다 +1 (기본 1) |

보지 않기 일수는 공지마다 두지 않고 관리자 설정 `NOTICE_HIDE_DAYS`(`ConfigKey`, 기본 7, 1~30)로 둔다.
| `starts_at` · `ends_at` | 한국 시각. `ends_at` 은 NULL 이면 끝없음. `starts_at < ends_at` |
| `enabled` | 관리자가 켜고 끈다 (기간과 별개) |
| `created_by` · `updated_by` | 관리자 아이디 |
| `created_at` · `updated_at` | |

마이그레이션 번호는 **머지 순서대로** 잡는다 — 다중 보호자 1단계(#360)도 V22 를 계획하고 있으므로 먼저
머지되는 쪽이 V22, 나머지가 다음 번호로 바꾼다.

**앱 API (인증 없음)**

- `GET /api/app/notices?platform=IOS` → `{ "hideDays": 7, "notices": [ … ] }`. 지금 게시 중(`enabled` ·
  기간 안 · 플랫폼 일치)인 공지를 우선순위·시작 시각 순으로 최대 5개. 앱이 기기에 숨긴 것을 빼고 남은 것을
  슬라이드로 보여준다(숨김은 기기에 있으므로 서버는 거르지 않는다).
  항목: `id, revision, title, body, imageUrl|null, button{label,url}|null`. `title` 의 `**…**` 는 그대로 보낸다.
- `GET /api/app/notices/{id}/image` → 이미지. 게시 중이 아니면 404.
- `SecurityConfig` 에서 두 GET 을 `permitAll`. 점검 모드 필터는 막지 않아도 된다(점검 중이면 앱이 점검 화면만 띄운다).

**관리자 (`/admin/notices`)** — 약관 관리(`consents`) 화면과 같은 모양
- 목록: 상태 배지(**예약** · **게시 중** · **끝남** · **꺼짐**), 제목, 기간, 플랫폼, 우선순위, 수정 시각
- 새로 만들기 · 편집 (같은 폼) — 왼쪽 입력, 오른쪽 미리보기
- 이미지 올리기(png·jpg·webp, 2MB 이하) · 지우기
- 켜기/끄기, 삭제(확인 창). 게시 중인 것을 지울 때는 한 번 더 묻는다
- CSRF 는 기존 관리자 폼과 같다

### 3-2. 앱

- `NoticeRepository.fetch(platform)` — 실패하면 빈 목록(로그는 남긴다: `AppLogger.error`, 에러 화면은 없다)
- 기기 저장 `notice.hidden.{id}` = `{revision, until(ms)}` — 같은 revision 이고 `until` 이 지나지 않았으면 숨김
- 보호자 홈이 **앱 실행 중 처음** 그려질 때 한 번 부른다(프로세스 단위 플래그)
- 팝업 모양은 2-1. 카드 폭 = 화면 폭 × 0.9 (최대 360), 모서리 20, 이미지 16:10(위 모서리만 둥글게), 글 영역 여백 20,
  제목 18/굵게, 본문 14, 선택 버튼은 기존 주 버튼 모양(높이 44), 점 8 · 간격 6, 화살표 누름 영역 44×44
- 슬라이드는 `PageView`. 오른쪽 위 "☐ 일주일간 보지 않기"(체크박스 + 글자 전체가 누름 영역) · ✕(누름 영역 44×44)
- ✕ 또는 바깥을 누르면 닫힌다. 체크돼 있으면 **이 팝업에 있던 공지 전부**를 `hideDays` 동안 숨긴다
- 선택 버튼 → 외부 브라우저로 링크를 연다(`https://` 만)
- 접근성: 모든 버튼에 읽을 이름(#339 의 `AppPressable.semanticLabel`) — ✕ `공지 닫기`, 화살표 `이전 공지`·`다음 공지`,
  체크박스는 상태까지. 슬라이드가 바뀌면 "2/4" 처럼 위치를 읽어 준다. 글꼴 2.0 에서도 버튼이 가려지지 않게 본문만 스크롤

## 4. 엣지 케이스

| # | 경우 | 동작 | 확인 |
|---|---|---|---|
| N1 | 오프라인·서버 오류로 공지를 못 받음 | 팝업 없이 지나간다. 로그만 남긴다 — 공지는 부가 기능이라 앱을 막지 않는다 | 앱 위젯 테스트 + 실기기(비행기 모드) |
| N2 | 응답 형식이 깨짐·필드 빠짐 | 그 항목만 버리고 나머지를 쓴다. 앱이 죽지 않는다 | 앱 단위 테스트 |
| N3 | 이미지 로드 실패 | 이미지 자리를 없애고 글만 보인다(빈 칸 금지) | 앱 위젯 테스트 |
| N4 | 본문이 길다 (1000자) | 본문만 스크롤, 버튼은 항상 보인다 | 앱 위젯 테스트(작은 화면·글꼴 2.0) |
| N5 | 기기 시간이 틀리다 | 게시 기간은 서버가 판단. 숨김 만료만 기기 시간 기준(받아들인다) | 서버 테스트 |
| N6 | 끝난 공지를 이미 받아 둔 채 앱을 켜 둔다 | 다음 실행에 서버가 빼므로 안 뜬다. 한 실행 안에서는 이미 한 번 떴으므로 문제없다 | — |
| N7 | 보지 않기 누른 뒤 관리자가 "다시 보이게"로 고침 | revision 이 달라 다시 뜬다 | 앱 단위 테스트 |
| N8 | 보지 않기 누른 뒤 오타만 고침("다시 보이게" 끔) | 안 뜬다 | 앱 단위 테스트 |
| N9 | 게시 중인 공지가 여러 개 | 숨기지 않은 것 중 첫째만. 닫으면 다음 실행에 그다음 | 앱 단위 테스트 |
| N10 | 이룸이 휴대폰(연결 암호로 붙은 폰) | 보호자 홈이 아니므로 안 뜬다 | 앱 위젯 테스트 |
| N11 | 일과 만들기 도중 홈으로 돌아옴 | 이번 실행에서 이미 한 번 불렀으면 안 뜬다 | 앱 위젯 테스트 |
| N12 | 버튼 링크가 `https://` 가 아님 | 관리자 저장 거부(에러 코드). 앱도 한 번 더 걸러 버튼을 숨긴다 | 서버 테스트 + 앱 단위 테스트 |
| N13 | 버튼 문구만 있고 링크가 없음(또는 반대) | 저장 거부 | 서버 테스트 |
| N14 | 시작 ≥ 종료 | 저장 거부 | 서버 테스트 |
| N15 | 제목·본문이 비었거나 공백뿐 · 길이 초과 | 저장 거부(에러 코드), 500 이 아니다 (#257 의 교훈) | 서버 테스트 |
| N16 | 이미지 형식·크기 위반 | 저장 거부. 올리던 폼 내용은 남는다 | 서버 테스트 |
| N17 | 게시 중인 공지를 끄거나 지움 | 다음 실행부터 안 뜬다. 지우면 이미지 파일도 지운다 | 서버 테스트 |
| N18 | 관리자 두 명이 같은 공지를 동시에 고침 | 마지막 저장이 남는다(관리자는 소수). 수정 시각을 목록에 보인다 | — |
| N19 | 점검 모드가 켜짐 | 앱이 점검 화면만 띄우므로 공지는 뜨지 않는다 | — |
| N20 | 금지어가 들어감 | 편집 화면이 짚어 준다(저장은 막지 않음). 법적 문구가 필요할 때가 있어서다 | 관리자 화면 확인 |
| N21 | 미리보기와 앱의 모양이 다르다 | 미리보기는 `ElumDialogCard` 치수를 그대로 쓴다. 구현 뒤 앱 캡처와 미리보기를 나란히 대조해 보고서에 남긴다 | 실기기 + 관리자 화면 캡처 |
| N22 | 공개 API 를 누가 마구 부름 | 응답이 작고 캐시 가능(`Cache-Control: max-age=60`). 쓰기 경로가 아니다 | — |
| N23 | 공지가 한 장뿐 | 점·화살표를 숨긴다 | 앱 위젯 테스트 |
| N24 | 게시 중인 공지가 6개 이상 | 서버가 우선순위 순 5개만 준다 | 서버 테스트 |
| N25 | 제목의 `**` 짝이 안 맞음 | 관리자 저장 거부. 앱도 짝이 안 맞으면 강조 없이 글자 그대로(`**` 는 지운다) | 서버 테스트 + 앱 단위 테스트 |
| N26 | 일부 공지만 숨겨진 상태에서 새 공지가 올라옴 | 숨기지 않은 것(새 공지 포함)만 슬라이드로 뜬다 | 앱 단위 테스트 |
| N27 | 체크하고 닫았는데 그 사이 슬라이드를 끝까지 안 넘김 | 안 본 슬라이드도 함께 숨긴다 — 체크박스는 "이 팝업"에 대한 것이다. 문구로 오해가 없게 "일주일간 보지 않기"(공지 하나가 아니라 팝업 전체) | 앱 단위 테스트 |
| N28 | 이미지가 있는 슬라이드와 없는 슬라이드가 섞임 | 카드 높이가 슬라이드마다 튀지 않게, 이미지 영역은 이미지가 하나라도 있으면 모든 슬라이드에 두고 없는 슬라이드는 연한 배경으로 채운다 | 앱 위젯 테스트 |

## 5. 검증

- 서버: 게시 판단(기간·켜짐·플랫폼·순서), 저장 검증(N12~N16), 이미지 올리기·서빙·삭제, 관리자 화면 렌더(태그 균형 테스트 포함).
- 앱: 숨김 판단(N7~N9), 실패 경로(N1~N4), 보호자 홈에서만(N10·N11), 접근성 이름.
- 실기기: 공지 하나를 운영 관리자에서 올려 보호자 홈에서 뜨는지 → "일주일간 보지 않기" → 앱 재실행에서 안 뜨는지 → "다시 보이게"로 고치면 다시 뜨는지. 캡처를 보고서에 남긴다.
- 운영에 올린 시험 공지는 확인 뒤 끈다.
