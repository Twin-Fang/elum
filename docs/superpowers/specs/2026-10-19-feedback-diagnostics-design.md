# 의견 보내기 진단 정보 확장 설계

## 의도와 이유

2026-10-19 카카오 로그인 실패 건에서 폰이 보낸 의견으로 원인을 확정하지 못했다.
의견에는 앱 버전과 OS 문자열만 있어서 "설치 경로"와 "앱 서명 해시"를 알 수 없었고, 원인 추정이 두 번 틀렸다.
의견 한 건만 보고 원인을 좁힐 수 있게 진단 정보를 늘린다.

## 목표

- 의견 첨부 기록 머리글에 진단 구역을 더해, 로그인 실패 같은 환경 의존 문제를 의견 한 건으로 판별한다.
- 읽지 못한 값은 `-`로 두고 전송을 막지 않는다 (기존 머리글과 같은 방침).
- 사용자가 보내기 전에 진단 정보가 함께 간다는 것을 본다.

## 하지 않는 것 (비목표)

- IMEI, 시리얼, 광고 ID 같은 **기기 하드웨어 식별자는 수집하지 않는다.**
  안드로이드 10부터 일반 앱은 읽을 수 없고, Google Play가 금지하며, 서비스 원칙에도 어긋난다.
- 위치, 연락처, 설치된 다른 앱 목록, 진단명, 카드 원문은 담지 않는다.
- 서버 스키마와 API는 바꾸지 않는다. 머리글은 이미 `app_log` 본문에 들어간다.

## 구조

- 머리글 생성은 `core/logger/app_log_header.dart` 한 곳이다. 구역별로 값을 읽는 함수를 나눠 한 파일이 300줄을 넘지 않게 한다.
- 안드로이드 전용 값(설치 경로, 서명 해시, 카카오톡 버전)은 `MainActivity.kt`의 MethodChannel 하나로 읽는다.
- 값 읽기는 전부 try/catch로 감싸 실패하면 `-`로 둔다. 읽다가 의견 전송이 막히면 안 된다.
- 단위 시험: 머리글 구역 이름과 순서, 읽기 실패 시 `-`, 설치 식별자가 한 번 만들어진 뒤 유지됨.

## 화면

- 의견 보내기 화면의 "앱 상태 기록 보내기" 안내 문구에 "기기 정보(모델, 설치 경로 등)도 함께 가요"를 더한다.
- 문구는 해요체 · 능동형. "기기"는 서비스 용어 규칙에 따라 "휴대폰"으로 쓴다.

## 법적 문구

- 개인정보처리방침의 의견 보내기 수집 항목에 위 진단 항목을 더한다. 번들 문서 버전과 서버 시딩 txt는 글자까지 같게 맞춘다.
- 법적 효력이 있는 문장이라 변경 근거를 남기고 사용자 확인을 받은 뒤 반영한다.
- 방침 시행일 전에는 새 항목 전송을 켜지 않는다. 구체적인 시행일은 사용자가 정한다.

## 실패 경로

- 플러그인이나 네이티브 호출이 실패하면 그 줄만 `-`.
- 저장소를 못 읽으면 설치 식별자는 `-`.
- 첨부 기록이 비어 있으면 기존처럼 글만 보낸다.

## 빌더에게 남기는 것

- 구역 안의 줄 순서와 표기 문구
- MethodChannel 이름과 Kotlin 구현 세부
- iOS에서 읽을 수 있는 값의 범위 (읽을 수 없으면 `-`)

## 결정 기록

- 하드웨어 식별자 요청은 불가능, 금지, 서비스 원칙 위배로 대체안(설치 식별자)을 제안했고 사용자가 승인했다 (2026-10-19, 채팅).
- 방침 시행일은 아직 정하지 않았다 (사용자 결정 필요).
