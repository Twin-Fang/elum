# 카드 검토 화면 코치마크 설계

- 작성일: 2026-10-21
- 대상 화면: `client/lib/features/guardian/presentation/card_review_screen.dart` (일과를 만든 직후 카드를 검토·수정·저장하는 화면)
- 시안: **없음.** 사용자가 기존 코치마크 모양으로 알아서 만들라고 위임했다.

## 1. 왜

- 보호자가 카드 검토 화면에서 **`카드 저장하기` 를 누르지 않고 나간다.** 운영 DB 에 `PENDING_REVIEW`(임시저장) 일과가 많이 쌓여 있다.
- 처음 온 보호자는 카드 고치는 법(특히 그림 바꾸기)과 순서 바꾸는 법(버튼 > 길게 눌러 끌기)을 모른다.
- 목표: 처음 한 번, **짧게(3단계)** 어려운 것만 알려 주고, 마지막에 **저장해야 완성된다**를 가장 강하게 남긴다.

## 2. 목표 · 비목표 · 반목표

목표
- 카드 검토 화면 첫 진입 때 3단계 코치마크를 한 번 띄운다.
- 각 단계는 실제 화면의 해당 버튼을 가리키고 누르기 시범을 보여 준다.
- 마지막 단계는 `카드 저장하기` 버튼이다.
- 상단바의 `?` 버튼으로 언제든 다시 볼 수 있다 (사용자 요청).

비목표
- 이름만 봐도 아는 기능(카드 넘기기, `카드 추가`, 카드 위 ✕ 삭제)은 안내하지 않는다. 사용자 요청: 단계를 적게, 어려운 기본 기능만.
- 저장하지 않고 나가는 흐름 자체(나가기 팝업 문구, 임시저장 정리·알림)는 바꾸지 않는다.
- 카드 수정 시트 안의 별도 코치마크는 만들지 않는다. 그림 바꾸는 법은 1단계 문구에 넣는다.
- 설정의 `다시 보기` 줄은 만들지 않는다. 이 화면은 일과가 있어야 열리므로 설정에서 바로 데려갈 수 없다. 대신 화면 안 `?` 버튼을 둔다.
- 새 시범 위젯은 만들지 않는다.

반목표 (돌아가도 실패)
- 코치마크가 실제 카드 순서·내용·서버 데이터를 바꾼다.
- 코치마크가 매번 뜨거나, 닫을 방법 없이 반복된다.
- 코치마크 때문에 저장·뒤로가기·나가기 팝업이 막히거나 엉뚱하게 동작한다.
- 문구가 실제 버튼 이름과 어긋난다.

## 3. 단계 (3단계)

| # | 단계(enum) | 가리키는 대상 | 시범 | 문구(ko, `*강조*`) |
|---|---|---|---|---|
| 1 | `editCard` | 도구 줄 `이 카드 수정` 버튼 | 누르기(손가락 + 링) | 보고 있는 카드의 *글과 그림*을 고쳐요\n그림은 *내 사진*으로 바꿀 수도 있어요 |
| 2 | `reorderCards` | 도구 줄 `카드 순서 변경` 버튼 | 누르기 | 여기를 누른 뒤 카드를 *길게 눌러 끌면*\n순서가 바뀌어요 |
| 3 | `save` | 하단 `카드 저장하기` 버튼 | 누르기 | 다 고쳤으면 꼭 *카드 저장하기*를 눌러요\n눌러야 일과가 완성돼요 |

- 시범은 기존 누르기 시범(`coach_demo_layers.dart`)을 재사용한다.
- **카드가 1장이면 2단계를 뺀다** (순서를 바꿀 수 없다). 단계 목록은 켤 때의 카드 수로 정한다. 그 밖에 대상을 못 재면 `CoachMarkOverlay` 의 기존 건너뛰기를 쓴다.
- 1단계는 사진 버튼 이름을 직접 말하지 않는다. 수정 시트의 사진 자리는 그림 유무에 따라 `사진 추가`(`cardAddPhoto`) / `사진 바꾸기`(`cardPhotoChange`) 로 갈리고, 서버 id 없는 카드는 사진 칸이 없다. 그래서 `내 사진으로 바꿀 수도` 로 둔다.
- 3단계 문구는 "이룸이에게 간다"고 말하지 않는다. 저장 뒤 이룸이 화면에 언제 나가는지는 오늘 보내기 흐름에 따라 다를 수 있어 `일과가 완성돼요` 로 둔다.

## 3-1. 다시 보기 `?` 버튼

- 위치: 카드 검토 화면 상단바(`RoutineFlowTopBar`) 오른쪽, `임시저장` 바로 왼쪽.
- 아이콘: 기존 `AppAssets.iconQuestionCircle`(보상 설정·크레딧 안내에서 쓰는 물음표 원)을 상단바 아이콘 크기(24)로 그린다. 색은 상단바 아이콘과 같은 토큰. 누름 영역 40×40 (뒤로·집 버튼과 같은 방식: 자리는 아이콘 크기, 누름 영역만 덮음).
- 낭독: `사용법 보기` (ARB 키 1개 추가).
- 누르면: 저장된 "봤음" 기록과 무관하게 지금 카드 수 기준 단계로 코치마크를 다시 켠다. 기록은 바꾸지 않는다.
- 다른 화면에는 나오지 않는다: `RoutineFlowTopBar` 에 선택 인자 `onHelp`(null 이면 안 그림)를 더하고, 카드 검토 화면만 넘긴다. 순서 변경 모드는 상단바가 바뀌므로 자연히 안 보인다.
- 시안이 없어 디자이너 확인 대상이다. 완료 보고에 캡처와 함께 적는다.

## 3-2. 구현 중 더한 것 (사용자 요청)

- `?` 버튼은 공통 위젯 `CoachHelpButton` 하나로 두고 **일과관리 머리(제목 옆)에도** 넣는다. 홈에는 넣지 않는다.
- `?` 그림은 자리 24 안에 20 으로 그린다. 물음표 원은 테두리까지 꽉 찬 그림이라 24 로 그리면 옆 24 아이콘보다 커 보인다.
- 일과관리 코치마크의 구멍이 칸 자리 전체(넓음)를 재고 있어 실제 칸(그림 + 이름, 자리 왼쪽 위에 붙음)과 어긋났다. 코치마크 키를 그려진 칸에 단다.
- 코치마크 시작 판단(화면 맨 앞·전환 끝·추적 허용 팝업 끝·재시도)이 홈·일과관리·카드 검토 세 곳에 복사돼 `CoachMarkStartGate` 로 모았다.

## 4. 언제 띄우나

조건을 모두 만족하는 첫 순간 한 번.
1. 카드가 1장 이상이다 (빈 상태 `CardReviewEmpty`·실패 화면이 아니다).
2. 순서 변경 모드가 아니다.
3. 저장 중(busy)이 아니다.
4. 이 화면 라우트가 맨 앞이고 전환 애니메이션이 끝났다.
5. 추적 허용 팝업이 끝났다 (`waitForTrackingPrompt`, 일과관리 트리거와 같다).
6. 이 기기에서 아직 본 적이 없다.

- 새로 만든 일과(`PENDING_REVIEW`)든 홈에서 편집하러 온 저장된 일과든 같은 화면이므로 **처음 들어온 쪽에서 한 번** 뜬다.
- 한 번 띄우면 끝까지 보든, ✕ 로 닫든, 뒤로가기로 닫든 "봤음"으로 남긴다.
- 저장소를 못 읽으면 **봤다고 친다** (기존 코치마크와 같은 규칙: 닫을 방법 없는 반복 방지).
- 같은 실행에서 두 번 뜨지 않는다 (`_hasShownThisRun`).
- 온보딩 초기화(`resetCoachMarks`)는 이 기록도 지운다.

## 5. 구조 (기존 홈 코치마크 패턴을 따른다)

실제 화면 위에 막을 덮는 방식이다. 일과관리처럼 별도 안내 무대(가짜 화면)는 만들지 않는다. 이 화면은 항상 실제 카드와 버튼이 있어서 가리킬 대상이 늘 있다.

| 역할 | 파일 | 내용 |
|---|---|---|
| 응용 | `features/guardian/application/card_review_coach_notifier.dart` | `CardReviewCoachStep` enum, `CardReviewCoachState`, `CardReviewCoachNotifier`(`maybeStart(cardCount)`·`next`·`finish`). `RoutineManageCoachNotifier` 와 같은 규칙 |
| 저장 | `core/storage/local_storage.dart` 외 구현 2곳(`shared_prefs_storage.dart`, `in_memory_storage.dart`) | `isCardReviewCoachSeen` / `setCardReviewCoachSeen`, `resetCoachMarks` 에 포함 |
| 표현 | `features/guardian/presentation/widgets/card_review_coach_mark.dart` | `HomeCoachMark` 처럼 루트 오버레이(`OverlayPortal`)에 `CoachMarkOverlay` 를 그린다. 단계 > `CoachMarkStep` 매핑, 띄울 때 판단(4장 조건) |
| 시범 | `features/guardian/presentation/widgets/coach_demo_layers.dart` | 새 파일 없음. 기존 누르기 시범을 재사용 |
| 화면 연결 | `card_review_screen.dart`, `card_review_parts.dart`, `routine_flow_scaffold.dart`, `routine_flow_top_bar.dart` | `GlobalKey` 3개: 수정·순서 버튼, 저장 버튼. 도구 버튼(`_ToolButton`)에 key 를 받을 자리를 연다. 상단바 `onHelp`, 스캐폴드가 그 값을 넘기고 코치 중 뒤로가기를 가로챌 자리 |
| 문구 | `l10n/app_ko.arb` 외 en·ja·zh·es | 3개 키 `cardReviewCoach*` + `?` 낭독 1개 (ko 위 표, 나머지는 번역) |

- 막은 루트 오버레이에 그린다. `RoutineFlowScaffold` 의 상단바·하단 버튼까지 덮고 누름을 막는다.
- 뒤로가기는 **안내만 닫는다.** 화면을 떠나거나 나가기 팝업을 띄우지 않는다.
  - 주의: `RoutineFlowScaffold` 는 `backLeavesFlow: true` 라 자기 `PopScope` 로 `onBack`(나가기 팝업)을 부른다. 오버레이 `PopScope` 도 같은 라우트에 걸리면 둘 다 불린다(홈에는 이 문제가 없었다).
  - 스캐폴드의 `PopScope` 는 `onBack` 전에 `_mayLeave`(나가기 확인 팝업)부터 띄운다. 그래서 `onBack` 분기만으로는 막히지 않는다.
  - 스캐폴드에 "지금 뒤로가기를 가로챌지" 선택 인자를 더해, 코치마크가 켜져 있으면 `_mayLeave` 전에 안내 닫기만 하고 끝낸다. 두 `PopScope` 의 호출 순서와 무관하게 팝업이 안 뜨는지 위젯 테스트·실기기로 확인한다.
- 시범은 `ExcludeSemantics` + `IgnorePointer` 층에 그림만 그린다(기존 구조). 동작 줄이기 켠 사람에게는 멈춘 장면만 보인다(`buildCoachDemoLoop` 기존 동작).

## 6. 실패 경로

| 상황 | 동작 |
|---|---|
| 저장소 읽기 실패 | 봤다고 치고 띄우지 않는다. `AppLogger.error` |
| 저장소 쓰기 실패 | 이번 실행에서는 다시 안 뜬다. 다음 실행에 한 번 더 뜰 수 있다 (허용) |
| 가리킬 위젯을 못 잼 (화면 밖 등) | 그 단계 건너뜀 (기존 오버레이 동작) |
| 코치마크 중 화면이 사라짐 (라우트 교체 등) | 위젯 dispose 때 `finish()` 를 불러 봤음으로 남긴다 |
| 화면 회전·분할 | 기존 오버레이가 다시 잰다 |
| 카드 그림이 아직 그려지는 중 | 상관없다. 대상은 버튼이다 |
| 글자 크기 최대 | 기존 오버레이가 배율 1.5 로 묶는다. 문구는 두 줄 이내로 쓴다 |

## 7. 검증

앱 테스트 코드는 #848 에서 지웠다(CI 도 분석만 한다). 그래서 자동 테스트는 쓰지 않고 아래로 확인한다.
- `flutter analyze` (바꾼 파일) 경고 0.
- iOS 시뮬레이터 실측 (Maestro, 기존 로그인 세션):
  - 카드 검토 화면 첫 진입 > 3단계 차례로 캡처 (라이트·다크)
  - 끝까지 본 뒤 다시 들어오면 안 뜸
  - `?` 로 다시 켜짐
  - 코치마크 중 뒤로가기 > 안내만 닫히고 나가기 팝업 없음
  - 카드 1장 일과에서 순서 변경 단계 빠짐 (가능하면. 카드를 지워 1장으로 만든다)
- 일과 생성은 AI 비용이 든다. 이미 있는 임시저장 일과를 열어 확인하고, 새로 만들어야 하면 한 번만 만든다.
