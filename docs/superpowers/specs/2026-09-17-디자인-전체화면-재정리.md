# 1. 전체 플로우 — Before / After

## 1-1. 진입 ~ 온보딩

```
Before (현재 앱)
로그인 → 약관 → 이름 → 목표 4개 → 캐릭터 → PIN → 보호자 홈

After
로그인 → 약관 → 【역할 선택】🆕 ─┬─ 보호자 ─→ 이름 → 목표 4개 → 캐릭터 → PIN → 보호자 홈
                                │                              └→ 【기기 연결 코드 발급】🆕
                                │                                  (건너뛰기 가능)
                                └─ 당사자 ─→ 【코드 입력】🆕 ─→ 당사자 홈
```

> **당사자 기기는 온보딩을 하지 않는다.** 이름·목표·캐릭터·PIN은 전부 보호자가 정한 값을
> 그대로 받는다. 당사자가 입력하는 것은 **연결 코드 하나뿐**이다. (이슈 #158)

## 1-2. 일과 만들기 (보호자)

```
Before
일과 입력 → AI 질문 → 카드 생성 → 카드 검토 → 아이 화면으로

After 🔒 확정
일과 입력 → AI 질문 → 카드 생성 → 카드 검토 → 【보상 설정】🆕 → 사용자 화면으로
                                       ↑              ↑
                                  추가·삭제·순서    건너뛰기 가능
```

> 🔒 **보상 설정은 카드 검토 "다음"이다.** 2026-09-13 명세는 카드 생성 "앞"(`3/4`)이었으나
> **이 문서 기준으로 뒤집는다.** 카드를 다 보고 나서 보상을 정하는 편이 맥락이 잡힌다.
> → 진행 표시는 `4 / 4`, 카드 검토는 `3 / 4`.

## 1-3. 당사자 흐름

```
당사자 홈 → 카드 수행 → 보상 완료
   ↑           ↑            ↑
보상 배너   상단 고정 바   보상 문구 1줄
"오늘 전부 완료" 상태
```

# 2. 신규 화면 ①②③ — 역할 선택과 기기 연결 🆕

> 근거: [이슈 #158](https://github.com/Twin-Fang/elum/issues/158) — 서버 구조(`Account` / `Profile` / `DeviceLink`)는
> 이미 작업 중이다. **클라이언트 화면이 아직 없다.**

## ① 역할 선택 화면 🆕

**위치**: 약관 동의 다음 · 온보딩 이름 앞

```
┌──────────────────────────────────┐
│                                  │
│   이 기기는 누가 사용하나요?        │  ← 제목
│                                  │
│   나중에 바꿀 수 있어요             │  ← 설명
│                                  │
│   ┌────────────────────────────┐ │
│   │  👤                        │ │
│   │  보호자예요                 │ │  ← 카드형 선택지
│   │  일과를 만들고 관리해요       │ │
│   └────────────────────────────┘ │
│                                  │
│   ┌────────────────────────────┐ │
│   │  🧒                        │ │
│   │  제가 사용해요              │ │
│   │  보호자가 준 코드로 연결해요  │ │
│   └────────────────────────────┘ │
│                                  │
└──────────────────────────────────┘
```

| 요소 | 규격 |
| --- | --- |
| 선택 카드 | 아이콘 + 제목 + 한 줄 설명 · 세로 2개 |
| 선택 상태 | 온보딩 `도움 목표` 칩 선택 스타일 재사용 |
| CTA | **탭 즉시 이동** (별도 `다음` 버튼 없음) |

> ⚠️ **"아동"이 아니라 "당사자/사용자"로 쓴다.** 9/13 내부회의에서 타겟을
> *"행동 카드의 시각정보와 순서를 이해할 수 있는 발달장애인"* 으로 재정의했다.
> 성인 사용자도 이 화면을 본다.

## ② 기기 연결 — 코드 발급 (보호자 쪽) 🆕

**진입 경로 2개**: 온보딩 PIN 설정 직후 / 보호자 홈 → 설정 → `연결 코드 만들기`

```
┌──────────────────────────────────┐
│ ←                                │
│                                  │
│  사용자 기기를 연결할까요?          │
│                                  │
│  사용자 기기에서 아래 코드를        │
│  입력하면 연결돼요                 │
│                                  │
│      ┌──────────────────┐        │
│      │   [ QR 코드 ]     │        │  ← QR
│      └──────────────────┘        │
│                                  │
│        4 8 2 1 9 3               │  ← 6자리 · 크게 · 자간 넓게
│         [ 복사 ]                  │
│                                  │
│      ⏱ 09:42 남음                │  ← 10분 카운트다운
│                                  │
│  [ 코드 다시 만들기 ]              │
│  [ 나중에 할게요 ]                 │  ← 온보딩 진입 시에만
└──────────────────────────────────┘
```

| 요소 | 규격 | 상태 |
| --- | --- | --- |
| **QR 코드** | 정사각 · 여백 충분히 | 유효 / 만료(흐리게 + 오버레이) |
| **6자리 코드** | 숫자 · 자간 넓게 · 3-3 묶음 가능 | 유효 / 만료 |
| 남은 시간 | `09:42` 형식 · **10분 유효 · 1회용** | 정상 / 1분 미만 강조 / 만료 |
| `코드 다시 만들기` | 보조 버튼 | 만료 시 주 버튼으로 승격 |
| `나중에 할게요` | 텍스트 버튼 | 온보딩 경로에만 노출 |

**QR과 코드는 같은 값의 두 표현이다.** 카메라가 없거나 못 쓰는 상황을 대비해 **둘 다** 준다.

### 상태 분기 3가지

| 상태 | 화면 |
| --- | --- |
| 정상 | QR + 코드 + 카운트다운 |
| **만료(10분 경과)** | QR·코드 흐리게 + `코드가 만료됐어요` + `다시 만들기` 강조 |
| **연결 성공** | `사용자 기기가 연결됐어요 ✅` → 자동으로 홈 이동 |

## ③ 기기 연결 — 코드 입력 (당사자 쪽) 🆕

```
┌──────────────────────────────────┐
│                                  │
│   보호자에게 받은 코드를 넣어주세요  │
│                                  │
│      ┌─┐┌─┐┌─┐ ┌─┐┌─┐┌─┐         │  ← 6칸 · PIN 화면 스타일 재사용
│      │4││8││2│ │ ││ ││ │         │
│      └─┘└─┘└─┘ └─┘└─┘└─┘         │
│                                  │
│      [ QR로 연결하기 ]             │  ← 카메라 실행
│                                  │
│      ┌─────────────────┐         │
│      │  1  2  3        │         │  ← 커스텀 숫자패드
│      │  4  5  6        │         │     (기존 PIN 화면 것 재사용)
│      │  7  8  9        │         │
│      │     0   ⌫       │         │
│      └─────────────────┘         │
└──────────────────────────────────┘
```

| 상태 | 화면 |
| --- | --- |
| 입력 중 | 채운 칸 강조 · **6자리 입력 시 자동 제출** |
| **코드 틀림** | 칸 흔들림 + `코드가 맞지 않아요 (E-LINK)` · 입력 초기화 |
| **코드 만료** | `코드가 만료됐어요. 보호자에게 새 코드를 요청하세요` |
| **네트워크 실패** | `연결하지 못했어요 (E-NET)` + `다시 시도` 버튼 |
| 연결 성공 | `연결됐어요!` → 당사자 홈 |

> ⚠️ **당사자 기기다. 에러를 빨간 경고로 덮지 않는다.** 기존 PIN 화면 규칙과 동일하게
> 부드러운 톤으로 처리하고, **에러 코드는 작게라도 화면에 남긴다** (제보 추적용).

> 💡 **보호자가 대신 입력할 수 있다.** 당사자가 코드를 못 읽어도 되는 구조다.

# 3. 온보딩 도움 목표 — 문구 유지 · 렌더링 수정 🔧

## 🔒 결정 — 선택지 4개 문구는 **그대로 간다**

> 메모에 *"4가지 고르잖아 바뀌어야 함 — 명세 어디에 적어놨는데"* 라고 되어 있었으나,
> **저장소 문서 전체와 과거 대화 기록을 모두 검색해도 새 문구 기록이 없다.**
> (`docs/` 명세 25건 · 회의록 4건 · 리포트 전수 · 과거 대화 아카이브)
> → **구두로만 언급되고 기록되지 않았다. 현행 유지로 확정.**

```
{이름}의 어떤 순간을 도와주고 싶으신가요?
여러 개를 선택할 수 있어요

[블록]   해야 할 일을 순서대로 이해해요        STEP_BY_STEP
[색연필] 필요한 준비물을 스스로 챙겨요         PREPARE_ITEMS
[체크리스트] 새로운 상황을 미리 준비해요        PREPARE_NEW
[퍼즐]   혼자 끝까지 해내는 경험을 만들어요     INDEPENDENT
```

## ⚠️ 그런데 실제 화면에 문제가 3개 있다

문구는 그대로여도 **지금 렌더링 상태는 손봐야 한다.** 실기기 스크린샷에서 확인했다.

### (1) 🔴 4번 칩 텍스트가 깨진다

```
현재                                  고쳐야 할 모습
┌──────────────────────────────┐     ┌──────────────────────────────┐
│ [퍼즐] 혼자 끝까지 해내는 경험을 만들어│     │ [퍼즐] 혼자 끝까지 해내는      │
│        요                     │     │        경험을 만들어요         │
└──────────────────────────────┘     └──────────────────────────────┘
   "요" 한 글자만 떨어져 나간다            2줄이면 2줄답게 나눠 떨어진다
```

**원인** — 칩 높이가 `68` **고정**인데(`goal_chip.dart:25`) 텍스트에 줄 수 제한이 없다.
4번 문구만 한 줄에 안 들어가 2줄이 되고, 고정 높이 안에서 눌린다.

| 안 | 내용 | 비고 |
| --- | --- | --- |
| **A. 칩 높이를 내용에 맞춘다 (권장)** | 68 최소 높이 + 2줄이면 늘어남 | 칩 간격 18은 유지 |
| B. 문구를 줄인다 | `혼자 끝까지 해내요` 등 | 서버 enum은 그대로라 안전 |
| C. 2줄 고정 높이로 전부 통일 | 4개 다 같은 높이 | 1줄짜리에 여백이 크게 남음 |

> 📐 **디자이너가 정해야 할 값** — 2줄일 때 칩 높이, 줄 간격, 세로 정렬(가운데/위).

### (2) 아이콘 톤이 하나만 다르다

| # | 목표 | 아이콘 | 톤 |
| :-: | --- | --- | --- |
| 1 | 순서대로 이해해요 | 블록 쌓기 | 컬러 |
| 2 | 준비물을 챙겨요 | 색연필 | 컬러 |
| 3 | 새로운 상황을 준비해요 | 체크리스트 | ⚠️ **무채색** |
| 4 | 혼자 끝까지 해내요 | 퍼즐 | 컬러 |

**3번만 회색이라 눈에 덜 띈다.** 의도가 아니면 컬러로 맞춘다.

> 📌 참고 — [2026-07-21 온보딩 목표 명세](./2026-07-21-onboarding-goals-screen-design.md)에는
> *"아이콘이 4개 모두 동일"* 이라고 적혀 있으나 **현재 구현은 목표별로 4종이 다르다**
> (`app_assets.dart:16-21`). **그 문서는 낡았다. 이 문서가 기준이다.**

### (3) 제목에 이름이 들어간다 — 이번엔 두고 본다

```dart
'${profile.displayName}의 어떤 순간을\n도와주고 싶으신가요?'
```

9/13 회의에서 타겟을 **발달장애인 전반**으로 재정의했다. 성인 당사자 이름이 들어가면
어색해질 수 있으나, **이번 범위에서는 건드리지 않는다** (호칭·말투 프리셋 분기는 본선 과제).

> **여기서는 메모로 추가된 요구만 적는다.**

```
┌──────────────────────────────────┐
│ ←                          4 / 4 │  ← 🔒 카드 검토 다음 (§7-C 확정)
│                                  │
│  다 하면 무엇을 할 수 있나요?       │
│                                  │
│  평소에 "이거 다 하면 젤리 먹자"    │
│  라고 말씀하시죠? 미리 정해두면     │
│  카드를 보는 내내 그걸 기억할 수     │
│  있어요.                          │
│                                  │
│  최근에 정한 보상                  │  ← ✅ 메모 요구: "최근 보상 정보"
│  [🍪 젤리] [📺 유튜브 10분]         │     (없으면 섹션 전체 숨김)
│                                  │
│  [🍪 좋아하는 간식] [📺 유튜브 10분] │  ← 프리셋 2열
│  [🧸 좋아하는 놀이] [🚶 산책]       │
│  [⭐ 직접 입력]                    │  ← ✅ 메모 요구: "직접입력"
│                                  │
│  💡 한 달 뒤 선물보다 오늘 받을     │
│     수 있는 게 더 잘 통해요         │
│     왜 필요한가요? ›               │  ← 바텀시트
│                                  │
│  [ 건너뛰기 ]        [ 다음 ]      │  ← ✅ 메모 요구: "건너뛰기 있어야됨"
└──────────────────────────────────┘
```

**메모의 3가지 요구는 기존 명세에 이미 전부 반영되어 있다.**

| 메모 요구 | 기존 명세 | 판정 |
| --- | --- | :-: |
| 건너뛰기 있어야 됨 | `건너뛰기` 보조 버튼 · 항상 활성 | ✅ 일치 |
| 직접 입력 | `⭐ 직접 입력` 칩 + 최대 20자 텍스트 필드 | ✅ 일치 |
| 최근 보상 정보 | `최근에 정한 보상` 섹션 · 최대 3개 · 없으면 숨김 | ✅ 일치 |

> **`다음` 버튼은 미선택이어도 항상 활성이다.** 보상은 선택 사항이다.

# 5. 카드 검토 화면 — 추가·삭제·순서 변경 🔧

## 현재 되는 것 / 안 되는 것

| 동작 | 현재 | 메모 요구 |
| --- | :-: | :-: |
| 카드 문구 수정 | ✅ 있음 (`이 카드 수정하기` 칩 → 바텀시트) | 유지 |
| 카드 **삭제** | ✅ 있음 (단, **최소 1장은 남김**) | 유지 |
| 카드 **추가** | ❌ **없음** | 🆕 필요 |
| 카드 **순서 변경** | ❌ **없음** | 🆕 필요 |

> ⚠️ 9/13 명세에서 카드 추가·순서 변경은 **P1(본선 10/28)** 으로 미뤄둔 항목이다.
> 🔒 **메모 기준으로 이번 범위에 포함하기로 확정했다** (§7-D). 9/13의 P1 보류를 뒤집는다.

## 추가로 그려야 할 인터랙션 3종

### (1) 카드 추가

```
카드 캐러셀 마지막 자리
┌ ─ ─ ─ ─ ─ ─ ┐
│             │
│      +      │  ← 점선 테두리 · 빈 카드
│  카드 추가   │
│             │
└ ─ ─ ─ ─ ─ ─ ┘
  탭 → 기존 `카드 수정` 바텀시트 재사용 (제목·설명 입력)
```

| 정할 것 | 선택지 |
| --- | --- |
| 추가 위치 | **항상 맨 뒤** / 현재 보는 카드 **다음** |
| 그림 | AI 재생성 / **기본 일러스트 1종** (권장 — AI 호출 없이 즉시) |

### (2) 순서 변경

두 안 중 하나를 고른다.

| 안 | 인터랙션 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 목록 모드 (권장)** | `순서 바꾸기` 버튼 → 세로 리스트 + 드래그 핸들 | 전체가 한눈에 · 구현 안정적 | 화면 전환 1번 |
| B. 캐러셀 직접 드래그 | 카드를 길게 눌러 좌우로 끌기 | 전환 없음 | 좁은 화면에서 오조작 |

```
A안 — 순서 바꾸기 모드
┌──────────────────────────────┐
│ ←    카드 순서 바꾸기    [완료] │
│                              │
│  ☰  1. 가방을 챙겨요          │  ← ☰ 드래그 핸들
│  ☰  2. 신발을 신어요          │
│  ☰  3. 우산을 챙겨요          │
│                              │
└──────────────────────────────┘
```

### (3) 삭제 — 마지막 1장 방어

| 상태 | 표시 |
| --- | --- |
| 카드 2장 이상 | 삭제 버튼 활성 |
| **카드 1장** | 삭제 버튼 **비활성** + `카드는 최소 한 장이 필요해요` |

# 6. 보호자 홈 — 구조 변경 + 설정 메뉴 🔧

## 6-1. 메모에 적힌 구조

```
┌────────────────────────────────┐
│ 안녕하세요, ○○님          [⚙️] │  ← ✅ 인사말 + 🆕 설정 아이콘
│                                │
│ ┌────────────────────────────┐ │
│ │  + 새로운 일과 만들기        │ │  ← 기존
│ └────────────────────────────┘ │
│                                │
│ 오늘 일과                       │  ← 섹션 제목
│ ┌────────────────────────────┐ │
│ │ ☂️ 비 오는 날 학교 가기       │ │
│ │ ●●●○○  3/5                 │ │
│ │ 🍪 다 하면: 젤리 먹기        │ │  ← 보상 줄
│ └────────────────────────────┘ │
│                                │
│ 진행 중                         │  ← 오늘 것 중 일부만 완료
│ ┌────────────────────────────┐ │
│ │ 🎒 아침 등교 준비            │ │
│ │ ●●○○○  2/5                 │ │
│ │ 🍪 다 하면: 산책             │ │  ← 보상 줄
│ └────────────────────────────┘ │
│                                │
│ 임시저장                        │  ← PENDING_REVIEW
│ ┌────────────────────────────┐ │
│ │ 🏥 병원 가기                 │ │
│ │ 이어서 수정할 수 있어요       │ │
│ │ 🍪 다 하면: 유튜브 10분      │ │  ← 보상 줄
│ │                    [ 수정 ] │ │  ← ✅ 메모 핵심 요구
│ └────────────────────────────┘ │
│                                │
│ 최근 일과                       │  ← ⚠️ 기존 명세는 "지난 일과 ▾"
│ ┌────────────────────────────┐ │
│ │ 🎒 아침 등교 준비   5/5      │ │
│ │              [ 다시 하기 ]  │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

> 💬 메모 원문: *"수정을 눌러서 그 화면에서 생성 (이거가 필요하다함)"*
> → **임시저장 타일의 `수정`을 누르면 카드 검토 화면으로 바로 들어가서,
> 거기서 이어서 만들고 최종 생성까지 끝낸다.** 새 화면이 아니라 **진입 경로**의 요구다.

## 6-2. 설정 메뉴 🆕

홈 우측 상단 `⚙️` → 바텀시트 또는 전체 화면.

| 항목 | 현재 | 비고 |
| --- | :-: | --- |
| **알림 설정** | ❌ 없음 | 🆕 — 일과 시작 알림 (§7-D로 범위 포함 확정) |
| **연결 코드 만들기** | ❌ 없음 | 🆕 — §2-② 화면으로 진입 |
| 로그아웃 | ✅ 있음 | 확인 다이얼로그 유지 |
| 회원 탈퇴 | ✅ 있음 | 확인 다이얼로그 유지 |

```
┌──────────────────────────────┐
│  설정                         │
│                              │
│  🔔  알림 설정            ›   │  🆕
│  📱  사용자 기기 연결      ›   │  🆕
│ ──────────────────────────── │
│  ↪  로그아웃                 │
│  ⚠  회원 탈퇴                │  ← 위험 · 약하게
└──────────────────────────────┘
```

> 회원 탈퇴는 **위험 색을 쓰되 시각적 위계는 가장 낮게.** 오탭으로 계정이 날아가면 안 된다.

## 6-3. 상태 분기

| 상태 | 화면 |
| --- | --- |
| 오늘 일과 있음 | 정상 |
| 오늘 일과 **0건** | `오늘은 등록된 일과가 없어요` (로딩과 구분되는 빈 상태) |
| 임시저장 **0건** | **섹션 전체 숨김** |
| 최근 일과 **0건** | **섹션 전체 숨김** |
| **로딩 중** | 스켈레톤 (빈 상태와 반드시 구분) |
| **조회 실패** | `불러오지 못했어요 (E-HOME)` + `다시 시도` 버튼 |

# 7. 확정된 결정 (2026-09-18)

**메모를 기준으로 전부 확정했다.** 디자이너는 아래 표대로 진행하면 된다.

| | 쟁점 | 🔒 결정 | 근거 |
| :-: | --- | --- | --- |
| **A** | OAuth를 줄일 것인가 | **4종 전부 유지** (카카오·네이버·Google·Apple) | 이미 심사 중인 앱이다. 로그인 수단을 지우면 **그 수단으로 가입한 계정이 잠긴다.** Apple은 iOS 심사 필수 |
| **B** | 목표 4개 문구 변경 | **현행 유지** · 대신 §3의 **렌더링 3건 수정** | 저장소·과거 대화 전수 검색 결과 **새 문구 기록이 없다.** 구두로만 언급되고 기록되지 않았다 |
| **C** | 보상 설정 위치 | **카드 검토 다음** (`4 / 4`) | 메모 기준. 카드를 다 보고 정하는 편이 맥락이 잡힌다 |
| **D** | 카드 추가·순서변경·알림 | **이번 범위에 포함** | 메모 기준. 9/13의 P1 보류를 뒤집는다 |
| **E** | 보호자 홈 섹션 | **4구역** — `오늘 일과` / `진행 중` / `임시저장` / `최근 일과` | 메모 기준. 9/13의 "임시저장 = 배지" 안을 뒤집는다 |

> 🔒 **이 문서가 2026-09-13 명세보다 우선한다.** 충돌하면 이쪽을 따른다.

## E에 남은 실무 판단 2개

메모를 그대로 옮기면 디자이너가 그릴 수는 있으나, 아래는 그리면서 자연스럽게 정해진다.

| 항목 | 해석 | 대응 |
| --- | --- | --- |
| `오늘 일과` vs `진행 중` | 오늘 배정된 일과 중 **일부만 완료된 것**이 `진행 중`이다 | 두 섹션에 **같은 타일 디자인**을 쓴다. 섹션 제목만 다르면 된다 |
| `추천 일과` 섹션 | 메모에 없으나 **현재 앱에 있고 동작한다** | **유지한다.** 맨 아래 그대로 둔다 (삭제 지시가 아니라 생략으로 본다) |

# 7-2. 구현 현황 — **데이터는 이미 다 있다** ✅

> 디자인이 나오면 바로 붙는다. **서버 API도 클라 모델도 이미 준비돼 있다.**
> 없는 것은 **화면(UI)뿐**이다.

| 기능 | 데이터·API | 화면 |
| --- | :-: | :-: |
| 보상 텍스트·프리셋 저장 | ✅ `Routine.rewardText` · `rewardPresetKey` | ❌ |
| 보상 프리셋 5종 | ✅ `RewardPreset` (클라·서버 동일) | ❌ |
| 보상만 수정 | ✅ `updateReward()` | ❌ |
| 최근 보상 불러오기 | ✅ `getRecentRewards()` · `RecentReward` | ❌ |
| 임시저장 목록 | ✅ `getDraftRoutines()` | ❌ |
| 지난/최근 일과 목록 | ✅ `getPastRoutines()` | ❌ |
| 다시 하기 | ✅ `duplicate()` | ❌ |
| 일과 삭제 | ✅ `delete()` | ❌ |
| 보상 표시 문자열 | ✅ `routine.rewardDisplay` → `🍪 젤리 먹기` | ❌ |
| 카드 추가·순서 변경 | ❌ | ❌ |
| 기기 연결 (QR·코드) | 🔶 서버만 ([#158](https://github.com/Twin-Fang/elum/issues/158)) | ❌ |
| 알림 | ❌ | ❌ |

**보상 프리셋 확정값** (`reward_preset.dart` — 서버와 1:1)

| key | 라벨 | 이모지 |
| --- | --- | :-: |
| `SNACK` | 좋아하는 간식 | 🍪 |
| `VIDEO` | 유튜브 10분 | 📺 |
| `PLAY` | 좋아하는 놀이 | 🧸 |
| `WALK` | 산책 | 🚶 |
| `CUSTOM` | 직접 입력 | ⭐ |

> 이모지는 **그림이 준비되기 전까지의 임시 표현**이다.
> 아동·성인 사용자 화면에는 **프리셋별 일러스트가 필요하다** — 글자를 못 읽는 사용자에게
> 텍스트만 보여주면 의미가 없다. → 디자인 요청 항목.

# 8. 당사자(사용자) 화면 — 보상 노출 3곳

> 상세는 [2026-09-13 디자인 명세 §⑤⑥⑦](./2026-09-13-디자인-명세.md) 에 있다.
> 메모의 *"보상 표시, 마지막에 다 마쳤을 때 어떤 식으로 보여주느냐"* 가 곧 이 3곳이다.

| 위치 | 요소 | 규칙 |
| --- | --- | --- |
| **당사자 홈** | 상단 보상 배너 | 보상 없으면 배너를 띄우지 않는다 |
| **카드 수행 중** | **상단 고정 보상 바** | 카드가 바뀌어도 유지 · 카드 이미지를 가리지 않는 최소 높이 |
| **보상 완료 화면** | 보상 문구 1줄 | 보상 없으면 기존 화면 그대로 |

## "다 마쳤을 때" — 전부 완료 상태

```
┌──────────────────────┐
│ ⭐15          하늘이   │
│                      │
│        🎉            │
│  오늘 할 일을 다 했어요! │  ← `지금 할 일` 카드 자리를 교체
│                      │
│  🍪 젤리를 먹어요      │  ← 보상 있을 때만
│                      │
├──────────────────────┤
│ ✅ 학교 가기 준비      │
│ ✅ 아침 약 먹기        │
└──────────────────────┘
```

| 상태 | 화면 |
| --- | --- |
| 일과 있음 + 미완료 | `지금 할 일` 카드 (크게 1장) |
| 일과 있음 + **전부 완료** | 🎉 축하 + 보상 문구 |
| 일과 **0건** | 기존 빈 상태 그대로 |

> ⚠️ **상단 고정 보상 바는 자문의 핵심 요구다.**
> *"수행하는 동안 최종 보상을 계속 확인할 수 있어야 한다."*

# 9. 기존 컴포넌트 재사용 — 새로 그릴 것은 생각보다 적다

| 새 요소 | 재사용할 기존 컴포넌트 |
| --- | --- |
| 역할 선택 카드 | 온보딩 `도움 목표` 선택 칩 |
| 코드 입력 6칸 + 숫자패드 | **온보딩 PIN 화면 그대로** |
| 보상 프리셋 칩 | 온보딩 `도움 목표` 선택 칩 |
| 홈 섹션 제목 | 보호자 홈 `추천 일과` 제목 |
| 카드 추가 버튼 | 점선 테두리 빈 카드 (신규) |
| 순서 변경 리스트 | 신규 |
| 진행률 링 | `RoutineProgressRing` |
| 완료 타일 | `childTileDone` 색상 |
| 설정 시트 | 기존 다이얼로그/시트 스타일 |

**실제로 새로 그려야 하는 것은 6개다.**

1. 역할 선택 카드
2. QR + 6자리 코드 발급 화면
3. 보상 설정 화면 (프리셋 칩 배치)
4. 상단 고정 보상 바
5. 카드 추가 / 순서 변경 인터랙션
6. 설정 메뉴 시트

# 10. 모든 화면 공통 — 실패 경로

> 저장소 규칙이다. **행복 경로만 그린 디자인은 미완성으로 본다.**

| 상황 | 요구 |
| --- | --- |
| 네트워크 실패·타임아웃 | 빈 화면·무한 로딩 금지. **재시도 버튼 + 상태 표시** |
| 응답이 비었거나 형식이 다름 | 앱이 죽지 않게 방어 · **빈 상태 UI** |
| 권한 거부 (카메라·마이크·알림) | 거부해도 앱은 동작. **왜 필요한지 안내 + 우회 경로** |
| 예상 못 한 예외 | 전체 붉은 에러 금지. **에러 코드 노출** (`E-1023` 형태) |
| 목록 0건 | **로딩과 구분되는** 빈 상태 화면 |

**이번 신규 화면에서 특히 필요한 것:**

| 화면 | 놓치기 쉬운 상태 |
| --- | --- |
| 코드 발급 | 만료 · 발급 실패 · 연결 성공 알림 |
| 코드 입력 | 틀림 · 만료 · **카메라 권한 거부** (→ 숫자 입력으로 우회) |
| 보상 설정 | 최근 보상 없음 · 20자 초과 |
| 카드 순서 변경 | 저장 실패 → 원래 순서로 롤백 + 안내 |
| 보호자 홈 | 로딩 · 조회 실패 · 각 섹션 0건 |
