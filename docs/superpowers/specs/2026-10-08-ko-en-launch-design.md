# 한국어·영어 두 언어 먼저 열기 (다국어 #521 범위 축소)

- 이슈: [#521](https://github.com/Twin-Fang/elum/issues/521)
- 작성일: 2026-10-08
- 상태: 설계 검토 대기
- 상위 설계: `2026-10-02-multi-language-design.md` (5개 언어 구조)

## 1. 목적과 범위

5개 언어(ko·en·ja·zh·es)를 받는 구조는 #525(클라이언트)·#526(서버)로 이미 main에 있다.
이번에는 **ko와 en 둘만 실제로 연다.** 나머지 언어는 구조에 자리만 있고 열지 않는다.
언어를 더 열 때 코드가 아니라 데이터(번역 파일 + 열린 언어 목록 한 줄)만 더하는 것이 성공 기준이다.

| 포함 | 제외 (다음 작업) |
| --- | --- |
| 클라이언트 화면 문구 영어 번역 (`app_en.arb`) | AI가 영어로 카드 글·음성 생성 (계획 3) |
| 서버 문구 영어 번역 (에러, 일과 폴백 질문, 추천 목록) | 영어 약관·개인정보방침·공지 (계획 4) |
| 열린 언어 목록 도입 — 목록 밖 언어는 영어로 대체 | ja·zh·es 번역, 번역 품질 점검, 네이티브·스토어 문구 |
| 용어집 | 법무 검토 |

**서비스 원칙은 영어에서도 그대로 지킨다.** 진단명 미수집, AI 결과는 보호자 승인 후 노출, AI 실패 시 fallback.

## 2. 현재 상태 (2026-10-08 코드 기준)

| 영역 | 상태 |
| --- | --- |
| 클라 ARB | `app_ko.arb` 1599줄, `app_en.arb` 5줄(대체 문구만), ja·zh·es도 같다 |
| 클라 언어 결정 | `resolveAppLocale` — `supportedAppLocales` 5개에서 고르고 밖이면 `en` |
| 서버 문구 | `messages_ko` 131줄, `routine-phrases_ko` 202줄. en·ja·zh·es는 각 2줄 |
| 서버 열린 언어 | `EnabledLocales` — 시스템 설정 `ENABLED_CONTENT_LOCALES`(콘텐츠 언어용). ko는 늘 켜짐 |
| 일과 언어 | `Routine.language` 있음. 요청 언어가 켜져 있지 않으면 en이 켜진 경우 en, 아니면 ko |

## 3. 설계

### 3.1 열린 언어 목록 (클라이언트)

`supportedAppLocales`는 ARB가 존재하는 5개 그대로 둔다(gen-l10n 입력이라 줄이지 않는다).
그 위에 **`openAppLocales = [ko, en]`** 를 하나 더 둔다. `resolveAppLocale`은 이 목록에서만 고른다.

- 휴대폰 언어가 ko·en이면 그 언어. 그 밖(ja·zh·es·번체 포함)은 en.
- 언어를 더 열 때: ARB 번역을 채우고 `openAppLocales`에 한 줄.
- 개발자 도구의 언어 강제 스위치는 5개 모두 보여 준다(QA용). 릴리스에는 없다.

### 3.2 열린 언어 (서버)

서버 응답 언어도 같은 규칙이다. `Accept-Language`가 열린 언어면 그 언어, 아니면 en, 헤더가 없으면 ko(이미 배포된 앱 보호).
서버에는 `ENABLED_CONTENT_LOCALES`가 이미 있어 **이 설정을 화면 언어의 열린 목록으로도 쓴다.** 새 설정은 만들지 않는다.
운영 값은 `ko,en`으로 올린다(배포로는 운영 DB가 바뀌지 않으므로 관리자 화면에서 올린다).

### 3.3 영어 번역

- **클라이언트**: `app_ko.arb`를 원본으로 `app_en.arb`를 채운다. 키·플레이스홀더·`select`/`plural` 구조는 ko와 같다.
  한국어 조사(`batchim select`)는 영어에서 필요 없으므로 영어는 단순 보간으로 쓴다.
- **서버**: `messages_en`(에러 문구), `routine-phrases_en`(폴백 질문, 추천 목록)을 채운다.
- **용어집** `docs/i18n/glossary.md`를 먼저 만든다. 아래를 못 박는다.
  - 이룸이 = `Irumi`, 보호자 = `guardian`, 카드 = `card`, 일과 = `routine`, 보상 = `reward`, 연결 암호 = `link code`
  - 해요체·능동형·긍정형 원칙은 영어에서 평이하고 짧은 문장·명령형으로 옮긴다. "아이·아동"에 해당하는 표현(`child`, `kid`)을 쓰지 않는다.
- 번역 초안은 내가 쓰고 사용자가 확인한다. 법적 문구는 이 범위에 없다.

### 3.4 영어 화면에서 AI가 한국어로 나오는 구간

영어 휴대폰에서 일과를 만들면 AI 카드 글은 아직 한국어다(계획 3이 제외 범위). 서버 `EnabledLocales.resolveContentLocale`이
en을 열면 en 콘텐츠로 가려 하므로, **영어 AI 생성이 준비되기 전까지 서버의 콘텐츠 언어 목록은 `ko`만** 둔다.
화면 언어 열린 목록(3.2)과 콘텐츠 언어 열린 목록을 **서로 다른 설정 두 개로 나눈다**: 화면은 `ko,en`, 콘텐츠는 `ko`.
이 분리가 이번 작업에서 새로 필요한 유일한 서버 설정이다.

### 3.5 실패 경로

| 상황 | 동작 |
| --- | --- |
| 영어 번역 키 누락 | gen-l10n 테스트가 ko와 en의 키 집합을 비교해 CI에서 실패시킨다 |
| 서버 문구 키 누락 | 기동 검사(이미 있음)가 막는다. 런타임에는 en, ko 순으로 대체 |
| 열린 목록 설정을 못 읽음 | ko만 열린 것으로 본다(`EnabledLocales`의 기존 동작) |
| 번체 중국어·미지원 언어 휴대폰 | 영어 |
| 영어에서 AI 생성 | 콘텐츠 언어는 ko이므로 일과는 한국어 카드로 생성된다. 화면은 영어 |

## 4. 테스트

- `resolveAppLocale`: ko→ko, en→en, ja·zh·es·번체→en, 목록 비어 있음→en.
- ARB 키 동일성: `app_en.arb`와 `app_ko.arb`의 키·플레이스홀더 집합이 같다.
- 서버: `Accept-Language`별 에러 문구 언어 (en 열림 / 닫힘 각각), 화면 목록과 콘텐츠 목록 분리.
- `ko` 화면은 기존 골든과 앱 테스트가 그대로 통과한다.
- 영어 화면 골든은 이번에 만들지 않는다(긴 글자 줄바꿈 확인은 시뮬레이터 스크린샷으로).

## 5. 열어 둔 것

- 영어 AI 생성(계획 3)과 영어 약관(계획 4)은 다음 이슈로 분리한다. 그 둘이 끝나야 **영어 가입을 실제로 연다**.
  이번 배포만으로는 영어 휴대폰에서 약관이 한국어로 보인다.
- 앱 이름·권한 문구·스토어 문구(계획 6)는 이번에 영어로 바꾸지 않는다.
