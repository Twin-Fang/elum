# 일과를 링크로 보내고 받은 사람이 가져가기 (#1002)

2026-10-29 · 설계 승인 위임 (사용자가 미정 3건을 정함, 나머지는 보수적 기본값)

## 문제

일과를 앱 밖 사람에게 보내는 길이 `이야기 공개 글 > 글 공유 링크(#966)` 하나뿐이다.
공개 글이라 모든 보호자에게 보이고, 일과관리에서 바로 보낼 수 없다.

## 사용자가 정한 것 (2026-10-29)

| 질문 | 결정 |
|---|---|
| 남이 만든 일과를 보낼 수 있나 | **못 보낸다.** 내가 만든 일과만 |
| 링크 만료 | **없다.** 보낸 사람이 끌 수 있다 |
| 이미 공개 이야기 글이 있는 일과 | **별도 링크.** 공개 글 링크를 재사용하지 않는다 |

## 고른 안: 이야기 글 + 공개 범위 `LINK_ONLY`

`talk_post` 에 `visibility`(`PUBLIC` / `LINK_ONLY`) 를 더한다. 링크로 보내면 `LINK_ONLY` 글이 하나 생기고,
주소는 지금과 같은 `/s/{글id}` 다.

- **"별도 링크" 와 맞는가** — 맞다. 링크 글은 공개 글과 다른 글(다른 id)이라 주소가 다르다. 한쪽을 끄거나 내려도 다른 쪽은 그대로다.
  같은 일과에 공개 글 하나 + 링크 글 하나가 함께 있을 수 있다 (유니크 인덱스를 `(source_routine_id, visibility)` 로 넓힘).
- **링크를 가진 사람만 보는가** — 글 id 는 UUID 라 추측할 수 없다. 피드·인기·내 글 목록은 `PUBLIC` 만 읽는다.
- **재사용** — 이름 가리기·금칙어·사진 흐리게·카드 스냅샷·그림 사본·`/s/` 페이지(OG·썸네일·앱 열기·스토어)·앱 링크 받기(맡겨 두기·이룸이 기기 거절)·가져가기·가져감 알림을 그대로 쓴다.

### 검토하고 버린 안

| 안 | 버린 이유 |
|---|---|
| 별도 공유 토큰 표 (`routine_share_link`) | 원본 일과를 그대로 보여 주면 보낸 뒤 고친 내용·사진이 흐림 없이 나간다. 스냅샷을 두면 이름 가리기·흐리게·그림 사본·OG 페이지·가져가기를 한 벌 더 만든다 (사본끼리 개인정보 규칙이 어긋날 위험). 더 단순하지 않다 |
| 글 상태(`status`)에 `LINK_ONLY` 추가 | 관리자 가림/되돌림이 `VISIBLE` 을 기대·복원해서 되돌리면 공개 글이 된다. 생애(보임·가림·지움)와 공개 범위는 다른 축이라 칼럼을 나눈다 |
| 공개 글 링크 재사용 | 사용자 결정(별도 링크)과 다르다 |

## 규칙

| 항목 | 정한 것 | 근거 |
|---|---|---|
| 보낼 수 있는 일과 | 내가 만든 일과(`created_by` = 나)만. 오늘 일과 복사본이면 원본 기준 | 사용자 결정. 남의 일과는 `TALK_LINK_ROUTINE_NOT_MINE`(403) |
| 공유 불가 | 이야기와 같은 4개: 예시 일과, 일과관리에서 지움, 이야기·링크에서 가져온 일과(재전송 금지), 승인 전 > `TALK_LINK_ROUTINE_NOT_SHAREABLE`(400) | #983: 예시 일과를 고치면 예시 표시가 지워져 보낼 수 있다 (`RoutineRules.clearExampleMark`). 판정은 `RoutineShareService.isShareable` 한 곳 |
| #999 와의 관계 | 남이 만든 일과는 일과관리에 보이지만 `링크로 보내기` 줄이 없다 (`isEditableByMe` 와 같은 기준) | 고치기를 막는 것과 같은 결 |
| 같은 일과를 다시 보내기 | 켜진 링크가 있으면 그 링크를 돌려준다 (새로 만들지 않음) | 두 번 눌러도 링크는 하나. 내용을 바꾸려면 끄고 다시 보낸다 |
| 만료 | 없음 | 사용자 결정 |
| 끄기 | 기존 글 내리기(`DELETE /api/talk/posts/{id}`): 본문·카드·그림 사본을 지운다. 끈 주소는 다시 켜지지 않고, 다시 보내면 새 주소 | 내린 글 본문을 남기지 않는 개인정보 원칙 그대로 |
| 링크가 살아 있는 조건 | 글 보임 + 보낸 사람 정지 아님 + **원본 일과가 내 일과관리에 남아 있음 + 보낸 사람이 아직 그 이룸이의 보호자** | 끄는 입구가 일과관리 메뉴뿐이다. 일과를 지우거나 연결이 끊기면 끌 방법이 없어지므로 그때 링크도 꺼진 것으로 본다 |
| 이용 규칙 동의 | 묻지 않는다 | 이야기(커뮤니티) 규칙이다. 링크 글은 피드에 안 올라간다 |
| 분류·한마디 | 받지 않는다 (`category` NULL, `note` NULL) | 새 입력 없음 (진단명 수집 금지 원칙) |
| 도움돼요·댓글 | 링크 글에는 안 된다 (서버도 `TALK_POST_NOT_FOUND`) | 아는 사람에게 보낸 글이다. 반응 기능은 공개 글 것 |
| 신고·숨기기 | 된다 | 관리자 검토 경로는 남긴다 |
| 가져가기 | 받은 보호자 계정에 일과관리 원본 생성 (`created_by` = 받은 사람, `talk_post_id` = 링크 글) | 기존 가져가기 그대로. `talk_post_id` 가 있어 다시 보낼 수 없다 |

## 받는 쪽

| 받은 사람 | 동작 |
|---|---|
| 앱 없음 | `/s/{글id}` 웹 미리보기(제목·카드 수·첫 그림) + 스토어 버튼 + "앱을 받은 뒤 링크를 다시 눌러 주세요" |
| 앱 있음 · 로그인 전/온보딩 중 | 지금처럼 맡겨 두고 보호자 홈에서 연다 (10분) |
| 앱 있음 · 보호자 | 글 상세(머리 `받은 일과`, 도움돼요·댓글 없음) > `일과로 가져오기` > 이룸이·묶음 고르기 |
| 이미 가져감 | 버튼이 `✓ 일과관리에 넣었어요` (누르면 한 번 더 넣음, 기존과 같음) |
| 이룸이 기기 | 받지 않고 "보호자 화면에서 열어 주세요" (기존 그대로) |

## 개인정보

- 링크 미리보기(OG·웹 페이지)에는 **이름을 가린 제목 · 카드 수 · 첫 카드 그림(흐림 반영본)** 만 싣는다. 글쓴이·아이 호칭·한마디는 싣지 않는다 (링크 글은 한마디가 없다).
  #966 과 같은 원칙이다 (`TalkSharePage`: 글쓴이·댓글을 싣지 않음, 제목은 `maskNames` 를 거친 값).
- 링크 페이지는 `noindex` (검색 엔진에 올리지 않음).
- 로그에는 id·결과만: `[talk link] created : postId=…`, 원문·호칭 없음. AI 호출 없음.

| 위치 | 내용 |
|---|---|

| `TalkPostVisibility` | `PUBLIC` / `LINK_ONLY` |
| `TalkPostRepository` | 피드·인기·내 글 목록 `PUBLIC` 만, 원본별 조회에 공개 범위 |

옛 서버의 같은 일과 공개 글 올리기는 링크 글 때문에 `TALK_ALREADY_SHARED` 가 날 수 있다 (되돌린 동안만).

## 하지 않는 것

- 원본 일과와 실시간 동기화, 링크 만료, 링크 다시 켜기
- 받은 사람의 재전송 (가져온 일과는 보낼 수 없다)
- 웹에서 로그인 없이 가져가기, 설치 후 자동 이어받기(지연 딥링크)
- 남이 만든 일과 보내기 · 만든 사람에게 알리기
- 디자인 시안 (기존 이야기 올리기 화면 결을 따른다)
