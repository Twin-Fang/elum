# 글자 배율 정책 · 정적 접근성 보강 설계 (#662)

- 이슈: https://github.com/Twin-Fang/elum/issues/662
- 날짜: 2026-10-29
- 범위: 코드로 지금 할 수 있는 부분 (글자 배율 정책, 규칙 검사, 공통 부품의 낭독 이름·큰 글자 넘침).
  실기기 VoiceOver/TalkBack 점검과 200% 전 화면 실측은 사람이 한다 (남은 일).

## 문제

| 갈래 | 지금 | 결과 |
|---|---|---|
| 배율 상한 | `AppTextScale` 이 하한(1.0)만 둔다. iOS 접근성 큰 글자는 3.1배까지 올라간다 | 고정 높이 칸·한 줄 글이 2배를 넘으면 잘리거나 겹친다. 인사말만 따로 2배에서 멈춘다 |
| 배율 우회 | 부품 안 글자를 줄이는 두 곳이 `TextScaler.linear(textScalerOf.scale(1) * k)` 로 다시 만든다 | 안드로이드 14 비선형 배율이 선형으로 바뀌고, 앞으로 생길 우회를 막을 규칙이 없다 |
| 진행 링 | `RoutineProgressRing` 다 한 상태는 그림만 있어 낭독기가 아무것도 읽지 않는다. 진행 중은 `25%` 만 읽는다 | 일과를 다 했는지 들어서는 모른다 |
| CTA 버튼 | `ElumButton` 이 높이 66 고정 · 줄바꿈된 문구가 칸 밖으로 잘린다. 버튼 역할도 알리지 않는다 | 200% 에서 두 줄 문구 아래가 잘린다. 낭독기가 "버튼"이라 말하지 않는다 |
| 알약 버튼 | `ElumFloatingPillButton` 높이 44 고정 · Row 안 글자 | 200% 에서 세로 넘침 |
| 약관 체크 | `ConsentRow` 동의 토글이 "필수"만 읽고 켜짐 상태를 알리지 않는다 | 어느 약관에 동의했는지 들어서는 모른다 |
| 체크 원 | `ElumCheckCircle` 체크 그림이 빈 이름의 그림 노드로 남는다 | 낭독기가 "이미지"를 덧붙여 읽을 수 있다 |

## 검토한 안

| 안 | 내용 | 판단 |
|---|---|---|
| A. 상한 없이 레이아웃만 대응 | 모든 화면이 3.1배까지 버티게 고친다 | 화면 수백 곳 + 시안이 정한 고정 좌표가 많아 지금 범위로 불가 |
| B. 상한 1.3~1.5 | 많이 쓰는 앱처럼 낮게 자른다 | WCAG 1.4.4(200%) 와 이슈 목표(글자 200%)에 못 미친다. 저시력 보호자가 키운 글자를 앱이 무시한다 |
| **C. 상한 2.0 (선택)** | 시스템 배율을 1.0~2.0 으로 자르고, 2배 안에서는 공통 부품이 칸을 늘린다 | 이슈 목표와 같고, 이미 인사말이 2배에서 멈추던 값과 같다 |

- 보호자 · 이룸이 화면 **같은 정책**. 이슈에 다르게 하자는 결정이 없어 원본 하나로 둔다.
  이룸이 카드가 2배에서 깨지면 그 화면을 고치거나 이룸이만 낮추는 안을 실측 뒤 다시 정한다 (남은 일).
- 폭 배율(창 폭/393, 0.9~1.15)은 상자도 같이 커지므로 상한 계산에 넣지 않는다 (시스템 배율에만 상한).

## 바꾸는 것

1. `core/layout/app_text_scale.dart`
   - `minSystemScaleFactor = 1.0`, `maxSystemScaleFactor = 2.0` 을 공개 상수로 둔다 (원본).
   - `AppTextScale.scaledBy(context, factor)`: 앱 배율 위에 부품 비율을 곱한 TextScaler (비선형 유지).
2. 우회 두 곳(`action_card_tablet_view`, `child_step_strip`)을 `scaledBy` 로, 인사말 상한 숫자 2.0 을 상수로.
3. 규칙 검사 `tool/check_design_rules.dart` `text-scale` 에 `TextScaler.linear(` · `textScaleFactor` · `textScaleFactorOf` 를 더한다.
   예외는 `design_rules.yaml` `text_scale_owners` 에 이유와 함께 둔다 (원본 파일, 진단 로그).
4. 공통 부품
   - `RoutineProgressRing`: 낭독 이름 `N% 했어요` / `다 했어요` (ARB 5개 언어).
   - `ElumButton`: 최소 높이 66 + 위아래 여백으로 글자만큼 늘어난다. 버튼 역할 · 사용 가능 여부를 알린다.
   - `ElumFloatingPillButton`: 최소 높이 44 로 바꾼다.
   - `ElumCheckCircle`: 체크 그림을 낭독에서 뺀다 (상태는 쓰는 쪽이 알린다).
   - `ConsentRow`: 동의 토글에 약관 이름 · 켜짐 상태를 붙인다.

기본 글자 크기(1.0)에서는 모든 화면이 지금과 같다 (최소 높이 = 지금 고정 높이).

## 하지 않는 것

- 최소 터치 영역 44 → 48 변경 (`MinTapTarget`): 시안 배치가 바뀌어 디자이너 확인이 필요하다.
- 화면별 고정 높이 수정 (`login_provider_button` 등 기능 화면): 200% 실측 뒤 화면별로 고친다.
- 이룸이 화면만 다른 상한: 실측 근거가 없다.
- 위젯 테스트: 앱 테스트를 두지 않는 규칙(#848). 규칙 검사기로 막는다.

## 실패 경로

| 상황 | 동작 |
|---|---|
| 시스템 배율 2배 초과 | 2배로 자른다. 글자가 시안보다 작아지지는 않는다 (하한 1.0 유지) |
| 시스템 배율 1배 미만 | 1배 (기존과 같다) |
| 루트 밖에서 세운 위젯 (미리보기 등) | `scaledBy` 는 `MediaQuery.textScalerOf` 를 그대로 쓰므로 MediaQuery 가 있으면 동작 |
| 버튼 문구가 2배에서 세 줄 | 버튼이 늘어나고 위 본문(Expanded)이 줄어든다. 잘리지 않는다 |
| progress 가 범위 밖 | 기존처럼 0~1 로 자른 값으로 읽는다 |
