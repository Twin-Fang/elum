# 관리자 대시보드: 확인할 일 · 추이 그래프 · AI 상태 (#654)

## 왜

관리자가 조치가 필요한 상태(새 의견, 검토 대기 일과, AI 크레딧 소진, 멈춘 예약, 비용 상한)를 알려면 화면 여러 개를 돌아다녀야 한다.
가입·방문·AI 사용량은 오늘 숫자만 있고 추이가 없다. AI 제공자의 결제 화면 없이도 "지금 AI 가 정상인가"를 바로 알고 싶다.

## 원칙

- 첫 화면(대시보드) = 지금 상태 + 확인할 일. 자세한 추이와 필터는 각 화면(회원 관리, AI 모니터링)에 둔다.
- 신규 가입과 방문은 **각각 다른 카드·다른 그래프**로 보여 준다 (사용자 요청).
- 운영 중 서비스: 앱 API·JSON·에러 코드·기존 스키마는 바꾸지 않는다. 새 표 1개만 추가.
- 그래프는 chart.js 를 `static/admin/vendor/` 에 동봉한다 (CDN 금지 — 기존 admin.css 와 같은 이유).

## 화면

### ① 대시보드
1. **확인할 일** 카드 — 0건인 항목은 숨기고, 모두 0이면 "확인할 일이 없어요".
   새 의견(`FeedbackStatus.NEW`) · 검토 대기 일과 · AI 이상(제공자 상태가 정상이 아님) · 멈춘 크레딧 예약 · 오늘 AI 비용 상한 도달/사용률.
   각 항목은 해당 목록(필터 적용)으로 링크.
2. **숫자 4개** — 지금 접속 중(최근 5분 활동) · 오늘 방문(어제 n) · 오늘 신규 가입(전체·7일 활성·정지) · 오늘 AI 호출·비용(USD, 원화 환산).
3. **AI 상태** — 제공자별 카드(아래 판정 규칙).
4. **작은 그래프 3개 (30일)** — 신규 가입(막대) · 방문(선) · AI 호출(막대)+비용(선). 각 카드에 "자세히" 링크.
5. 기존 요금제 분포 · 적용 중 설정 · 24시간 서버 오류 유지. 오류 카드에 "서버가 다시 뜨면 0부터 센다" 문구와 로그 화면 바로가기.

### ② 회원 관리 (목록 위)
- **가입 추이** — 신규 가입·탈퇴 막대, 일별(기본 90일)/월별(12달), 시작·끝 날짜. 이번 달 가입·탈퇴 요약. 막대 클릭 → 그날(그달) 가입자로 목록 필터.
- **방문 추이** (별도 카드) — 하루 방문자, 일별/월별. 지금 접속 중 · 오늘 방문 · 최근 7일 방문 요약.
- 목록에 **가입일 기간 필터**(joinedFrom~joinedTo) 추가.

### ③ AI 모니터링 (목록 위)
- **사용량 추이** — 용도(`AiCallPurpose`)별 쌓은 막대. 일별(30일)/월별(12달) × 지표(호출 수 · 비용(원) · 실패율 %).
- 이번 달 요약 — 호출 · 비용 · 일과 1건 평균 비용(이번 달 비용 ÷ 성공한 일과 생성 호출 수) · 실패율.
- 제공자별 비용 비율(도넛, 이번 달) · 최근 24시간 오류 유형 표.

### 사이드바
- 의견 관리: 새 의견 수 배지 · 일과 관리: 검토 대기 배지 · AI 모니터링: 이상 있으면 "주의" 배지.
- 기존 서버 로그 오류 배지와 같은 방식(JSON 한 번 fetch, 실패하면 배지만 숨김).

## 데이터

| 지표 | 원천 | 비고 |
|---|---|---|
| 가입 | `member.created_at` | 과거 전부 |
| 탈퇴 | `member.withdrawn_at` | 과거 전부 |
| 지금 접속 중 | `member.last_activity_at > now-5분`, 탈퇴 제외 | 60초 스로틀이라 근사값 |
| 방문 | **새 표 `member_daily_visit (member_id, visit_date)` UNIQUE** | 배포일부터. V51 이 오늘 활동한 회원으로 첫 줄을 채움 |
| AI 호출·비용·실패 | `ai_call_log` | `idx_ai_call_log_created` 사용 |

**방문 기록** — 마지막 활동 시각을 바꾸는 네 곳(접근 가드, 로그인, 토큰 갱신, 소셜 로그인)을 `MemberActivityRecorder.touch(member, now)` 하나로 모은다.
이전 활동 날짜가 오늘이 아니면 `INSERT ... ON CONFLICT DO NOTHING` 1회. 같은 날 두 번째부터는 쿼리 없음.
실패해도 요청을 막지 않는다(가드의 가용성 우선 방침 유지). 회원 FK 없음(V47 과 같은 이유) · 탈퇴 정리 시 함께 삭제.

**시계열** — DB 에서 `date_trunc` 로 묶고, 빈 날은 서비스가 0으로 채운다. 방문 기록 시작 전 날짜는 null(그래프에서 빈칸).
조회 범위 상한: 일별 366일 · 월별 36달 (넘으면 잘라서 보여 줌).

## AI 상태 판정

창: 최근 60분. 제공자 = `AiCallType` 에 제공자 값을 추가(GEMINI · OPENAI · FLUX · LOCAL_LLM). 글·그림을 나눠 "Gemini 글", "OpenAI 그림" 단위 카드.
대상 = 지금 설정에서 선택된 글·그림 제공자 + 최근 24시간에 호출 기록이 있는 제공자.

오류 분류(운영 실패 기록 실측 기준, 대소문자 무시, 위에서부터 첫 일치):

| 분류 | 문구 |
|---|---|
| 크레딧·결제 | `no credits`, `insufficient_quota`, `exceeded your current quota`, `billing`, `balance`, `402` |
| 키·권한 | `401`, `403` |
| 한도 초과 | `429`, `rate limit`, `resource_exhausted` |
| 안전 필터 | `safety` |
| 제공자 장애 | `500`, `502`, `503`, `504`, `unavailable` |
| 시간 초과 | `timeout`, `timed out` |
| 기타 | 그 밖 |

상태(위에서부터):
1. **크레딧 소진 의심** — 창 안 마지막 실패가 크레딧·결제이고 그 뒤 성공 없음
2. **키 오류** — 창 안 마지막 실패가 키·권한이고 그 뒤 성공 없음
3. **오류 늘어남** — 창 안 호출 3건 이상, 실패율 50% 이상
4. **호출 없음** — 창 안 호출 0건 (판단 보류, 마지막 성공 시각 표시)
5. **정상**

잔액 숫자는 보여 주지 않는다(제공자 API 로 조회하지 않음).

## 성능

- 대시보드 요약은 기존 60초 캐시에 함께 넣는다. 추이 API 는 (종류, 단위, 기간) 키로 60초 캐시.
- 시계열 쿼리는 날짜 범위 조건 + group by 한 번 (회원 38명 · AI 기록 1,772건 규모, 연 수십만 건까지 인덱스로 충분).
- 사이드바 배지는 페이지마다 1회 fetch, 서버 60초 캐시.
- 방문 기록은 회원당 하루 1회 insert.
- 로컬에서 쿼리 시간 측정해 보고.

## 실패 경로

- 집계 실패: 대시보드는 이전 캐시 유지(기존 방침), 추이 API 실패 시 카드에 "불러오지 못했어요 (E-ADMIN-STATS)" + 다시 시도 버튼, 다른 카드는 그대로.
- chart.js 로드 실패: 그래프 자리에 같은 문구, 숫자 카드는 서버 렌더라 영향 없음.
- 방문 기록 실패: warn 로그, 요청 통과.
- 잘못된 단위·날짜 파라미터: 기본값(일별 30일)으로 보정.

## 설정 추가

- `USD_TO_KRW_RATE` (PRICING 그룹, DECIMAL, 기본 1400) — 비용 원화 환산용.

## 하지 않는 것

- 제공자 잔액 API 조회, 알림 웹훅(후속), 실시간 접속(WebSocket).
- 2단계(별도 이슈): 공동 보호자·초대 조회, 하드코딩 운영 값의 설정 이전, 광고 보상·알림 조회, 다른 목록 기간 필터, CSV 내보내기.

## 테스트

- AI 오류 분류·상태 판정(운영 실측 문구로) — 단위 테스트. 깨지면 크레딧 소진을 정상으로 보여 준다.
- 시계열 빈 날 채우기·방문 시작 전 null — 단위 테스트. 깨지면 그래프가 날짜를 건너뛴다.
- 방문 기록 하루 1회 — 단위 테스트. 깨지면 매 요청 insert.
- 쿼리·마이그레이션은 로컬 Postgres 에서 서버를 띄워 실측(이 레포에 SpringBootTest 없음).
- 브라우저로 세 화면 라이트·다크 확인.
