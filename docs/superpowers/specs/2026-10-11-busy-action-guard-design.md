# 서버 요청 버튼 — 진행 중 표시와 중복 실행 방지 공통화

- 날짜: 2026-10-11
- 모듈: 클라
- 계기: 카드확인 `저장하기`가 두 번 실행돼 저장은 됐는데 `ROUTINE_INVALID_STATUS` 팝업이 떴다

## 1. 무엇이 문제인가

운영 로그(10/10 19:36, 일과 `57012127…`)에서 본 순서다.

```
28.245  DELETE steps/0c63…   200   ← 1번째 저장
28.800  DELETE steps/41c3…   200
29.285  PATCH  /confirm      200   ← 저장 완료 (PENDING_REVIEW → CONFIRMED)
29.360  DELETE steps/41c3…   404   ← 2번째 저장 (약 1초 뒤 다시 누름)
29.471  PATCH  /confirm      409 ROUTINE_INVALID_STATUS  ← 팝업
```

저장이 1초쯤 걸리는 동안 버튼이 잠기지 않고 아무 표시도 없어, 보호자가 한 번 더 눌렀다.

전수조사 결과 누르면 서버로 가는 곳이 36곳이다. 지금은 화면마다 `_busy`·`_saving` 플래그를
따로 두고, 공통 장치가 없다. 그래서 빠진 곳이 생긴다.

| 상태 | 곳 | 비고 |
|---|---|---|
| 중복 방지 없음 | 7 | 높음 1(카드확인 저장), 중간 1(오늘 일과 삭제), 낮음 5 |
| 방지는 있고 진행 표시 없음 | 13 | 비밀암호 변경, 온보딩 시작하기, 홈 일과 만들기 등 |
| 둘 다 있음 | 6 | 로그인, 약관, 의견 보내기, 연결 암호 입력, 초대 참여, 광고 대기 |

## 2. 목표

- 누르면 서버로 가는 동작은 **누르는 즉시 잠기고, 진행 중임이 보인다.**
- 화면 쪽 잠금이 뚫려도 **같은 요청은 한 번만** 나간다.
- 화면마다 플래그를 새로 만들지 않고 **공통 부품을 쓴다.**

## 3. 공통 부품

### 3.1 `ElumButton(loading:)` — `core/widgets/elum_button.dart`

- `bool loading = false` 를 더한다.
- `loading == true` 이면 누를 수 없고(비활성 색), 버튼 오른쪽에 스피너가 돈다.
- 모양은 의견 보내기 화면에서 쓰던 것을 표준으로 삼는다: `ElumSpinner(size: 22.w,
  color: colors.buttonDisabledText)`, 오른쪽 안쪽 여백 `24.w`. 문구는 그대로 둔다.
- 시안에 없는 상태다. 사용자가 이 모양을 표준으로 쓰기로 했다(2026-10-11).
- 의견 보내기의 `_SendButton` 은 `ElumButton(loading:)` 으로 바꾸고 지운다.

### 3.2 `BusyStateMixin` — `core/state/busy_state_mixin.dart`

화면(State)이 쓰는 공통 메서드다.

```dart
mixin BusyStateMixin<T extends StatefulWidget> on State<T> {
  bool get busy;                         // 아무 작업이든 진행 중
  bool isBusy(Object key);               // 목록 항목별 진행 중 (삭제 중인 타일 등)
  Future<R?> runBusy<R>(Future<R> Function() task, {Object key = _global});
}
```

- 진행 중이면 다시 부르지 않고 `null` 을 돌려준다.
- 시작할 때 `setState` 로 잠그고, 끝나면(성공·실패 모두) `finally` 에서 푼다.
- 화면이 닫혔으면(`!mounted`) `setState` 하지 않는다.
- **예외를 삼키지 않는다.** 그대로 던져 화면의 기존 실패 처리(`showFailure`)가 받는다.

### 3.3 `SingleFlight<T>` — `core/state/single_flight.dart`

상태 관리(notifier) 쪽 공통 장치다.

```dart
class SingleFlight<T> {
  Future<T> run(Future<T> Function() task);  // 진행 중이면 그 Future 를 그대로 돌려준다
  bool get running;
}
```

- 끝나면(성공·실패 모두) 비운다. 다음 호출은 새로 실행한다.
- 카드 생성(`generateCards`)은 성공 뒤에도 가드를 유지하는 다른 규칙이라 **바꾸지 않는다.**

### 3.4 공통 팝업 버튼 — 하지 않는다

- 전수조사에서 "팝업 버튼을 빠르게 두 번 누르면 아래 화면까지 닫힐 수 있다"를 의심했다.
- 시험으로 밟아 보니 닫히는 중인 팝업은 Flutter 가 터치를 받지 않아 일어나지 않는다. 고치지 않는다.

### 3.5 설정 타일 — `core/widgets/settings_tile.dart`

- `bool loading = false` 를 더한다. 켜지면 오른쪽 화살표 자리에 스피너가 돌고 누를 수 없다.

## 4. 적용 대상

번호는 전수조사 표 번호다.

| # | 화면·동작 | 지금 | 바꾼 뒤 |
|---|---|---|---|
| 1 | 카드확인 `저장하기` | 방지·표시 없음 | `runBusy` + `ElumButton(loading)`, notifier `save()` 에 `SingleFlight` |
| 9 | 홈 오늘 일과 스와이프 삭제 | 방지·표시 없음 | `runBusy(key: 일과 id)`, 삭제 중인 타일은 스와이프 잠금 + 스피너 |
| 3 | 카드 추가 시트 저장 | 회색만 | `ElumButton(loading)` |
| 13 | 임시저장 스와이프 삭제 | 잠금만 | 삭제 중인 타일에 스피너 (`isBusy(key)`) |
| 14 | 홈 `새로운 일과 만들기` (최대 3초 크레딧 확인) | 표시 없음 | 버튼 로딩 표시 |
| 16·17 | 보호자 설정 로그아웃·회원탈퇴 | 타일 잠금만 | `SettingsTile(loading)` |
| 18 | 그림 방식 선택 | 표시 없음 | 고른 항목에 스피너 |
| 19 | 비밀암호 변경 `저장하기` | 회색만 | `ElumButton(loading)` |
| 20 | 온보딩 `시작하기` (요청 6개) | 표시 없음 | `ElumButton(loading)` |
| 23 | 약관 화면 뒤로가기(로그아웃) | 방지 없음 | `runBusy` |
| 27 | 연결된 휴대폰 `끊기` | 잠금만 | 로딩 표시 |

### 하지 않는 것

| # | 동작 | 이유 |
|---|---|---|
| 2 | 카드 수정 시트 저장 | 시트가 닫힌 뒤 같은 값 PATCH. 멱등 |
| 10·12 | 일과·카드 드래그 순서 변경 | 낙관적 UI. 멱등이고 표시를 넣으면 드래그를 방해한다 |
| 21·22·25·30·15 | 로그인·약관·연결 암호·초대·광고 | 이미 방지·표시가 있다. 로그인의 `연결 중…` 같은 문구 교체는 그대로 둔다 |
| - | 서버 `confirm` 을 멱등으로 바꾸기 | API 동작 변경이다. 운영 중인 앱이라 API 를 바꾸지 않는다 |

## 5. 흐름

**행복 경로**: 누름 → 즉시 잠금·스피너 → 요청 → 성공 → 잠금 해제(또는 화면 이동).

**실패 경로**

| 상황 | 처리 |
|---|---|
| 서버 실패·타임아웃 | 잠금을 풀고 기존 실패 팝업(에러 코드 포함)을 띄운다. 다시 누를 수 있다 |
| 진행 중 화면이 닫힘 | `setState` 하지 않는다. 요청은 끝까지 가고 결과만 버린다 |
| 진행 중 다시 누름 | 화면: 무시. notifier: 진행 중인 같은 Future 를 돌려준다 → 서버 요청 1번 |
| 예외 | 삼키지 않는다. 화면의 `showFailure` 가 에러 코드와 함께 보여준다 |

## 6. 검증

- 단위 시험: `SingleFlight`(동시 2번 → 실행 1번, 실패 뒤 다시 실행), `BusyStateMixin`(진행 중 재호출 무시,
  실패해도 해제, dispose 뒤 setState 없음), `ElumButton(loading)`(눌러도 콜백 없음, 스피너 있음),

- 화면 시험: 카드확인 `저장하기` 두 번 → `confirm` 1번, 실패 팝업 없음. 오늘 일과 삭제 두 번 → DELETE 1번.
- 기존 시험 전체 1회.
- 실기기: iOS 시뮬레이터에서 일과 만들기 → 카드 빼기 → `저장하기` 연타 → 팝업 없음, 스피너 보임.
  비밀암호 변경·로그아웃 로딩 표시를 눈으로 확인한다.
