> 관련 설계: [이미지 프로바이더 추상화](./2026-09-18-image-provider-abstraction-design.md) ·

## 배경

[라이선스 설계](./2026-09-18-license-entitlement-design.md)에서 **Free는 AI 이미지
생성을 쓰지 못한다**고 정했다. 원가의 99%가 이미지이므로 옳은 결정이다.

**다만 그림이 아예 없으면 서비스가 작동하지 않는다.**

> CLAUDE.md 타겟 정의 — *"행동 카드의 **시각정보**와 순서를 이해할 수 있는 발달장애인"*

글자만 남은 카드는 기능 하나가 빠진 게 아니라, 당사자 입장에서 **쓸 수 없는 물건**이다.
글을 읽을 수 있으면 애초에 카드가 필요 없다.

그래서 Free에도 그림이 있어야 하되 **원가가 0이어야** 한다.

## 왜 프리셋이 아니라 검색인가

공용 삽화를 미리 100장 만들어두는 안을 먼저 검토했다. 커버리지에서 막힌다 —
*"친구랑 인사하고 자리에 앉기"* 같은 단계는 어떤 프리셋 목록에도 없다. 일과는
사용자가 자유롭게 쓰므로 미리 다 만들 수 없다.

**키워드로 픽토그램을 찾는 방식**이 이 문제를 푼다. 넓은 심볼 집합에서 고르면
커버리지가 비교할 수 없이 넓고, 원가는 여전히 0이다.

## 라이선스 — 여기가 핵심이다 ⚠️

Pro 유료 구독을 붙이는 순간 elum은 **상업적 제품**이 된다. 심볼 라이선스가
이걸 허용해야 한다.

### ARASAAC은 쓸 수 없다

AAC 분야의 사실상 표준이라 무심코 집어 쓰기 쉽다. **CC BY-NC-SA**다.

- `NC` = NonCommercial. 공식 안내도 *"상업적 목적의 제품·출판물 내 사용은 제외된다"*
- 별도 허가 없이는 **불가**
- 표기 의무도 무겁다 (저작자 Sergio Palao, 소유 Gobierno de Aragón, 출처 ARASAAC, 라이선스)

### Mulberry Symbols를 쓴다

**CC BY-SA 4.0** (Mulberry Symbols v3.6.1) — 상업적 제품에서 사용 가능하다.

그리고 elum에 특히 맞는 이유가 하나 더 있다.

> Mulberry Symbols — *"communication symbol set designed for **adults** with
> language difficulties"*

**성인 대상으로 설계된 세트**다. CLAUDE.md의 *"20대 당사자가 자기 휴대폰에서 이 앱을
연다"*, *"아이라고 부르지 않는다"* 와 같은 방향이다. 아동용 일러스트를 쓰면 그
원칙과 정면으로 어긋나는데 Mulberry는 그 문제가 없다. SVG라 확대해도 깨지지 않는다.

**의무 사항**

1. **출처 표기** — 앱 안에 오픈소스 라이선스 화면이 필요하다 (클라이언트 작업).
2. **동일 라이선스(SA)** — 파생물은 같은 라이선스로 배포해야 한다.
   → **심볼을 변형하지 않고 그대로 쓴다.** 색 변경·합성은 파생물 논란을 부를 수 있다.
   크기 조정과 배치는 변형이 아니다.

> ⚠️ 심볼을 그대로 갖다 쓰는 것이 앱 전체를 BY-SA로 만들지는 않는 것으로 이해되나,
> 이 문서를 쓴 사람은 변호사가 아니다. **실제 과금을 시작하기 전에 한 번 확인받는다.**

### OpenSymbols API를 쓰지 않는 이유

6만 개를 통합 제공하지만 **세트마다 라이선스가 섞여 있다.** 그대로 붙이면 어느 순간
NC 심볼이 상업 제품에 들어간다. 쓴다면 Mulberry로 필터링하는 전제여야 하는데,
그럴 바에는 Mulberry를 직접 번들하는 편이 안전하고 빠르다.

## 목표 / 비목표

**목표**

1. 그림이 없는 카드(그림 방식 직접 사진 · AI 그림 실패 · Free 요금제)에 의미가 맞는 그림이 붙는다. 원가는 글 호출 수준.
2. 매칭에 실패해도 카드 생성이 성공한다.
3. 라이선스 의무를 지킨다.

**비목표**

- 사용자가 픽토그램을 직접 고르는 UI. 이번에는 자동 매칭만 한다.
- Pro의 AI 삽화를 픽토그램으로 대체하는 것. 둘은 다른 물건이다.
- 심볼 색상·스타일 커스터마이즈 (SA 조항 때문에 하지 않는다).

## 설계

### 심볼은 앱에 번들하고, 서버는 `pictogramId` 만 저장한다

Mulberry SVG 전체(811개 사용)는 **앱에 번들**한다. 서버는 SVG 를 서빙하지 않는다.

- 외부 서비스 장애가 카드 생성을 막지 않는다 (외부 API 호출 없음)
- 앱이 오프라인이어도 그림이 보인다
- 서버는 SVG 파일명 stem(예 `get_dressed_,_to`)인 `pictogramId` 만 저장한다 — 파일 복사도 정적 서빙도 없다

서버와 앱이 같은 카탈로그를 본다. 카탈로그는
`server/src/main/resources/pictograms/catalog.json`(id·label·category·verb, 최상위 source·license·
attribution·fallbackId)이 원본이고, 앱은 같은 파일을 복사해 동기 테스트를 한다. **수정하지 않는다.**

### 선택 방식 — 방식 1(검색어)에서 방식 2(제한 목록 선택)로

처음 설계는 LLM 이 영어 검색어(`pictogramKeyword`)를 만들고 서버가 라벨과 매칭(정확 → 부분 → 폴백)하는
**방식 1** 이었다. 저가 모델로 실측해 **방식 2** 로 바꿨다.

| 방식 | 내용 | 결과 |
| --- | --- | --- |
| 1. 검색어 | 모델이 영어 키워드 생성 → 서버가 라벨과 매칭 | 방식 2 와 비교해 채택하지 않음(수치는 #247 댓글) |
| **2. 제한 목록 선택** | **811개 id 목록을 주고 그중 하나를 고르게 한다** | **의미 적중 93%, 폴백 2%** |

방식 2 가 이기는 이유 — 모델이 카탈로그에 **없는 말을 만들 수 없고**, 서버는 매칭 로직 없이 "목록에 있나"만
검증한다. 실측 기록은 이슈 #247 댓글의 '실측 기록'에 있다.

**요청**

- 카탈로그를 요청 JSON 의 필드 `pictogramCatalog`(id 문자열 배열)로 함께 보낸다.
- 지시는 프롬프트(운영 DB 값이라 배포로 안 바뀐다)가 아니라 **코드(스키마의 `pictogramId` description)** 에 둔다:
  *"pictogramCatalog 안에서 이 단계의 행동이나 사물을 가장 잘 나타내는 id 하나. 알맞은 것이 없거나 확신이
  없으면 null. 억지로 고르지 마세요(비슷하지만 뜻이 다른 것 금지)"*
- 스키마는 **nullable string** 이다. enum 으로 만들지 않는다(811개라 비대해진다). OpenAI strict 변환은
  `nullable: true` 를 `type: ["string", "null"]` 로 바꾼다.

```java
/// pictogramId: 카탈로그에서 고른 id. 선택 필드 — 옛 프롬프트·모델이 빠뜨려도 카드 생성은 실패하지 않는다.
public record StepDraft(Integer order, String title, String description, String imagePromptEn, String pictogramId) {}
```

**검증 · 폴백**

1. `pictogramId` 가 카탈로그에 없으면 null 로 취급한다.
2. **null · 무효면 폴백 `go_,_to`(카탈로그 `fallbackId`)를 저장한다.** 개념이 없어도 카드에는 항상 그림이 있다.
3. 이미지 생성 여부·그림 방식과 무관하게 **항상 요청하고 저장**한다(AI 그림이 실패해도 픽토그램이 나오게).
   앱이 우선순위 **사진 > AI 그림 > 픽토그램** 으로 고른다.
4. 카탈로그 파일이 없거나 깨지면 서버는 그대로 뜨고(빈 카탈로그 + 경고 로그) `pictogramId` 는 항상 null.

**카드 직접 추가(addStep)** 는 일과 생성 호출이 없으므로 저가 글 모델을 한 번 더 부르는 `PictogramPicker` 가
제목·설명·카탈로그로 id 하나를 고른다. 호출 실패·타임아웃·무효는 폴백이며 **카드 추가는 절대 실패하지 않는다.**
크레딧은 쓰지 않는다(글 호출 단가라 별도 청구 없이 원가로 흡수). 하루 비용 상한에 걸리면 호출을 건너뛰고
폴백을 쓰며, 호출은 `ai_call_log`(`*_TEXT_PICTOGRAM`)에 남아 하루 합계에 잡힌다.

### 저장 방식

`RoutineStep.pictogramId`(nullable, `VARCHAR(100)`, Flyway V29) 하나만 추가한다. AI 삽화(`imagePath`)와
**배타적이 아니다** — 둘 다 채워질 수 있고 앱이 우선순위로 고른다. 응답 `RoutineStepResponse.pictogramId`
가 null 이면 이 카드는 픽토그램이 없는 것이다(이 기능 이전 카드 등).

> Pro였다가 Free로 내려온 회원의 **기존 AI 삽화는 지우지 않는다.** 이미 만든 것을 뺏는 것은 부당하고,
> 지워도 쓴 돈이 돌아오지 않는다.

## 행복 경로

```
보호자가 일과를 만든다 (그림 방식이 직접 사진이거나, AI 그림이 없는 요금제이거나, AI 그림이 실패해도)
  → 글 호출이 카드 글 + pictogramId(카탈로그 안의 id)를 함께 생성 — 추가 호출·추가 원가 없음
  → 서버가 pictogramId 를 카탈로그로 검증
  → RoutineStep.pictogramId 저장 (파일 복사 없음)
  → 앱이 사진 > AI 그림 > 픽토그램 순으로 골라 그린다
```

## 실패 경로

| 상황 | 동작 | 사용자에게 |
| --- | --- | --- |
| 모델이 `pictogramId` 를 안 줌 · null | 폴백 `go_,_to` 저장 | 폴백 그림. 카드는 정상 |
| 카탈로그에 없는 id(환각) | 폴백 `go_,_to` 저장 | 〃 |
| addStep 픽커 호출 실패 · 타임아웃 · 잘못된 응답 | 폴백 저장. 카드 추가는 성공 | 〃 |
| 하루 비용 상한 | 픽커 호출 생략, 폴백 저장 | 〃 |
| 카탈로그 파일 없음·손상 | 빈 카탈로그 + 경고 로그, `pictogramId` null | 앱이 기본 그림으로 대체. **로그로 즉시 드러난다** |
| 앱에 SVG 가 없는 id | 앱이 폴백 그림으로 대체(클라이언트 작업) | 〃 |

**어떤 경우에도 일과 생성·카드 추가가 실패하지 않는다.** 그림은 카드를 더 좋게 만들지만,
그림 때문에 카드가 안 만들어지면 안 된다.

## 영향 범위

- `RoutineStepDraft.StepDraft` — `pictogramId` 선택 필드
- `GeminiTextClient` / `OpenAiTextClient` — 요청에 `pictogramCatalog`, 스키마에 nullable `pictogramId`,
  카드 추가용 `pickPictogramJson`
- `RoutineAiPipeline` — 검증 · 폴백
- `RoutineStep` · `RoutineStepResponse` · Flyway V29 — `pictogramId`, 일과 복제가 복사
- 신규: `PictogramCatalog`(카탈로그 로딩·검증), `PictogramPicker`(카드 추가 시 고르기), `AiCallType`
  `*_TEXT_PICTOGRAM`
- 클라이언트: 카탈로그 복사·SVG 번들·렌더링, 오픈소스 라이선스 화면

## 테스트

- 카탈로그 무결성: 811개, id 중복 없음, `fallbackId` 가 목록에 있음, id 에 경로 위험 문자 없음
- 카탈로그 로딩 실패(없음·손상)에도 서버가 뜬다
- 유효 / 무효 / 누락 id 처리와 폴백, 그림 방식·이미지 실패와 무관한 저장
- 스키마 nullable, OpenAI strict 변환
- addStep 픽커 성공 · 실패 · 타임아웃 · 무효 · 비용 상한, 복제, 응답 필드
- **실제 LLM을 부르지 않는다.** 응답을 고정해 검증한다

## 열린 질문

1. ~~Mulberry 라벨이 한국어 일과를 얼마나 덮는가.~~ 실측했다 — 제한 목록 선택 방식에서 의미 적중 93%,
   폴백 2%(위 '선택 방식'). 폴백 비율은 서버 로그(`픽토그램 폴백 적용`)로 계속 본다.
2. **폴백 아이콘 `go_,_to`("가다")가 적절한가.** 개념이 없는 카드에 "가다"가 붙는다. 디자인 확인이 필요하다.
3. **Pro 사용자에게도 픽토그램 선택지를 줄까.** AI 삽화가 마음에 안 들 때 대안이 될 수
   있다. 이번 범위 밖이다.
