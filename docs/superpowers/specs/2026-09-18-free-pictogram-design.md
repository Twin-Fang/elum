## 배경

[라이선스 설계](./2026-09-18-license-entitlement-design.md)에서 **Free는 AI 이미지
생성을 쓰지 못한다**고 정했다. 원가의 99%가 이미지이므로 옳은 결정이다.

**다만 그림이 아예 없으면 서비스가 작동하지 않는다.**

> CLAUDE.md 타겟 정의 — *"행동 카드의 **시각정보**와 순서를 이해할 수 있는 발달장애인"*

글자만 남은 카드는 기능 하나가 빠진 게 아니라, 당사자 입장에서 **쓸 수 없는 물건**이다.
글을 읽을 수 있으면 애초에 카드가 필요 없다.

그래서 Free에도 그림이 있어야 하되 **원가가 0이어야** 한다.

## 왜 프리셋이 아니라 검색인가

공용 삽화를 미리 100장 만들어두는 안을 먼저 검토했다. 커버리지에서 막힌다 —
*"친구랑 인사하고 자리에 앉기"* 같은 단계는 어떤 프리셋 목록에도 없다. 일과는
사용자가 자유롭게 쓰므로 미리 다 만들 수 없다.

**키워드로 픽토그램을 찾는 방식**이 이 문제를 푼다. 넓은 심볼 집합에서 고르면
커버리지가 비교할 수 없이 넓고, 원가는 여전히 0이다.

## 라이선스 — 여기가 핵심이다 ⚠️

Pro 유료 구독을 붙이는 순간 elum은 **상업적 제품**이 된다. 심볼 라이선스가
이걸 허용해야 한다.

### ARASAAC은 쓸 수 없다

AAC 분야의 사실상 표준이라 무심코 집어 쓰기 쉽다. **CC BY-NC-SA**다.

- `NC` = NonCommercial. 공식 안내도 *"상업적 목적의 제품·출판물 내 사용은 제외된다"*
- 별도 허가 없이는 **불가**
- 표기 의무도 무겁다 (저작자 Sergio Palao, 소유 Gobierno de Aragón, 출처 ARASAAC, 라이선스)

### Mulberry Symbols를 쓴다

**CC BY-SA 2.0 UK** — 상업적 제품에서 사용 가능하다.

그리고 elum에 특히 맞는 이유가 하나 더 있다.

> Mulberry Symbols — *"communication symbol set designed for **adults** with
> language difficulties"*

**성인 대상으로 설계된 세트**다. CLAUDE.md의 *"20대 당사자가 자기 휴대폰에서 이 앱을
연다"*, *"아이라고 부르지 않는다"* 와 같은 방향이다. 아동용 일러스트를 쓰면 그
원칙과 정면으로 어긋나는데 Mulberry는 그 문제가 없다. SVG라 확대해도 깨지지 않는다.

**의무 사항**

1. **출처 표기** — 앱 안에 오픈소스 라이선스 화면이 필요하다 (클라이언트 작업).
2. **동일 라이선스(SA)** — 파생물은 같은 라이선스로 배포해야 한다.
   → **심볼을 변형하지 않고 그대로 쓴다.** 색 변경·합성은 파생물 논란을 부를 수 있다.
   크기 조정과 배치는 변형이 아니다.

> ⚠️ 심볼을 그대로 갖다 쓰는 것이 앱 전체를 BY-SA로 만들지는 않는 것으로 이해되나,
> 이 문서를 쓴 사람은 변호사가 아니다. **실제 과금을 시작하기 전에 한 번 확인받는다.**

### OpenSymbols API를 쓰지 않는 이유

6만 개를 통합 제공하지만 **세트마다 라이선스가 섞여 있다.** 그대로 붙이면 어느 순간
NC 심볼이 상업 제품에 들어간다. 쓴다면 Mulberry로 필터링하는 전제여야 하는데,
그럴 바에는 Mulberry를 직접 번들하는 편이 안전하고 빠르다.

## 목표 / 비목표

**목표**

1. Free 카드에 의미가 맞는 그림이 붙는다. 원가 0.
2. 매칭에 실패해도 카드 생성이 성공한다.
3. 라이선스 의무를 지킨다.

**비목표**

- 사용자가 픽토그램을 직접 고르는 UI. 이번에는 자동 매칭만 한다.
- Pro의 AI 삽화를 픽토그램으로 대체하는 것. 둘은 다른 물건이다.
- 심볼 색상·스타일 커스터마이즈 (SA 조항 때문에 하지 않는다).

## 설계

### 심볼을 서버에 번들한다

Mulberry는 SVG 전체가 공개 저장소에 있다. **외부 API를 호출하지 않고 서버에 동봉**한다.

- 외부 서비스 장애가 카드 생성을 막지 않는다
- 네트워크 왕복이 없어 빠르다
- 라이선스 검증을 빌드 시점에 한 번만 하면 된다

> 심볼 개수·파일 구조·메타데이터(라벨) 형식은 **저장소를 받아 실제로 확인한 뒤**
> 확정한다. 이 문서에 추정치를 적지 않는다.

### 검색 키워드는 LLM이 함께 만든다

Mulberry는 영어 기반이라 *"양치하기"* 로는 걸리지 않는다. **이미 LLM을 부르고 있으니
거기서 같이 받는다 — 추가 호출도, 추가 원가도 없다.**

```java
/// pictogramKeyword: 이 단계를 나타내는 영어 검색어 1~2단어 (예: "brush teeth").
/// 카드 글과 함께 받으므로 AI 호출이 늘지 않는다.
public record StepDraft(String title, String description, String pictogramKeyword) {}
```

프롬프트 템플릿(`PromptKey`)에 이 필드를 요구하는 지시를 더한다. 기존 응답 파싱은
필드가 없어도 깨지지 않게 **선택 필드**로 둔다 — 옛 프롬프트로 생성된 응답이나
LLM이 필드를 빠뜨린 경우에도 카드 생성이 실패하면 안 된다.

### 매칭 단계

```
1. 정확 매칭    keyword == 심볼 라벨
2. 부분 매칭    라벨에 keyword의 주요 단어 포함
3. 폴백         기본 아이콘 1종
```

어느 단계에서 걸렸는지 로그로 남긴다. 폴백 비율이 높으면 프롬프트를 손봐야 한다는
신호다.

### 저장 방식

AI 삽화는 생성 결과를 `RoutineImageStorage`에 파일로 저장한다. 픽토그램은 **번들된
자산이라 복사할 이유가 없다.** `RoutineStep`에 심볼 식별자만 저장하고 조회 시
경로를 만든다.

```java
/// AI 삽화 경로. 픽토그램을 쓰는 카드는 null이다.
private String imagePath;

/// 픽토그램 식별자. AI 삽화를 쓰는 카드는 null이다.
private String pictogramId;
```

둘 중 하나만 채워진다. 응답 DTO가 어느 쪽인지 알려주면 클라이언트가 렌더링을 가른다.

> Pro였다가 Free로 내려온 회원의 **기존 AI 삽화는 지우지 않는다.** 이미 만든 것을
> 뺏는 것은 부당하고, 지워도 쓴 돈이 돌아오지 않는다.

## 행복 경로

```
Free 회원이 일과를 만든다
  → LLM이 단계 글 + pictogramKeyword("brush teeth")를 함께 생성
  → EntitlementService: AI_IMAGE_GENERATION 불허 확인
  → 픽토그램 검색 → 매칭 성공
  → RoutineStep.pictogramId 저장 (파일 복사 없음)
  → 카드에 그림이 보인다. 원가 0
```

## 실패 경로

| 상황 | 동작 | 사용자에게 |
| --- | --- | --- |
| LLM이 `pictogramKeyword`를 안 줌 | 단계 제목에서 추출 시도 → 실패 시 폴백 | 폴백 아이콘. 카드는 정상 |
| 키워드 매칭 0건 | 폴백 아이콘 | 〃 |
| 심볼 파일 누락·손상 | 폴백 아이콘 + 에러 로그 | 〃 |
| 번들 자체가 없음 (빌드 사고) | 전부 폴백 | 카드는 뜨지만 그림이 전부 같다. **로그로 즉시 드러나야 한다** |

**어떤 경우에도 일과 생성이 실패하지 않는다.** 그림은 카드를 더 좋게 만들지만,
그림 때문에 카드가 안 만들어지면 안 된다.

## 영향 범위

- `RoutineStepDraft` — `pictogramKeyword` 선택 필드 추가
- `PromptTemplate` — 프롬프트에 키워드 요구 지시 추가
- `RoutineStep` — `pictogramId` 컬럼 추가
- `RoutineStepResponse` — 그림 출처 구분 필드
- `RoutineAiPipeline` — 권한에 따른 분기
- 신규: 픽토그램 검색 서비스, 번들 자산, 정적 서빙 경로
- 클라이언트: 픽토그램 렌더링, 오픈소스 라이선스 화면

## 테스트

- 키워드 정확·부분 매칭, 0건 폴백
- `pictogramKeyword` 누락 응답이 파싱에 실패하지 않는지
- Free/Pro 분기가 올바른 경로로 가는지
- **실제 LLM을 부르지 않는다.** 응답을 고정해 검증한다

## 열린 질문

1. **Mulberry 라벨이 한국어 일과를 얼마나 덮는가.** 실제로 받아서 흔한 일과
   (아침 준비·등교·식사·위생)로 매칭률을 재본 뒤 폴백 비율을 판단한다.
2. **폴백 아이콘을 무엇으로 할까.** 의미 없는 회색 네모보다는 "활동"을 뜻하는
   중립적 심볼이 낫다. 디자인 확인이 필요하다.
3. **Pro 사용자에게도 픽토그램 선택지를 줄까.** AI 삽화가 마음에 안 들 때 대안이 될 수
   있다. 이번 범위 밖이다.
