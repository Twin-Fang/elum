# 이룸 참여·흐름·디자인 전면 개편 설계 (2026-11-14)

## 1. 왜 하는가

사용자(대표) 의견, 2026-11-14:
- passQL 은 깔끔하고 정갈한데 이룸은 아기자기하려다 애매하게 못생겼다. 단조롭고 옛날 앱 같다. 애니메이션이 거의 없다.
- 에셋이 적고 질이 낮다. "와, 앱 잘 만들었다" 느낌이 나야 한다. 에셋을 아낌없이 쓰고 애니메이션은 깔끔하고 멋있게.
- 돈 버는 요소가 여기저기 있다. 너무 돈 밝히는 느낌은 아니게, 대신 **개념을 설명하고 도움을 주는** 앱이어야 한다.
- 디자인 시스템을 대충 붙이는 게 아니라 **사용자 흐름(UI·UX 플로우)에 맞게**, 기능이 잘 작동해야 한다. **모든 흐름이 납득 가능**해야 한다.
- 이 앱을 **쓰게 만들어야** 한다. 알림을 적극적으로, 리텐션. 보상형 광고 흐름, 오버레이, 일정 기능이 보호자·이룸이 화면 모두에 있어야 한다. passQL 에는 다 있다.

**성공 기준**: 새 보호자가 가입 당일 첫 일과를 만들어 이룸이 기기로 보내고, 이룸이가 끝낸 것을 보호자가 축하받는다. 다음 날 알림으로 다시 들어온다. (측정: D1·D7 복귀율, 첫 일과 완료율, 알림 열림·24시간 복귀)

## 3. 목표 · 하지 않는 것 · 실패로 보는 것

**목표**
1. 보호자 첫날 흐름을 끝까지 이어지게(가입 > 기기 연결 > 첫 일과 > 보내기 축하 > 이룸이 완료 축하).
2. 매일 돌아올 이유(알림·스트릭·다음에 할 일·잠금화면 카드).
3. 화면마다 "왜 여기 있고 다음은 무엇인지"가 보이는 흐름. 개념은 짧게 설명하고 더 알고 싶으면 사이트 가이드로.
4. 깔끔한 바탕 + 아낌없는 3D 에셋 + 절제되고 멋진 모션(passQL 수준 규율).
5. 판매는 막힌 순간·자연스러운 순간에만.

**하지 않는 것**
- 이룸이 화면을 복잡하게 만들지 않는다 (발달장애 당사자용: 크게, 하나씩, 예측 가능).
- 외부 애니메이션 패키지(Lottie·Rive) 도입은 이번에 하지 않는다. Flutter 기본 애니메이션 + 토큰으로 (passQL 과 같은 이유: 무게·일관성).
- iOS 잠금화면 오버레이(불가). iOS 는 위젯·알림으로 대신.

**실패로 보는 것 (기술적으로 돼도)**
- 알림이 잦아 끄게 만든다 (하루 1개 상한 유지, 야간 금지).
- 판매 화면이 흐름을 끊는다.
- "아이" 호칭, 겁주는 문구, 효과 단정.

## 4. 접근 방식

| 안 | 내용 | 장단점 |
|---|---|---|
| A. 껍데기 먼저 (디자인 시스템 전면 교체 후 기능) | 토큰·컴포넌트를 새로 만들고 화면에 일괄 적용 | 겉은 빨리 바뀌지만 흐름 문제는 그대로, 사용자가 반려한 방식("대충 붙여놓으면") |
| **B. 흐름 단위로 기능+디자인 함께 (선택)** | 보호자 여정을 단계로 나눠, 단계마다 기능·안내·알림·모션·에셋을 한 번에 완성 | 단계마다 "완성된 경험"이 나감, 측정 가능. 전체 완료까지 여러 배포 |
| C. 알림·리텐션만 먼저 | 서버 알림 켜고 규칙 추가 | 빠르지만 들어와서 볼 화면이 그대로라 이탈 |

**B 를 고른 이유**: 사용자가 "흐름에 맞게, 납득 가능하게, 기능이 잘 작동하게"를 요구했고, 디자인만 바꾸는 A 는 이미 반려됐다. 단, 공통 모션·에셋 기반(단계 0)은 모든 단계가 쓰므로 먼저 만든다. (설계 결정은 대표가 "너가 봤을 때 설계해 줘"로 위임)

## 5. 설계

### 단계 0 · 공통 기반 (모든 단계가 씀)
- **모션 규율**: `AppMotion` 에 순차 등장(stagger 50ms, 상한 8), 스프링 곡선, 카운트업, 눌림(0.97) 정리. 공용 위젯 `AppReveal`(순차 등장), `AppPopIn`, `AppCountUp`, `AppCelebration`(보상 연출: 그림 튀어나옴 > 빛 > 이유 한 줄 > 게이지). 화면 코드의 `Duration(`·`Curves.` 직접 사용을 규칙 테스트로 금지(예외 목록).
- **에셋 세트**: 3D 일러스트를 이미지 하네스(`docs/image-harness`, 루미 규칙)로 추가 제작 — 빈 상태 6종(일과 없음, 연결 전, 리포트 빈 주, 알림 없음, 오류, 오프라인), 축하 4종(첫 일과, 보내기, 이룸이 완료, 연속 기록), 기능 아이콘 3D 12종(일정, 알림, 보상, 리포트, 가이드 등). `AppAssets` 경유.
- **작은 카드·하이라이트 컴포넌트**: `ElumInfoCard`(3D 그림 + 제목 + 한 줄 + 행동), `ElumHighlight`(민트/피치 띠). 홈 안내 카드·가이드 팁·빈 상태가 모두 이것을 쓴다.

### 단계 1 · 첫날 흐름 (가장 중요)
```
역할 선택 > ABA 소개 > 이름 > (새) 이룸이 기기 연결 단계(지금/나중에) > 예시 분류 > 캐릭터 > 그림 방식 > PIN > 알림 안내(미리보기 카드) > 홈
홈(첫날) = 「다음에 할 일」 카드 하나: 첫 일과 만들기 > 보내기 > 기기 연결 > 이룸이 첫 완료 기다리기
첫 일과 저장·보내기 > (새) 보내기 축하 화면(루미, 카드 묶음 날아감, "이룸이 기기로 보냈어요", 다음: 기기 연결/이룸이 화면 미리 보기)
이룸이 완료 푸시 > (변경) 그 일과의 완료 축하 화면(별 수, 걸린 시간, 칭찬 보내기 버튼)
```
- 왜: 지금은 저장 후 그냥 홈. 보낸 일과가 이룸이에게 닿는지가 첫 성공인데 연결 진입점이 설정에만 있다.
- 「다음에 할 일」 판정은 순수 함수(상태 > 한 가지), 판매·광고는 넣지 않는다 (passQL DEC-0305 와 같은 원칙).
- 빈 상태 회색 칸 > 3D 그림 + 한 줄 + 버튼.
- 쓰이지 않는 `card_completion_screen` 은 보내기 축하로 대체하거나 지운다.

### 단계 2 · 매일 돌아올 이유 (알림·스트릭·일정)
- **운영 켜기**: 자동 알림 5종, 주간 리포트 알림(Free 포함, 요약만), 광고 보상 — 운영 설정 확인 후 켬 (대표 승인 필요).
- **새 자동 알림 규칙** (서버 규칙 테이블에 추가, 사람당 하루 1개·야간 금지·종류별 끄기 유지, 문구 5개 언어):
  - `ONBOARDED_NO_ROUTINE` 가입 다음 날 첫 일과 없음 (D1, D3 각 1회)
  - `SENT_NOT_DONE` 보낸 일과를 이룸이가 그날 시작 안 함 (보호자에게, 저녁 1회)
  - `STREAK_AT_RISK` 어제까지 연속 완료, 오늘 아직 (이룸이 기기에 부드럽게 + 보호자 요약)
  - `LINK_PENDING` 일과는 보냈는데 기기 연결이 안 됨
- **스트릭**: 이룸이 연속 완료 일수 (하루 유예). 보호자 홈 상단 작은 불꽃 + 이룸이 홈 별 줄. Free 포함.
- **일정**: 일과에 시간 정하기를 일과 만들기 마지막 단계와 홈 일과 카드에서 바로 (지금은 상세 시트 깊은 곳). 로컬 알림 탭 > 그 일과로. 이룸이 홈 "오늘 할 일" 시간순.
- **딥링크**: 완료 알림 > 그 일과 완료 화면, 알림으로 들어온 화면엔 판매 시트 금지.
- **측정**: 규칙별 발송·열림·24시간 복귀 관리자 표 (passQL 와 같은 모양).

### 단계 3 · 오버레이
- **Android 잠금화면 카드 (보호자 선택, 기본 꺼짐)**: 화면을 켜면 "오늘 이룸이 일과 2/3, 다음: 양치하기" 카드. passQL 구조 이식(포그라운드 서비스, showWhenLocked, 미리 데운 엔진, 1시간 쉬기, 통화 중 생략). 소개는 첫 완료 뒤 1회 + 7일 뒤 1회.
- **이룸이 기기 잠금화면 카드 (보호자가 켬)**: 일과 시간에 화면을 켜면 지금 할 카드 한 장 (크게, 하나만). 발달장애 당사자의 시작을 돕는 핵심 장치.
- **앱 안 오버레이**: 첫 일과 진행 안내 띠(3단계 진행도, 화면 위 작은 떠 있는 띠), 홈 코치마크 다시 보기(`?`).
- **iOS**: 잠금화면 대신 홈 화면 위젯(오늘 진행·다음 일과)과 시간 알림.

### 단계 4 · 보상형 광고 흐름 정리
- 크레딧이 막힌 순간에만: 생성 막힘 시트 = 광고(채운 버튼, "15~30초, 끝까지 보면 일과 1개") > Pro > 꾸러미. 보상량을 일과 1개 분량으로 (설정값, 대표 확인).
- 미리 불러 둔 경우에만 제안, 실패는 조용히·코드와 함께.
- 보상 연출을 `AppCelebration` 으로 (받은 이유, 이전>이후 게이지, 햅틱).
- 카드 검토 중 업셀(다시 그리기·나누기·AI 그림)은 판매 대신 "Pro 기능" 작은 표시 + 누르면 짧은 설명 시트(무엇을 해 주는지 먼저), 흐름 안 페이월 금지.

### 단계 5 · 화면별 디자인 마감
- 보호자 홈, 일과 만들기, 카드 검토, 주간 리포트(차트 차오름), 설정, 온보딩 전환을 단계 0 컴포넌트·모션·에셋으로 마감.
- 가이드 팁 카드(#1403)를 `ElumInfoCard` 로 다시 입혀 병합. 홈에는 「다음에 할 일」이 우선, 팁은 그 아래 하나.
- 이룸이 화면은 따로: 크게·하나씩 원칙 유지, 완료·보상 연출만 다듬음.

## 6. 실패 경로
- 알림 권한 거부 > 앱은 그대로, 홈 「다음에 할 일」에 "알림 켜기"가 한 번 들어감(7일 간격).
- 잠금화면 권한 일부 거부 > 단계 화면에서 멈추고 이유와 설정 열기, 기능은 꺼진 채.
- 광고 로드 실패 > 제안 자체를 안 보임, 막힌 사람에게는 Pro·꾸러미·다음 주 충전일 안내.
- 축하 화면 중 네트워크 실패 > 축하는 로컬로, 서버 반영은 재시도.
- 새 알림 규칙이 잘못 대상 고름 > 규칙별 끄기(관리자), 열림·복귀 지표로 감시.
