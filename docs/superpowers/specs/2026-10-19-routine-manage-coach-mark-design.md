# 일과관리 코치마크 설계 (#832)

> 상태: **초안, 승인 대기.** 승인 전에는 코드를 건드리지 않는다.
> 시안: 이슈 #832 댓글의 이미지, 눌러 보는 목업은 브라우저 시안 `coachmark-existing-v3` · `coachmark-group-v4`.

## 1. 목적
일과관리 칸에 처음 들어온 보호자가 **누르기 / 길게 누르기 / 보낸 뒤 ✓ / 묶음 만들기**를 알게 한다.
지금 있는 화면 요소만 가리키고, 새 화면·새 개념을 만들지 않는다.

## 2. 지금 있는 것 (조사 결과)

| 부품 | 위치 | 하는 일 |
|---|---|---|
| `CoachMarkOverlay` | `core/widgets/coach_mark_overlay.dart` | 어두운 막 + 구멍 하나 + 말풍선. 어디든 누르면 다음, ✕ 로 닫기, 구멍이 단계 사이를 미끄러짐, 대상을 못 재면 그 단계 건너뜀, 동작 줄이기 대응 |
| `CoachMarkStep` | `core/widgets/coach_mark_step.dart` | 단계 하나: `target`(GlobalKey) · `message` · 구멍 모양 · 화살표 위치 |
| `HomeCoachNotifier` | `features/guardian/application/home_coach_notifier.dart` | 시작 조건, 진행, "봤음" 저장 (`localStorage.isHomeCoachSeen`) |
| `HomeCoachMark` | `features/guardian/presentation/widgets/home_coach_mark.dart` | 단계를 홈의 위젯과 글에 연결 |

홈 코치마크에는 이미 "설명만으로는 모르니 실제 UI를 열어 보여 준다"는 선례가 있다 (`demoSwipeOpen`: 2단계에서 일과 카드를 실제로 밀어 연다).

**현재 없는 것:** 손가락 · 링 같은 **조작 시범 연출**, 단계마다 다른 대상을 가진 **일과관리용 상태·저장 키**, 격자 칸·✓ 배지·`+ 일과 만들기` 의 `GlobalKey`.

## 3. 설계 결정 (제 제안, 승인 필요)

### 3-1. 뼈대는 `CoachMarkOverlay` 를 그대로 쓴다
새 오버레이를 만들지 않는다. 일과관리용 `RoutineManageCoachMark`(홈의 `HomeCoachMark` 와 같은 자리)가 단계 목록만 만든다.

### 3-2. 시범 연출은 어떻게 보여줄까 → **방식 A 추천**

| | A. 오버레이 안에 시범 층을 얹는다 (추천) | B. 실제 화면을 움직여 보여 준다 |
|---|---|---|
| 방법 | 구멍 위에 손가락·링 위젯, 시트는 실제 시트 위젯을 **읽기 전용 미리보기**로 그린다 | 코치마크 중에 진짜 상세 시트·메뉴·묶기를 코드로 열고 닫는다 |
| 장점 | 서버·상태에 영향 없음. 데이터가 없어도 시범 가능 | 가장 정직하다. 홈 `demoSwipeOpen` 과 같은 방식 |
| 단점 | 미리보기가 실제 시트와 어긋날 수 있다 | 실제 보내기·묶기가 실행될 위험, 일과가 없으면 시범 불가, 시트 위에 막을 또 얹는 z-order 문제 |
| 판단 | 데이터를 안 바꾸는 쪽이 안전하다. 어긋남은 **실제 시트의 위젯을 재사용**해 줄인다 | 일과 데이터가 필요해 일과 1개일 때 묶음 시범이 불가능하다 |

가능한 한 **실제 위젯을 재사용**한다: `LibraryRoutineTile`, `RoutineDetailSheet` 의 버튼 줄, `_LibraryQuickMenu` 의 행. 그림만 따로 그리지 않는다.

### 3-3. 단계 구성

기본 (일과 1개 이상, 일과관리 첫 진입 1회)

| 단계 | target | 시범 | 문구 키 (ARB 신규) |
|---|---|---|---|
| 1 누르기 | 첫 번째 `LibraryRoutineTile` | 손가락 탭 → 상세 시트 미리보기 | `routineManageCoachTapTitle/Body` |
| 2 길게 누르기 | 같은 칸 | 꾹 + 링 → 빠른 메뉴 미리보기 | `routineManageCoachLongPressTitle/Body` |
| 3 보낸 뒤 | 오늘 보낸 칸의 ✓ (**없으면 첫 칸 위에 ✓ 만 그려 보여 준다**) | ✓ 팝 + 토스트 문구 | `routineManageCoachSentTitle/Body` |

묶음 (#807 은 2026-10-19 develop 에 병합됨. 일과 2개 이상 + 묶음 0개, 별도 1회, 저장 키도 별도)

| 단계 | target | 시범 |
|---|---|---|
| 끌어서 묶기 | 첫 두 칸 | 들어 올림 → 옆 칸 위 → 2×2 묶음 칸 |
| 버튼으로 묶기 | `+ 일과 만들기` | 탭 → `무엇을 만들까요?` 시트 미리보기 |

### 3-4. 상태·저장
- `RoutineManageCoachNotifier`: `HomeCoachNotifier` 와 같은 규칙을 따른다 — **저장을 못 읽으면 봤다고 친다**, **같은 실행에서 두 번 뜨지 않는다** (`_shownThisRun`).
- 저장 키 2개: `coach.manageSeen`, `coach.groupSeen` (`LocalStorage`, `SharedPrefsStorage`, `InMemoryStorage` 세 곳에 같이 추가).
- 시작 조건: 목록이 **준비됐고(성공)** 일과 ≥ 1. 로딩·실패·0건에서는 띄우지 않는다.

### 3-5. 다시 보기
내정보에 `사용법 다시 보기` 줄을 두고, 누르면 "봤음"을 지우지 않고 코치마크만 강제로 띄운다.
(어느 사용법을 다시 볼지: 일과관리 / 홈 두 줄로 나눌지는 §5 질문.)

## 4. 실패 경로 (행복 경로와 함께)

| 상황 | 동작 |
|---|---|
| 대상 칸 좌표를 못 잼 | `CoachMarkOverlay` 가 그 단계를 건너뜀. 전부 건너뛰면 막을 띄우지 않음 |
| 목록 로딩 중·실패·0건 | 시작하지 않음 (실패 화면은 기존 `ElumErrorView` 그대로) |
| "봤음" 저장 실패 | 이번 실행에서는 다시 띄우지 않고, 화면은 계속 동작 |
| 태블릿 넓은 격자 | 대상은 `GlobalKey` 로 재서 좌표를 하드코딩하지 않음. 막은 화면 전체를 덮음 (#794) |
| 동작 줄이기 켬 | 시범 연출 대신 정지 그림 + 문구 |
| 코치마크 중 뒤로가기 | 닫고 "봤음" 저장 |

## 6. 테스트 (깨지면 어떤 사용자 문제인가)

| 테스트 | 막는 문제 |
|---|---|
| 첫 진입에만 뜨고 두 번째 진입에는 안 뜬다 | 안내를 닫은 사람에게 계속 뜬다 |
| 목록 0건·로딩·실패에서는 안 뜬다 | 빈 화면을 가리키는 막 |
| 저장소를 못 읽으면 안 뜬다 | 닫을 수 없는 반복 안내 |
| 대상을 못 재면 해당 단계 건너뜀 | 막만 남고 아무것도 안 가리킴 |
| 태블릿 폭에서 막이 화면 전체를 덮는다 | 양옆이 밝게 남는 회귀 (#794) |
| 코치마크가 떠 있는 동안 서버 호출이 0건이다 | 시범 중 실제로 보내져 버림 |
