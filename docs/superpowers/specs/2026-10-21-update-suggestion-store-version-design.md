# 업데이트 권유: 스토어 버전 확인 + 캐릭터 안내 (#914)

## 왜

- #660 의 업데이트 권유는 서버 `최신 버전`(관리자 수동 입력)만 본다. 값을 안 올리면 새 버전을 내도 아무도 모른다.
- 배포 워크플로가 값을 올리게 하면 심사 중인 버전을 권하게 된다 (main 배포 = 심사 제출). 스토어에 아직 없는 버전으로 보내면 사용자는 받을 게 없다.
- 권유 팝업이 글자뿐인 기본 팝업이고 보호자 홈에서만 뜬다. 이룸이 기기는 업데이트 소식을 받을 길이 없다.

## 정한 것

| 항목 | 결정 | 누가 |
|---|---|---|
| 새 버전 판단 | 앱이 스토어에 직접 묻는다. iOS App Store 공개 조회(`itunes.apple.com/lookup`), Android Play 앱 내 업데이트 확인(`in_app_update`) | 사용자 |
| 서버 `최신 버전` | 스토어 확인이 안 될 때만 쓰는 비상용으로 남긴다 | 사용자 |
| 모양 | 폰: 바닥 시트, 태블릿: 가운데 카드. 손 흔드는 루미 그림 | 사용자 (A안) |
| 어디서 | 보호자 홈 + 이룸이 홈 | 사용자 ("둘 다 보는 화면") |
| 얼마나 자주 | #660 그대로 하루 한 번 (새 버전마다 기록) | 구현 판단: 배포된 동작 유지 |
| 문구 | #660 문구(5개 언어) 그대로 | 구현 판단: 번역 유지 |

## 판단 순서

1. 강제 업데이트 대상(`최소 버전` 미만)이면 권하지 않는다. 앱 상태 게이트가 막는다.
2. 스토어 확인이 됐으면 스토어 답을 따른다. 새 버전이 없다고 하면 서버 값이 높아도 권하지 않는다.
3. 스토어 확인이 안 됐으면(네트워크, 스토어 밖 설치, 형식 다름) 서버 `최신 버전`과 비교한다.
4. 오늘 이 새 버전으로 이미 띄웠으면 띄우지 않는다. 기록: `{새 버전 표시}|{yyyy-MM-dd}` (iOS `2.68.0`, Android `build-{versionCode}`).

## 실패 경로

| 상황 | 결과 |
|---|---|
| 앱 상태 조회 실패 | 띄우지 않음, 홈 그대로 |
| 스토어 조회 실패·시간 초과(5초) | 서버 값으로 판단 |
| Play 밖 설치(테스트 APK) | `in_app_update` 예외 > 서버 값으로 판단 |
| 스토어 주소 없음 | 띄우지 않음 |
| 스토어 열기 실패 | 공용 실패 팝업 + `E-UPDATE-STORE` |
| 기록 저장 실패 | 로그만 남기고 계속 |

## 하지 않는 것

- Play 의 앱 내 즉시·유연 업데이트 화면은 쓰지 않는다. 판단만 빌리고 화면은 우리 안내로 통일한다.
- 서버 코드는 바꾸지 않는다.
- 강제 업데이트·점검 화면은 건드리지 않는다.
