# 알림 켜기 다시 권하기 + 이룸이 기기 알림 설계

- 날짜: 2026-10-23
- 범위: 클라(폰·태블릿, iOS·Android) + 서버

## 1. 왜

- 지금 알림 권한은 **보호자가 첫 일과를 보낸 직후 한 번**만 묻는다 (`client/lib/features/notification/application/push_permission_prompt.dart` `maybeAsk`).
  "나중에"를 눌렀거나 시스템 창에서 거부한 보호자, 일과를 아직 안 보낸 보호자는 다시 안내받지 못한다.
- 이룸이 기기는 **알림을 전혀 받지 않는다.** 토큰 등록을 막아 두었고(`push_token_registrar.dart` `_canRegister`), 서버 알림 7종은 모두 보호자 대상이다.
- 사용자 요구: 이룸이 기기에도 알림이 가야 한다. 지금은 "일과가 도착했어요", 나중에는 "○○할 시간이에요"(화면 전환 포함)까지.
  이번 작업은 그 바탕(권한·토큰·발송 경로)과 첫 알림 하나를 만든다.

## 2. 목표 / 하지 않는 것

**목표**
1. 보호자 기기: 기기 알림이 꺼져 있으면 보호자 홈에서 다시 권한다.
2. 이룸이 기기: 알림 권한을 받고, 토큰을 서버에 **이룸이 기기로 구분해** 등록한다.
3. 보호자가 일과를 보내면 그 이룸이에 연결된 이룸이 기기에 "일과가 도착했어요" 푸시를 보낸다.
4. 이룸이 기기에서 그 푸시를 누르면 이룸이 화면에서 그 일과를 연다.

**하지 않는 것**
- "○○할 시간이에요" 일과 시간 알림, 알림으로 화면 바꾸기 — 다음 작업.
- 보호자 화면에서 이룸이 기기 알림 켜기/끄기 — **사용자 결정: 기기 설정에 맡긴다.**
- 이룸이 기기의 알림 목록(알림 화면)·안 읽음 표시 — 이룸이 화면은 그대로.
- 이룸이 기기에 보호자 알림 7종 보내기 — **절대 안 됨** (아래 3.1).

**실패로 보는 것 (동작해도)**
- 이룸이 기기에 "이야기 댓글", "크레딧" 같은 보호자 알림이 뜬다.
- 연결을 끊은 이룸이 기기에 계속 알림이 간다.
- 다시 권하는 팝업이 앱을 켤 때마다 뜨거나, 공지 팝업·일과 만들기 흐름과 겹쳐 뜬다.

## 3. 서버

### 3.1 기기 구분 (핵심 위험)
이룸이 기기는 **보호자 회원 ID로 로그인**한다 (`Caller.memberId` = 붙여 준 보호자, `Caller.linkId` = 연결 ID).
`push_device` 는 `member_id` 로만 기기를 찾으므로(`PushDispatcher.dispatchOne` → `findAllByMemberId`),
이룸이 토큰을 그대로 넣으면 보호자 알림이 이룸이 기기로 샌다.

- `push_device` 에 `link_id` 열 추가 (nullable). `null` = 보호자 기기, 값 = 이룸이 기기(그 연결).
- 보호자 기기 조회를 `member_id = ? and link_id is null` 로 바꾼다. 호출처: `PushDispatcher.java:75`(발송), `PushDeviceService.devicesOf`(`:61`, 관리자 회원 상세). 관리자 상세는 이룸이 기기도 보여 주되 구분 표시 (제 결정).
- 마이그레이션: 기존 행은 모두 보호자 기기이므로 `null` 그대로. 운영 DB는 Flyway(V 스크립트)·JPA 방식 중 레포가 쓰는 쪽을 따른다.

### 3.2 등록·해제
- `PUT /api/push-devices`, `DELETE /api/push-devices/{token}` 을 `ROLE_ELUMI` 에도 연다. `SecurityConfig.java:165` `anyRequest().hasAuthority(GUARDIAN)` 보다 **앞에** 규칙을 둔다.
- 등록 시 `Caller.linkId` 가 있으면 그 값을 `link_id` 로 저장한다. 앱이 보내는 값은 믿지 않는다 (토큰에서만 읽음).
- 같은 토큰이 이미 있으면 기존 규칙대로 소유자 갱신 — 이때 `link_id` 도 갱신. 한 물리 기기는 한때 한 역할이므로 **마지막 등록이 이긴다** (제 결정). 보호자 기기를 이룸이 기기로 바꾸면 그 기기의 보호자 푸시는 끊기는 것이 맞다.
- 해제(`unregister`)는 `member_id` 에 더해 `link_id` 도 호출자와 같아야 지운다 (보호자 호출 = `null` 행만, 이룸이 호출 = 자기 연결 행만). 지금은 `member_id` 만 비교해(`PushDeviceService.java:69-72`) 이룸이 기기가 보호자 토큰을 지울 수 있다.
- 연결이 끊기면 그 `link_id` 의 토큰을 지운다. 끊기는 `DeviceLinkService` 의 종료(`terminate`) 한 곳을 거친다 (갈아치우기는 아직 안 쓴 암호만 폐기하므로 지울 토큰이 없음).
- 보호자 탈퇴: 기존 `member_id` 기준 전부 삭제가 이룸이 기기 행도 함께 지운다 (같은 `member_id`). 추가 작업 없음.
- 이룸이 세션 만료(리프레시 만료로 로그아웃)는 토큰을 지우지 않는다. 연결이 살아 있으면 알림은 계속 받는 것이 맞다 (제 결정).

### 3.3 발송: 일과 도착
- 계기: 기존 `RoutineSentEvent(routineId, profileId, actorMemberId)` (`RoutineService:91`, `RoutineLibraryService:64`).
- 받는 기기: 그 `profileId` 의 **살아 있는 연결**(`revokedAt is null`, `redeemedAt not null`)의 `link_id` 를 가진 `push_device` 전부. 한 이룸이에 기기가 여러 대(폰·태블릿)면 **전부** 보낸다 (제 결정, 사용자 요구 "폰·태블릿 둘 다").
- 알림 행(`notification` 표)은 **만들지 않는다.** 이룸이는 알림 목록이 없다. 보호자용 `ROUTINE_SENT_BY_CO_GUARDIAN` 기록·발송은 그대로 둔다.
- 따라서 `PushDispatcher`(알림 행 기반)와 별도 경로가 필요하다. 이름 예: `ElumiPushDispatcher` — 대상 기기 조회 > 메시지 생성 > 발송 > 무효 토큰 삭제. 한 기기 실패는 로그만.
- 보호자 알림 설정(전체 끔·종류별)은 이룸이 발송에 적용하지 않는다.
- 문구(제 결정, 해요체·짧게): 제목 없이 또는 `이룸` / 본문 `새 일과가 도착했어요`. 언어는 그 기기의 `push_device.locale`(기기 화면 언어). ko 외 언어는 번역 키를 함께 넣는다.
- 데이터: `type=ELUMI_ROUTINE_ARRIVED`, `routineId`. 일과 제목은 넣지 않는다 (잠금 화면 노출 최소화 — 제 결정).
- 같은 일과를 짧게 여러 번 보내도 막지 않는다 (지금 보호자 알림과 같은 수준).
- 로그: `[elumi push] sent routine arrived : devices=N`, 실패는 원인 클래스만. 토큰·ID 원문을 남기지 않는다.

## 4. 클라

### 4.1 공통: 권한 다시 권하기 규칙 (보호자·이룸이 기기 같은 규칙)
- 띄우는 조건: 기기 알림 꺼짐(권한 상태가 허용 아님) **그리고** 마지막으로 권한 뒤 **7일** 지남 (제 결정).
- 마지막 권한 시각은 로컬 저장소에 기기별로 둔다 (`LocalStorage` 에 키 추가, `StorageKeys` 한 곳).
- 버튼 동작: 한 번도 안 물은 기기 → 시스템 권한 창 / 이미 거부 → 기기 설정 열기. 기존 `requestIfNeverAsked` + `DeviceNotificationPermissionController` 의 켜기 경로를 재사용한다.
- 앱 복귀 시 권한을 다시 읽어, 켜졌으면 토큰 등록.
- 권한 상태를 못 읽으면 띄우지 않고 다음 기회로 (로그만).
- 시트는 기존 `showPushPermissionSheet` 를 쓴다. 다시 권하는 경우·이룸이용 문구가 다르면 문구 인자만 늘린다. 새 디자인 요소는 만들지 않는다 (시안 없음).

### 4.2 보호자 기기
- 보호자 홈에 들어올 때 4.1 조건이면 띄운다.
- **공지 팝업과 겹치지 않게:** 그날 공지 팝업이 떴으면 띄우지 않고 다음 진입으로 미룬다 (`features/notice/presentation/guardian_notice_launcher.dart` 순서와 맞춤).
- 일과 만들기 중, 이룸이 화면을 보여 주는 중(`resumeOnElumiScreen`)에는 띄우지 않는다.
- 첫 일과 직후 한 번 묻는 기존 `maybeAsk` 는 유지한다. 그 시각도 "마지막 권한 시각"으로 기록해 7일 안에 또 뜨지 않게 한다.

### 4.3 이룸이 기기
- **연결 성공 직후**(`link_enter_screen.dart` 에서 `Routes.child` 로 가기 전후) 한 번 권한다. 이 순간에는 보호자가 기기를 들고 설정해 줄 가능성이 높다 (제 결정).
- 이미 연결된 이룸이 기기(업데이트한 기존 사용자)는 이룸이 홈(`child_home_screen.dart`) 진입 시 4.1 규칙으로 권한다.
- 문구는 이룸이가 읽는다는 전제로 짧게: 예 `새 일과가 오면 알려 드릴게요` / 버튼 `알림 켜기` · `나중에`. 용어 규칙(아이 금지 등) 준수.
- 토큰 등록: `PushTokenRegistrar._canRegister` 의 이룸이 차단을 풀고, 로그인 세션이 있고 권한이 허용이면 등록. 서버가 `link_id` 를 붙인다.
- 연결 끊김·로그아웃 시 토큰 해제 호출 (서버도 3.2에서 지우지만 앱도 정리).

### 4.4 푸시 수신 (이룸이 기기)
- `push_message_router.dart` 는 지금 이룸이 기기면 아무것도 안 한다 (`_isGuardianSignedIn`). 이 조건은 **세 곳**에 있다: 전경 수신(:141 부근), 탭(`_onTapped` :232 부근), 대기 중 열기(:259 부근). 세 곳 모두 `ELUMI_ROUTINE_ARRIVED` 를 이룸이 기기에서 처리하는 분기를 더한다.
- 전경 수신: 배너 대신 이룸이 홈 일과 목록을 새로 받는다 (`routine_auto_refresh.dart` 재사용).
- 알림 탭(백그라운드·종료 상태): 이룸이 홈으로 간 뒤 일과 목록을 새로 받고, `routineId` 로 일과를 찾아 `Routes.childRoutineDetail` 에 `extra` 로 넘긴다. 라우트는 `extra`(Routine 객체)를 받고 없으면 홈으로 돌리므로(`routes_child.dart:31-40`) 라우트 계약은 바꾸지 않는다 (제 결정). 목록 받기 실패·일과 없음(삭제됨 등)이면 이룸이 홈에 머문다. 종료 상태 탭은 세션 복원 뒤에 처리한다 (기존 대기 중 열기 흐름).
- Android 알림 채널: 이룸이용 채널을 따로 둔다 (`pushChannelElumiRoutines` 같은 이름, 중요도 high). 기기 설정에서 따로 끌 수 있게.
- 보호자 기기가 이룸이 화면을 보여 주는 중이면 기존대로 보호자 알림 배너를 띄우지 않는다 (변경 없음).

## 5. 실패 경로 정리

| 상황 | 동작 |
|---|---|
| 권한 상태 읽기 실패 | 팝업 안 띄움, 로그, 다음 기회 |
| 권한 거부 | 토스트 안내(기존 문구), 7일 뒤 다시 권함 |
| 토큰 등록 API 실패 | 조용히 다음 앱 실행 때 재시도 (기존 registrar 규칙), 화면 영향 없음 |
| FCM 무효 토큰 | 서버가 그 행 삭제 |
| 연결 끊김 | 서버가 그 `link_id` 토큰 삭제, 앱도 해제 호출 |
| 푸시 탭했는데 일과 없음 | 이룸이 홈 |
| 옛 앱(이룸이 토큰 등록 안 함) | 푸시 안 감. 동작 변화 없음 |

## 6. 운영 호환
- 앱스토어·Play 운영 중. 기존 API 응답 형태·저장 키·에러 코드는 바꾸지 않는다.
- `push_device.link_id` 추가는 nullable 이라 옛 서버/앱과 충돌 없음.
- 서버 먼저 배포해도 옛 앱은 이룸이 토큰을 안 보내므로 영향 없음.

## 7. 검증
- 서버: 이룸이 토큰 등록 → `link_id` 저장, 보호자 알림 발송 시 이룸이 기기 제외, 일과 보냄 → 이룸이 기기만 발송, 연결 끊기 → 토큰 삭제. 관련 테스트만 지정 실행.
- 클라: `flutter analyze`, `client/tool/check_*`. 시뮬레이터 2대(보호자·이룸이 iPhone)로 실측 — 권한 팝업(첫 연결·7일 뒤), 일과 보내기 → 이룸이 기기 알림 → 탭 → 일과 상세. 폰·태블릿 레이아웃, 라이트·다크.
