# 08. 디자인 원칙 — 이룸을 어떻게 그리는가

> **모든 화면은 이 문서에서 나온다.**
> 개별 화면 명세가 이 문서와 다르면, 명세가 틀린 것이다.
>
> 화면 명세: [2026-09-18 화면 전체명세](./superpowers/specs/2026-09-18-화면-전체명세.md)
> 서비스 원칙: [docs/README.md](./README.md)

# 1. 우리는 두 사람을 위해 만든다

```
        보호자                        사용자(당사자)
    ┌──────────────┐              ┌──────────────┐
    │    50대       │              │    20대       │
    │              │              │              │
    │ 일과를 만든다  │   ────────▶  │ 카드를 본다   │
    │ 카드를 고친다  │              │ 하나씩 해낸다  │
    │ 보상을 정한다  │   ◀────────  │ 다 했다고 누른다│
    └──────────────┘              └──────────────┘
      자기 휴대폰                     자기 휴대폰
```

| | 보호자 | 사용자 |
| --- | --- | --- |
| 나이 | 50대 | 20대 (연령으로 나누지 않는다) |
| 처음 겪는 것 | **낯선 개념이 많다** — 보상 · 임시저장 · 휴대폰 연결 | — |
| 못 하는 것 | 복잡한 설정을 오래 읽기 | **글자를 못 읽을 수 있다** |
| 화면이 해야 할 일 | **가르쳐 주기** | **보여 주기** |

> **한 앱에 두 사람이 있다.** 보호자 화면은 설명하고, **이룸이 화면**은 보여 준다.
> 이 둘을 같은 규칙으로 그리면 둘 다 실패한다.

# 2. 디자인 철학 6가지

```mermaid
flowchart TD
    P1["① 한 화면에 하나만 시킨다"]
    P2["② 낯선 건 한 줄로 말하고<br/>설명은 접는다"]
    P3["③ 글자 없이도 뜻이 통한다"]
    P4["④ 되돌릴 수 있다고<br/>먼저 말한다"]
    P5["⑤ 실패해도 화면은 살아 있다"]
    P6["⑥ 겁주지 않는다"]

    P1 --> R1["카드 1장 = 행동 1개<br/>화면 1개 = 결정 1개"]
    P2 --> R2["본문 한 줄<br/>+ '왜 그런가요? ›' 시트"]
    P3 --> R3["이룸이 화면은<br/>그림이 먼저, 글자가 나중"]
    P4 --> R4["건너뛰기를 늘 연다<br/>'나중에 바꿀 수 있어요'"]
    P5 --> R5["빈 화면 금지<br/>에러 코드 노출"]
    P6 --> R6["경고색 절제<br/>긍정형 문장"]
```

## ① 한 화면에 하나만 시킨다

카드 한 장에 행동 하나. **화면 하나에 결정 하나.**

| 좋음 | 나쁨 |
| --- | --- |
| 보상만 고르는 화면 | 보상 고르고 날짜도 정하고 알림도 켜는 화면 |
| 이름만 넣는 화면 | 이름·나이·목표를 한 화면에 |

> 발달장애 당사자를 위해 과제를 쪼개는 앱이다. **화면도 같은 원리로 쪼갠다.**

## ② 낯선 건 한 줄로 말하고, 설명은 접는다

50대 보호자에게 `보상`, `임시저장`, `휴대폰 연결`은 처음 보는 개념이다.
**그렇다고 화면을 설명으로 채우면 아무도 안 읽는다.**

```
❌ 이렇게 하지 않는다              ✅ 이렇게 한다
┌──────────────────────┐        ┌──────────────────────┐
│ 다 하면 뭘 할 수      │        │ 다 하면 뭘 할 수      │
│ 있나요?              │        │ 있나요?              │
│                      │        │                      │
│ 평소에 "이거 다 하면   │        │ 미리 정해두면 끝까지   │
│ 젤리 먹자"라고 하시죠? │        │ 해낼 힘이 돼요        │
│ 미리 정해두면 카드를   │        │                      │
│ 보는 내내 그걸 기억할 │        │ [칩들]                │
│ 수 있어요. 한 달 뒤   │        │                      │
│ 선물보다 오늘 받을 수 │        │ 왜 정하나요? ›        │  ← 시트로
│ 있는 게 더 잘 통해요  │        │                      │
└──────────────────────┘        └──────────────────────┘
      아무도 안 읽는다                 읽을 사람만 읽는다
```

**규칙** — 본문 설명은 **한 줄**. 더 필요하면 `› 시트`로 접는다.

## ③ 글자 없이도 뜻이 통한다

이룸이 화면은 **그림이 먼저, 글자가 나중**이다.

| 요소 | 규칙 |
| --- | --- |
| 카드 | 그림이 화면의 절반 이상 |
| 보상 | **반드시 그림이 있어야 한다.** 자유 텍스트만 받으면 의미가 없다 |
| 완료 | 체크 표시 + 색 변화 (글자 없이도 구분) |
| 진행률 | 점(`●●○○○`) — 숫자보다 먼저 |

> 보상에 프리셋을 두는 이유가 이것이다. 키가 있어야 그림을 띄운다.

## ④ 되돌릴 수 있다고 먼저 말한다

사람은 되돌릴 수 없을까 봐 버튼을 안 누른다.

| 화면 | 먼저 말하는 것 |
| --- | --- |
| 역할 선택 | `나중에 바꿀 수 있어요` |
| 보상 설정 | `건너뛰기` — 늘 활성 |
| 나갈 때 | `임시저장하면 이어서 만들 수 있어요` |
| 코드 발급 | `나중에 할게요` |

**`건너뛰기`를 없애지 않는다.** 선택 항목은 끝까지 선택으로 둔다.

## ⑤ 실패해도 화면은 살아 있다

| 상황 | 화면 |
| --- | --- |
| 못 불러옴 | 빈 화면·무한 로딩 **금지**. 상태 + `다시 시도` |
| 0건 | 로딩(스켈레톤)과 **구분되는** 빈 화면 |
| 권한 거부 | 앱은 계속 돈다. 왜 필요한지 + **우회 경로** |
| 모르는 오류 | 화면을 덮지 않는다. **작은 에러 코드**를 남긴다 |

> **에러 코드는 반드시 노출한다.** 사용자에겐 "문제가 생겼어요"로 충분하지만,
> 화면 어딘가에 `E-1023`이 있어야 제보를 받았을 때 어디서 터졌는지 안다.

## ⑥ 겁주지 않는다

**이룸이 휴대폰에도 이 앱이 깔린다.** 빨간 경고가 화면을 덮으면 안 된다.

| 대신 |
| --- |
| 경고색 대신 중립색 (`임시저장` 배지) |
| 흔들림 + 짧은 문구 (PIN 틀림) |
| `사라집니다` 대신 `이어서 만들 수 있어요` |

# 3. 말투 — 토스 라이팅 원칙을 따른다

## 3-1. 기본 셋

| 항목 | 규칙 | 예 |
| --- | --- | --- |
| **해요체** | 하나로 통일 | `저장했어요` / ~~저장되었습니다~~ |
| **능동형** | 주어가 행동한다 | `코드를 보냈어요` / ~~코드가 발송되었습니다~~ |
| **긍정형** | 할 수 있는 걸 말한다 | `이어서 만들 수 있어요` / ~~저장 안 하면 사라집니다~~ |

## 3-2. 8원칙

| # | 원칙 | 우리 화면에서 |
| :-: | --- | --- |
| 1 | 다음을 예측할 수 있게 | 버튼에 **바로 다음에 올 화면**을 쓴다 — 검토는 `보상 정하기`, 보상은 `이룸이에게 보내기` |
| 2 | 잡초 뽑기 | `이 카드 수정하기` ❌ → `고치기` ✅ |
| 3 | 빈 문장 제거 | 공간이 비었다고 설명을 채우지 않는다 |
| 4 | 핵심만 | 이미 아는 걸 다시 말하지 않는다 |
| 5 | 말하기 쉽게 | 소리내어 읽어 어색하면 고친다 |
| 6 | 권유하되 강요 금지 | `건너뛰기`를 늘 연다 |
| 7 | 모두를 위한 단어 | 유행어·은어 금지. **50대가 아는 말만** |
| 8 | 숨은 감정 찾기 | 다 해냈을 때 축하한다 |

## 3-3. 쓰지 않는 말

| 금지 | 대신 | 왜 |
| --- | --- | --- |
| 🔴 **아이 · 아동 · 우리 아이** | **이룸이** | **20대 당사자가 자기 휴대폰에서 이 앱을 연다** |
| 휴대폰 | **기기** | 이룸이는 태블릿을 쓴다. 폰만 가리키는 말이 아니어야 한다 (2026-10-19 결정, 루트 CLAUDE.md 용어표) |
| 코드 | **연결 암호** | 처음 보는 사람이 뜻을 모른다 (예외: 2026-09-18 온보딩 시안 · `초대 코드`, 루트 CLAUDE.md) |
| 강화 · 강화물 · 행동중재 | **보상** | 전문 용어다 |
| 서버 | (안 쓴다) | 사용자에게 남의 일이다 |
| 승인 · 승인 대기 | **임시저장 · 이어서** | 만들다 만 것이지 심사가 아니다 |
| 발송 · 저장되었습니다 | 보냈어요 · 저장했어요 | 해요체 |

## 3-4. 🔴 우리는 사용자를 `이룸이`라고 부른다

```
아이 · 아동 · 우리 아이  ❌   →   이룸이  ✅
```

| 자리 | 문구 |
| --- | --- |
| 이름 묻기 | `이룸이를 어떻게 부를까요?` |
| 역할 선택 | `이룸이예요` |
| 설정 메뉴 | `이룸이 기기 연결하기` |
| 보상 정하기 CTA | `이룸이에게 보내기` |
| 이름 없을 때 | `이룸이` (기존 `우리 아이`) |

**이름을 알면 이름을 쓴다.** `이룸이`는 이름을 모를 때 쓰는 말이다.

> ⚠️ **법적 문구는 예외다.** 약관·법정대리인 동의처럼 법적 효력이 있는 문장은
> 임의로 바꾸지 않는다. 바꾸려면 근거를 남기고 확인을 받는다.

# 5. 화면 규칙

## 5-1. 레이아웃

| 항목 | 값 |
| --- | --- |
| 기준 프레임 | **393 × 852** |
| 좌우 여백 | **24** (콘텐츠) · **16** (하단 CTA) |
| 하단 CTA | **360 × 66 · r18** |
| 카드 · 칩 | r20 |
| 칩 세로 간격 | 18 |

## 5-2. 색

| 용도 | 값 |
| --- | --- |
| 배경 | `#F7F2EF` |
| 본문 | `#242634` |
| 설명 | `#898B98` |
| 칩 배경 | `#FFFFFF` · 테두리 `#EFEFEF` 1px |
| **선택됨** | 배경 `#B5EAEC` · 테두리 `#93DBCC` **2px** |
| 위험 | 위험색 사용 · **위계는 가장 낮게** |

> **선택 색은 용도별로 나눈다.** 목표 칩과 캐릭터 카드는 색이 다르다.
> `selectedFill` 같은 단일 토큰을 두지 않는다 — 다음 사람이 잘못 고른다.

## 5-3. 버튼 위계

```
주 버튼      ████████████████   채운 색 · 굵게
보조 버튼    ┌──────────────┐   테두리만
텍스트 버튼       계속 만들기      글자만
위험 버튼    ┌──────────────┐   위험색 테두리 · 주 버튼보다 약하게
```

| 상황 | 주 버튼 | 나머지 |
| --- | --- | --- |
| 나갈 때 팝업 | `임시저장` | `나가기`(위험) · `계속 만들기`(텍스트) |
| 보상 설정 | `다음` | `건너뛰기`(보조) |
| 설정 | — | `로그아웃` · `회원 탈퇴`(위험, 가장 약하게) |

> **위험한 일이 주 버튼이 되지 않는다.** 삭제·탈퇴는 절대 주 버튼이 아니다.

## 5-4. 상태 — 4개는 항상 그린다

```
   정상            로딩            빈 상태          실패
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ ▤▤▤▤▤   │   │ ░░░░░   │   │         │   │   (!)   │
│ ▤▤▤▤▤   │   │ ░░░░░   │   │  없어요  │   │ 못 불러왔어요│
│ ▤▤▤▤▤   │   │ ░░░░░   │   │         │   │ [다시 시도]│
└─────────┘   └─────────┘   └─────────┘   └─────────┘
                스켈레톤      로딩과 구분!    에러 코드 포함
```

**빈 상태와 로딩을 같게 그리면 안 된다.** 사용자는 기다려야 할지 포기해야 할지 모른다.

## 5-5. 재사용을 먼저 찾는다

| 새로 필요한 것 | 이미 있는 것 |
| --- | --- |
| 선택 카드 | 온보딩 **도움 목표 칩** |
| 연결 암호 6칸 | **PIN 화면 박스** |
| 보상 프리셋 칩 | 온보딩 **도움 목표 칩** |
| 카드 추가 시트 | **카드 고치기 시트** |
| 섹션 제목 | 보호자 홈 **추천 일과 제목** |
| 확인 팝업 | 기존 **다이얼로그** |

> **새로 그리기 전에 이 표를 본다.** 비슷한 게 있으면 그것을 쓴다.

## 5-6. 확인·실패 팝업 — 세 단계와 실패 한 모양 (#1171)

> 디자이너 시안 전 임시 기준. 시안이 나오면 이 절만 다시 본다.

**확인 단계는 "무엇이 사라지는가"로 정한다.**

| 단계 | 언제 | 모양 | 부품 |
| --- | --- | --- | --- |
| 입력 확인 | 계정·이룸이 **전체** 데이터가 사라짐 | 경고 팝업 > 문구 입력 > 위험 버튼 | `confirmDangerousAction` 다음 `confirmByTyping` |
| 한 번 확인 | 하나를 지움 · 되돌릴 수 있는 위험(연결 끊기·로그아웃) | 아이콘 + `취소`(회색) · 행동 이름(빨강) | `confirmDangerousAction` |
| 일반 확인 | 잃는 것 없음 (묶음 풀기 · 임시저장에 남는 나가기) | 아이콘 없음 · 주 버튼 | `showElumDialog` |

| 동작 | 단계 | 아이콘 | 위험 버튼 |
| --- | --- | --- | --- |
| 회원탈퇴 (보호자) | 입력 확인 | ! | `탈퇴하기` |
| 마지막 보호자 그만두기 | 입력 확인 | ! | `그만두기` |
| 함께 돌보기 그만두기 (다른 보호자 있음) | 한 번 | ! | `그만두기` |
| 오늘 일과 지우기 · 일과관리 지우기 · 카드 지우기 · 임시저장 지우기 | 한 번 | 휴지통 | `지우기` |
| 보호자 목소리 지우기 · 이야기 글 내리기 · 댓글 지우기 | 한 번 | 휴지통 | `지우기` / `내리기` |
| AI 메모 모두 지우기 | 한 번 | 휴지통 | `모두 지우기` |
| 기기 연결 끊기 · 링크 끄기 · 글 숨기기 | 한 번 | ! | `연결 끊기` / `링크 끄기` / `숨기기` |
| 로그아웃 · 이룸이 기기 로그아웃·탈퇴 | 한 번 | ! | `로그아웃` / `탈퇴하기` |
| 만들기 나가기 (잃음) | 한 번 | ! | `나가기` |
| 만들기 나가기 (임시저장에 남음) · 묶음 풀기 · 묶음에서 빼기 | 일반 | 없음 | 주 버튼 |

- **위험 버튼은 행동 이름이다.** `확인` 을 쓰지 않는다 (§3-2 1번).
- AI 메모 모두 지우기는 입력 확인까지 가지 않는다 — 일과·기록·별은 남고 메모는 다음 일과부터 다시 쌓인다.

**없애는 동사는 앱 전체 `지우기` 하나다 (#1182).** `삭제` 를 화면 문구에 쓰지 않는다.

| 자리 | 모양 | 예 |
| --- | --- | --- |
| 버튼·메뉴 줄 | `지우기` / `{대상} 지우기` | `지우기` · `이 카드 지우기` · `메모 모두 지우기` |
| 확인 제목 | `{대상}을/를 지울까요?` | `일과를 지울까요?` · `임시저장을 지울까요?` |
| 실패 제목 | `{대상}을/를 지우지 못했어요` | `임시저장을 지우지 못했어요` |
| 끝난 알림 | `{대상}을/를 지웠어요` | `일과를 지웠어요` |
| 안내 | `지울 수 있어요` · `지우면 …` | `수정하거나 지울 수 있어요` |

- 왜 `지우기` 인가: §3-2 7번 "50대가 아는 말" — 한자어 `삭제` 보다 입말이고, 일과관리·댓글·목소리·AI 메모·카드 지우기 버튼이 이미 `지우기` 였고 `삭제` 는 오늘 일과·카드 검토·임시저장 세 곳뿐이었다. 제목·버튼·토스트를 한 동사로 맞춰야 `일과를 지울까요?` > `지우기` > `일과를 지웠어요` 가 한 흐름으로 읽힌다.
- **같은 동사를 쓰지 않는 자리** — 뜻이 다르면 그 행동 이름을 쓴다: `내리기`(이야기 글) · `숨기기` · `링크 끄기` · `연결 끊기` · `묶음 풀기` · `묶음에서 빼기` · `탈퇴하기` · `그만두기`.
- 예외: 법적 문구(약관·개인정보처리방침의 `삭제`)는 바꾸지 않는다. 서버가 보내는 문구도 같은 규칙을 따른다.

**실패는 붉은 ! 하나, 안내는 아이콘 없음.**

| 종류 | 모양 | 부품 |
| --- | --- | --- |
| 실패 | 붉은 ! + 문장 + 에러 코드 줄 + 붉은 `확인` | `showFailure` (예외) · `showFailureMessage` (문장·코드를 가진 앱 쪽 실패) |
| 한도·규칙 안내 (크레딧 0 · 시작한 일과 · 이룸이 먼저 연결) | 아이콘 없음 + 주 버튼 (코드가 있으면 코드 줄) | `showElumDialog` |

- **에러 코드는 본문 아래 작은 회색 줄 한 모양**이다 (`ElumErrorCodeText`). 팝업·실패 화면·화면 안 안내 모두 같고, `다시 시도` 글에 괄호로 넣지 않는다.
- 규칙 검사: `client/tool/design_rules.yaml` `restricted_patterns` — `ElumDialogTone.danger` · `ElumDialogIcon.alert|trash` 는 공통 부품 파일 밖에서 쓰면 `check_design_rules` 가 실패한다.

## 5-7. 요금제 말과 Pro 화면 — Free · Pro 를 모양으로 보여 준다 (#1189)

> 디자이너 시안 전 임시 기준 (HTML 시안 A · 미리보기 1). 결정 이유는 이슈 #1189 결정 표. 시안이 나오면 이 절만 다시 본다.

**요금제 말은 한 벌이다.**

| 뜻 | 쓰는 말 | 쓰지 않는 말 |
| --- | --- | --- |
| 요금제 이름 (문장 안) | `Free` · `Pro` | 프로 · 무료 요금제 · 유료 · 플랜 |
| 배지 | `PRO` (배지 안에서만 대문자) | 문장 안 `PRO` |
| 둘을 묶는 말 | `요금제` (`내 요금제`) | 플랜 · 멤버십 |
| 계약 | `구독` (`구독 시작하기` · `구독 관리`) | `구독 결제` |
| 돈이 나가는 일 | `결제` (`결제하지 못했어요` · `결제 허락을 요청했어요`) | `구매` — 예외: 스토어 용어 `구매 복원` |
| 크레딧이 안 드는 것 | `크레딧 없이` (`일과 글은 크레딧 없이`) | `무료` — Free 요금제와 헷갈린다 |
| 체험 | `{기간} 무료 체험` · `{기간} 무료로 시작하기` · `{기간} 무료로 써 보기` | 무료 이용 · 무료 사용 |
| 가격 · 기간 · 체험 | 스토어가 준 값 그대로 (`₩59,000` · `7일`) | 앱이 만든 가격 · 코드에 박은 크레딧 수 |

- `무료` 는 **체험에만** 쓴다. 크레딧이 안 드는 것은 `크레딧 없이` 다.
- 법적 문구(자동 갱신 안내 · 약관)는 바꾸지 않는다. 스토어 메뉴 이름(`정기 결제`)도 그대로 둔다.
- 해요체 · 용어표(§3-3)가 그대로 적용된다 — 시안의 `우리 아이만을 위한` 은 `이룸이만을 위한` 으로 썼다.

**화면 모양**

| 자리 | 모양 | 부품 |
| --- | --- | --- |
| PRO 배지 | 둥근 금빛 그라데이션 알약 + 반짝 표시 + `PRO` | `ProBadge` · `LabelWithProBadge` 만 |
| 요금제 화면 | 머리(Free 카드 → Pro 카드) > 혜택 4묶음 > 기간 카드(1년 기본 · `N% 아껴요` · `한 달에 X원 꼴`) > 작은 법적 안내 · 바닥 고정 주 버튼 + 한 줄 · 위 ✕ | `showPlanPaywall` |
| Pro 미리보기 | 또렷한 견본 > 아래로 사라짐 > 떠 있는 카드(PRO · `예시 화면` · 제목 · 한 줄 · 민트 버튼 · `Pro 혜택 모두 보기`) | `ProTeaser` + `watchProUpsellActions` |
| 권유 버튼 | 민트 그라데이션 (미리보기) · 밑줄 글자 (보조 안내) | `ProUpsellButton` 만 |
| 내 요금제 줄 값 | Free 회색 알약 · PRO 배지 · PRO 배지 + `선물` | `PlanTierChip` |

- 혜택은 서버 Pro 권한이 실제로 주는 것만 보인다 (#1165). 빈 묶음은 빠진다.
- `N% 아껴요` 는 내림한다 (과장하지 않게). 두 상품이 같은 통화일 때만 띠와 `한 달에 X원 꼴` 을 보인다.
- 체험 문구는 스토어가 체험 대상이라고 할 때만 (#1166). 아니면 `구독 시작하기` · `Pro 알아보기`.
- 규칙 검사: `client/tool/design_rules.yaml` `restricted_tokens` — 금빛(`proPlanBadge*`) · 배지 문구는 `pro_badge.dart`, 민트 버튼(`proPlanCta*`) · 체험 버튼 문구는 `pro_upsell_button.dart` 밖에서 쓰면 실패한다.

## 5-8. Pro 와 크레딧을 화면에 놓는 법 (#1081)

> HTML 시안으로 정한 기준. 시안 원본은 `docs/projectops/ui-design/20261110_1081_Pro_출시_완성도/`.

**PRO 배지는 Free 회원에게만 보인다.**

| 누가 볼 때 | 기능 옆 PRO 배지 | 요금제가 보이는 곳 |
| --- | --- | --- |
| Free | 보인다 (누르면 Pro 안내) | 내 정보와 설정의 요금제 줄, 내 크레딧 `FREE` 표시 |
| Pro | **보이지 않는다** | 내 정보와 설정의 요금제 줄, 내 크레딧 `PRO` 표시, 요금제 화면 |

- Pro 회원에게 기능마다 배지를 붙이지 않는다. 이미 열린 기능에 자물쇠 표시가 남은 것처럼 읽힌다.
- Pro 전용 화면(AI 메모리, 주간 리포트)의 PRO 배지도 Free 미리보기에서만 보인다.

**잠긴 주 버튼은 Pro 버튼으로 바꾼다.**

- 쓸 수 없는 회색 주 버튼 아래에 작은 `Pro 알아보기` 를 따로 두지 않는다. 주 버튼 자리에 `ProUpsellButton` 하나만 둔다.
- 누르면 요금제 화면이 그 기능의 혜택을 강조한 채 열린다.

**크레딧은 표 그림이다.**

| 뜻 | 그림 | 부품 |
| --- | --- | --- |
| 크레딧 (주간, 월간) | 민트와 노랑 표 | `AppAssets.creditTicket` |
| 보너스 크레딧 | 복숭아색 표 | `AppAssets.creditTicketBonus` |
| 구매한 크레딧 | 보라색 표 | `AppAssets.creditTicketPurchased` |
| 이룸이 보상 | 별 | 크레딧에는 별을 쓰지 않는다 |

- 반짝 표시(sparkle)는 AI 가 한 일에만 쓴다. 크레딧 수 옆에는 표 그림을 쓴다.
- 비용 한 줄은 공통 위젯 하나로 그린다: `Pro 무료 (오늘 N회 남음)`, `크레딧 N개를 써요`.
- 내 크레딧 화면: 위 카드에 요금제 표시와 합계와 `쓴 내역`, 색으로 나눈 막대, 아래에 종류별 줄. 구매한 크레딧은 `기간 제한 없음`.
- 묶음 상품: 할인은 작은 알약(`-20%`), `인기!` 는 가운데 상품 아래에 두고 가격을 가리지 않는다. 가격은 스토어가 준 값만 쓴다.

**말**

- 화면 문구에 중간점을 쓰지 않는다. 쉼표나 줄바꿈으로 나눈다.
- 리포트의 제안은 `~해 볼 수 있어요` 로 쓴다. 효과를 단정하지 않는다.
- AI 메모리는 `나만 봐요` 를 화면에 적는다. 이룸이가 한 기록으로 규칙을 만들지 않고, 보호자가 고친 것에서만 찾는다.
- 고친 직후에는 `항상 이렇게` 와 `이번만` 두 가지로 묻는다. 누르지 않은 것은 같은 수정이 일과 여러 개에서 반복될 때만 적용한다.

**알림이 꺼져 있을 때**

| 자리 | 모양 | 부품 |
| --- | --- | --- |
| 보호자 홈 | 일과 만들기 버튼 아래 줄 카드 하나: 루미 타일, `알림을 켜 둘까요?` 와 한 문장, 오른쪽 아래 연한 알약 `켜기`, 오른쪽 위 닫기 x. 닫으면 7일 동안 홈에서 숨긴다 | `HomeNoticeCard` |
| 알림 화면, 알림 설정 | 맨 위 꺼짐 띠 (시안 1732:8433): 종 아이콘, `기기 알림이 꺼져 있어요`, `켜기` | `DeviceNotificationPermissionBanner` |
| 설정 | `알림 설정` 줄 오른쪽 값 `꺼짐` (작은 점과 함께). 버튼은 넣지 않는다 | `SettingsTile` 의 값 자리 |

- 문구는 긍정형으로 쓴다. `받을 수 없어요` 가 아니라 `켜 둘까요?`, `알려 드려요`.
- 카드의 글은 줄이지 않고 어절 단위로 줄을 바꾼다(`KeptText`). 큰 글자와 긴 번역에서도 잘리지 않아야 한다.
- 홈 안내 카드는 카드 수정 시트의 녹음 칸과 같은 줄 카드 부품(`elum_row_card.dart`: 흰 판, 1px 테두리, 모서리 20, 연한 알약 버튼)으로 만든다. 검정 사각 버튼과 그림자를 새로 만들지 않는다.
- 권유 카드(자동 보내기, 이야기 올리기, 일과 더 만들기)도 같은 `HomeNoticeCard` 를 쓴다. 홈에는 안내 카드를 한 번에 하나만 보인다.
- 꺼짐 띠의 검정 `켜기` 는 시안 1732:8433 의 것이라 띠 안에서만 쓴다.
- 빨간색과 느낌표를 쓰지 않는다 (§2 ⑥). 권한이 켜지면 바로 사라진다.
- 이룸이 화면에는 넣지 않는다. 요금제, 결제, 크레딧 안내도 이룸이 화면에 넣지 않는다.

## 5-9. 안내 창·시트 규칙 (#1272)

> 크레딧 더 받기 시트, 광고 보상 받은 순간 창, 크레딧 안내 창, 광고 대기 창이 이 규칙을 따른다.
> 부품은 `core/widgets/elum_guide_panel.dart` 하나다. 새 안내 창·시트는 이것으로만 만든다.

**무엇을 쓰나**

| 모양 | 언제 | 부품 |
| --- | --- | --- |
| 창 (가운데) | 한 번 읽고 닫는 안내, 받은 순간, 기다림 | `showElumGuideDialog` + `ElumGuidePanel(placement: dialog)` |
| 시트 (아래) | 고를 길이 둘 이상 (광고, Pro, 꾸러미) | `showElumGuideSheet` + `ElumGuidePanel(placement: sheet)` |
| 홈 안내 카드 | 미리 알림, 닫을 수 있음. 홈에는 한 번에 하나 | `HomeNoticeCard` |
| 실패 팝업 | 실패. 에러 코드와 붉은 확인 | `showFailure` (안내 창을 실패에 쓰지 않는다) |

**순서** (위에서 아래로, 빠지는 칸은 자리도 없다)

1. 그림: 루미, 크레딧 표 PNG (`ElumGuideIllustration`). 크기는 창 96, 시트 120 (`ElumGuideIllustrationSize`). 코드로 그리지 않는다
2. 제목: 한 문장. 이모지는 제목 앞 1개까지
3. 제목 옆 표지 (있을 때만): 요금제 칩 `PlanTierChip` 처럼 "누구 기준인지"
4. 한 줄 설명: 한 문장, 회색
5. 내용 줄: 표 줄 `ElumGuideRow` (아이콘 타일, 항목, 오른쪽 값), 설명 줄 `ElumGuideNote`, 구분선 `ElumGuideDivider`, 고를 길 칸
6. 주 버튼 1개: 채운 민트 (`ElumGuideAction`)
7. 보조: 글자 버튼 (`ElumTextLink`, `Pro 알아보기` 링크, 닫기)

간격은 토큰만 쓴다: 그림 > 제목 16(`space.md`), 제목 > 설명 8(`space.xs`), 머리 > 내용 > 버튼은 시트 24(`space.lg`), 창 16(`space.md`).

**버튼 위계**

- 채운 버튼은 한 화면에 하나다. 시트에서 광고 칸의 `광고 보기` 가 채운 버튼이면 Pro 칸은 테두리 버튼(`ProUpsellStyle.outlined`), 꾸러미와 닫기는 글자 버튼이다.
- 받은 순간 창, 안내 창은 `알겠어요`, `이어서 만들기` 같은 주 버튼 하나만 둔다.

**아이콘과 이모지**

- 이모지는 창·시트 제목 앞 1개만 쓴다. 표 줄, 설명 줄, 칸 제목, 버튼, 홈 안내 카드에는 쓰지 않는다.
- 줄 머리는 `AppAssets.icon*` 선 아이콘을 둥근 타일 위에 얹는다 (`ElumGuideIconTile`: 타일 32, 모서리 10, 아이콘 16, 홈 안내 카드 타일과 같은 바탕색).
- 맞는 아이콘이 없으면 기존 아이콘 SVG 와 같은 viewBox, 선 굵기로 새로 만들어 `AppAssets` 에 등록한다.
- 고를 길 칸(광고 칸 등)의 머리는 그림 타일(`ElumGuidePictureTile`: 타일 44, 모서리 12, 홈 안내 카드 타일과 같은 모양)에 PNG 그림을 얹는다.

**말**

- 해요체, 한 문장에 정보 하나. 문구에 중간점(·)을 쓰지 않는다.
- 비교·과장 금지: `Pro가 더 이득`, `훨씬`, 할인 강조를 쓰지 않는다. Pro 안내는 사실만 적는다 (`Pro는 일과 글이 제한 없어요`).
- 값은 서버 단가, 지급량, 요금제 권한에서 계산한다. 숫자를 문구에 박지 않는다. 서버가 숫자를 주지 않으면 숫자 없는 문구로 둔다.
- `제한 없음` 은 정말 횟수 제한이 없을 때만 쓴다. 하루 한도가 있으면 `하루 N번 무료`.

**못 쓸 때**

- 쓸 수 없는 길은 숨기지 않고 버튼을 끄고 이유를 한 줄로 적는다 (`오늘은 다 받았어요. 내일 다시 볼 수 있어요`).
- 이 기기에서 아예 없는 길(광고 없는 요금제 등)은 칸째 숨긴다.
- 확인 중에는 꺼진 버튼과 준비 문구를 보인다. 빈 칸으로 두지 않는다.

**움직임**

- 누르는 모든 버튼, 카드, 줄은 `AppPressable` 눌림(살짝 줄었다 돌아옴)과 가벼운 햅틱(`core/haptics/tap_haptics.dart`)을 쓴다.
- 창·시트가 열리면 머리, 내용, 버튼 묶음이 위에서부터 차례로 떠오른다 (`AppFadeSlideIn`, 간격 `AppMotion.sectionStagger`). 뼈대가 해 준다.
- 숫자가 바뀌면 세며 바뀐다 (`ElumGuideCountUpText`, `AppMotion.valueChange`). 받은 크레딧 `+N`, 잔액이 그렇다.
- 받은 순간 그림은 튀어 오른 뒤 위아래로 두 번 둥실하고 멈춘다 (`ElumGuideRewardIllustration`, `celebrationEntrance` 다음 `float`).
- 홈 안내 카드는 아래에서 살짝 올라오며 나타나고, 닫으면 접히며 사라진다.
- 시간과 곡선은 `AppMotion` 토큰만 쓴다. 기기 "동작 줄이기"(`MediaQuery.disableAnimations`)면 모두 바로 끝 모습으로 보인다.

**강제**

- `tool/design_rules.yaml` `guide-dialog-skeleton`: 내용을 직접 그리는 창(`showElumDialogContent`)은 뼈대 파일에서만 부른다. 이미 있는 창은 동결 목록에 있고, 늘리지 않는다.
- 시트는 `showElumSheet` 로만 띄운다 (`material_wrappers`). 안내 시트는 `showElumGuideSheet` 를 쓴다.

# 6. 부드러움 — 모션

> 모션 값은 코드에 있고(`app_motion.dart`) 문서가 없었다. **여기가 그 자리다.**
> 화면에서 `250ms` 같은 숫자를 직접 쓰지 않는다.

| 토큰 | 시간 | 언제 |
| --- | :-: | --- |
| `instant` | 100ms | 손가락이 닿은 반응 |
| `fast` | 200ms | 선택 상태 · 작은 전환 |
| `normal` | 300ms | 카드·리스트 등장 |
| `slow` | 400ms | 페이지 전환 · 모달 |
| `emphasis` | 500ms | 온보딩 · 특수 진입 |
| `shake` | 440ms | **틀렸을 때** — 색 대신 움직임으로 알린다 |

## 부드럽다는 건

| 규칙 | 내용 |
| --- | --- |
| **끊기지 않는다** | 화면이 바뀔 때 요소가 사라졌다 나타나지 않는다. 이어진다 |
| **순서가 있다** | 여러 요소가 동시에 튀어나오지 않는다. 위에서 아래로 시차를 둔다 |
| **되돌아간다** | 뒤로 갈 때는 왔던 방향 그대로 |
| **기다리게 두지 않는다** | 200ms 넘게 멈춰 있으면 스켈레톤을 띄운다 |
| **모션을 끌 수 있다** | 시스템에서 애니메이션을 껐으면 따른다 ✅ 이미 대응됨 |

## 오류는 색이 아니라 움직임으로

```
PIN 틀림 · 코드 틀림
┌─────────────────┐
│  ← ⟷ →          │   한 번 흔들고 멎는다 (440ms)
│  ○ ○ ○ ○        │   빨간 테두리 ❌
└─────────────────┘   경고 아이콘 ❌
```

> **이룸이 휴대폰에도 깔리는 앱이다.** 틀렸다고 화면이 빨개지면 다시 안 연다.

# 7. 디테일 — 손끝과 눈

## 7-1. 손끝

| 항목 | 값 | 왜 |
| --- | --- | --- |
| 최소 터치 영역 | **48 × 48** | 50대 손가락 · 20대 소근육 |
| 버튼 사이 간격 | **8 이상** | 옆 버튼 오탭 방지 |
| 위험 버튼 | 다른 버튼과 **떨어뜨린다** | 삭제를 잘못 누르면 되돌릴 수 없다 |
| 누른 느낌 | `instant`(100ms) 축소 또는 명도 변화 | 눌렸는지 모르면 두 번 누른다 |
| 스크롤 중 탭 | 무시한다 | 스크롤하다 눌리는 사고 |

## 7-2. 눈

| 항목 | 값 |
| --- | --- |
| 본문 최소 | **16** (50대 기준. 14 이하 금지) |
| 설명 최소 | **14** |
| 명암비 | 본문 **4.5:1 이상** · 큰 글자 3:1 이상 |
| 한 줄 길이 | 너무 길면 눈이 길을 잃는다. 좌우 여백 24 유지 |
| **시스템 글자 확대** | 🟡 **보호자 홈·설정은 대응했다** (1.0 ~ 3.1배). 나머지 화면은 아직이다 — §8 QA 항목 |

> 🟡 **시스템 글자 크기를 키운 보호자에게 화면이 깨진다 — 보호자 홈·설정은 고쳤다.**
> 50대 보호자가 흔히 켜 두는 설정이다. **고정 높이 컴포넌트부터 점검한다**
> (목표 칩 68 고정이 이미 문제를 내고 있다).
>
> 고친 방식: 시안 높이는 **최소 높이**(`minHeight`)로 두어 기본 배율에서는 시안 그대로이고 커지면 늘어난다.
> 진행률 `NN%` 는 `FittedBox(scaleDown)` 한 덩어리, 이미 큰 인사말만 2배에서 멈춘다.
> 앱 전체 배율을 묶지 않는다. 테스트는 `font_scale_home_settings_test.dart`.

## 7-3. 입력

| 항목 | 규칙 |
| --- | --- |
| 키보드가 가리지 않는다 | 입력칸이 키보드 위로 밀려 올라온다 |
| 자동 넘어감 | PIN·코드는 마지막 자리 채우면 **자동 제출** |
| 글자 수 | 제한이 있으면 **미리** 보여 준다 (`0/20`) |
| 붙여넣기 | 코드 입력은 붙여넣기를 허용한다 |
| 완료 후 | 키보드를 내린다 |

## 7-4. 빠뜨리기 쉬운 것

| 항목 | 점검 |
| --- | --- |
| 뒤로가기 | 하드웨어 뒤로가기(안드로이드)도 같게 동작하는가 |
| 화면 회전 | 세로 고정인가 |
| 긴 이름 | 이름이 10자여도 제목이 안 깨지는가 |
| 0건 · 1건 · 100건 | 목록 개수가 극단이어도 괜찮은가 |
| 앱 복귀 | 백그라운드 갔다 오면 상태가 남아 있는가 |
| 연속 탭 | 버튼을 빨리 두 번 누르면 두 번 실행되는가 |

## 8-1. 화면 공통 (11항목)

# 10. 금지

| 금지 | 왜 |
| --- | --- |
| 화면을 설명으로 채우기 | 길면 아무도 안 읽는다 |
| 정상 경로만 그리기 | 그 "나중"은 대개 오지 않는다 |
| 빈 상태 = 로딩 | 기다릴지 포기할지 모른다 |
| 에러 코드 숨기기 | 제보를 받아도 추적을 못 한다 |
| 삭제·탈퇴를 주 버튼으로 | 오탭으로 되돌릴 수 없는 일이 생긴다 |
| 이룸이 화면 입력 오류에 붉은 표시 | 겁먹으면 앱을 안 연다. 실패 팝업은 예외로 시안 `로그인실패` 그대로 붉다 (#433) |
| 자유 텍스트만 받기 (보상) | 글자를 못 읽으면 의미가 없다 |
| 연령을 암시하는 말 | 20대 당사자도 쓴다 |
