## 완료

### 서버

| 항목 | 내용 |
|---|---|
| 계정 구조 | `Member`(로그인 계정)와 `Profile`(당사자)를 분리. 일과는 프로필에 속한다 |
| 소셜 신원 | `AuthIdentity` — `provider + providerUserId`가 계정 조회 키. **이메일로 합치지 않는다** |
| 검증기 | 카카오·네이버(REST 호출), 구글·애플(ID 토큰 서명 검증) 4종 |
| 세션 | `RefreshToken` — 해시만 저장, 회전, 재사용 감지 시 계정 전체 폐기 |
| 엔드포인트 | `POST /api/auth/oauth/{provider}`, `/refresh`, `/logout` 추가 |
| 기존 API | `/signup`·`/login` 그대로 유지 — 이미 배포된 APK가 계속 동작한다 |
| 토큰 수명 | 액세스 1일 / 리프레시 180일 |
| 연동 | 계정 정지·강제 로그아웃·탈퇴 시 세션도 함께 끊는다 |
| 마이그레이션 | `V10`(프로필 분리) `V11`(리프레시 토큰) `V12`(소셜 신원) |
| 검증 | 운영 스키마 복사본에 V10~V12 적용해 이관 확인, 전체 테스트 통과 |

### 개인정보처리방침

- https://twin-fang.github.io/elum/privacy.html
- `gh-pages` orphan 브랜치로 게시. `docs/`를 소스로 쓰지 않아 내부 문서가 노출되지 않는다

### 카카오

- 앱 생성, 카테고리 교육, 앱 대표 도메인 등록
- 플랫폼 키 > 네이티브 앱 키에 Android(패키지명·키 해시 2개)·iOS(번들 ID) 등록
- 카카오 로그인 활성화
- 동의항목 — 닉네임·프로필 사진·이메일 필수 동의

### 구글

- 인증 플랫폼 브랜딩 — 앱 이름, 지원 이메일, 홈페이지, 개인정보처리방침, 승인된 도메인
- 데이터 액세스 — `openid` · `userinfo.email` · `userinfo.profile` (민감하지 않은 범위만)
- **프로덕션 게시 완료** — 테스트 100명 제한 해제됨
- 클라이언트 4개 — Android(디버그·릴리스), iOS, 웹
- 로고는 올리지 않았다. 올리면 브랜드 확인 심사가 걸린다

> 웹 클라이언트의 `client_secret`은 **저장하지 않았다.** 서버는 ID 토큰 서명만 검증하고
> 인가 코드 교환을 하지 않아 시크릿이 필요 없다. 앱에도 넣지 않는다.

### 애플

- App ID `kr.twinfang.elum`에 **Sign In with Apple** 권한 — 프로젝트 초기부터 켜져 있었다
- 프로비저닝 프로파일 `Elum AppStore Distribution`에 `com.apple.developer.applesignin` 포함 확인
  (2026-07-21 발급, 2027-07-21 만료). **재발급 불필요** — 권한을 켠 뒤 발급됐다
- `Runner/Runner.entitlements` 추가 후 Runner 타겟 3개 컨피그에 `CODE_SIGN_ENTITLEMENTS` 연결
  → 이것만 빠져 있었다. 프로파일이 권한을 허용해도 앱이 요청하지 않으면 로그인이 실패한다

> 프로파일은 **발급 시점의 capability를 박제한다.** App ID를 나중에 바꾸면 기존 프로파일은
> 자동으로 갱신되지 않으므로, 권한을 새로 켠 경우에는 재발급해야 한다.
> 포함 여부는 아래로 확인한다.
>
> ```bash
> security cms -D -i <프로파일>.mobileprovision | plutil -extract Entitlements xml1 -o - -
> ```

## 남은 일

### 1. 네이버 마무리

- [ ] **iOS 환경 추가** — URL Scheme `elum`, 다운로드 URL(App Store Apple ID 필요)
- [ ] 카테고리를 `기타` → `교육`으로 변경
- [ ] **검수 요청** — 지금은 `개발 중`이라 멤버로 등록한 계정만 로그인된다

> 검수는 **앱에 네이버 로그인을 붙인 뒤** 신청해야 통과한다. 네이버가 실제 동작을 본다.
> 승인에 며칠 걸리므로 앱 구현이 끝나면 바로 신청한다. 스토어 심사 직전에 하면 늦는다.

### 2. 앱(Flutter) 구현

- [ ] SDK 4종 추가 — `kakao_flutter_sdk_user`, `flutter_naver_login`, `google_sign_in`, `sign_in_with_apple`
- [ ] `AndroidManifest.xml` — 카카오 리다이렉트 스킴
- [ ] `Info.plist` — 카카오 스킴, 네이버 URL Scheme(`elum`), 구글 reversed client ID,
      `LSApplicationQueriesSchemes`
  - 구글 reversed client ID는 iOS 클라이언트 ID를 뒤집은 형태다
    (`com.googleusercontent.apps.<ID 앞부분>`). 콘솔에서 받은 plist에도 들어 있다
- [ ] 로그인 화면 4버튼 + `POST /api/auth/oauth/{provider}` 연동
- [ ] 리프레시 토큰 보관(Keychain/Keystore)과 자동 갱신
- [ ] 설정 화면에 개인정보처리방침 링크

> **URL 스킴은 `.env`로 주입할 수 없다.** 빌드 타임에 필요해서 네이티브 파일에 직접 적어야 한다.
>
> 갱신 요청은 **동시에 여러 번 나가지 않게 묶어야 한다.** 리프레시 토큰은 회전 방식이라
> 같은 토큰으로 두 번 요청하면 재사용으로 간주돼 로그아웃된다.

### 3. 배포 반영

- [ ] **GitHub Secret `APPLICATION_PROD_YML`** — `jwt` 블록(토큰 수명)과 `oauth` 블록 반영
- [ ] **GitHub Secret `CLIENT_ENV_FILE`** — 앱 키 반영
- [ ] 서버 변경 커밋 → develop → 배포
- [ ] 배포 후 실제 로그인 동작 확인

> ⚠️ **`application-*.yml`은 gitignore라 커밋되지 않는다.** 토큰 수명을 1일/180일로 바꿔 두었지만
> 시크릿을 갱신하지 않으면 배포에 반영되지 않고 옛 값(1시간/7일)으로 동작한다.

## 값이 있는 곳

키와 시크릿은 아래에만 있다. **모두 gitignore 대상이라 커밋되지 않는다.**

| 파일 | 담긴 것 |
|---|---|
| `server/src/main/resources/application-prod.yml` | 카카오 앱 ID, 네이버 ID/시크릿, 애플 번들 ID, 토큰 수명 |
| `server/src/main/resources/application-dev.yml` | 위와 동일 (로컬 실행용) |
| `client/.env` | 카카오 네이티브 앱 키, 네이버 ID/시크릿/서비스명 |
| `client/android/key.properties` | 릴리스 서명 정보 |

배포용 값은 GitHub Secret `APPLICATION_PROD_YML`·`CLIENT_ENV_FILE`에 넣는다.
필요한 키 이름은 `client/.env.example`에 정리돼 있다.

## 알아 둘 제약

| 항목 | 내용 |
|---|---|
| **네이버 앱 특정 불가** | 네이버는 토큰이 어느 앱 것인지 알려주는 값을 주지 않는다. 다른 네이버 앱 토큰으로도 사용자 조회가 성공한다. 없애려면 인가 코드 교환 방식으로 바꿔야 한다 |
| **애플 이메일 숨기기** | `privaterelay` 주소가 오며 앱마다 다르다. 이메일로 사람을 식별할 수 없다 |
| **애플 이름은 1회만** | 최초 로그인에만 이름이 온다. 필요하면 그때 저장해야 한다 |
| **카카오 이메일 없는 계정** | 전화번호로만 가입한 계정은 이메일이 없다. 필수 동의면 그 사용자는 이메일 등록 단계에서 이탈한다 |
| **이메일로 계정 병합 금지** | 같은 이메일이 이미 있으면 409로 알리고 합치지 않는다. 검증되지 않은 이메일로 남의 계정에 올라타는 경로를 막기 위해서다 |
